# 项目工作流迁移

先读目标项目的 AGENTS.md、现有决策记录、检查命令和 CI。已有 ADR 或笔记机制时优先整合，不创建竞争性记录体系。用户授权和目标项目规则优先，不转移来源项目的提交、发布或生产权限。

本 Skill 分发包包含 `workflow.py` 和 `payload/`，不需要来源仓库或网络。

1. 运行 `python3 <本目录>/workflow.py install <目标项目>` 查看计划；默认只读。
2. 检查冲突。相同已有文件可接纳；不同文件保留，按目标项目实际约定人工合并。不得为通过安装而删除已有规则或绕过冲突检查。
3. 已授权接入时运行相同命令加 `--apply`。需要独立 GitHub Actions 时加 `--ci`；已有 CI 可直接调用安装后的校验入口。
4. 检查项目真实能力，补全 `docs/FEATURE_MAP.md`，已有地图优先沿用。安装生成的空表不是能力核对的完成证据。
5. 在项目根目录执行 `python3 .agents/workflow.py verify`，按实际接入改动检查 CI 和项目约定。只提交本次文件；提交、发布按目标项目授权执行。

升级使用新包重复 install；冲突时先比较现有自定义内容与包内容，不强制覆盖。`doctor` 检查安装完整性和运行时，`verify` 执行笔记结构/格式/归档检查。完整迁移、命令和限制见 [README](README.md)。
