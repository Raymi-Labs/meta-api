# 公告邮件同步

超级管理员在“系统设置 → 仪表盘设置 → 系统公告”管理公告。添加或编辑弹窗只修改本地草稿，点击“保存设置”才发布到网站。

发布时可选择“发布新公告时同步邮件”（默认勾选）。开启后，本次新增公告会进入后台发送队列；每次最多同步 10 条新公告，取消勾选则只保存网站公告。旧公告编辑、删除、排序、重复保存及删除后重新添加相同公告都不会再次群发。发布日期沿用网站展示用途，邮件在保存后发送，不提供预约发送。

## 收件范围与发送结果

收件人取发布时启用、未删除且绑定有效邮箱的平台用户，相同邮箱去重。发送前再次核对账号资格，逐封发送，各用户看不到其他收件人的邮箱。

正文和收件范围按点击保存时快照固定。后续编辑或删除网站公告不会撤回已入队的邮件；邮件按正文文本展示，Markdown 标记保留为文本。

同步邮件需要先完成平台 SMTP 配置。确有新邮件任务且 SMTP 未配置时，保存失败并保留本地草稿；可以配置 SMTP 后重试，或取消邮件同步后仅保存公告。

设置页的邮件记录显示每条公告的收件总数和发送进度，可翻页、刷新。状态含义：

| 状态 | 含义 |
| --- | --- |
| 待发送 | 已持久保存，等待后台处理 |
| 发送中 | 已被后台认领，正在尝试提交 |
| 已提交邮件服务器 | SMTP 接受本次邮件，不等于收件箱已收到 |
| 失败 | 明确未提交，有限重试后仍失败 |
| 结果未知 | 发送中断，无法判断邮件服务器是否接受；不自动重发 |
| 已跳过 | 收件账号或邮箱在发送前不再符合条件 |

大批量通知按节奏发送，不会一次性全部完成。发送记录仅超级管理员可读，不向页面返回收件邮箱。邮件的最终投递、退信或垃圾邮件归类需结合邮件服务商记录核实。

## API 兼容与升级

继续使用超级管理员 `PUT /api/option/`，公告请求示例：

```json
{
  "key": "console_setting.announcements",
  "value": "[{\"id\":\"new-unique-id\",\"content\":\"维护公告正文\",\"publishDate\":\"2026-10-26T08:00:00Z\",\"type\":\"warning\",\"extra\":\"\"}]",
  "email_sync": true
}
```

旧调用省略 `email_sync` 时只保存公告。成功响应的 `data.email_jobs_queued` 是本次新建的群发任务数，不是送达数量。`GET /api/option/announcement-email/jobs?p=1&page_size=10` 返回分页进度。

升级新增兼容的持久任务表，待发送记录可跨重启继续；发送租约过期记为结果未知以避免重复。发布超过 90 天且已全部处理的任务及收件快照会清理，公告防重摘要继续保留，清理记录不会重新触发群发。首次升级不会主动群发历史公告。版本发布与生产部署是独立步骤，生产升级仍使用受保护的 `newapi-update` 入口。
