# Claude 缓存时长计费

## 配置与计数

普通按量配置仍沿用 `CreateCacheRatio`：这是通用/5分钟缓存创建倍率，1小时价按既有 `1.6` 倍关系派生。此变更没有调整任何已配置单价、分组倍率或历史余额。

| 用量 | 普通计费 | 阶梯变量 |
|---|---|---|
| 非缓存输入 | 输入价 | `p` |
| 缓存读取 | 缓存读价 | `cr` |
| 明确5分钟创建 | 5分钟创建价 | `cc` |
| 明确1小时创建 | 1小时创建价 | `cc1h` |
| 有创建总量但未细分时长的余量 | 通用创建价 | `cc`（不伪造TTL） |

缓存创建总量已包含明细；总量、5分钟、1小时不可重复相加。只给明细时可推导总量；明确总量0不是缺失。流式usage按快照合并，不逐事件累加。新总量发生变化时，未同时报告的旧TTL明细不继续套用；总量未变时可保留已有细分证据。

阶梯判断 `len` 是包含缓存的完整输入长度，不含输出。只有总量而没有TTL明细时，创建量仍保留在 `cc` 和 `len` 中。表达式没有独立计价的缓存子类留在 `p` 按输入价处理，不能漏计；已有表达式若故意省略缓存变量，需要确认这种输入价回退符合其业务意图。

## 入口与兼容边界

原生 Messages 与 Chat 兼容入口，在最终上游为Claude用量语义时共用时长组成与普通费用计算；Chat入口不再把1小时创建按5分钟价处理，也不会把缓存only请求误判为无用量。语义由最终上游格式与明确usage标记决定，不靠模型名称或客户端路径猜测。Messages入口使用OpenAI、Responses、OpenRouter等包含缓存的输入总量时，普通倍率先扣除读写缓存，再按各分项价格计费；阶梯按上游总量语义规范化，两种模式均只计入一次缓存。

普通Claude保留既有截断为整数quota的规则，兼容Claude使用相同规则。阶梯保持原有舍入规则；某些小额样本两种模式最多可能差1个内部quota，不自动更改历史舍入政策。免费分组仍按0结算。

上游负数、整数溢出、明确创建总量小于细分之和，返回异常响应而非正常消费；不在输出后重试，沿用错误退款路径。一般断流、用户取消、独立工具费用及上游缺失全部usage的原有策略不在本次统一改写范围内。

## 管理、价格页、日志

- `/api/option/` 返回只读 `CacheCreationPriceMeta`，依据已启用模型的缓存配置及Anthropic端点能力，告知编辑器哪些模型展示5分钟标签和派生1小时价。该字段不保存为收费配置；新建或未发布模型尚无能力信息时保留通用提示。
- 普通 `/api/pricing` 提供 `supports_cache_creation_ttl` 和 `cache_creation_ratio_1h`，价格页不自行按模型名猜时长能力。声明能力不是上游实测保证；混合渠道或上游丢失细项仍需要按请求核查。
- 原生与兼容消费日志保存相同的5分钟、1小时、未细分创建量和结算时价格；新增 `cache_creation_tokens_unclassified` 为只读日志字段。
- 摘要与展开公式保留未细分余量，旧日志有矛盾时提示明细冲突，不用当前价格重算实际扣费。阶梯优先使用当次保存的 `tiered_params`。

## 跨协议输入与历史统计

新文本消费日志保存原始上游 `prompt_tokens`，并在 `other.prompt_tokens_semantic` 中明确其含义：`inclusive` 表示已包含缓存，`non_cache` 表示不包含缓存。`usage_semantic` 和兼容 `claude` 标记跟随实际用量语义。全局缓存率的分母为完整输入总量；公开令牌分布的非缓存输入则是完整输入减去缓存读写，前端日志摘要及公式遵循同一规则。分组健康与渠道亲和性统计也按实际用量语义累计。

旧 Messages→OpenAI 日志可能错误地带有 Anthropic 标记，但不能直接按转换链覆盖它：部分旧 OpenRouter 日志已在落盘前扣除了缓存。因此仅在同时满足以下条件时只读修正旧日志的解释：原有 Anthropic 标记、转换链从 Claude Messages 到 OpenAI Compatible 或 OpenAI Responses、阶梯计费、存在正缓存量、保存的 `tiered_params.len` 与落盘 prompt 精确相等。新语义字段优先于这一兼容判断；缺少充分证据的旧普通倍率记录继续保留原解释。

2026-10-23 生产排查快照中的 516 条阶梯记录属于此误标情形，缓存读量 19,972,736、完整输入 23,840,639，正确全局缓存率约为 83.78%，而重复加缓存的旧显示约为 45.59%。这批阶梯记录的结算快照已使用正确分母，未发现此显示问题造成重复扣费。另行确认的普通倍率代码路径存在缓存重复计价，本次修正其未来结算；历史额度、消费日志、渠道映射和定价均不改写。

## 验证与发布

完整控制器回归使用合成上游HTTP与隔离SQLite，检查钱包、令牌余额、消费日志和失败退款。覆盖两入口、流式/非流式、普通/阶梯，另有100k边界、缺失/显式0、变化的usage快照、免费分组及非法值回归。

跨协议控制器回归另覆盖 Messages→Chat/Responses、流式/非流式、普通/阶梯共8种组合；服务层验证原生、明确Anthropic语义、OpenRouter和缓存创建分项，模型层验证新语义、历史长度证据、旧OpenRouter及缺证据回退。统计兼容在Go中处理，不新增数据库专属SQL或迁移；这些新回归使用SQLite，未单独运行MySQL/PostgreSQL集成环境。

浏览器回归使用真实编辑器和展示函数、拦截全部API；覆盖自动1小时预览、保存/重开、通用模型不误标TTL、未细分公式、移动布局。无真实模型请求或收费验证。

修正曾经少扣的路径后，未来费用可能高于错误实现下的金额，但配置价格不变。部署需前后端配套更新；合并代码不是部署成功。此变更不追扣、不自动退款、不改线上配置。
