# OpenRouter 充值与消耗

账户管理 → OpenRouter 使用一个“充值与消耗”看板。原模型消耗看板、现金收益、现金流三个独立入口已合并；查看数据无需启用现金账本、绑定或核实凭证。

## 页面与口径

- 账户累计：累计购入额度和累计消费按官方 credits 金额乘以 1.05 估算含手续费的美元成本。余额显示官方购入额度减消费后的可用 USD。三项均覆盖账户生命周期。逐笔充值订单可通过“OpenRouter 官方账单”查看。
- 区间消耗：最近 30 个完整 UTC 日内选择日期或最近 7/30 天，显示上游消费与本站消耗折合人民币及请求数。点击区间标题旁的信息图标可查看统计口径及换算比例。上游USD（含单列BYOK）固定乘6.7；本站先还原平台闪电数再除以5，六位小数展示。该比例由用户指定，不使用站点当前值为1的usd_exchange_rate，不修改全站设置或扣费。
- 明细：默认按渠道，支持按模型、按日期切换。渠道用名称和 ID 区分；渠道金额只有本站消费的人民币折算，不将账户级上游支出强行分摊给渠道。模型/日期保留双方消费与请求对照及单列 BYOK 外部成本。未知的一侧显示 `--`，不补成零。
- 搜索、分页和导出只影响明细，不改变顶部整个日期范围的合计。CSV 保留归集对象、本站请求数、本站消耗三列，消耗表头明确CNY并使用与页面一致的人民币数值；模型名称以历史日志的 upstream_model_name 优先，否则使用原 model_name。

官方 keys 自动匹配当前本站渠道，混合账户密钥的渠道排除；当前归属不证明历史归属，站外调用、密钥变更、已删除渠道及清理日志可能造成上下游差异。人民币折算用于对照，不证明实际净收付或现金利润，BYOK 外部成本不加入 OpenRouter 支出。

## 统一快照

日常页面只读取管理员 `/api/upstream_accounts/:id/openrouter/finance` 快照。每个服务进程启动预热最近 30 个完整 UTC 日，每 5 分钟后台更新一次；同一次日志遍历生成模型和渠道统计，不新增渠道日志扫描。日期、搜索及维度切换在已取得的快照上完成，不触发远端请求或重新统计。手动刷新只读取已有快照，不绕过采集间隔。

快照按账户和凭据隔离，后台最多两路并发，每次两分钟总超时。冷启动显示准备状态并自动短轮询；刷新失败保留同日期范围的旧分项和保守时间，模型与渠道本地分项一起保留。页面展示快照时间及错误，未知不补零。停用账户不采集，删除账户清理缓存；多副本分别预热。

## 历史接口兼容

既有 cash_* 表、资金审计写入、现金报表和受权限保护的维护 API 保留，不更改钱包、扣费、路由或已有凭证。旧 `/cash/report` 不再自动预热 7/30 日，只有兼容调用登记的范围由后台调度生成并五分钟刷新；闲置30分钟回收，仍限128个范围、两路并发和90秒总超时。自定义范围旧API保留，日常页面统一使用官方支持的30个完整UTC日。
