# 企业API能力对等：本地实现与对抗性验收

日期：2026-11-13（America/New_York）

本报告记录前一轮验收。企业价格来源随后按用户要求改为直接复用所选分组倍率，当前规则和操作位置见[企业选组倍率](2026-11-13-enterprise-group-multiplier.md)。

## 业务目标

企业客户与个人客户使用同一套现有API、协议、参数、任务与模型能力。企业身份只改变适用价格、付款来源和明确配置的企业/成员预算与模型权限。成员管理不应成为按接口类型裁剪服务的理由。整体UI保持用户的本地版本。

## 实现框架

```text
账号授权组 → 原模型/渠道/路由权限
企业计费组 → 企业特殊倍率、时间价与价格快照
请求付款方 → 企业成员预算（或原个人资金）
             ├─ 同步：统一预留 → 实际结算/退款
             ├─ 视频/音乐任务：持久付款快照 → 持久终态意图 → 原子差额/退款
             ├─ Midjourney：提交意图 → 可信受理结果 → 结算 → 可信轮询终态冲正
             └─ Realtime：同一会话累计预留 → 关闭并等待双向读协程 → 最终结算
```

不增加一套模型价格引擎。企业 `BillingGroup` 继续作为现有特殊倍率和时间价的价格身份；新增 `EnterpriseBillingGroup` 请求上下文和 `RelayInfo.BillingUserGroup()`，账号 `UserGroup` 保留授权用途。企业定价组不再增加或删除账号可用渠道组。模型、分组目录和令牌展示读取同一价格身份。

## 本轮完成的改动

### 全部API入口

移除企业专用路由类型白名单；所有已注册个人API入口共用原有鉴权与请求处理。企业/成员冻结、停用、令牌状态、额度和显式模型策略仍检查；不赋予平台管理员权限，不开放普通账号原本无权访问的渠道。

### 视频、音乐等通用任务

- Task增加企业与成员归属、初始收费快照、首次统计确认、最终金额及待结算标记；历史任务默认个人。
- 任务落库后企业初始收费可幂等恢复；首次企业结算与令牌已用量原子更新。
- 成功/失败的状态CAS同时保存最终金额意图，之后资金、令牌用量、调整账单与确认标记在同一主库事务提交。
- 重复轮询、并发完成和进程重启不会重复补扣/退款；成员停用、令牌删除或企业开关关闭后仍按原主体完成已受理任务。
- 后台重试处理待确认账务，企业账本是财务事实，日志不充当唯一资金凭据。初次请求次数、渠道用量及终态渠道差额均与任务确认同事务，后台恢复不会漏记或重复统计。
- 企业任务单独按持久主体轮询，防止不同渠道账号返回相同上游ID时覆盖付款记录；原地址与提交密钥绑定，渠道改址不带走旧凭据。
- Token计价任务读取提交时的倍率快照，后续改价格不重新解释既有任务。
- API任务查询/内容/续作按账号、企业和成员代次隔离；个人令牌不能读取同账号企业任务，企业令牌也不能读取个人任务。
- 上游发送后结果不明保留预留并进入待对账，不自动退款重发；已受理但任务落库失败保留请求账务证据。渠道暂时不可用不伪造上游失败；保留原任务以待后续轮询或超时流程。

### Midjourney

- 提交、动作及换脸复用企业预留和结算；任务保存原付款主体、初始收费、受理与结算状态。
- 重复上游任务ID、排队/已存在返回按同主体与凭据核对，避免重复收费；免费动作不得在失败时凭空退款。
- MJ轮询按用户、企业、成员、渠道、提交时地址和实际单个密钥分批；同ID保留全部本地记录，密钥或地址变更不改写旧任务连接，不跟随轮询重定向发送凭据。
- 查询、批量查询、图片、image-seed、父任务与customId跟进动作校验付款归属。
- 普通用户令牌提交的notify不是上游真实结果证明：企业notify核验归属并确认收到，资金与任务终态以已配置渠道的后台轮询为准，避免伪造失败骗退款。
- 可信终态与账务冲正、渠道统计在主库内幂等完成，失败保留后台恢复条件。
- 补齐共享action/simple-change解析器的长度检查，短参数返回协议错误而非越界；MJ图片代理的初始地址也执行现有fetch安全策略，拒绝被策略禁止的地址。

### Realtime

- 企业会话增量用量复用统一资金会话预留，不读取个人余额、订阅或个人令牌剩余额度。
- 初次预留可以覆盖后续用量，不重复占用；最终结算扣真实累计费用。
- 双向WebSocket读取在最终结算前关闭并等待退出，使用互斥保护共享用量；同一事件ID的重复response.done不重复累计。
- 已产生用量但下一次额度预留失败时仍纳入最终结算，沿用企业预算可短暂为负、阻止后续请求的规则。

### 体验区付款契约

- `/pg/chat/completions` 在选路前解析 `payer`，只接受 `personal` 或 `enterprise`；缺省仍个人。
- `payer=enterprise` 根据登录账号解析有效企业及成员，执行企业模型限制，之后复用原Relay和企业资金会话。
- 生图会话入口复用相同payer解析，令牌复用限定用户、付款方、企业和成员代次，避免拿到个人或已离职代次的令牌。
- 本轮没有改整体界面，也没有在现有体验页新增付款选择控件；后端可接受显式payer。现有前端不传payer时仍按个人付款，不能将其描述为页面已自动使用企业额度。

### 首页语言修复

仅将“工作区、模型生态、为开发者准备、自动路由”从已有控制台翻译同步至16个公开语言字典及keys清单；简体沿用源文案。没有修改用户的布局、字号、配色、悬停效果。

## 不扩大范围的原则

- 个人账户不自动迁移到企业，也不改变个人Group或个人历史账本。
- 同步图片和其他既有API走同一资金抽象，不复制供应商实现。
- 企业定价仍由平台配置，前端不能传入企业ID、成员ID或价格来获得权限。
- 企业应用开关控制新请求；已接受任务仍有账务处理责任。
- “API类型不再额外限制”不等于所有供应商在生产已经逐一实测。
