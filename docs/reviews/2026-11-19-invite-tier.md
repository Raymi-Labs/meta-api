# 邀请档位 B–I 验收记录

实现范围覆盖规划 B–I：六档分配、周期账单、欠款抵扣、晋级部门、管理和用户 API、钱包/运营设置入口、语言资源、有效消费、实名及风险处置。用户确认的调整为“集中注册只记录风险，人工冻结”；划转门槛沿用原值、实名要求默认关闭、补足采用 FIFO。

## 对抗性审查修复

- 重复支付、首次奖金和注册奖励分别有持久化幂等凭证；退款释放二级月基数。
- 收款人与支付源加锁，退款按收款人 ID 排序；防止多实例重复结算及结算/退款交叉。
- 冻结和实名要求不因关闭入池开关被绕过；冻结延后不耗重试次数。配置读取与启用校验分离，缺少密钥时仍保留已持久化的激活和冻结边界。解冻、实名批准和补出账会恢复待发放扫描。
- 全额抵债后的退款恢复欠款；日限额释放包含抵债金额。混合钱包扣回同步减少可划转额度，账单扣减包含日上限截断，已处理账单满足应发 = 实发 + 扣减。
- 提前发放申请与审批均检查档位，审批不能包含申请后的新台账。
- 部门部长晋级结束旧成员记录，避免被成员维护任务误降档。
- 处置撤销只恢复动作涉及字段；清退撤销检查关系成环，不覆盖已改绑用户。
- API 强制所有者范围、管理员层级限制，实名原文仅 Root 可查并审计。
- 配置保存完整快照、首次启用时间不可重置，拒绝截断数组、超池组合与金额溢出。

## 实现边界

17 种语言包均包含新键和占位符；当前新增文本的非中文语言使用英文回退，不伪称已完成各语言母语审校。浏览器设备信号可被清除；付款主体仅在服务端确实有数据时采集。集中注册扫描最多一千个候选，不能作为完整反作弊识别保证。真实支付渠道和生产负载没有在本地测试中发生；发布成功也不表示已部署生产。

CI 首轮在容器初始化失败：Actions 参数解析将单引号健康检查命令拆开，误把 `ping` 当成镜像名；未执行任何测试。健康检查已改用仓库现有工作流的双引号格式，重新运行验证。
