## 整体框架

```text
企业服务 /enterprise（原地址保留）
  ├─ 访客 / 非企业成员 → 联系开通；访客可登录后回到本页
  ├─ 企业所有者 / 企业管理员 → 企业工作台
  ├─ 普通成员 → 我的额度 → 令牌管理
  ├─ 平台管理员 → 企业管理
  └─ 定制需求 → 原有业务邮箱

企业资金 → 未分配余额 → 成员额度 → 企业令牌调用
角色规则 → 与后端权限一致，明确Owner与Admin区别
```

平台身份与企业身份分别判断。如果平台账号同时是企业成员，保留工作台/我的额度主入口和平台管理入口；仅平台账号直接进入企业管理。Root在企业开关关闭时仍能找到管理入口。

## 完成的优化

### 1. 企业定制升级为企业服务

- 主站顶部导航、页脚和页面标题统一为“企业服务”。
- 保留 `/enterprise` 及尾斜杠路由，原链接继续有效。
- 去掉重复模型Logo、宣传口号、供应商接入对比和线路演示。
- 改为企业余额、成员管理、审批、用量四项实际能力。
- 技术接入直接连接现有文档；原协议示例生成器及回归测试保留。
- 联系开通与定制咨询复用原有业务邮箱，没有新增收集个人资料的表单，也没有发送邮件。

### 2. 真实身份与异常状态

- 已加入企业时展示真实企业名称和角色，不用示例业务数据填充正式界面。
- Owner/Admin进入企业工作台，Member进入我的额度，并可打开令牌管理。
- 加载中显示状态；读取失败提供重试，不将错误解释为“未加入”。
- 冻结企业显示冻结状态并保留管理/额度入口，后端继续拒绝不允许的请求。
- 企业功能关闭时不显示缓存的企业信息；普通访客仍可查看企业服务介绍。
- 页面入口仅负责导航，不替代目标页面及后端的权限检查。

### 3. 角色和本人审批

| 身份 | 额度权限 |
| --- | --- |
| 所有者 Owner | 开通时指定，管理企业和管理员；可给自己分配额度，也可批准或拒绝本人申请 |
| 管理员 Admin | 管理普通成员及其申请；本人申请由Owner处理，不能自批 |
| 成员 Member | 使用分配的企业额度、创建企业令牌、申请追加额度 |

上一轮本人审批修复已在当前分支：已有待办更新后即可处理，不需要重建申请。批准仍受余额和申请金额约束；重复/并发审批只划拨一次，保留审计；所有权转移后按新角色判断权限。该修复不新增企业资金，也不转入个人钱包。

### 4. 视觉与多语言

- 复用现有品牌、顶栏、下载按钮、主题和页脚。
- 首屏以企业服务标题和按身份变化的主操作建立层级，不增加次要标签与营销段落。
- 额度分配流程允许换行，箭头与对应标签保持一起。
- 更新17种语言，复用现有翻译运行时。
- 手机下改为单列；德语等长标题使用适合界面的译名。

## 下一步讨论建议

1. **先验收这轮页面与权限规则。** 确认企业服务的内容、角色入口和Owner本人审批符合你的使用习惯。
2. **确认后再推送、跑三库CI并合并发布。** 这是当前最短的交付路径，不需要单独建立长期测试环境。
3. **第二批企业付款另排一轮。** 网页体验区、异步视频/音乐、Midjourney、实时语音尚未接通企业完整计费；继续保持拦截，不能仅放开白名单。

本轮没有引入SSO、部门管理、在线企业充值或自助创建企业，也没有将这些能力写成已支持。
