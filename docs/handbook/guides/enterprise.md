# 企业接入与定制

企业接入从实际工作负载开始：需要哪些模型、使用什么协议、由谁管理密钥，以及什么情况会影响业务。可通过[企业定制](/enterprise)了解方案，联系邮箱为 [nanashiwang@gmail.com](mailto:nanashiwang@gmail.com)。

## 联系前准备这些信息

| 信息 | 示例内容 |
| --- | --- |
| 场景 | 内部助手、客服、代码生成、图像或音视频生产 |
| 模型与协议 | 现有模型 ID、Chat Completions / Messages / Responses 等 |
| 负载 | 日请求量、峰值并发、平均输入输出与突发持续时间 |
| 时延目标 | 首字节、整体任务时长、可接受的失败比例 |
| 网络 | 部署地域、出口 IP、代理、专线或私有部署需求 |
| 权限与预算 | 密钥负责人、业务隔离方式、额度和告警需求 |
| 数据与支持 | 数据类型、保留要求、响应时间和迁移窗口 |

不要在首次咨询邮件中附上生产密钥、数据库密码或真实客户数据。

## 当前可复用的管理能力

本站已有账户、令牌、分组、额度限制、来源 IP 限制、模型限制、使用日志和管理员渠道管理。可以先按业务创建独立令牌，把测试与生产流量分开，并通过日志与通知监控消耗。

这些能力不等于完整企业工作区产品。共享预算池、团队成员角色、工作区级审计、统一身份管理或独立部署，应逐项确认实现与服务范围，而不是根据其他平台的同名页面推断已有。

## 迁移与验收

先选小流量业务验证协议、模型能力、缓存、流式和错误处理，再进行容量测试。记录输入输出规模和费用，以实际数据确定预算。为回退保留原有配置，并明确由谁决定切换。

私有部署、定制容量、专属渠道或特定数据条款需要单独约定。公开文档不构成固定 SLA、吞吐或“全模型零保留”的承诺。详见[数据与隐私](/docs/guides/privacy)。

## 日常管理建议

密钥只保存在后端或安全配置中，按用途分配，不多人共用一个无限额度令牌。交接或泄露后及时轮换；保留变更记录和联系渠道。平台管理员应遵循发布与回滚流程，避免在业务高峰直接改变全局渠道或计费配置。
