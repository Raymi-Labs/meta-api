# 认识元衡 API

元衡 API 将不同厂商的模型接入同一个网关。你可以在模型广场查找模型，用控制台创建的令牌调用，也可以在模型体验和元衡生图中试用。它基于 New API 建设；不同协议仍有各自的数据结构，不能只改模型名就假定所有功能通用。

## 先区分三个地址

| 地址 | 用途 |
| --- | --- |
| `https://meta-api.vip` | 网站、控制台和 API 服务 |
| `https://meta-api.vip/v1` | OpenAI 兼容 SDK 的常用 Base URL |
| `https://docs.meta-api.vip` | 公开文档，不接受模型调用或账户管理请求 |

文档可以匿名阅读。创建密钥、查看个人用量和充值需要登录主站；切换文档语言不改变账户权限、模型价格或分组。

## 四个核心概念

- **模型**：请求中的 `model` 标识符。显示名称、厂商名称和模型 ID 不是一回事，调用时复制实际 ID。
- **分组**：账户和令牌所选择的服务范围，影响可选渠道、模型与计费倍率。相同模型在不同分组中的可用性可能不同。
- **令牌**：提供给客户端或后端的 API Key，可配置有效期、额度、模型范围和来源 IP。它与网页登录密码、账户管理令牌不同。
- **渠道**：平台连接上游服务的配置。普通用户选择模型和分组，由网关分配可用渠道；管理员负责渠道运维。

## 能力如何确认

先看模型广场当前列出的模型和支持端点，再用自己的令牌查看可见模型。文档中的协议支持表示网关有相应入口，不表示所有模型、所有分组都已开放该功能。图片、音频、视频和工具调用尤其需要同时确认模型与上游支持。

参考资料中的专有功能不会自动成为本站能力。请阅读[兼容范围与功能边界](/docs/guides/compatibility)，避免把工作区、文件存储或后台任务等概念直接套用到普通聊天接口。
