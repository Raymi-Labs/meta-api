# 选择模型与阅读价格

模型广场提供公开的模型目录与价格说明。它适合筛选候选模型；你的令牌是否能调用，还取决于账户分组、令牌限制和当时可用渠道。

## 按能力筛选，而不是只看名称

1. 明确任务：文本问答、代码、图片理解、图片生成、语音、视频、向量或重排序。
2. 在[模型广场](/pricing)搜索厂商或模型 ID，查看支持的接口端点。
3. 选择客户端支持的协议，例如 Chat Completions、Responses、Messages 或 Gemini。
4. 核对价格的单位、输入输出计价、缓存计价及分组倍率。
5. 用小规模代表性任务验证质量、响应时间与实际账单，再逐步增加并发。

## 公开目录与令牌模型列表

| 数据 | 能说明什么 | 不能说明什么 |
| --- | --- | --- |
| 模型广场 | 公开配置的模型、价格与端点说明 | 你的令牌一定有权限 |
| `GET /v1/models` | 当前令牌可见的模型标识 | 每个模型支持全部可选字段 |
| 成功的最小请求 | 当前配置下这个请求可执行 | 后续无限并发或永远可用 |
| 使用日志 | 这次请求实际记录的用量和费用 | 所有未来请求都有相同成本 |

SDK 内置模型列表可能滞后。允许手动填写时，使用本站返回的模型 ID，不要自行补上厂商前缀或删除日期后缀。

## 估算成本

文本模型通常需要分别计算输入和输出；缓存命中、缓存写入、推理 token、多模态输入与按次计费会改变结果。图片的尺寸、质量和张数，音频时长及视频时长也可能影响价格。不要把其他平台的美元价格直接当本站最终扣费。

比较方案时，保留相同的任务集、输出长度上限和模型版本，再对照[用量统计](/docs/account/usage)与[计费说明](/docs/account/billing)。更便宜的单价并不一定意味着完成任务的总成本更低。

## 更换模型的检查表

- 上下文长度和最大输出是否足够。
- 系统消息、工具调用、JSON Schema、图片和推理参数是否支持。
- 原有代码是否依赖特定响应字段或流式事件。
- 令牌分组与模型限制是否允许新模型。
- 回退到其他模型是否会改变数据处理范围与业务结果。

具体请求模板见[模型请求样例](/docs/api-examples)，迁移流程见[版本与迁移](/docs/guides/migrations)。
