# 模型映射与渠道回退

调用方通常指定模型和令牌，由网关按当前渠道配置选择上游。这是统一接入的核心，但不是保证把每次请求自动换成“最便宜或最聪明”的任意模型。

## 请求经过哪些选择

1. 校验账户与令牌状态、额度、IP、模型范围和分组。
2. 按模型与分组寻找可用渠道。
3. 应用渠道配置中的模型映射和协议适配。
4. 发起上游请求，根据错误类别与配置决定是否尝试其他渠道。
5. 记录结果、用量及相关错误信息。

具体权重、优先级、禁用状态和重试策略由管理员配置。普通用户可通过分组和模型选择控制自己的调用范围，不能在客户端假设某个底层上游永远固定。

## 模型映射与自动选模不同

模型映射将对外模型 ID 对应到渠道实际使用的模型名称。它不自动解决不同模型之间的工具格式、上下文和质量差异，也不保证厂商的新版本已开放。

本站不默认提供其他平台的 `auto` 模型、公开路由排行榜、延迟 SLA 或基于任务语义的自动模型选择。需要固定模型、特殊线路或企业吞吐时，请明确告知需求。

## 回退的实际边界

在[令牌管理](/console/token)编辑令牌时，可选择一个具体分组作为首选；若该令牌开放“故障时自动切换分组（Auto）”，启用后会在账号允许的备用分组顺序中继续尝试。关闭后不会因此跨到其他分组，但首选组内部仍可能有多条可用渠道。

备用范围受账户权限、模型及渠道限制约束，不会因开启 Auto 就扩大权限。它也不等于把请求的模型换成另一款模型。切组后按实际使用的分组计费，价格与缓存表现可能变化；保存前核对可用模型，调用后在使用日志确认实际分组。某些购买所得令牌不开放这一开关，以页面为准。

已返回流式内容后再切换上游，可能导致重复文本、工具执行或上下文不一致，因此应用不能假定任何中途失败都能透明修复。不可重试的认证、额度或参数错误也不应通过反复换渠道解决。

图像、音频和视频可能创建独立资源或任务；网络断开后优先检查已有任务 ID。对外部系统产生动作的工具调用，应由应用实现幂等键和执行确认。

## 调试渠道差异

记录外部模型 ID、分组、请求时间、协议和 `X-Oneapi-Request-Id`，由有权限的管理员结合日志核查实际渠道。不要把管理后台地址或上游凭据放入客户端。

跨渠道缓存命中可能不同，详见[缓存说明](/docs/guides/caching)。应用层的重试预算见[限流与重试](/docs/guides/limits-retries)。
