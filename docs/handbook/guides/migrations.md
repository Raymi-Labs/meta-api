# 版本更新与迁移检查

模型与客户端会持续更新。参考站的新闻、活动价格或发布日期不能作为元衡已上线的证据；本站可用模型以模型广场、公告和实际配置为准。

## 查看版本信息

本站维护分支的代码与发布记录位于 [GitHub Releases](https://github.com/nanashiwang/new-api/releases)。New API 上游的功能也可能经过适配后才进入本站版本。发布附件生成、镜像构建完成和生产实际升级是不同阶段。

文档站可以独立更新，不表示业务服务或所有渠道已经升级。阅读新接口说明后仍应确认当前环境和令牌的支持情况。

## 模型迁移流程

1. 保存当前模型 ID、协议、分组和关键参数。
2. 在模型广场核对新模型的端点、价格和上下文限制。
3. 使用独立测试令牌完成代表性任务，比较输出质量、时延与费用。
4. 验证流式、工具、结构化输出、多模态和缓存等实际依赖。
5. 小流量切换，保留回退配置，确认日志与告警正常后再扩大范围。

不要假设新模型完全接受旧模型的采样参数或推理配置。遇到 400 时根据明确错误调整字段，而不是全局删掉所有可选能力。

## 客户端与 SDK 更新

第三方工具可能改变配置文件位置、提供商名称或认证模式。升级前备份自己的配置，优先使用工具正式支持的自定义端点方式。不要把网页登录订阅、厂商账号登录和本站 API Key 混用。

具体接入入口见[客户端接入](/docs/clients)与[集成指南](/docs/integrations/overview)。

## 应用需要持续验证的内容

| 项目 | 验证要点 |
| --- | --- |
| 请求 | 模型名、协议、字段和 token 限制 |
| 响应 | 文本、工具、停止原因、错误和流式终止事件 |
| 费用 | 输入输出、缓存及多模态计价 |
| 运维 | 超时、重试、限流、日志和取消行为 |
| 权限 | 令牌范围、分组与敏感配置 |

任何迁移都应以真实结果为准。版本号变大、接口返回 200 或页面显示模型名称，不能替代完整业务验收。
