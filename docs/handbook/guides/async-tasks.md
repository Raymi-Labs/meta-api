# 异步任务与结果查询

有些生成任务需要先提交再查询，视频是常见例子。异步流程属于具体接口协议，不是把任意聊天请求加上某个参数就会进入平台通用任务队列。

## 一个可靠的任务流程

1. 提交前验证模型、文件格式、时长和大小；在应用中生成自己的业务操作 ID。
2. 提交成功后立即保存服务返回的任务 ID、协议、模型、创建时间和用户归属。
3. 使用相同协议的查询端点轮询，设置最短间隔和总等待上限。
4. 成功后获取结果，检查内容类型和 HTTP 状态，再存入自己的授权存储。
5. 失败或过期时记录错误和请求 ID，允许用户决定是否重新生成。

提交成功只说明任务已被接受。排队、运行、完成、失败等状态应依据实际响应；不要把百分比达到某个值当作成品已可下载。

## 视频任务示例

支持 `/v1/videos` 的模型可通过提交、查询和内容下载完成流程，详细字段见[视频生成](/docs/reference/video)。其他厂商视频接口可能返回不同字段，不能混用任务 ID 和查询地址。

应用保存任务记录时，至少包含下面的业务字段。它们是应用的数据结构示例，不是要求发送给网关的额外参数。

```json
{
  "operation_id": "YOUR_OPERATION_ID",
  "task_id": "RETURNED_TASK_ID",
  "protocol": "videos",
  "model": "MODEL_ID",
  "state": "submitted"
}
```

## 超时与重复提交

提交连接超时有两种可能：服务未接收，或者已经接收但响应丢失。若已经拿到任务 ID，应继续查询，不能再次提交同一生成请求。没有 ID 时需要结合应用记录与使用日志判断，不应假定任何重复请求都会自动去重。

下载链接和上游结果可能过期。完成后及时保存需要保留的成品，并为自己的存储设置访问控制；不要公开含授权信息的临时链接。

## 本站的边界

控制台若开放“任务日志”，可在[任务日志](/console/task)核对已记录的任务；入口可见性取决于站点配置和账号权限。它不是通用批处理调度器，也不表示所有上游异步服务都接入了同一个任务列表。当前不承诺 Responses 后台模式的查询、取消或保留生命周期，也不提供任意请求的完成 Webhook。账户通知设置用于额度等提醒，不能当作生成完成回调。

取消本地等待也不保证取消上游任务或撤销已经产生的消耗。费用以任务处理结果及[使用日志](/docs/account/request-logs)为准。长任务服务约定见[异步生成条款](/legal/asynchronous-generation)。
