# 数据、隐私与密钥保护

一次模型调用通常涉及你的应用、元衡网关和所选上游服务。需要分别评估发送了什么数据、谁可以访问、日志记录哪些字段以及各方的保留约定。

## 阅读适用政策

本站的约定以[服务条款](/user-agreement)、[隐私政策](/privacy-policy)、[数据隐私说明](/legal/data-privacy)、[ZDR 条款](/legal/zdr)和[异步生成条款](/legal/asynchronous-generation)为准。本文是接入操作说明，不替代具体协议。

不要从其他平台的“零数据保留”、不训练或固定保存时间推断本站所有模型都采用相同约定。上游、模型、功能和企业合同可能有不同要求；有明确保留或地域要求时，应先确认可用方案。

## 尽量减少发送的数据

- 删除与任务无关的姓名、联系方式、账号和业务机密。
- 用最短必要上下文完成请求，避免把整个内部数据库交给模型。
- 图片、文档和音频也可能包含个人信息或隐藏元数据。
- 工具调用结果与检索网页属于新的模型输入，同样需要审核。

API Key 不应出现在提示词、工具结果、公开网页、浏览器脚本或故障截图中。密钥应放在服务端环境变量或专门的凭据管理设施。

## 访问控制与日志

按应用和环境划分令牌，设置有效期、额度、模型与来源 IP 限制。只给必要人员访问使用日志和任务结果的权限，不把管理访问令牌交给模型客户端。

故障排查优先提供请求 ID、模型、时间、状态与脱敏结构。对请求正文、日志和生成结果的保留期限，应由你的应用制定并落实，不依赖临时下载链接永久存在。

## 泄露后的处置

发现密钥公开或被滥用时，立即在控制台禁用或删除该令牌，创建新令牌并更新相关应用。检查使用日志和账户通知，确认异常调用时间与范围；通过[支持入口](/docs/guides/status-support)报告必要证据。

轮换密钥不会自动撤销已经导出的数据或已完成的上游任务。涉及客户数据的事件，应按适用协议和组织流程处理，并记录实际结果。
