# 创建与管理 API Key

模型调用使用[令牌管理](https://meta-api.vip/console/token)里的 API Key。每个应用或环境使用不同的 Key，能够分别控制额度、停用访问并查看用量。个人设置中的“系统访问令牌”用于站点管理接口身份验证，不能代替这里的模型调用 Key。

## 创建一把可用的 Key

1. 点击新增，填写便于识别的名称，例如应用用途和运行环境，不要把密码写进名称。
2. 选择模型厂商和可用分组，查看该范围下的模型。公开模型广场列出的模型不等于当前 Key 一定有权限。
3. 按需要设置有效期与额度；展开高级选项限制模型、出网 IP、并发或时间窗请求数量。
4. 保存后复制 Key 到应用的安全配置或环境变量，使用令牌行的“测试”或一次最小 API 请求验证。
5. 到[使用日志](/docs/account/request-logs)核对请求结果，不要只凭保存成功判断接入完成。

## 常见限制的含义

| 配置               | 实际影响                                               |
| ------------------ | ------------------------------------------------------ |
| 过期时间           | 到期后停止使用；长期任务也要安排轮换                   |
| 额度与无限额度     | 限制这把 Key 可消耗的量；无限不代表钱包余额无限        |
| 模型限制           | 只允许指定模型，仍受分组和渠道可用性约束               |
| IP 白名单          | 检查调用设备的实际出网 IP，支持 CIDR；代理出口也要核对 |
| 并发与时间窗限制   | 限制同时进行或一个时间窗内的请求，不等同模型速度       |
| 故障时自动切换分组 | 在账号允许的备用范围内尝试，实际分组和费用看日志       |

切换分组后应重新核对模型限制列表。自动切换不会授予额外权限，也不保证目标模型始终有备用渠道。历史或购买所得令牌可能有不同的可编辑范围，以页面实际允许的设置为准。

## 停用、轮换与排错

临时排查先停用，确认不再需要后再删除；删除后原 Key 永久失效。轮换时先创建替代 Key，更新应用并验证，然后停用旧 Key，避免遗漏定时任务或后台进程。怀疑泄漏应立即停用旧 Key 并检查异常调用。

调用被拒绝时依次检查启用状态、有效期、令牌额度、钱包余额、模型范围和 IP；遇到限流再核对并发与时间窗设置。不要把完整 Key 放进截图、工单、仓库或 URL。认证请求头示例见[认证与 API Key](/docs/reference/authentication)，分组选择见[模型与分组](/docs/reference/models)。
