# 配置账户通知

顶部铃铛用于阅读平台系统公告；个人额度提醒在[个人设置](https://meta-api.vip/console/personal)的“其他设置 → 通知配置”中管理。两者用途不同，读完公告不会改变额度提醒配置。这里的 Webhook 是账户通知接收地址，不是任意图像、视频或异步生成任务的完成回调。

## 选择接收渠道

| 方式    | 需要配置的内容                                                    |
| ------- | ----------------------------------------------------------------- |
| 邮件    | 通知邮箱；留空时使用账号绑定邮箱，两者都为空则无法接收            |
| Webhook | HTTPS 地址，可选接口凭证；平台发送 POST，凭证以 Bearer 请求头传递 |
| Bark    | 推送 URL，可使用 `{{title}}` 和 `{{content}}` 模板变量            |
| Gotify  | 服务器地址、应用令牌和消息优先级                                  |

选择一种通知方式，填写对应字段和正数的“额度预警阈值”，按页面显示确认额度含义后点击“保存设置”。Webhook、Bark 和 Gotify 地址必须能从通知服务所在网络访问。通知接口凭证与模型 API Key 相互独立，不要在通知设置中复用模型 Key。

## 会收到哪些提醒

当钱包或适用的订阅剩余额度低于预警阈值时，系统可通过所选渠道发送额度提醒。“额度不足导致调用失败时提醒”则覆盖额度不足造成的持续调用受阻，按用户合并并限制发送频率，不会每失败一次就发一条；已成功回退的调用不会因此提醒。

管理员还可按页面开关接收上游模型变更或检测异常的汇总通知。普通用户无需配置这一项。具体模型任务是否支持回调，要分别查对应[接口文档](/docs/reference/overview)，不能由账户通知设置推断。

## 用通知记录排查

“调用受阻通知记录”只展示额度不足持续失败的提醒，不是所有公告或所有低余额邮件的收件箱。记录会展示待发送、处理中、已提交通知服务、失败、结果未知、跳过或达到频率上限等状态。“已提交通知服务”表示服务接受了提交，不代表收件人已经收到。

未收到通知时，先确认设置已保存、接收地址有效、开关已启用，再看记录原因。邮件检查垃圾邮件和绑定地址；Webhook 检查 HTTPS、鉴权及接收端日志；Bark、Gotify 检查设备或应用令牌。触及频控或调用已经恢复时可能不再发送。不要靠大量失败请求测试提醒，也不要向支持人员公开完整通知 URL 中的密钥。
