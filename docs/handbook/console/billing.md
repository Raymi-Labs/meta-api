# 消费、账单与发票

核对费用时，应把模型调用、钱包支付和发票分开看。[使用日志](https://meta-api.vip/console/log)记录调用与消费；[钱包管理](https://meta-api.vip/console/topup)里的支付记录说明资金或购买订单；发票用于已确认交易的开票处理。它们的时间、金额和状态并不总是一一对应。

## 核对一笔模型消费

1. 在日志中找到 Request ID，确认模型 ID、实际分组、时间与调用方式。
2. 展开详情，核对输入、输出、缓存及该模型使用的其他计费项。
3. 查看[模型广场](https://meta-api.vip/pricing)的价格说明，区分按 Token、次数或其他能力计量的条目。
4. 开启自动分组切换时，以该次请求实际使用的分组和日志结算信息为准。

不要只拿输出字数估算全部费用：输入上下文、工具结果或多轮会话也可能参与用量。缓存计费取决于模型和渠道的实际返回与规则，不能保证所有重复输入都有相同折扣。页面显示单位和折算方式以当前配置为准；历史订单付款金额、到账额度与模型消耗额度也不能直接混为同一数值。

## 支付记录与发票入口

| 要核对的事项                   | 查看位置                       |
| ------------------------------ | ------------------------------ |
| 某次模型请求的消耗             | 使用日志中的消费明细           |
| 充值是否完成、支付方式和订单号 | 钱包管理 → 支付记录            |
| 钱包购买或历史商品订单         | 支付记录中的订单类型和商品信息 |
| 可申请开票的交易               | 支付记录 → 发票 → 申请发票     |
| 已申请、已开票或驳回原因       | 发票列表和申请详情             |

## 申请发票

从页面提供的可开票订单中选择交易，填写个人或企业抬头、接收邮箱以及页面要求的资料；企业抬头需填写税号。提交前核对金额、手续费提示及所需附件选项。订单已经处于待审核或已开票申请中时，不能重复申请。审核通过后可在详情查看发票文件或发送状态，邮件未收到时也先查看这里。

若页面提供银行转账凭证申请，按表单填写实际转账资料。该申请只用于开票审核，不会自动创建充值订单或增加钱包余额；也不能把平台订单和手工转账混在同一申请中。

遇到扣费或开票疑问，保留订单号、Request ID、申请编号和时间，通过支持入口提供脱敏资料。具体退款、付款与开票要求以站点当前协议及审核结果为准。
