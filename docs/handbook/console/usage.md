# 查看用量统计

[数据看板](https://meta-api.vip/console)同时展示账户累计信息与一段时间内的统计。判断消耗变化前，先确认当前账号、时间范围及筛选条件，再比较相同口径的数据。普通用户查看自己的用量，部分全站排行和渠道监控只向管理员开放。

[常用接口速查](/docs/reference/common-endpoints)

## 看懂顶部指标

| 指标                            | 阅读方式                                   |
| ------------------------------- | ------------------------------------------ |
| 当前余额                        | 当前账户可用余额，不是本次查询时间段的结余 |
| 历史消耗                        | 账户累计消耗，不会随着图表时间范围一起清零 |
| 请求次数                        | 账户累计请求计数，与区间“统计次数”区别查看 |
| 统计次数、统计额度、统计 Tokens | 当前选定区间中已汇总的数据                 |
| 平均 RPM                        | 区间请求量除以区间分钟数                   |
| 平均 TPM                        | 区间 Token 量除以区间分钟数                |

平均 RPM、TPM 是这段时间的平均值，不能当作瞬时峰值、令牌限流配置或服务承诺。时间范围内的空闲时段也参与平均，因此扩大时间范围后均值可能下降。

## 从图表定位消耗

1. 打开时间筛选，选择包含目标调用的开始与结束时间，再执行查询或刷新。
2. 查看消耗分布和调用次数排行，确定消耗集中在哪些模型、哪些时段。
3. 对异常时间段打开[使用日志](https://meta-api.vip/console/log)，使用相同时间范围并加上模型或令牌名称。
4. 展开具体请求，检查输入、输出、缓存等用量明细，以及实际使用的分组和费用。
5. 比较应用端记录时保留时区；导出的日志时间使用 UTC，需统一后再核对。

页面金额或额度的显示方式可能随站点及个人设置变化。Token 数量也不等于费用：不同模型、输入输出、缓存或特殊能力可能使用不同计费项。请结合[模型广场](https://meta-api.vip/pricing)当前说明与[计费核对](/docs/account/billing)，不要把所有请求套用同一个单价。

## 数据为空或对不上

先清除过窄的筛选条件、核对登录账号，再确认调用确实落在该时间范围。刚完成的请求与汇总图表可能存在刷新时间差，可刷新后对照明细。调用失败不等同成功消耗记录；客户端一次操作也可能发起多次模型请求。

如仍存在差异，保留时间范围、模型 ID、令牌名称及几个代表性的 Request ID，按[请求日志](/docs/account/request-logs)逐条核对；不要提供完整 Key。
