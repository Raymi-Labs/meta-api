# 查询与导出请求日志

[使用日志](https://meta-api.vip/console/log)用于核对消费、调用失败以及账户相关事件。日志是定位问题的起点：先找到对应请求，再检查错误内容和计费明细。普通用户只能查询自己的记录；渠道尝试、其他用户等管理信息不会因为修改筛选参数而开放。

## 快速找到一次请求

1. 记录客户端报错时间及其时区，选择覆盖该时间的查询范围。
2. 填入令牌名称、模型名称或实际分组，点击“查询”；找不到时先“重置”再缩小范围。
3. 若响应提供 `X-Oneapi-Request-Id`，复制其值到 Request ID 筛选框精确查找。
4. 选择合适的日志类型：成功消耗看“消费”，失败看“调用失败”，余额变动还可查看充值或退款记录。
5. 展开命中记录，将错误文本、模型和计费详情与应用端请求对应起来。

## 需要关注的字段

| 字段             | 用途                                           |
| ---------------- | ---------------------------------------------- |
| 时间、令牌       | 确认是哪一个应用在何时发起调用                 |
| 模型、分组       | 核对请求与实际结算范围，尤其是自动切换分组时   |
| 输入与输出 Token | 判断上下文和生成长度，特殊计费还需看详情       |
| 缓存或费用明细   | 分辨不同用量项及适用倍率，不以一个总数推测计费 |
| 耗时、流式标记   | 辅助区分长请求、流式请求与超时现象             |
| Request ID、内容 | 向支持人员提供可定位的请求标识和错误原文       |

模型映射信息和上游声明的模型名用于排查请求路径，单靠返回的名字不能证明模型的实际身份。客户端显示的一次操作也可能包含重试或多轮请求，核对时应逐条对应。

## 导出与常见问题

需要离线对账时，设置明确时间范围后使用 CSV 导出。导出沿用当前过滤条件，而非只导出屏幕上当前一页；时间列为 UTC，额度字段按文件列名解释，不能直接当作页面显示金额。导出有时间跨度、条数与文件大小限制，超限会提示缩小范围，不会悄悄截断成完整报表。

没有记录时先确认账号、时间与令牌名称；失败详情中没有成功消费记录，不足以单独判断客户端是否还在重试。导出失败应分段查询，正在导出时等当前任务结束。反馈问题提供 Request ID、时间、模型、脱敏错误内容即可，隐藏完整 Key、Cookie、通知凭证和私人输入。
