# 模型能力自动同步

模型管理与模型广场共用 `context_length`、`input_modalities`、`output_modalities`。开启模型的“参与官方同步”后，主节点在启动一分钟后同步，此后默认每24小时检查；管理员也可以在模型管理点击“同步模型能力”立即刷新。

默认来源为 [basellm/llm-metadata](https://github.com/basellm/llm-metadata) 的完整模型库 `/api/all.json`。该项目汇集 models.dev 与社区数据，**不是逐家厂商的官方 API**。已有“同步”向导继续处理介绍、图标和供应商；自动能力同步只处理上下文及输入/输出模态，不覆盖介绍、展示名、价格、协议声明、分组、权限或实测性能。

## 人工配置与自动更新

- 只匹配完全相同的模型 ID，且模型匹配规则必须为“精确匹配”。不从标签推算上下文，不猜测别名或自定义后缀。
- 空字段可以自动补齐。自动填入的值会继续跟随来源更新；管理员修改为不同的非空值后，保留人工值。
- 清空字段表示允许重新自动补齐；需要保持空值时，关闭该模型的同步开关。
- 来源没有记录、字段缺失、值不合法或请求失败时，保留已有数据，不清空。来源的 `pdf` 映射到本站“文件”类别，仅表示 PDF 输入，不代表支持所有文件格式。
- 启用渠道中的模型尚未配置展示元数据时，只为来源精确匹配且不受已有规则覆盖的模型补建记录；已删除记录不自动恢复，不会向渠道增加可调用模型。
- 已关闭同步的模型保持关闭。旧版本同步创建的个别记录可能实际保存为关闭，需按需在模型管理中开启，不批量猜测其原本意图。

内部 TEXT 状态保存实际自动应用过的字段值、来源及同步时间，用于识别手工修改。同步写入带原始字段条件，避免覆盖同时进行的人工保存。该状态不通过公开定价接口暴露。启用模型的自动补建、管理员新增和旧版同步共用能力行的事务锁，防止重复创建；SQLite 使用写事务冲突保护。

## 配置与故障处理

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `MODEL_METADATA_SYNC_ENABLED` | `true` | 控制后台任务，关闭后仍可由管理员立即同步 |
| `MODEL_METADATA_SYNC_INTERVAL_HOURS` | `24` | 检查周期，至少1小时 |
| `SYNC_UPSTREAM_BASE` | `https://basellm.github.io/llm-metadata` | 与原模型库同步共用来源基址 |
| `SYNC_HTTP_TIMEOUT_SECONDS` | 连接10秒 / 总任务30秒 | 显式配置后同时作为连接及总任务超时 |
| `SYNC_HTTP_MAX_MB` | `10` | 最大响应大小 |

手动接口为管理员 `POST /api/models/sync_capabilities`。返回匹配、更新、新建和跳过计数；跳过包含手工保护、禁用、无变化和并发冲突等情形，不能把跳过数当作失败数。后台失败记录日志，等待下一个周期，不循环重试或切换来源。后台只在主节点启动，同进程的后台和手动任务互斥。

新字段由现有 GORM 迁移增加，使用跨数据库兼容的 TEXT 类型。多实例应继续遵循现有主节点部署规则。代码发布不等于生产部署；本功能要在升级后的服务上才会运行。
