# 调用失败日志

用户可在使用日志的“调用失败”筛选中查看自己的失败请求，展开后可复制排查信息。字段包含请求 ID、模型、接口路径、HTTP 状态码、失败状态码、错误码、总耗时、处理建议及可用的 Retry-After。

- 一次请求只按最终结果记录失败。渠道重试最终成功时不新增失败行；最终失败时最近 5 次渠道尝试作为管理员诊断保存。
- HTTP 200 并不代表流式请求成功。响应开始后的显式流内错误仍会记录为调用失败，HTTP 状态与错误状态分开展示。
- 记录已识别用户且非已禁用令牌的鉴权拒绝、限流、渠道分配失败、参数及额度校验失败、上游错误和任务提交接口失败。无法识别用户的无效密钥请求不归入任何用户日志。
- 不读取或复制请求正文，也不缓冲模型响应。用户接口只返回公开的排查字段；渠道信息、上游诊断和尝试详情仅管理员可见。
- 失败行不充当账单，也不凭 usage 缺失推断免费。费用以相同 Request ID 下的消费或退款记录为准。
- 异步任务提交成功后的运行结果继续在任务日志查看；已有消费日志中的流式异常标记继续保留。本功能不将无明确错误的 HTTP 200 或零 usage 自动视为失败。

## 已禁用令牌与身份信息

令牌已手动或自动禁用时，客户端继续发送请求仍收到 HTTP 401 和原拒绝提示，但不再新增使用日志。服务端访问/错误日志仍可按 Request ID 排查。连续三次额度不足中触发禁用的那次失败仍记录；已通过鉴权的在途请求按实际结果记录，不因随后禁用而隐藏。过期、耗尽、IP 限制和上游鉴权错误仍保留，已有可信额度拒绝在日志中显示为“账户或令牌额度不足”。

早期失败缺少用户名时按已识别用户 ID 补齐；历史空用户名在管理员列表显示用户 ID。管理员复制排查信息包含用户名、用户 ID、令牌名称和令牌 ID，普通用户复制范围保持公开排查字段。均不复制密钥、IP 或管理员内部诊断。鉴权阶段尚未解析模型的请求仍保留空模型，不额外读取请求体猜测。

此规则仅影响升级后的新请求，不删除或回填历史日志，也不改变令牌状态、费用或自动禁用计数。

## 开关与升级

管理设置 → 运营设置 → 日志设置 → “启用调用失败日志记录”。默认开启；未保存面板设置时使用 `ERROR_LOG_ENABLED`（默认 `true`），已有显式 `false` 配置继续有效。

升级不会补造历史失败日志。旧错误日志可能来自单次渠道尝试，无法推断当时整个请求是否最终失败；其内部诊断仅管理员可见。

用户查询接口为 `/api/log/self?type=5`，支持现有时间范围、模型、令牌名称和 `request_id` 筛选，始终按登录用户隔离。错误行沿用既有日志保留和清理策略，不计入消费金额统计。

## HTTP 请求 ID 与上游 ID

客户端应从 HTTP 响应头 `X-Oneapi-Request-Id` 读取本站请求 ID，再用于日志的 `request_id` 筛选。该 ID 在同一次请求的渠道重试间保持一致；上游返回同名头时也不会覆盖本站 ID。响应 JSON 中的 `id`（例如 `resp_...` / `msg_...`）仍属于模型响应对象，不作为本站日志查询键。

管理员可在消费/失败日志 API 返回的 `other.admin_info.upstream_request_ids` 中查看共用 HTTP 出站入口最近五个实际响应的 `channel_id`、`request_id` 和 `request_id_header`。优先识别上游的 `X-Oneapi-Request-Id`，再识别已有供应商请求 ID 头；只保存长度不超过 256 字节且无控制字符的值。该列表不是最终响应 ID：后续连接失败或响应没有 ID 时不会补造条目。原有失败尝试诊断也识别该上游头。普通用户接口继续删除 `admin_info`。

独立 SDK、WebSocket 的上游请求 ID 不承诺由此入口采集。升级不回填历史缺失的上游 ID，也不改变历史日志的本站 ID；发布后的 HTTP 契约需要部署新版本才生效。
