2026-11-01，生产 v1.12.1。用户核对企业级与官方价格后，要求纠正所列八个型号。现已按 **官方美元单价 ×6.6×5 = 能量单价** 重建输入、输出及缓存价格。企业级倍率1，充值价¥0.2/能量，因此人民币单价为官方美元价×6.6。官方参考栏使用独立汇率，与固定6.6可能存在小幅差异。

此前 [OpenAI](openai-retail-66.md) 和 [Claude](claude-retail-66.md) 操作将旧站内售价乘6.6，保留了旧输入/输出/缓存比例。三个 Claude 4.5 名称当时没有独立 ModelRatio，将共同的默认37.5明确设为247.5，导致售价全部为99/495。之后企业级接入遵循“已有价格保留”，只有新定价型号使用官方USD×33。官方价格元数据用于参考展示，不会自动覆盖销售配置。

本次部分取代上述旧价格及 [OpenAI企业级](openrouter-openai.md)、[Claude企业级](openrouter-claude.md) 的八个名称“保留现价”决定；其余型号沿用既有规则。基础价格为全局配置，其他分组调用这八个名称时也使用新基础价，再乘各自分组/用户/时段倍率。

## 分项和边界

官方标准价格与来源、原值和最终配置完整记录在[审计JSON](retail-official-correction-audit-2026-11-01.json)。价格来源为各型号的 [OpenAI官方文档](https://developers.openai.com/api/docs/pricing) 和 [Claude官方价格表](https://platform.claude.com/docs/en/about-claude/pricing)。

- 三个 Claude 4.5 保留普通倍率模式：输出为输入的5倍，缓存读取0.1倍、5m写入1.25倍、1h写入2倍。
- gpt-4o-mini 保留普通模式：官方USD 0.15/0.60，输出倍率4、缓存读取0.5；没有独立缓存写入定价，不新增该收费。
- gpt-6.1-terra、gpt-6.1-sol、gpt-6-sol、gpt-5.6-sol 使用 `len <= 272000` 标准档，超过边界输入、缓存读取和默认缓存写入单价为标准档2倍，输出为1.5倍。默认写入使用已有30m计量，不新增12h扩展时长。

## 在线切换与恢复

复用 root options API 和既有 `tiered_bundle`。先原子切换八个型号到完整新表达式，再分四步同步 ModelRatio、CompletionRatio、CacheRatio、CreateCacheRatio，最后原子恢复四个普通型号的原模式，四个长上下文 GPT 保持阶梯，共六次写入。基础倍率更新期间由完整表达式计费，避免新输入价与旧输出/缓存比例混用。

每步写前重读、校验目标旧值并保留其他键；写后比对整个映射。失败按日志反向核对并只恢复本次目标，不整表回滚覆盖并发修改。私有目录 `/opt/meta-api/operations/retail-official-correction-20261101` 保存完整快照、操作/校验脚本和回执；凭据仅在服务器内读取使用。已经完成的操作不能直接重跑。

首次预检因公开目录的分组和协议数组顺序不同中止，尚未写入；按集合语义规范化并刷新快照后执行成功。非目标目录的原始哈希另因 `model/pricing.go` 把 `pricing_version` 兼容标记放在非确定的第一条模型记录而变化；保留该原始结果，排除非价格标记、规范化数组后，全部216个非目标模型与调查时快照逐字段一致。非目标价格配置也与写前快照完全一致，分组/充值和渠道静态摘要保持。
