首次预检发现小米渠道 1621 的模型名和映射被其他更新修改，在任何写入前中止。重新读取后，采用最新 5 个别名和映射：V2.6 的三个型号通过审核；V2.5 两个型号根据[小米现行价表](https://mimo.mi.com/docs/en-US/price/pay-as-you-go)的退役说明暂停。没有覆盖小米新增型号或改回旧名称。

## 路由约束

复用渠道 `param_override`，在协议转换后生成下列规则：

- `provider.sort: "price"`：在符合约束的服务商中按价格排序。
- `provider.allow_fallbacks: true`：便宜服务商失败时可回退到其他合格服务商。
- `provider.max_price.prompt/completion`：模型开发商公开的实时标准 API 美元价，每百万 Token；不是 OpenRouter 目录价，也不是零售价格。
- `provider.only`：仅允许当日逐项核对过输入、输出、已公开缓存价和附加收费项的服务商。量化/区域端点使用 OpenRouter 精确 tag。
- `service_tier: "default"`：使用标准等级，移除优先顺序和加速偏好；不纳入独立的 flex 服务等级。
- 额外按请求/图片收费上限为零；拒绝收费插件、托管搜索和非 `function` 原生工具，普通客户端函数工具保留。
- 拒绝未知模型、未审核模型和跨模型回退，防止日后自动添加型号直接绕过价格审核。

这些约束参考 [OpenRouter 服务商路由](https://openrouter.ai/docs/features/provider-routing)。没有合格服务商时返回错误，不能为了调用成功突破价格上限。分时或长上下文有多档价格时，采用已核实的较低标准档作为固定保守上限；可能因此减少可用路由。

全局或渠道的请求体透传会绕过现有参数覆盖，应用前已确认两者关闭。以后启用透传前必须重新设计和验证限价路径。普通 Chat DTO 不透传任意 `provider` 字段；覆盖引擎保留较低客户端限价的单独测试不代表公网接口支持客户端自定义该字段。上游账号隐私设置未改变。

## 超价实例与核实边界

- `moondream/moondream3.1-9b-a2b`：原厂输出 $1/百万 Token，当前 OpenRouter 服务商 $2.5，暂停。[原厂实时价](https://moondream.ai/pricing)
- `thinkingmachines/inkling-small`：原厂输入/输出/缓存为 $0.3/$1.2/$0.06，当前服务商为 $0.45/$1.2/$0.1，暂停。[原厂 Serverless inference 价](https://thinkingmachines.ai/tinker/pricing/)
- `mimo-v2.6-flash`：部分服务商输入价更低，但缓存价 $0.003 高于原厂 $0.0028，未纳入允许列表；符合三项价格约束的端点仍可用。

未知价格项不是一律“没有官方 API”：有的价表需要登录，有的旧型号已退役，有的只开放权重，有的使用不可直接对应的计费单位或独立附加收费。每项来源、原因、已核实原厂价、端点报价、允许/排除服务商都在 JSON 清单中；开源免费或试用免费不能当作生产 API 价格为零。

`max_price` 没有独立缓存价字段。缓存通过当日价格审核与服务商允许列表收窄，**不能据此承诺服务商以后涨价也会被实时拦截**。原厂降价同样需要重新审核；本次没有部署定时抓价任务。平台充值手续费、税费不属于模型 Token 单价。昂贵长上下文、多模态、缓存命中和全部工具能力没有逐一实测。

## 变更与核验

私有操作目录为生产 `/opt/meta-api/operations/openrouter-price-20261101`，目录权限 0700，文件 0600。管理员凭据和上游密钥只在服务器内存中使用。保存去密钥的变更前快照、操作计划、逐渠道执行进度、读回结果及验收记录。

写入前逐渠道比较 ID、类型、状态、名称、模型、映射、参数覆盖、地址和分组；通过现有 API 仅更新状态、模型列表和参数覆盖。每次读回核对目标字段，并确认模型映射、分组、地址、其他设置、权重等不变。生产 MySQL 仅进行只读核验，不直接写业务表。全部 45 个渠道完成更新，50 条启用能力与计划精确一致；销售配置和范围外渠道的前后哈希一致。

本地使用实际 `relay/common.ApplyParamOverride` 执行 733 项请求检查，覆盖 133 个模型的限价、允许列表、未知型号拒绝、附加收费入口拒绝和普通函数工具保留；`go test ./relay/common` 通过。公网验收及核验共 10 项通过，临时令牌均已删除。

公网结果：

- `/v1/models` 与审核范围取交集后恰好是 50 个保留模型，83 个暂停项均未暴露。旧式固定分组令牌的目录还展示 70 个其他渠道模型，因此不把整个列表大小当作本轮渠道数量；临时令牌的实际渠道限制已读回确认。
- Mistral 普通/流式、小米别名和 MiniMax 别名共 4 次请求获得有效正文和 usage；流式包含 `[DONE]`。4 条消费日志分别落到渠道 1605、1621、1620、1605，分组均为企业级，扣除额度依次为 19、45、1125、19。
- OpenRouter generation API 确认三次普通请求的实际服务商与费用；由返回的 Token 数及成本明细计算单价如下，均不高于上限。
- 收费搜索入口返回 400；暂停模型在路由前返回 404 `model_not_found`。最初验收脚本只接受 403/503，已据实际可见性处理修正判断，失败记录保留；没有因此放开模型。
- 直接向 OpenRouter 发送价格上限为零的付费模型短请求，得到 404，并明确标注 `Filter by Max Price`，没有产生推理费用。
- 首次目录断言错误和一次 SSH 连接超时均保留记录；之后只补做未完成的核验，没有重复四次成功推理。没有故意制造服务商故障来验收真实跨服务商回退。

## 维护与恢复

1. 重新核实原厂当前、同型号、同计费单位的生产 API 价，保留来源与生效时间；不能只复制 OpenRouter 目录或本站展示的“官方参考价”。
2. 拉取当前 OpenRouter 端点价格，核对缓存和附加收费，更新审核清单；没有合格端点则继续暂停。
3. 读取最新渠道配置，按模型映射后的上游名生成规则，保留其他任务新增的设置。生成器只接受尚无覆盖规则的输入快照；已配置渠道需要明确合并，不能盲目重放初次计划。
4. 用实际覆盖引擎验证，再通过管理员 API 更新对应模型和渠道；读回、核对 abilities，并做短请求验收。切勿整份覆盖旧快照、开启透传或只改启用状态。
