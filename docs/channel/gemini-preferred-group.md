# Gemini vertex 分组并入优选

2026-11-01 按用户要求，将 `Gemini · vertex` 的渠道和未删除令牌迁入 `优选`，随后移除旧分组的运行配置。此操作不更换应用，生产版本仍为 v1.11.12。

本文记录该轮完成时的状态。随后用户要求将 Gemini 企业专属、优质并入福利，渠道 1510 当前为 `福利、优选`；其余优选关系保留，见[后续迁移](gemini-welfare-group.md)。

## 渠道

| 渠道 ID | 原分组 | 当前分组 | 模型数 |
| --- | --- | --- | ---: |
| 1510 | Gemini · 企业专属、Gemini · vertex | Gemini · 企业专属、优选 | 7 |
| 1566 | Gemini · vertex、企业专属 | 优选、企业专属 | 3 |
| 1576 | Gemini · vertex | 优选 | 1 |

三个渠道继续启用；模型、密钥、优先级、权重、映射与参数覆盖保留原值。优选新增 11 条渠道/模型能力，对应 7 个不同模型，仍按既有优先级和权重选渠。

## 令牌与计费

迁移 22 个未删除令牌：20 个固定组由旧组改为优选，2 个多组令牌替换 `routing_config.groups` 中的旧组；重复优选合并到首次出现的位置，其他相对顺序保留。支持逐模型 `model_groups` 的同样替换，本次两条多组记录均无逐模型子规则。主组不是旧组的令牌保留主组。

只写入 `group` 和 `routing_config`，不重新生成密钥，不写回余额、使用量、有效期、状态、套餐或权限限制。迁移中的一个停用令牌保持停用。原组倍率 4，目标优选倍率 0.8；按实际选择的优选组计费，模型基础售价保持本次迁移前的配置。多组令牌若选择其他组，则继续按该组收费。

`GroupRatio`、`UserUsableGroups` 及当前渠道/能力不再引用旧组。预检确认用户默认组、商品允许组/发放请求、订阅升级/恢复组、CRS 站点和用户设置均没有额外引用；受影响用户所属 default、EMOXIA 均有优选权限，适用 0.8 倍率。34 个已删除令牌以及日志、统计、任务历史保留旧归属，不重写历史账单。

## 执行与恢复

先通过管理 API 为三个渠道增加优选，同时保留旧组；在生产同引擎、同结构、同排序规则的临时表完成迁移与旧值冲突回滚演练后，用 MySQL 事务只改令牌的两个路由字段，并按 HMAC 精确失效这 22 个令牌的 Redis 缓存。最后从渠道和选项移除旧组。旧应用和依赖全程在线。

本人令牌更新 API 无跨用户管理员局部更新能力，且会全量写回额度等字段，因此本次使用旧值比较和行数断言的事务列更新，避免覆盖并发消费。空字符串与 NULL 分别保留。首次演练发现连接默认排序规则与表的 `utf8mb4_unicode_ci` 不同，以及空十六进制字面量需使用 `X''`；两者均在临时表阶段修正，未影响生产记录。修正后成功迁移与预期冲突两种演练通过。

生产私有操作目录：`/opt/meta-api/operations/vertex-to-preferred-20261101`。保存盘点、执行脚本、迁移前路由/非敏感校验快照、操作日志和验证结果；不向仓库导出用户令牌内容。若需要恢复，应先补回旧组权限和渠道能力，再按预期当前值恢复令牌路由，最后移除本次新增的优选关系；不能覆盖后续人工改动或消费计数。

## 验收结果

- 当前渠道、能力和未删除令牌均无旧组引用；公开可用分组和倍率中已移除旧组，七个模型可从优选调用。
- 三个真实迁移令牌的只读模型目录鉴权通过，覆盖固定组、多组以及 EMOXIA 用户；实际新缓存使用优选且受影响键没有旧组残留。
- 三个渠道分别实测一次 `gemini-4-argon`，全部 HTTP 200。每次 35 输入/5 输出 Token，日志分组为优选、倍率 0.8，实际消耗均为 1598 quota，只有一条消费，临时令牌全部删除。
- 渠道 1510/1566 耗时约 3.74/3.54 秒，1576 约 28.69 秒；这些是单次验收结果，不代表长期延迟指标。
