# 2026-11-16 流式请求异常排查与线路缓解

## 范围与证据

针对客服反馈复核目标账号最近 72 小时的消费、最终失败和流结束摘要，同时参考线路最近 24 小时逐次尝试指标。公开记录不包含客户身份、令牌、对话、文件或 IP；完整变更快照保存在生产私有操作目录。

不能将所有报错归为“输出一半断流”：

- GPT/Claude 的一批失败包含 `video_url` 无法转换为 Messages、Responses 的 `input_file.file_data` 不接受 `video/mp4`，属于请求格式/能力不匹配。
- Claude 有历史上下文超过上游限制的明确拒绝，例如约 245 万 Token 超过该上游返回的 100 万上限。不能通过自动裁剪客户历史或无条件换渠道解决。
- GPT 两个渠道有约 2 秒的 `upstream_stream_break`，错误来自上游，现有日志不足以证明已向客户交付正文；不能根据上游的 `safe to retry` 字样重放已输出内容。
- Gemini 有约 60 秒等待上游响应头超时。119/179 秒的两条下游取消记录没有输出 Token，不据此断言用户主动停止或已输出一半。
- Claude 1499 近 48 小时有 18 条 `cache creation breakdown exceeds total`，目标账号涉及两条。保留缓存用量守恒和失败退款规则，不用猜测或取最大值伪造计费用量。

源站 API Nginx 的读写超时为 3600 秒，应用没有配置 HTTP 总时限；这些设置不能解释 119/179 秒的固定时间点。没有客户端配置或逐帧历史，不能进一步确定下游取消的发起方。现场应用为 v1.34.2。

## 现场验证

用不含客户对话的短文本序列测试记录 HTTP 状态、事件数、首事件时间、间隔与协议终态，不保存生成正文。直接测试不覆盖客户的长上下文/视频场景，也不直接证明本站完整链路正常。

- GPT 1502/1657 返回完整 `response.completed`，约 6.47/7.54 秒。
- Claude 1499/1508 返回完整 `message_stop`，约 4.18/3.25 秒；1499 两次重复短请求本次未复现缓存冲突，不能据此否定历史错误。
- Gemini Carbon 1336/1374/1669 收到 `STOP`，约 27.31/38.31/3.51 秒；1543 一次等待约 54.82 秒后返回 503，随后短请求恢复成功，属于间歇性故障。
- 初次 Python 默认 User-Agent 在部分上游收到 403；按应用请求头和渠道覆盖重测成功。这些测试器差异不当成生产线路故障证据。
- 复用本站管理员单渠道流式测试：1576 Hydrogen 明确 `model_not_found`，1576 Carbon 明确无可用渠道；1543 Carbon、1669 Carbon、1337 Opus 均通过。测试使用管理员身份，不使用客户令牌。

备用仍可能被路由选中，因此本次是降低故障暴露，不是保证第三方上游永不断流。将整个模型切入不同计费组、全局延长超时或输出后自动拼接另一条线路，均不能由本次证据证明安全有效，未采用。

## 后续验收与恢复

客户端需将视频交给已验证的视频输入接口，不能把 mp4 作为普通文件发给拒绝此格式的 GPT/Claude；超长 Claude 会话应在客户端摘要或新建会话。已确认客户端为自研脚本；仍需其 HTTP 客户端初始化、读取/总超时、SSE 循环和异常重试代码，以及新的 Request ID，才能继续定位下游断开。未在客户客户端修改设置，也未宣称客户真实会话已验证恢复。

生产 `/opt/meta-api/operations/stream-reliability-20261116`（0700，文件 0600）保存修改前配置、最小补丁、修改后配置、能力表及密钥/价格哈希核对。供应商修复并通过对应模型的长流/缓存测试后，可通过管理员 API 恢复原优先级与模型绑定，同时从忽略名单移除已恢复型号；恢复前核对并保留后续其他变更，不直接覆盖整份旧快照。
