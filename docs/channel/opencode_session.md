# OpenCode 会话头转发

从 `v1.0.0-compat.39` 起，公共 HTTP 转发会为 OpenCode 官方 API 自动保留客户端的 `x-opencode-session`。不依赖渠道 ID、名称、分组或模型，新建或重建渠道不需要再填写相同的透传配置。

自动识别实际出站 URL：HTTPS、主机名为 `opencode.ai`、默认端口或 443，路径以 `/zen/v1/` 或 `/zen/go/v1/` 开头。Chat、Messages、Responses 的流式与非流式请求共用该处理。

## 调用方约定

- 同一对话的各次请求携带稳定的会话 ID；新对话使用另一个 ID。UUID 可以使用。
- 普通请求缺少该头时，网关不生成共享或随机会话 ID，上游仍可能返回 `MissingSessionID`。
- 后台“渠道测试”没有业务对话，每次测试生成独立 UUID，不读取管理员浏览器传入的会话 ID。
- 会话头只影响会话路由，不代表模型支持视频、声音或其他模态。

上游的公开要求见 [OpenCode Go](https://dev.opencode.ai/v2/docs/console/go#where-can-i-use-it)。

## 已有覆盖配置与代理域名

非空的管理员请求头覆盖仍优先于自动转发；此前填写的客户端头占位符可继续保留。自定义代理域名不会根据渠道名称被当作官方上游，继续使用渠道编辑页的“请求头覆盖”：

```json
{
  "x-opencode-session": "{client_header:x-opencode-session}"
}
```

不要把所有调用方的会话头写成同一个固定值。客户端头内容按值转发，不替换其中的 `{api_key}` 等文本。

自动携带该头的请求发生重定向时，目标不再符合上述官方 API 范围则移除会话头，同时继续执行已有重定向检查。其他客户端头不会因此自动透传。

## 验证与升级

源码回归覆盖不同渠道 ID、三种协议、流式/非流式、覆盖配置、缺头、后台测试隔离、目标地址边界及重定向。升级后可新建未配置请求头覆盖的 OpenCode 渠道，用稳定会话 ID 连续发送两轮文字请求验证，再按目标模型分别验收多模态能力。

该修复随应用版本生效，不需要数据库迁移；只发布 Release 不会升级现有生产应用。
