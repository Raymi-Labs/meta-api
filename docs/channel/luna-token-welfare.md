# Luna 调用令牌迁入福利

**当前状态：已按用户要求撤回并停止。** 2686 个令牌的原主组和 29 个多组路由均恢复，逐条与迁移前快照一致；定向清理 13 个缓存，残留旧路由为零。此前 51 个 default 继承令牌迁入福利的独立操作保留。密钥、配额、其他限制、渠道和价格未因撤回改写。见[撤回决定](../../.agents/notes/implemented/process/2026-11-01-revert-luna-caller-migration.md)及审计 JSON 的 rollback_receipt。下文保留原迁移与验证历史，不代表当前分组状态。

2026-11-01 按用户要求，将调用 Luna 且仍在福利、优选、企业级之外的令牌迁入通用福利。此前的 [Luna 渠道分组限制](luna-routing.md)保持。本次仅更新运行配置；验收时生产为 v1.12.1，没有应用发布、服务重启或付费模型请求。

## 原迁移范围与结果（已撤回）

根据现有消费/失败日志的 token_id 找到 2800 个未删除 Luna 调用令牌，2686 个需要迁移，114 个已经只在允许组内且保持原样。调用证据包含 Luna 正式型号、历史名称及请求中的 Luna 别名；名称相近的 `sao10k/l3-lunaris-8b` 排除。另有 46 个范围外令牌只在白名单配置 Luna、没有调用记录，不属于本次实际调用者迁移。

| 项目 | 数量或结果 |
| --- | ---: |
| 迁移令牌 / 所属用户 | 2686 / 1790 |
| 有成功消费记录 / 仅失败记录 | 2471 / 215 |
| 固定分组 / 多组路由 | 2657 / 29 |
| 保留模型白名单 | 213 |
| 保留停用 / 过期状态 | 42 / 66（可能重叠） |
| 主组迁移后 | 全部为福利 |
| 多组迁移后 | 25 个仅福利，4 个福利、优选 |
| 已合规且保持原样 | 114 |
| 最终已知调用者范围外分组引用 | 0 |

固定令牌只改变主组的有效值。多组令牌同步将 `group`、`routing_config.groups` 和 `model_groups` 的范围外分组替换为福利，并按原顺序去重；已有允许组、逐模型规则键保留，避免主组与路由配置不一致。不会清空已有的模型、IP 或渠道限制。

四种用户组（default、EMOXIA、OpenAI · 蒸馏、Kimi · 福利）的福利适用倍率均为 0.6；用户自身分组、全局模型价格及分组倍率不变。迁移的是整个令牌，其其他模型也按新分组的渠道可用性及倍率处理；保留白名单不代表所有白名单模型都有福利渠道，历史账单不重算。

## 执行与验证

复用原有令牌路由契约，先在生产相同 MySQL 引擎、完整 schema 和排序规则的临时表中验证正常迁移、旧路由冲突和用户组冲突拒绝。事务只写 `group`、`routing_config`，逐行核对旧值和当前所有者组；保护字段在临时表中完整对比，运行中的余额/用量字段不以快照覆盖。密钥只比摘要，原始凭据留在服务器内存中。

2686 行变更及非路由字段已核对，114 个已合规令牌的路由/密钥摘要保持，所有者组/状态和价格/分组选项一致。按 HMAC 缓存键定向失效，共删除 10 个已有缓存，全部目标缓存无旧组或旧路由。

11 个真实迁移令牌只读模型目录鉴权均返回 200，覆盖四种用户组、固定/多组、白名单、Luna 逐模型规则和内部 image_playground 来源。重建的缓存主组为福利、路由与数据库一致；一个只允许其他模型的样本正确不显示 Luna，其模型限制未被绕过。这验证了鉴权、权限目录和缓存，不宣称对每个模型执行过真实推理。

初次历史查询触及大量日志，30 秒上限触发后停止；最终通过模型名称索引筛出 Luna 请求并完成聚合，再覆盖扫描窗口、按日志 ID 水位增量复查，末次核对没有遗漏的范围外调用者。只依据当前保留日志，不推断已清理历史中的调用。

私有记录位于 `/opt/meta-api/operations/luna-token-welfare-20261101`，保存清单、计划、同引擎演练、带密钥摘要的保护字段快照、执行脚本、日志和结果。恢复只在当前路由仍等于本次写入值时恢复原两个路由列，再定向清理缓存，不能覆盖后续人工配置或消费计数。脱敏回执见[审计 JSON](luna-token-welfare-audit-2026-11-01.json)。
