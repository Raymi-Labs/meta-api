# 视频模型接入与本地验收范围

核对日期：2026-10-26。以下描述当前代码与本地模拟结果，不代表任意第三方同名模型、最新型号或生产账号已经生成成功。

## 已有协议范围

| 渠道/协议 | 本地覆盖 | 仍须核对 |
| --- | --- | --- |
| MiniMax H3 V2 | H3/Highspeed/Lite/Max 文生视频、明确时长/分辨率/比例、提交与 V2 查询、成功输出、失败/取消退款、账号固定、秒价模板 | 图生/参考视频/参考音频等输入成本未实现；第三方必须兼容 V2 |
| 旧 Hailuo V1 | 旧模型提交/查询协议保留、映射模型不可被 metadata 更换、文件结果获取失败不会标成功 | 新型号不能自动继承 V1；图像字段仍以原适配器能力为准 |
| Grok Imagine Video | 原生提交/查询、seconds/size 别名、分辨率默认值进入计价、缺结果不成功 | 具体版本参数、参考输入和第三方售价需按实际文档核对 |
| Sora / OpenAI 视频 | JSON 秒数与默认尺寸同源计价、原 multipart 文件路径、公开任务 ID、内容接口 | multipart 不能使用新表达式模板，直接拒绝而非错误报价；原按次/倍率方式保留；供应商型号生命周期另核实 |
| 阿里 Wan | 现有 video-synthesis 协议、按映射型号处理默认参数、时长/size/resolution 快照、结果 URL | 新协议或新字段（例如多镜头/其他视频系列）未自动接入；模板文生尺寸使用实际出站尺寸如 1280*720 |
| Seedance / 豆包 | 现有 contents/generations/tasks 协议、顶层时长/分辨率传递、model 不能被 metadata 改写、原用量路径保留 | `duration=-1` 自动时长不支持固定秒价；视频 Token 与输出秒是两种计费口径，不相互猜测 |
| Kling | 文生/图生路由、原 JWT/Bearer 规则、保存账号、首尾帧输入、成功结果检查 | 新版模型字段不自动新增；模板中用 STD/PRO 等实际 mode 作档位，不能假称像素分辨率 |
| Vidu | 原 text2video/img2video/start-end2video/reference2video、模型/时长/分辨率保真、成功结果检查 | 新型号/素材范围按供应商确认；参考输入额外费用用完整表达式，不由简单输出秒价自动覆盖 |
| Gemini Veo | 现有 predictLongRunning/operations 协议、durationSeconds/resolution 参数传递、缺输出不成功 | 当前适配器仅文生；新版替代接口不自动迁移，实际可用模型必须按供应商当前文档与账号确认 |
| Vertex Veo | 现有 predictLongRunning/fetchPredictOperation、保存凭据、参数与 sampleCount 同源计价、现有内联视频结果 | 当前只支持文生和已有结果格式；仅 GCS 对象等其他输出形态不宣称可下载，需要单独接入 |
| 即梦视觉接口 | 原提交/查询、查询沿用持久化 req_key、错误响应不覆盖为成功、原帧数表达式可用 | 帧数不自动换算秒；通用秒价模板不提供；新 req_key/帧率必须核实 |

未注册原生适配器的 Runway、Luma、HappyHorse 等，视频安全识别只用于避免误点收费测试，不表示已接入。未经确认的第三方 OpenAI 视频兼容协议也不能依据模型名称自动选择原生厂商协议。

## 统一计价契约

1. 复用请求验证和模型映射，先调用适配器转换一次，得到实际出站字节。
2. 表达式读取出站快照派生的 duration/seconds/resolution/sampleCount，同时保留原生字段和其他合法请求字段。metadata 中被丢弃或覆盖的收费字段不再作为真实收费依据。计价与发送使用同一次转换，报价也复用它。
3. 请求时长与适配器最终时长冲突则拒绝；Seedance 自动时长保留原用量模式。未知有效时长不猜测。
4. 新生成的通用价格模板明确档位范围，未配置档位、冲突区间、非法金额都不生成或拒绝请求。零价是明确配置，缺价不是零价。模板单位为 USD/请求输出秒或 USD/固定时长任务，按 sampleCount 计份数，再应用分组/时间倍率。
5. 原手写表达式仍可使用；需要特别复核依赖 metadata、字段大小写或默认值的旧表达式。本次可能纠正原有少扣或错扣的展示/计算，不能直接把代码部署等同于生产价格迁移完成。

已配置固定任务价格的任务快照保留该单位，避免完成后又按 Token 重算；原 Token 用量模式及表达式任务各自保持原结算规则。尚未增加通用“实际视频秒数补差额”结算机制。

## 管理员配置

现有定价页为已接入协议家族提供“视频按秒 / 表达式”。H3 保留精确已知参数模板；其他家族选择 USD/s 或固定价格，填写实际分辨率/尺寸/mode、秒数范围（固定档位为一个秒数）和售价。

这张表配置本站售价，不是模型能力声明；不能随意填写 4K/任意时长并期待上游支持。输入素材、音频开关、质量附加成本请用完整表达式或另设准确模型别名/档位。模板生成不会保存，需点击应用更改；重新打开看到保存的完整表达式，不反解任意旧公式为简单表格。

公开模型目录不会将模板中的配置预览分支显示成 0 元或按百万 Token 的首档价格，而是标明视频参数计价并进入完整规则。当前公开端尚未提供面向用户的时长/分辨率交互报价器。

## 提交、查询和费用安全

- 原生视频任务保存提交时选中的 Key，后续查询不切换到渠道其他账号；新任务生效，不恢复旧任务未保存的密钥。
- 视频开始提交后不自动重发。断线或错误响应可能发生在上游受理之后，需核对上游任务再手动重试；本站退款不证明供应商没有收费。
- 缺任务 ID 不返回假受理成功。未知查询状态、认证/查询错误、没有输出的“成功”不会被写成生成完成或直接退款；保持旧状态等待可靠结果，最终超时仍遵循原超时规则。
- Sora 是内容接口下载，成功不要求直接 URL；Google/Vertex 保留已有结果形式，不把空 operation 当成成功。Sora 兼容响应中的 id/task_id 均替换为本站公开 ID。
- 终态沿用现有 CAS、资金源及退款逻辑，本次没有解决 CAS 和资金调整之间的进程崩溃原子性，也不声称覆盖生产 MySQL/PostgreSQL 实例验收。

## 验收方式

本地测试矩阵覆盖九类出站转换/计价字段、成功缺结果/未知状态、缺任务 ID、账号持久化、即梦 req_key、Kling 文生路由、元数据冲突、模板保存/重开和 M2.5 隔离。另跑既有适配器、任务资金、终态和退款回归；所有生成请求仅发往本地模拟服务器或被浏览器拦截。

上线前逐实际渠道确认：协议、模型版本、合法参数、本站售价、上游成本；再按明确预算做每条实际链路的小量生成验收。不能以配置预检或同厂商另一个型号成功替代这些检查。
