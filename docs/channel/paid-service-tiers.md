# 显式加速档位

管理员只在已验证支持的OpenAI类型渠道上登记能力。新渠道先停用，先部署对应服务端与网页代码，再配置并验证，最后才启用。不需要更改生产表结构。

## 配置

渠道 `settings`（other settings JSON）保留原有字段并合并：

```json
{
  "allow_service_tier": true,
  "paid_service_tiers": {
    "gpt-6-astra": ["priority", "ultrafast"]
  }
}
```

网页渠道编辑提供“按模型开放加速档位”JSON字段；每个键必须是渠道Models里的精确对外模型名，不能填通配符。可仅登记priority；未验证的型号不登记。注册包含停用渠道，因此临时停用不会让加速请求静默进入其他普通渠道。移除最后一个登记等于取消该模型的受管策略，需明确评估既有客户端后再操作。

登记后的同名模型全局使用严格档位语义：不传或default=标准，priority=Fast×2，ultrafast=UltraFast×6；其他值（包括fast、auto、flex）拒绝。未登记模型保持原有行为。兼容旧客户端前应说明该变化；不要将普通渠道的AllowServiceTier开关当成已验证支持加速。

加速仅支持 `/v1/chat/completions`、`/v1/responses`、网页 `/pg/chat/completions`；其他协议不隐式丢字段。普通请求仍可使用原有渠道，付费档请求从原授权候选中筛选支持档位的渠道，不扩大账号/令牌分组范围，不改变模型或排序规则。亲和、指定渠道、重试与跨组回退不能跳过能力检查。

## 计费与出站

已登记模型使用现有tiered_expr基础价格；选付费档后后端将整段表达式冻结为“基础表达式×2/6”。分组和时间倍率继续由原有逻辑计算；缓存、长上下文价格仍在原表达式里，倍率同时作用于预扣及结算。不要再往原表达式加service_tier条件；检测到已有规则会拒绝，避免重复倍算。非表达式计费的模型暂不开放付费档。

出站序列化完成、过滤/参数覆盖之后复查实际service_tier。值被删除、降档、升档或普通请求被强制加速时，在HTTP请求之前拒绝。上游响应回显default不会回写原请求档位或改变结算；这是Muze实测兼容性事实，不构成固定速度提升承诺。

使用日志包含 `requested_service_tier` 与 `service_tier_multiplier`，列表和详情显示Fast×2/UltraFast×6，表达式结算保存实际总额。请求失败仍遵循原有退款/失败计费规则，不能仅凭超时承诺未收费。

## 能力查询与客户端

本人接口：`GET /api/user/service-tiers?model=...&group=...`，复用UserAuth与限流，private/no-store。只返回本人可选组和当前可用候选的档位，不返回渠道或Key。接口不承诺未来可用性，实际请求再次校验。当前为控制台账户鉴权，不是模型调用Key的鉴权端点。

客户端交接见 [接入约定](service-tiers-client.md)。网页模型体验仅单模型且非自定义JSON时显示控制；无登记且无保存的付费选择不添加无效控件。只查询当前活跃会话，无轮询。保留选择但重新确认能力，失败/切组/账号切换不偷偷降档发送；多模型模式不携带加速字段。

## 验收与回退

先隔离检查三档请求和日志，再确认所有备用渠道行为、用户余额/令牌结算、长上下文和缓存，随后按受保护发布流程上线。注册新渠道停用期间，能力接口仅显示标准；此时加速请求应拒绝。生产回退不能只退代码却保留允许上游加速的配置，必须先停止受管付费档的新请求并完成在途请求核账，否则旧代码无法保证倍率。

本次本地验证使用SQLite与模拟HTTP传输，三库通用GORM查询、无schema迁移；不代表生产/其他数据库实机验收。线上Muze最小请求验证了条件扣费，未通过Meta生产网关做收费验收。2026-11-08通过用户已登录后台新建独立渠道1657，归入OpenAI · 鹈鹕王，仅gpt-6-astra，允许service_tier，保持停用。创建时先用隔离占位模型，停用后再改真实模型；未使用正式模型的启用窗口接流量。线上尚无paid_service_tiers登记控件，待部署后补登记，不能提前启用。
