# 聊天请求的预留与结算

普通同步 Chat、Claude Messages、Responses、Gemini 文本生成，使用无限额且未启用周期包的令牌、钱包支付时，钱包可用余额高于10计费单位会采用首笔预留。按输入和最多4096个输出Token估算，首笔不超过原完整估算或10计费单位；收费请求至少预留1个内部quota。这里的10是站点计费单位，不是人民币；内部换算使用 QuotaPerUnit。

每笔请求在数据库事务中检查并占用余额。其他在途请求看到的是扣除占用后的可用余额；余额不高于10时仍须满足原完整预估。完成后按供应商实际用量及原计价规则补扣或返还，失败走现有退款流程。请求的 max_tokens 等输出上限保持原值，4096只用于首笔估算。

首笔金额不是费用上限。长输出的实际费用超过预留时仍补扣，并发结算可能使余额透支；本次不做流式实时费用截断。进程异常退出后未结预留需要按现有账本运维流程核对，不按超时自动退款。

有限额令牌、周期包、订阅资金来源、按次/阶梯计价、音视频、生成图片、异步任务和强制完整预扣场景保留原规则。Claude工具结果里的图片/PDF按媒体处理，Base64不再作为普通文本参与Token估算。

拒绝会区分余额耗尽、单次预估超过可用余额、在途请求占用。后两者不会触发连续三次自动禁用；在途占用也不触发充值提醒。原有禁用令牌需要手动启用。资金来源回退成功不算失败，回退仍不足时保留有余额来源的真实原因。

管理员可在使用日志展开“请求预扣费额度”，查看输入估算、请求输出上限、倍率、完整估算、首笔占用及拒绝原因。数值以内部quota记录并附 quota_per_unit，不包含请求正文或密钥；普通用户无法读取这些管理分项。历史日志不回填。

本次无数据库结构迁移。版本发布与生产升级分别执行，升级仍使用受保护发布入口。
