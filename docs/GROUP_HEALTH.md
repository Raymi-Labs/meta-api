# 分组健康、首字延迟与缓存命中率

普通用户在模型广场的“分组健康”、模型详情的“调用表现”，以及令牌创建/编辑的分组选择中查看平台分组表现。保留原有分组价格、描述、倍率和自动分组调用链路。

## 展示范围

- 仅登录用户可查询；服务端按用户可用分组和现有分组配置交集过滤，不能通过查询参数扩大范围。
- 用户状态、角色和分组以数据库当前值为准；全部模型汇总同样排除对该角色隐藏或禁止调用的模型。
- 展示平台在对应分组的聚合统计，不是当前用户自己的使用日志；不返回渠道名称、ID、类型、密钥、账号或其他用户身份。
- 模型详情按当前模型统计。令牌选择默认展示全部模型的分组汇总；不同模型的调用占比会影响整体均值，比较速度时优先在模型广场选择同一个模型。
- `auto` 是自动选择策略，不与固定分组混排为一条健康评分。真实结果归到实际使用的分组。

## 统计口径

- 同一次请求在同一分组内重试合并为一次，以该组的最终结果计成功/失败。跨分组兜底时分别记录各组结果，例如 A 失败、B 成功，不能将 A 记为成功。
- 成功率为成功次数除以总次数。汇总采用原始计数加权，不取各时段成功率的算术平均。
- 缓存命中率为成功请求的缓存读取 Token 总量 ÷ 输入 Token 总量 × 100%，包括未命中的有效请求；不平均各请求、模型或时段的百分比。OpenAI/Gemini 输入总量已包含缓存；Anthropic 输入总量为普通输入 + 缓存读取 + 缓存写入，写入不算命中，5 分钟/1 小时写入分项不重复累加。图像/音频接口的次数、字符或时长计费单位不纳入此项。
- 仅有效上游用量贡献缓存样本；本地估算、失败尝试、缺失用量和无输入 Token 不计入。有效用量中读取为零显示 0.00%；历史桶或没有有效用量显示 `—`。
- 首字均值只统计成功流式请求且确实观测到首个有效输出的样本。心跳、连接建立、空首包不算首字；缺失有效时间不以零或旧首包时间替代。
- 同步生图使用平均完成耗时，与文本首字延迟分开。异步任务的完成结果不由提交接口的 HTTP 200 推断。
- 时间格按一小时聚合，显示当前小时及前 23 小时；当前小时尚未结束，因此不是精确滚动 24 小时。百分比、成功/失败数和耗时使用同一查询窗口；首字/完成耗时有各自的有效样本数。
- 无样本显示“暂无样本”或 `—`；小样本明确提示“样本不足”。请求失败和统计不可用单独展示，不把接口错误渲染成零请求或正常状态。

## 升级说明

分组健康使用独立的新统计数据。升级前的历史消费日志、渠道尝试日志和旧性能首包指标不混入新口径，因此首次上线需要等待真实调用积累。

compat.11 为 `group_health_metrics` 增加缓存读取量、输入量及有效样本数三列，使用 GORM 增量迁移，兼容 SQLite、MySQL 和 PostgreSQL。既有记录默认零样本，不推算历史命中率；需要部署后积累新请求。API 汇总与每小时桶均返回 `cache_hit_rate`（0–100 或 null）及 `cache_sample_count`；旧后端缺少字段时前端显示 `—`。令牌摘要/下拉以“缓存”紧凑展示，分组备注保留，完整口径收在信息按钮。

接口为 `GET /api/health/groups`，可传 `model` 和 `group` 精确筛选，返回最近 24 个小时桶的分组汇总、有效样本数和小时序列。`updated_at` 表示最近采样时间。用户侧每分钟刷新；页面隐藏时暂停定时刷新。同一登录会话的相同查询共享请求，退出或切换用户不沿用其他会话的统计缓存。

每个实例按小时聚合，每 5 秒向主数据库写入独立 ID 的绝对快照，重复刷盘不会重复累计；查询只读取已持久化数据，多实例共享主数据库时自动汇总。数据保留 7 天，内存待写桶上限 8192。数据库写入失败或本实例丢弃样本时，接口返回采集不完整提醒；该提醒不是跨实例的全局监控。正常停机会尝试排空请求并刷盘；强制杀进程仍可能丢失尚未写入的最近样本。

当前覆盖同步转发接口的成功/失败，首字时间覆盖 OpenAI、Claude、Responses 和 Gemini 的有效文本、思考或工具输出；其他未采到有效输出时间的请求仍统计结果，但不填造首字样本。异步任务提交/轮询和实时会话不纳入。认证、用户余额或模型权限等前置拒绝不用于评估分组；配置存在但无可用渠道的分组故障计入失败。

管理员在智能路由页「分组概览」查看全部分组的同口径汇总：`GET /api/route_insight/groups?hours=1–168`（仅管理员）读半小时表，全部模型按分组求和，不按用户可用分组或模型可见性过滤，不列 `auto`，并附线路健康快照中的不健康渠道。

本功能不改变计费、自动分组顺序、渠道选择、令牌限制或重试策略。分组健康是历史调用表现，不是可用性承诺。
