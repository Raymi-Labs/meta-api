# Agent Note: 项目能力核对与决策笔记流程

Status: implemented

## Problem

围绕单个页面设计容易忽略相邻页面已有能力；聊天中的理由也无法随代码稳定传递。项目需要可检索的当前能力入口、决策依据和机械检查，但不需要给每次小改增加审批。

## Decision

AGENTS.md 要求按任务范围核对现有页面、接口与数据，优先复用，再实施。功能地图提供代码入口，决策笔记记录理由与真实备选；两者各司其职，不建立逐篇总索引。固定版本的 Skill 按项目安装；Bun 直接执行 TypeScript 校验，不增加 npm/tsx 在线下载依赖。

用户已有授权优先于上游重复确认流程。结构校验运行于本地 Makefile 和 CI；业务运行时、应用版本与生产部署不随流程接入改变。第一篇业务提案是 [渠道用量整合](../feature/2026-09-29-channel-usage-in-management.md)，随业务实现更新状态。

## Existing capabilities and impact

接入前已核对 AGENTS.md、Makefile、.agents/github 和现有 GitHub Actions，没有笔记目录或校验链。保留原有 Go/React 构建和发布任务；新增独立 Verify Agent Notes 作业。上游来源及本地差异见 [来源说明](../../../skills/write-notes-like-deepseek/UPSTREAM.md)。

## Alternatives considered

- **仅在聊天中提醒**：成本最低，但理由无法随仓库版本传递，不能解决后续会话重复遗漏。
- **只加入笔记 Skill**：能保存决策，但错误方案也可能通过格式检查，因此增加现有能力核对和跨入口验收规则。
- **全面补写历史决策并建立集中索引**：初期检索方便，但会猜测历史理由、增加维护和冲突；仅记录本轮确认的事实，后续按任务补充。

## Consequences

收益是重要选择可以追溯，旧约束容易检索，坏链接和归档改写可自动发现。代价是重要变更需同步文档；功能地图可能过时，使用时必须核对代码。脚本不能验证全局最优、语义质量或所有漏写行为；不将 CI 通过当成产品设计正确。

## Testing

`make verify-notes` 通过（2 篇活跃笔记，当前无归档）。临时隔离样本验证了缺失备选章节、死链、非法类别、缺少封印、修改归档正文及同时修改封印均返回失败；最后一项使用临时 Git 仓库基线。项目文档及代码相对链接通过存在性检查。看板打包成功包含 2 篇笔记，生成物仅在 /tmp，不纳入产品构建。远程 CI 结果以实际运行记录为准。

跨项目安装及独立分发由[迁移包决策](2026-10-15-portable-agent-workflow.md)补充，本项目原有 make/CI 入口继续使用。
