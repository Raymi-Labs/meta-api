# Agent Note: Luna 仅在福利、优选、企业级分组开放

Status: implemented

## Problem

用户要求从刚列出的混合分组渠道中拆出 Luna，仅允许福利、优选、企业级调用；明确 1352、1385、1640 已合规无需改动。现有渠道的 models 与 group 生成笛卡尔积 abilities，直接删整个渠道的其他分组会影响非 Luna 模型，直接改 abilities 又会被保存或重建覆盖。

## Decision

复用管理 API 新建六个只含原 Luna 型号的专用渠道，继承各自上游凭据、协议、代理、优先级、权重及其他设置。1365、1502 的 Luna 专用渠道只属优选；1398、1486、1495、1532 的只属福利。原六渠道移除 Luna，保留其他模型及原分组；原测试模型若已移除，换为仍在原列表中的模型。1352、1385、1640 不写入。当前其他停用渠道不启用、不迁移；最终所有启用 Luna 能力的分组集合须只含指定三个通用组。

新建先用停用状态、精确模型/分组创建，核对凭据摘要及配置后启用，随后从对应原渠道移除 Luna；原服务保持在线。现有 CopyChannel 立即复制全部启用能力，会短暂复制其他模型且无创建时收窄字段，采用 AddChannel 直接构造受限记录。六源均为单 Key，渠道配额策略未启用，无固定渠道限制的业务令牌引用；不需要改动业务令牌。新渠道历史使用量从零开始，原账单不搬移。

## Existing notes audit

- [Luna 官方价乘 33](../../implemented/process/2026-11-01-luna-official-retail-33.md)：全局价格继续沿用，本次只收窄渠道能力分组。
- [令牌模型分组](../../implemented/feature/2026-10-27-token-model-groups.md)：令牌范围是附加限制，不能替代全站渠道分组隔离，不改用户令牌。
- [Gemini 分组迁移](../../implemented/process/2026-11-01-gemini-groups-merge-welfare.md)：本次仅拆一个模型族，不能把整个原渠道移组；复用 API、快照、abilities 与目录核对方法。

## Alternatives considered

- 直接删除原渠道的非目标分组最简单，但会同时收窄全部其他模型，不符合仅处理 Luna。
- 只删除 abilities 中的禁用组合不创建渠道，但它是衍生数据，下一次渠道保存/重建会恢复，不采用临时改库。
- 参数覆盖按模型和分组拒绝无需新渠道，却仍在目录声明可用且路由后才失败；专用渠道让实际候选和目录一致。
- 全部混合渠道去掉 Luna、不保留专用线路可以更少记录，却会丢掉原有福利线路以及优选备用容量；保留各原上游的授权组入口。

## Verification

写前快照、旧值与配额/单 Key/令牌绑定预检通过；六新渠道为 1641–1646，移出原六渠道的 8 个 Luna 名称组合，三个源测试型号同步改为保留型号。全部非 Luna 能力与其原分组保持，所有启用 Luna abilities 和目录只在三个通用组。8 个新线路模型组合真实调用全部成功，按优选 0.8 / 福利 0.6 的当时倍率结算，日志与令牌单次扣费一致。三个禁止组的 6 次请求拒绝且零扣费，目录隐藏；14 个临时令牌已删除。价格/分组/业务令牌保持。1352 后台检查时间戳变化单独记录，其业务配置不变。见[配置与验收](../../../../docs/channel/luna-routing.md)及[审计](../../../../docs/channel/luna-routing-audit-2026-11-01.json)。

## Consequences

限制以实际路由/计费组为准，既有多组令牌仍能使用其获准的通用组，不扩大或修改令牌权限。新渠道 ID 独立承载使用量和健康记录，未来原渠道换密钥/设置须同步专用渠道。停用历史渠道若将来重新启用须再审核 Luna 分组；本次不自动修改它们。回退先恢复源模型，再停用新渠道，按预期值保护同期变更。

后续的[调用令牌迁移](2026-11-01-luna-callers-welfare.md)已[按用户要求撤回](2026-11-01-revert-luna-caller-migration.md)；本篇渠道拆分、既有价格和停用渠道边界继续适用。
