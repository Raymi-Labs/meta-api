# Agent Note: 大版本按产品里程碑递增

Status: implemented

## Problem

用户否定“不兼容变更直接升级大版本”，并确认采用：日常修复递增末位、功能更新递增中间位，不兼容变更按更新规模选择版本并说明迁移要求，大版本仅用于明确产品里程碑。刚落库的规则套用了严格 SemVer 的兼容性触发条件，需纠正为本项目的产品版本约定。

## Decision

保留正式三段式 vX.Y.Z、首次 v1.0.0、历史版本保护及预发布边界。修复递增 Z，功能更新递增 Y 并归零 Z；X 仅在明确的产品里程碑或整体重大升级时递增。发生不兼容变更时按更新性质与规模选择修订或次版本，不自动升主版本；中文更新说明单独列出受影响范围与迁移要求。

维护入口改称正式三段式版本，不再宣称严格语义化版本。现有工作流只消费完整标签并区分正式/预发布，无需修改。当前应用 VERSION、历史标签和运行时行为不变。

## Existing notes audit

- [正式版本号](../../implemented/process/2026-10-31-stable-version-policy.md)：部分取代兼容性决定主版本的规则；保留停止新增 compat、正式发布基线、历史保留及工作流复用。
- [公司仓库迁移](../../implemented/process/2026-10-27-company-repository.md)：部分重叠，其版本序列决定已由正式版本号笔记取代，其他仓库/产物边界继续有效。
- 其他运行时兼容修复和迁移笔记不负责版本命名，无需改写。

## Alternatives considered

- 严格 SemVer 可让消费者从主版本判断不兼容性，但用户明确选择大版本用于产品里程碑。
- 日常更新只递增末位最简单，但无法区分修复与功能更新，用户在两个选项中选择了保留中间位的方案。

## Verification

AGENTS、公司说明、发布文档和功能地图已统一为正式三段式版本，不再要求不兼容变更自动升主版本；逐项核对修订号、次版本号、产品里程碑和迁移说明规则。新旧决定互链，原规则在旧笔记中明确标为部分取代。发布策略检查与既有13项发布回归通过；工作流、脚本、VERSION 和应用代码无变化，无需重建应用产物。

## Consequences

版本号本身不保证升级兼容，使用者需要查看发布说明中的影响与迁移要求；不能因未升主版本省略必要的迁移验证。本次仅修改维护规范，不创建应用 Release 或部署生产。
