# Agent Note: 八个旧型号按官方价重建销售配置

Status: implemented

## Problem

用户核对企业级售价后明确要求纠正八个型号。此前“旧站内价 ×6.6”保留了旧输入、输出和缓存比例，三个 Claude 4.5 名称还将缺省 37.5 倍率写成正式售价；后续企业级接入保留旧价，未满足官方美元价 ×6.6×5。

## Decision

仅处理 claude-haiku-4-5、claude-sonnet-4-5、claude-opus-4-5、gpt-4o-mini、gpt-6.1-terra、gpt-6.1-sol、gpt-6-sol、gpt-5.6-sol。按官方标准美元分项乘33生成能量价；四个新一代 GPT 使用272000输入边界、输入/缓存两倍及输出1.5倍长档。Claude保留5m/1h缓存区分，OpenAI使用既有默认30m写入语义，不新增12h计量。

复用 root options API、普通四张倍率表及 tiered_bundle。先用一个原子 bundle 让八个型号全部使用完整新表达式，再同步不生效的基础/输出/缓存读写倍率，最后恢复四个普通型号的普通模式，四个长上下文型号保留阶梯。每一步写前重读、验证目标旧值、保留其他键；记录尝试步骤，失败只恢复符合预期的本次目标，不整表覆盖。服务器私有快照保存原值，凭据只在服务器读取。

## Alternatives considered

- 仅按差价再乘系数：改动少，但各分项偏差不同、缓存比例和档位也错误，不能保证官方价×33。
- 直接依次改四张倍率表：保留原模式，但在更新之间会产生新旧比例混用；先以原子表达式承接。
- 永久把八个型号改为表达式：一次切换简单，但普通型号无需改变计费模式和取整规则，因此过渡后恢复原普通路径。

## Verification

生产 v1.12.1 上通过六次管理 API 写入完成修正，无停服或应用部署。八项配置、公开目录与目标一致；其他价格配置、分组、充值及渠道静态摘要保持。第一次预检因目录数组顺序不同中止，未写入；将分组/协议数组按集合语义比较、重取快照后成功。原始非目标目录哈希还受到首行 pricing_version 标记位置变化影响；保留原始失败结果，另将完整目录按模型名对齐、数组排序并移除该非价格标记，216 个非目标模型逐字段一致。

独立官方美元表通过实际 Go 价格助手、缓存参数构造与结算引擎的6951项检查，覆盖过渡/最终配置、272000两侧、缓存/TTL组成、零用量、分组与时段倍率；实际前端解析/展示98项检查及相关后端、币种和阶梯回归通过。八个型号各一次企业级短 Chat 请求成功，日志、令牌和独立复算扣费完全一致，无重复消费；临时令牌全部删除。真实请求未触发缓存或长上下文，这些分支的证据来自实际引擎测试，不宣称付费长请求验收。

[配置说明](../../../../docs/channel/retail-official-correction.md)、[逐项审计](../../../../docs/channel/retail-official-correction-audit-2026-11-01.json)记录官方来源、前后配置、六步回执与八条消费。私有服务器目录保存完整快照、操作及校验脚本；仓库只收脱敏记录。配置及文档更新不发布新应用版本。

## Consequences

过渡期间普通型号短暂走既有表达式四舍五入，最多与普通截断相差1 quota；最终恢复原普通取整。已有在途请求使用冻结快照，不追溯更改。全局基础价格影响这八个型号的全部分组。官方参考价不等于自动改价规则，后续更新仍需显式审核；不自动扩展范围或支付大上下文验收费用。

八个型号的输入、输出、缓存与长档均有独立官方价格基准，解除默认值和旧比例造成的偏差。官方展示使用独立汇率；固定6.6换算售价不要求与实时人民币参考数字完全一致。

后续[其余型号校准](2026-11-01-enterprise-price-alignment.md)另修正29个名称及一个继承别名，本记录八项配置保持不变。
