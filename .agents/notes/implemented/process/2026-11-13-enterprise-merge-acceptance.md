# Agent Note: 企业工作空间合并验收与个人付款隔离

Status: implemented

## Problem

第一批企业功能已在本地验证，但缺外部数据库证据和可发现的开关入口；用户要求完成可验收改动、推送并合并main后自行验收，不另设测试环境。没有企业用户不能证明个人调用不受影响。复核发现用量汇总丢弃状态筛选、令牌额度筛选仍读个人字段。

## Decision

保留默认关闭和第一批入口范围，平台超级管理员可在企业管理页切换已有EnterpriseEnabled配置，普通平台管理员不能切换。关闭提示新企业请求被拒，在途账务保留；个人入口不变。状态读取失败不能伪装为关闭。控制台与公开壳共用状态读取代次，保存开关后拒绝旧响应，避免侧栏/付款选择被旧状态盖回。

用量列表/汇总/导出共享全部筛选；企业令牌额度筛选与排序读取企业预算，个人令牌沿用原字段。增加个人调用在开关开/关、加入企业/企业冻结时仍只扣个人钱包的回归。

GitHub Actions运行一次性MySQL5.7、MySQL8.0.46及PostgreSQL9.6，复用企业事务测试，加旧个人令牌和旧邀请增量迁移验证。数据库由CI销毁，不使用真实DSN或个人资料。CI通过后合并，不将合并等同部署或真实上游验收。

## Alternatives considered

只靠SQLite通过无法发现锁与方言问题；安装本机数据库或创建长期测试环境增加维护且不符合本轮意图。仅提供隐藏API开关难以验收，改为复用现有RootAuth配置入口。同步复制企业预算到个人字段会引入两份账源，选择查询时按付款方读取权威数据。第二批仅放开白名单会误扣个人资金，继续关闭并另行接入。

本地model/service/router/middleware/controller完整回归通过；开关开关、成员与冻结状态下个人调用只扣个人钱包；增量迁移与额度筛选回归SQLite通过。前端语言检查、状态与筛选测试、Vite构建通过。三库CI已配置，远端执行结果尚待核对，不将配置文件视作成功证据。

## Consequences

开通、所有者删除保护与所有权转移共享账号行锁，删除侧只读取企业归属，避免反向取企业锁；确定性交错测试覆盖开通未落库时注销竞争。管理员基础资料可编辑但模型范围只能所有者修改。精确thinking模型允许自身，不能扩成整族。CI证明合成数据下兼容，不代替生产备份、真实上游或SMTP验收。

首轮CI两组的三库模型阶段均通过；8.0.46组完整通过，5.7组controller全量测试中的独立路由观测后台任务在用例恢复DB为空后刷盘panic。企业流水线仅对切换全局数据库的controller测试显式设ROUTE_INSIGHT_ENABLED=false，service路由健康测试依赖开关保持默认启用，两者分进程执行；不改生产遥测默认值，不把首轮失败隐藏为成功。后续记录以修正后运行结果为准。

确定性交错回归在MySQL8实测失败揭示：删除事务内HasTable元数据读取会提前建立RR快照，即便随后等待账号行锁，普通归属查询仍可能看不到刚提交的企业。schema存在检查移到BEGIN之前，保留账号锁内的新鲜归属检查，避免使用企业行锁形成反向锁序。MySQL5.7和PostgreSQL原用例通过也不能替代8.0验证。
