# Agent Note: Gemini 企业专属和优质渠道、令牌迁入福利

Status: implemented

## Problem

用户要求将同时或分别属于 Gemini · 企业专属、Gemini · 优质的渠道加入福利，将这两组令牌迁入福利，再从渠道去掉两组。盘点命中 5 个渠道（3 启用、2 停用）、220 个未删除令牌（26 个主组企业专属、192 个主组优质，另 2 个仅多组引用；共 8 条多组路由）。目标福利倍率 0.6，优质原倍率 1，企业专属已无全局倍率/可用目录定义。

## Decision

复用[上一轮 vertex 迁移](../../implemented/process/2026-11-01-vertex-group-merge-preferred.md)的已验证流程：先管理 API 添加福利，再用同生产 MySQL schema 演练过的有条件事务更新令牌 group/routing_config，定向 Redis 失效后从渠道移除两源组。两个源组可以汇入同一目标，精确替换并按首次出现去重，模型子规则同样处理；原主组未命中时不改主组。两个停用渠道不启用，七个非启用状态令牌不改状态，模型、密钥、余额字段和其他限制不改写。

本次按用户明确范围移除渠道关联，保持全局分组定义/倍率设置；不把通用企业专属、Gemini · 福利等相似名称视为源组。192 个已删除令牌和历史账单不改。检查额外依赖为零；default、EMOXIA、OpenAI · 蒸馏 用户均获准福利，目标适用倍率均为 0.6。

## Existing notes audit

- [vertex 合并优选](../../implemented/process/2026-11-01-vertex-group-merge-preferred.md)：复用事务列更新、同引擎临时表、旧值冲突保护、Redis HMAC 和真实计费验收；本次为两个源组且只移除渠道关联，不删全局定义。
- [多模型分组](../../implemented/feature/2026-10-27-token-model-groups.md)：继续保持有序候选和逐模型子集；已有福利与两个源组去重不形成重复候选。
- [全站销售公式](../../implemented/process/2026-11-01-gemini-retail-fixed-666.md)：基础售价不变，实际使用福利组按现有 0.6 倍率计费。

## Alternatives considered

- 只改令牌主组最少，但会遗漏 8 条多组路由的候选/模型规则；迁移所有精确引用。
- 同时启用停用渠道可以扩大调用池，但用户没有要求恢复这些渠道，保持原状态。
- 复用上一轮并删除全局定义能够清理目录，但本次明确要求从渠道移除；保持定义，避免扩大配置变更范围。

## Verification

生产已完成 5 个渠道和 220 个未删除令牌迁移。218 个令牌主组变为福利，2 个保留主组但替换路由引用；8 条多组路由全部处理，其中 1 条含模型子规则，既有福利去重后不改变其他候选相对顺序。当前 channels/abilities/未删除 tokens 精确源组引用为零。192 个已删除令牌保留，7 个非启用状态令牌与两个停用渠道仍保持原状态。

同 MySQL 引擎/结构/排序规则的临时表正常迁移与旧值冲突拒绝两类演练通过，220 行只写 group/routing_config，保护字段核对通过。转换检查覆盖两个源组、NULL/空值、模型子集、稳定去重、通用企业专属和 Gemini · 福利等精确名称边界。模型价格/渠道密钥摘要及全局分组选项读回不变。

受影响令牌定向 Redis 失效（写入时已有缓存数 0）；用真实迁移 Key 重新访问目录，验证生成缓存 Group=福利，所有受影响缓存均无旧引用。5 个真实迁移令牌只读鉴权通过，覆盖两源组、带模型规则的多组令牌和 default/EMOXIA/OpenAI · 蒸馏 的福利权限。公开 pricing 源组能力消失，三个启用渠道提供 9 条福利能力、7 个不同模型。

三个启用渠道实测全部 200、日志分组福利、倍率 0.6，且每笔仅一条消费：1374 的 Gemini 3.8 Flash 为 258/69 Token、4518 quota；1510 的 Argon 为 35/5、1199；1525 的 Argon 为 35/77、8392。实际令牌扣费与独立参考价 ×33.3 公式一致，临时令牌全部删除。停用渠道未发送付费测试请求。

生产仍为 v1.11.12，无应用或依赖重启。私有恢复/验收材料在 `/opt/meta-api/operations/gemini-to-welfare-20261101`，公开记录见[配置说明](../../../../docs/channel/gemini-welfare-group.md)。仅操作文档提交推送，无应用新版本或 Release。

## Consequences

合并后使用福利共享渠道池及既有倍率/优先级，不为每个令牌单独保留原池。保留全局定义意味着旧组仍可能出现在配置目录中，但没有渠道能力；历史名称不用于授权。并发新建旧组令牌会被最终检查发现，不能误报全部完成。
