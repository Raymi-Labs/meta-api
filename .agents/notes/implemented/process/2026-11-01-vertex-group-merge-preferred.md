# Agent Note: Gemini vertex 分组并入优选

Status: implemented

## Problem

用户要求将 Gemini · vertex 的全部渠道加入优选，迁移该组令牌，并移除旧组。当前有 3 个渠道、20 个旧固定组令牌和 2 个引用旧组的多组令牌；另 34 个已删除令牌保留历史数据。源倍率 4，目标倍率 0.8，迁移按目标现行倍率计费。

## Decision

复用渠道管理 API 先给 1510、1566、1576 增加优选，保留其他组、状态、优先级、权重、模型和密钥。随后迁移未删除令牌的 group 与 routing_config.groups/model_groups，精确替换并按首次出现去重，保留相对优先顺序。主组不是旧组的多组令牌不改主组。最后从三个渠道、GroupRatio 和 UserUsableGroups 移除旧组。

令牌 API 仅允许本人编辑且全量写回额度/限制，不能作为跨用户的局部迁移接口。使用生产 MySQL 事务只更新 group/routing_config，条件比较旧值并校验全部行数，先在同引擎同结构的临时表演练；不写入余额、使用量、密钥或其他字段。按项目 HMAC 规则仅清理受影响令牌 Redis 缓存，验证数据库/缓存/鉴权模型目录。全程旧应用在线，不更换程序、不重启依赖。

预检确认无用户默认组、商品允许组/发放请求、订阅升级/恢复组、CRS 站点或用户设置引用；default 和 EMOXIA 用户均有优选权限，适用倍率都是 0.8。保留已删除令牌及日志、统计、任务等历史归属，不重写历史账单。旧组收藏属于客户端本地数据，不作为服务端授权来源。

## Existing notes audit

- [多模型分组](../../implemented/feature/2026-10-27-token-model-groups.md)：复用有序 groups 和逐模型子集契约，迁移全部精确引用，不扩大单条模型规则。
- [首选组与回退](../../implemented/feature/2026-10-24-preferred-group-fallback.md)：保留原开关及渠道/模型限制，按实际目标组收费。
- [候选置顶](../../implemented/bug-fix/2026-11-01-token-group-priority.md)：仅目录展示，无需程序更改。

## Alternatives considered

- 直接删旧分组配置操作最少，但现有令牌会立即因弃用组失效，故按加渠道、迁令牌、删旧组的兼容顺序执行。
- 通过本人令牌更新 API 可自动更新缓存，但跨用户无对应管理员局部入口，且全量额度写回会覆盖并发消费；采用带旧值条件的事务列更新和定向缓存失效。
- 全量改写历史分组能让字符串搜索归零，但破坏旧账单及已删除记录的原始归属，不属于运行配置迁移。

## Verification

生产迁移完成：1510、1566、1576 的优选能力分别为 7/3/1 条（7 个不同模型），所有其他静态配置及渠道密钥摘要保持；20 个固定组和 2 个多组令牌完成精确迁移，未删除令牌、当前渠道及 abilities 的旧组引用均为 0。一个停用令牌仍停用。迁移 SQL 只更新两个路由字段；非路由保护字段核对通过，不写回任何消费计数。34 个已删除令牌保留，模型价格配置摘要不变。

同生产 MySQL schema 的临时表演练通过正常迁移及旧值冲突拒绝两种场景，后者在提交前失败并回滚。首次临时表演练分别发现 utf8mb4 默认排序规则冲突、空十六进制字面量错误；显式 utf8mb4_unicode_ci 与 X'' 修正后通过，两个失败均未进入真实数据写入。现有 service/model 的令牌路由/分组回退回归通过，迁移转换检查覆盖 NULL、空字符串、精确名称、模型子规则、顺序与重复去除。

受影响令牌按真实运行 secret 和 Redis DB 计算 HMAC 键定向失效（当时已缓存数为 0）；再次用迁移后的真实令牌读取目录，核对新生成缓存 Group 为优选，受影响键均无旧组引用。三个真实令牌的目录鉴权通过，覆盖固定组、多组和 EMOXIA 用户权限；公开 pricing 的旧组消失且七个模型提供优选。

每个渠道各用临时令牌执行一次 gemini-4-argon：全部 HTTP 200，均为 35 输入/5 输出 Token、优选 0.8 倍率、1598 quota，消费日志与令牌实际消耗一致，每笔仅一次消费；临时令牌已删除。1576 响应约 28.69 秒，其余约 3.5–3.7 秒，不将迁移成功表述为三个渠道性能相同。

私有执行/恢复材料在 `/opt/meta-api/operations/vertex-to-preferred-20261101`，公开记录见[配置说明](../../../../docs/channel/gemini-preferred-group.md)。生产保持 v1.11.12，应用和依赖没有重启；只有配置操作文档提交，不创建新应用版本或 Release。

## Consequences

迁入优选后按目标组共享渠道池及 0.8 倍率选择和收费，属于用户指定的合并行为；保留原渠道优先级可能影响优选同型号的候选顺序。在途请求沿用原上下文/计费快照；失败恢复先补回旧组配置和渠道，避免令牌悬空。
