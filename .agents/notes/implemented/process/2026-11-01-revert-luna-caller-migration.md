# Agent Note: 按用户纠正撤回 Luna 令牌迁移

Status: implemented

## Problem

用户明确表示刚执行的 Luna 调用令牌迁移不对，要求改回且不再继续。2686 个目标当前仍精确等于本次迁移写入的路由，没有后续路由修改；此前独立完成的 51 个 default 继承令牌迁移不在撤回范围。

## Decision

仅撤回 [Luna 调用令牌迁移](../../implemented/process/2026-11-01-luna-callers-welfare.md)：从私有 before-apply 快照恢复 2686 个目标的 group/routing_config，用预期当前值和用户 ID 保护事务，其他字段不写回。恢复后定向失效缓存、逐条验证原路由，核对 default 迁移仍保留。停止本次 Luna 令牌调整，不改变之前已完成的渠道限制或定价。

## Alternatives considered

- 继续优化历史调用筛选再迁移可以缩小范围，但用户明确要求撤回并停止，不继续设计或执行替代迁移。
- 恢复整行快照最直接，但会覆盖执行后真实消费等字段；只恢复两个本次变更的路由列。
- 回滚此前全部分组变更会同时撤销独立的 default 迁移，超出本次纠正范围；以本次操作快照精确撤回。

## Verification

回滚前全部 2686 个记录仍精确等于本次写入值，没有同期路由冲突。相同 MySQL schema 的临时表反向更新演练通过；事务恢复全部原路由（含 29 个多组配置），逐条与原快照一致，其他保护字段保持，未覆盖实时消费字段。

定向失效 13 个 Redis 缓存，剩余缓存中主组和多组路由没有迁移后的旧值。此前 51 个 default 继承令牌仍与其完成快照一致，保持福利。生产核验版本为 v1.12.1，无应用发布或重启。历史迁移审计保留并标注撤回，见[当前状态与历史](../../../../docs/channel/luna-token-welfare.md)和[撤回回执](../../../../docs/channel/luna-token-welfare-audit-2026-11-01.json)。

## Consequences

恢复原组也恢复原来模型与分组的可用性，渠道侧 Luna 限制继续存在；不因回滚而扩展渠道权限。遇到同期人工修改时不覆盖，而是记录精确冲突；当前预检无冲突。
