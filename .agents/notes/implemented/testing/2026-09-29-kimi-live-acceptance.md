# Agent Note: K3 真实入口验收与证据边界

Status: implemented

## Problem

客户需要确认实际入口能否满足功能与性能要求，本地模拟回归不能回答这个问题。旧测试令牌属于非 Kimi 分组，用户已另行提供可访问 K3 的测试令牌。其默认 Kimi 分组存在多条渠道，单次成功和混合渠道汇总都不能证明任意单渠道达标。

## Existing capabilities and impact

- 复用[官方 KVV 对齐](../../implemented/testing/2026-09-29-official-kvv-alignment.md)固定提交及原始断言；该笔记部分重叠，保留其离线回归边界。
- [复测范围纠偏](../../implemented/bug-fix/2026-09-29-kimi-retest-scope-correction.md)约束异常计费、视频和完整请求体分别验收；保留，不把入口拒绝当作假成功退款。
- 本地正在进行的 usage 字段改动不属于本次验收实施范围，不修改、提交或部署；真实测试结论仅绑定已核实的线上版本。
- 复用生产请求日志的 token、时间、渠道与用量关联，不创建新账户或修改渠道、令牌、余额。

## Decision

- 用户授权的密钥仅存在测试进程内存或子进程环境中，不落盘、不显示、不传给第三方测试门户。
- 元衡真实入口使用已核实的 `nan.meta-api.vip`。默认分组测量视为分组链路验收，逐请求关联实际渠道；需要定向诊断时仅利用既有管理令牌能力指定该次请求，不改变普通用户路由。
- 固定官方 KVV 提交，不修改源码或降低断言。分阶段选择官方功能样例并保留原始结果、跳过与重试；实际运行范围清楚记录，不把子集称完整 KVV。
- 客户补充项使用合成工具返回、随机校验串、确定性图片与短视频。分别验证内容语义、完整流式终态、token 使用及请求日志，HTTP 200 不是唯一通过条件。
- 先功能后性能；并发最多 2，设请求数和连续异常停止边界。遇到已证实关键失败可停止相关后续测试，未执行的项目按未测保留。
- 不直接触发 192 MiB 大体积或全量视觉/长记忆基准。需要明确端到端大体积资源预算、供应商兼容条件后另行执行；应用配置 192 不等于端到端已通过。

## Alternatives considered

- **一次跑全部官方基准与客户负载**：覆盖面最好，但会混合多个渠道，官方默认长输出和重试扩大费用，也不能借此定位哪一层失败。先分阶段执行并保留未测范围。
- **为通过验收修改线上路由或手工选最佳渠道**：更容易得到稳定样本，但改变了客户真实使用路径。默认分组与定向诊断必须分开标注，不静默切换或禁用渠道。
- **仅用既有线上日志代替测试**：没有额外模型费用，但缺少可验证的输入和预期输出。日志只用于本次合成请求归因与计费核对。

## Verification

- 真实入口共执行 61 次接口请求；开始和结束均核实为 main-18a2e98。官方第一批 22 项得到 17 通过、3 失败、2 跳过；1468 定向复测执行 3 项均失败后停止，其余未执行。
- 视频对象样例、图片、普通工具回环及 75K 三位置校验码通过；字符串视频输入、动态工具、Messages 和 Responses 出现真实失败。完整证据见[验收报告](../../../../docs/KIMI_LIVE_ACCEPTANCE_2026-09-29.md)。
- 短上下文 25 次、并发 2，在 55 秒测试上限内 22 次完整成功、2 次意外连接中断、1 次测试主动超时取消。首个有效输出的 24 个可观测样本平均14.02秒、样本p99为45.44秒；未收到首字不记0，也不从延迟统计中静默移除已收到首字的失败样本。
- 独立进程三协议/交付复核中两次 Chat 通过，Messages 404、Responses 500。进程退出状态不能代替业务断言。
- 58 次请求通过请求 ID 精确关联选列生产日志；3 次响应头 ID 与日志不一致，另行保留边界。同令牌时段存在其他调用，不把整个令牌增量当本次费用。
- 测试密钥不落盘、不上传个人文件；不写生产配置或余额。26份相关产物检查未发现测试密钥；全部测试进程退出，SSH复用连接关闭，持有凭据的临时执行环境已重置，本任务遗留进程为0。

## Consequences

[HTTP 请求 ID 一致性](../bug-fix/2026-10-20-response-request-id-integrity.md)修复当前网关上游同名头覆盖本站 ID 的路径。该修复不补造本次历史实测缺失的原始响应头，也不把三次关联缺口直接归因为同一原因。

用户未提供原始门户 JSON 或完整性能脚本，补充样例只能验证明确的行为，不能冒充客户原脚本全量复现。默认路由、上游响应头及供应商状态可能变化，必须记录时段并核对生产日志；超出可归因范围的结论保留未知。

1459在测试期间变为停用，一次拟指定该渠道的请求实际落在1468。因此定向参数不能替代日志确认。实际链路验收已证实不满足要求，但仍不能把全部缺陷归给网关或供应商；192 MiB、假成功原始样例、S2全量性能和剩余官方套件保留未验收。不会为了形成全绿报告修改官方断言或继续扩张费用。
