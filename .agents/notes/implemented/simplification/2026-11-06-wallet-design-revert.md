# Agent Note: 撤销钱包整体设计与支付价差说明

Status: implemented

## Problem

用户在审阅实际钱包页面后明确要求“还是原来的，不用改了，撤销”。7fcc3d1e9 已推送，v1.19.0 标签和双架构镜像存在，原Release创建曾因GitHub HTTP500失败；后续主线v1.20.0已包含该提交及独立的Jev协议功能，不能回退整个仓库或重写已发布标签。

## Decision

在最新主线反向应用7fcc3d1e9的钱包界面、附加报价、历史价差接口及对应测试/翻译变更，恢复f69a6f86e时的钱包实现。保留后来Jev相关代码、所有版本历史与既有支付/兑换的安全行为；以新修订版发布恢复结果，不补发已取消的钱包设计版本，不执行生产部署。

已有能力核对：功能地图的钱包入口→TopUp/RechargeCard/InvitationCard/WalletOverview及确认弹窗→原用户鉴权报价/支付和账单/兑换接口；新增cost_reference读取、比较报价hook和展示组件均由待撤销提交引入，没有数据库迁移或需要还原的真实资金操作。

[11月5日设计](../../implemented/feature/2026-11-05-wallet-payment-costs.md)由本决定撤销；[经典钱包](../../implemented/feature/2026-10-30-wallet-classic-layout.md)和[资金操作边界](../../implemented/feature/2026-10-28-wallet-experience.md)恢复为当前行为；Stripe显示名设置继续沿用既有配置。

## Alternatives considered

- 将分支硬重置到设计前提交能获得完全旧树，但会丢失后续Jev功能并要求重写远程历史，因此不采用。
- 只回退CSS可以快速恢复部分外观，但会留下新增报价请求、历史价差接口和确认行为，无法完整满足撤销要求；采用仅针对原提交的可追溯回退。

## Verification

- 逐文件比对确认原提交涉及的34个钱包业务/测试/翻译文件与f69a6f86e完全一致（新增文件已移除）；后续Jev提交的非共享版本/地图文件与回退前HEAD一致。
- `go test ./controller ./model` 全包通过；原钱包支付/兑换防重与旧响应隔离、支付跳转、记录语义共12项Node回归通过，跳转脚本另覆盖桌面/手机的5条支付路径。
- 临时提取既有 pricing-wallet-layout 浏览器脚本的钱包部分执行，桌面和390px手机的原充值报价、支付说明位置、兑换入口、无资金写请求及无脚本错误验证通过。完整模型广场脚本不在本次回退范围。
- Bun完整构建和5个公开页面Chrome预渲染、Go构建通过；保留既有大包与第三方eval提示。笔记、发布策略和差异空白检查随提交执行。

## Consequences

恢复用户选择的旧界面和请求行为，原设计与撤销理由均可追溯；不再提供本次新增的多方式报价和历史价差参考。旧标签/镜像保留审计，以v1.20.1提供恢复结果，避免覆盖历史v1.19.0和后续Jev版本。发布恢复版不代表生产部署，未修改生产配置或资金数据。
