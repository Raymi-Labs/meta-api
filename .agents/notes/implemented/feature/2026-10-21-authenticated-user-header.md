# Agent Note: 认证用户身份头与大小写覆盖边界

Status: implemented

## Problem

会话缓存亲和需要可信中转区分真实用户；客户端提供的身份头不能成为隔离依据。已有 Header override 支持密钥及客户端头占位符，但没有认证用户来源。服务器候选 c99e8dea 增加身份占位符后，中间 map 仍可能同时保留通配转发的大写键与显式覆盖的小写键；最终 Header.Set 的 map 遍历顺序会使伪造值覆盖真实身份。只检查 map 的一个键无法验证出站契约。

## Decision

在当前主分支的共用渠道请求构造器中增加完整值占位符 `{authenticated_user_id}`，只读取认证上下文的正整数 id，缺失、类型错误或非法值均拒绝，不使用客户端身份回退。占位符只能作为完整配置值，混入常量时拒绝，避免误把模板作为共享身份发送。

通配与正则转发统一使用小写键，与已有显式覆盖规范保持一致；最终应用覆盖时删除请求中大小写等价的旧键，再设置唯一值。沿用现有会话头占位符和后台测试规则，不增加供应商专用路由、数据库字段、计费或自动生产配置。

[原生异步任务扩展](../bug-fix/2026-10-24-task-submission-and-terminal-consistency.md)复用该占位符：提交仍读取认证上下文，后台轮询和既有鉴权内容查询只读取已持久化任务的用户归属，不使用当前下载者或客户端头作为身份。

## Existing notes audit

[OpenCode 会话头](../bug-fix/2026-10-13-opencode-session-header.md)和[Claude 客户端上下文](../bug-fix/2026-10-17-claude-review-protocol-integrity.md)部分相邻，继续保持域名与协议边界；[发布入口安全](../process/2026-10-21-release-entrypoint-safety.md)管部署顺序，不改写其决定。没有现有认证用户占位符归属。[模型筛选抽屉](2026-10-21-pricing-filter-drawer.md)是独立前端工作，按用户要求共同交付，分别验证。

## Alternatives considered

- 透传客户端 tenant 或按会话名直接分组：无需认证关联，但同名会话与伪造身份可跨用户碰撞，不满足隔离目标。
- 新增特定渠道身份开关和独立转发逻辑：能固定身份来源，但重复现有配置入口并绑定供应商；复用通用占位符与现有管理接口。
- 仅添加占位符解析：改动最少，但通配与显式键大小写冲突已在最终出站头复现，必须同时消除歧义。

## Testing

- 共用 HTTP 构造器的36次合成 transport 请求覆盖两位用户、三种协议路径、流式/非流式和三个渠道 ID，验证最终身份唯一、会话不变、客户端凭据不泄漏；没有调用真实模型。
- 通配/正则、混合大小写与重复值、运行时覆盖、非法上下文、后台测试、模板拼接拒绝和旧配置兼容回归通过；无有效身份时 transport 调用次数不增加。
- `go test -p 2 -timeout 150s ./relay/... ./middleware ./controller ./service -count=1` 通过；定向 `go test -race` 重复两次通过。数据库 schema 和 SQL 没有变更，未以 SQLite 测试替代未来生产配置更新的 MySQL 验收。
- 前端既有筛选/厂商/货币测试、修改源码 ESLint、桌面与手机浏览器流程、完整 Vite 构建及五个公开页面预渲染通过。首次预渲染因浏览器路径和 bunx 缺失未执行，配置已有 Chrome 与 Bun 路径后的预渲染通过。

## Consequences

认证身份与会话头复用已有渠道入口，HTTP 覆盖不再受大小写重复键影响；代价是占位符缺少合法用户时明确失败、内部 map 的转发头名称统一为小写。用户 ID 只发往显式配置的可信上游，接收方仍须限制可信出口；服务端支持先于渠道配置启用，回退旧程序前先恢复对应配置，见[配置与回退](../../../../docs/channel/authenticated-user-header.md)。此次只提交代码，不改生产；真实跨渠道 wait_arm、账号亲和、缓存比例仍需两端生产验收，单测不能替代。
