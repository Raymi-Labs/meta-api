# Agent Note: 企业直接复用现有分组倍率

Status: implemented

## Problem

用户要求把企业放入现有优选等分组即统一使用该组倍率，例如优选0.8对全部企业API生效。当前企业表单已经读取GroupRatio，但请求把BillingGroup当作特殊倍率的第一层身份，没有逐渠道配置就回落到实际路由组，造成选组与收费不一致。

## Decision

保留企业BillingGroup字段与现有分组选择，直接读取该GroupRatio作为企业最终分组倍率，不叠乘路由组、个人或企业旧特殊倍率。普通用户继续原有规则；企业价格组不改变账号授权和渠道范围。复用统一PriceHelper，首次取价固定请求内倍率，任务沿用持久快照；缺失、auto或无效倍率拒绝新计费请求，不能默认为1或免费。模型基础价、计量、时段规则和资金结算维持既有能力。

复用/api/group的可选详细响应提供名称与倍率，不新增分组注册表。企业管理保留现有布局，仅选项与列表显示倍率、准确命名计费分组。企业令牌列表（含auto/多路由）与企业付款的可选组价格统一使用企业倍率；个人列表与权限不变。

## Alternatives considered

- 继续逐渠道设置特殊倍率可以保留旧合同，但不能满足用户一次选组全API生效，路由新增也会漏价。
- 新增企业专属价格表或折扣字段更独立，但重复现有GroupRatio且不满足直接选择优选分组的要求。
- 修改成员个人组或令牌路由组可以借用旧继承，却会改变私人请求和模型可用范围；企业选择仅作为价格来源。

## Verification

- 企业创建/编辑选择现有组，0.8、1、0倍率真实收费与列表显示一致；普通用户特殊倍率保持。
- 自动切组、多组路由、图片数量、按次/表达式任务、实时增量均沿用企业倍率；已有任务/会话不按更新后的倍率重算。
- 删除或无效企业价格组阻止新收费，无个人钱包回退；原任务退款恢复保留。
- 九包完整后端回归、六包企业相关race及真实Chrome合成API交互通过；36项语言检查、Vite构建、291篇笔记门禁通过；本轮测试进程为零，用户原预览保留。价格校验先于容量准入，视频保持本地503错误；路由测试复用健康采集手动flush避免后台ticker越过测试DB生命周期。操作步骤、发布边界与验证范围见[验收文档](../../../../docs/reviews/2026-11-13-enterprise-group-multiplier.md)。

[分组维护保护](../bug-fix/2026-11-14-enterprise-group-maintenance.md)补齐引用组删除/改名拦截、事务内绑定校验及编辑倍率刷新；运行时缺失倍率拒绝仍保留为防线。

## Consequences

已绑定企业的新请求从旧特殊倍率改为所选组基础倍率，这是明确的收费规则变更，需在发布前核对企业实际绑定组。共享同一组会随组倍率一起变化；跨实例沿用现有配置同步周期。本轮不修改线上价格，不部署；2026-11-14用户已授权推送GitHub并合并main，合并前验证企业数据库CI。
