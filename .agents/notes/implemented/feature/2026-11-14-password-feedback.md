# Agent Note: 新密码输入的即时反馈

Status: implemented

## Problem

注册和修改密码只有提交后才提示长度或确认不一致。管理员创建用户与初始化页面也缺少统一反馈，用户容易反复提交失败。

## Existing capabilities and notes audit

注册、个人密码修改、初始化 AdminStep 和管理员 EditUserModal 已有独立提交与权限校验；找回密码由服务端生成密码，不适用新密码输入提示。[认证同屏表单](../../implemented/feature/2026-10-25-auth-form-layout.md)部分重叠，保留协议、邀请码和跳转契约；[管理员编辑会话隔离](../../implemented/bug-fix/2026-10-24-admin-edit-session-isolation.md)仍持有编辑权限和 session 边界。SSH 密码禁用笔记无关。未发现已有密码反馈提案。

## Decision

复用共享 PasswordFeedback 组件显示长度、粗略强度和确认一致性。注册/个人/管理员用户入口沿用 model.User 的 8–20 字符约束；初始化入口只提示其现有最短 8 字符，不悄悄改变后端策略。强度仅是建议，不新增复杂度门禁；不截断、不上传分析、不记录密码，粘贴和密码管理器保持可用。空值不显示错误，确认输入后即时同步两边变化。

## Alternatives considered

- 直接移植上游 8–128 限制：界面统一，但与本地用户校验冲突，会提示可用而提交失败，故不采用。
- 同步重设全站密码策略：可统一初始化和用户限制，但涉及存量登录与密码哈希兼容，本次只补反馈。
- 使用重型密码强度依赖：可检测字典密码，但增加包体和词库维护；本次明确显示粗略提示，不宣称安全保证。

## Verification

- password-feedback.test.mjs 覆盖 8/20 边界、Unicode code point、短密码、重复字符、确认不一致与修改原密码后的重新计算。
- 四个既有入口复用同一组件，提交和校验 handler 不变；登录/生成的重置密码不增加提示，管理员空白编辑保留现有密码语义。
- Chrome 验证真实注册表单强度与匹配提示；改空/改短原密码时仍显示确认不一致，恢复后即时匹配；375px 窄屏可见。17 语言资源、主站/图片工作台构建和五页预渲染通过。

## Consequences

即时反馈减少提交前的信息盲区，代价是维护一份与后端限制对应的轻量提示逻辑。粗略强度不能证明密码未泄漏或难以猜测；界面只给建议。初始化后端当前按字节检查最小长度，与其他入口的 Unicode 字符校验不同，本次不改变既有后端策略。
