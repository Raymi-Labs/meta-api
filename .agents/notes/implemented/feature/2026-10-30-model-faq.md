# Agent Note: 模型专属 FAQ

Status: implemented

## Problem

用户希望模型详情下方提供可配置 FAQ。现有控制台 FAQ 是全站设置，公开首页 FAQ 是固定内容，都不能跟随模型元数据维护和展示。

## Decision

复用管理员模型 CRUD、模型元数据匹配和 pricing 可见性，新增有序 faq 问答数组，持久化为可空 TEXT。旧客户端省略或 null 保留已有配置，显式 [] 清空；旧数据库空值返回 []。模型属性同步不写入此字段；旧目录同步显式排除 FAQ，避免整行旧快照覆盖并发人工编辑。规则模型与介绍一样按既有元数据匹配继承，不新增一套匹配策略。

模型管理支持新增、编辑、删除和上下调整问答。问题及答案均为纯文本，保留换行，最多20项、问题200字符、答案2000字符、编码总量不超过60000字节以兼容 MySQL TEXT。详情底部以可键盘操作的折叠项展示；空数组不显示 section 和导航，不编造默认答案。

## Existing notes audit

- [模型展示元数据](../../implemented/feature/2026-10-25-model-catalog-metrics.md)：部分重叠，扩展已有模型元数据链路。
- [模型属性与官方来源](../../implemented/feature/2026-10-30-model-attributes-official-sources.md)：相邻但同步所有权独立，FAQ 为人工维护。
- [公开首页](../../implemented/feature/2026-10-24-public-home-redesign.md)：存在折叠问答样式，内容作用域不同，保持其现状。

## Alternatives considered

- 复用控制台全站 FAQ 能减少字段，但无法针对模型配置，也会混淆全站与模型帮助内容。
- 将 FAQ 写入介绍或 Markdown 能减少结构，但会混入头卡文案，无法稳定排序和折叠；使用独立有序问答数组。

## Verification

Go 全量测试通过。SQLite、MySQL 8、PostgreSQL 16 验证旧表新增可空列、重复迁移、保存、清空与顺序保持；控制器覆盖创建/读取/pricing 同源、旧客户端省略/null保留、[]清空、状态更新、规则继承与同步不覆盖。旧目录同步额外模拟读取之后发生人工编辑，确认只保留最新 FAQ。

真实 React 浏览器回归覆盖桌面、390暗色与320宽度无横向溢出、键盘展开、换行和HTML文本不执行、管理新增/编辑/上下排序/删除/空白校验/保存失败保留/重开/清空。手机暗色编辑器读取已保存顺序，原价格、属性与清空回归一并通过。本地预览已加入示例问答，生产内容保持空配置。

17语言资源、ESLint、Prettier、完整前端构建与笔记门禁通过。首次并行构建的两项语言扫描超过默认5秒时限，结束重负载后单独构建通过；浏览器测试修正多行文本选择方式后通过。未调用上游或部署生产。

## Consequences

pricing 列表载荷增加，因此限制条目与总量；新增列保持可空以支持旧数据。管理员内容作为 React 文本显示，不作为 HTML 执行。
