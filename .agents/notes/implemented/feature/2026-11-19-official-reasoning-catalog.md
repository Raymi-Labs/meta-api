# Agent Note: 账号模型目录合成官方精确档位

Status: implemented

## Problem

只返回人工填写的能力时，整批已知模型均可能没有档位；平台无法自动带入新型号资料。

## Decision

在[逐型号声明](2026-11-18-platform-reasoning-profiles.md)的账号接口合成资料。人工禁用或明确档位优先于同一精确 ID 的官方资料；社区同步的布尔值不是档位。主节点从固定 HTTPS 官方来源分别刷新，只发送公共文档 GET，不附带账号身份。成功解析后在一次事务内保存上次可用声明、确认撤销的 ID 以及解析所需的公开名称映射。其他实例只读同一数据库；首次离线使用内置快照。API 仅返回本账号可见型号和必要字段。

## Alternatives considered

手动逐条建档增加遗漏；客户端各自联网不便离线使用，还会向第三方暴露用户网络地址。

## Verification

离线维护命令把三份公开资料重建为同一快照，与客户端种子逐字节比对。Go race/SQLite 回归覆盖账号可见性、人工覆盖、缩档、撤销、失链及疑似改名、故障/重启保留上次结果；另测 Gemini 最终请求转换。不操作生产数据库、真实渠道或凭据。

## Consequences

同一来源新增、删除或修改已认识的档位，不必为单个型号发版。公开页面异常或身份不明确时可能延迟更新，不发布无法区分的变更。新来源、新协议枚举仍需适配。上线需由主节点执行新增快照表的迁移；此处未验证生产 MySQL/PostgreSQL。旧客户端可读取带已知默认的完整声明，正确处理无默认或撤销还需客户端配套升级；不更改路由或计费。
