# Agent Note: 邀请页与广告使用蓝白品牌角色

Status: implemented

## Problem

两轮纯文案邀请页不能满足用户的推广视觉预期。用户提供蓝白品牌人物四视图，要求沿用该形象并与站内蓝色 UI 一致。

## Existing capabilities and impact

已有 InviteBenefits、共享 invitePromotion 文案/HTML 构造器、广告预览和短链统计。活跃笔记检索命中[邀请推广](2026-10-22-invite-promotion.md)，统计与注册决定继续适用；本文仅替代其无图片素材约束，因为用户现在提供了明确的品牌资源。共享静态图片需随前端发布，否则外站横幅角色不能显示。

## Decision

原样复制用户图片到 public/images，横幅用CSS裁显正面形象。邀请注册页另用本地裁剪、去除连通外部白底得到的透明WebP正面素材，原图仍保留，不发收费生图请求。原文件无EXIF条目，仅含JFIF格式字段。邀请注册页使用深蓝星点与网格、蓝色渐变标题/CTA、发光环和透明正面角色，注册表单使用同一深蓝配色；普通注册页不应用这些样式。模型文字与角色分栏，保留原注册流程与模型广场链接。广告横幅继续蓝白配色。横幅引用与邀请链接同源的固定图片路径，不向任意第三方传图；img不带邀请码、来源或访客参数，设置no-referrer。图片请求不是点击/曝光统计，不新增收集接口。

## Alternatives considered

- 重新生成角色立绘：可以改变动作，但用户已给出希望使用的角色，重新生图有费用且可能改变辨识细节，本轮直接复用。
- 整张四视图展示：最忠实于原附件，但会变为设定展示页，降低推广重点；用CSS仅展示正面。
- 内嵌base64到HTML：不依赖站内图片托管，但会使每段代码增加约500KB，复制和网站编辑更不方便；采用缓存友好的静态路径。

## Verification

HTML单测通过：横幅图片来自邀请链接同源固定路径，且不带跟踪参数，保留危险协议拒绝、转义和安全rel；文字/按钮素材不加载图片。浏览器覆盖1440/1024/768/390/320宽度、手机暗色、英法长文案、邮箱注册带码、OAuth入口、复制素材、预览不计点击、统计失败重试。邀请页角色naturalWidth核验480、横幅原图核验1536，外嵌320/680宽度横幅加载通过，图片失效时模型文字与邀请链接仍可使用。主站Vite构建通过。原图原样复制为376KiB静态资源，无额外图像服务调用。

## Consequences

站外网站如果禁止外部图片，角色不会出现，文字和链接仍然可用。图片请求仍可能进入既有静态服务访问日志；本功能不添加曝光追踪或访客记录。此次没有生产发布，素材须先随网站部署后再投放。手机角色以CSS裁显和底部渐隐避免覆盖内容，桌面完整正面立绘；页面展示在裙摆处拼接同一张素材，上部46%保持原比例，下部54%纵向延长16%，并为足部留足高度；原图与横幅资源不改。角色仅入场动画一次，水晶浮动三次、光环旋转两次后停止；减少动态效果偏好禁用所有相关动画与过渡。未添加计时器、canvas或持续渲染循环。
