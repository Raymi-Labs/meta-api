# Agent Note: 分组阶梯价格逐行对比

Status: implemented

## Problem

官方缓存参考价包含当前不使用的12h档位；官方档位选择器要求反复切换，而本站动态价格始终取首档，无法直接核对长上下文价格。

## Decision

[官方分档匹配与说明](../bug-fix/2026-11-02-official-tier-matching.md)补充峰谷命名档位的单价对应及生效日历提示、中文/Standard上下文识别；无法比较的原因直接可见，取代相应静默回退，计价与币种规则保留。

复用当前 /api/pricing 可见模型、分组/时间倍率、币种及独立汇率计算。详情官方表与分组表共用展示投影：删除明确 cache 12h 的行，移除 cache 30m 标签，原始厂商元数据保持以便同步审计。本站已有30m接入限制不变，不修改结算或生产配置，也不把Claude 5m/1h混为30m。

分组表按本站实际阶梯展开，普通固定价格按官方档位展开；左列档位，右列各价格分项。只有同单位、明确同输入长度区间或双方唯一无条件档位才计算折扣，不以数组位置猜测匹配；无法匹配仍展示本站真实价格。条件乘数依旧由请求决定，表内价格不是完整请求报价。

## Existing notes audit

- [分组官方折扣](../../implemented/feature/2026-10-30-model-group-official-discount.md)：部分取代下拉及本站首档展示，币种/汇率/权限规则保留。
- [官方同步](../../implemented/feature/2026-10-31-official-pricing-sync.md)：部分重叠，保留原始来源与时长证据，新增面向用户的30m投影。
- [缓存写入计量](../../implemented/bug-fix/2026-11-01-openai-cache-write-metering.md)：运行时及渠道限制不变。
- 模型详情/元数据/缓存展示笔记继续适用；视频与图片专用表不改。

## Alternatives considered

- 只把官方下拉铺开最省代码，但动态本站价全部重复首档，会误导长上下文比较，因此同时展开实际阶梯并保守匹配。
- 从同步器删除12h可减少存储，但会丢弃厂商证据且不能处理已存旧数据；采用共享展示投影，刷新同步后仍保持30m展示。

## Verification

25项价格/真实组件回归覆盖30m/12h旧数据投影、来源数据不变、独立阶梯金额、条件边界/重复来源不误配、零价、分组时间倍率及K/M。既有完整Chrome流程覆盖分组搜索/筛选、充值及USD切换、单位转换、官方表和本站两档、320/390px窄屏及暗色、模型编辑保存与路由/可见性。完整前端构建含图片子应用、语言检查及五页Chrome预渲染通过。

## Consequences

原始官方元数据继续包含厂商全部时长用于同步审计，面向用户的详情统一显示30m。表格增加高度，窄屏只让表格横向滚动。条件未知、不同计量单位或无有效汇率时保留本站价格，不推断折扣；两档简单len条件可明确配对，其他复杂规则暂不自动匹配。发布不代表生产部署，不改变账单或请求缓存行为。
