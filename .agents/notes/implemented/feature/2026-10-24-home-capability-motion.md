# Agent Note: 首页接入示意的动态与页脚导航

Status: implemented

## Problem

三张接入卡片停留在静态图示，SDK 没有表达从官方地址迁移，线路图把模型误当作供应商。用户明确要求补充滚动商标、供应线路故障切换、个人/团队/智能体出口，以及参考站式分栏页脚。

## Decision

通过 HomeCapabilities 与 capabilityMotion 复用 EnterpriseHome、providerIcons、配置生成的 baseUrl 与 PublicHomeShell 的导航权限。模型图标采用重复轨道的 CSS 位移；路由按“主线路 → 模拟不可用 → 备用线路”推进，每轮保持同一模型，仅新一轮更换模型与供应商组合。装饰状态不请求健康接口，标注接入示意；隐藏、离屏、失焦暂停，减少动态效果回到静态正常状态。

失联供应商用文字渐淡、浅灰虚线边框与居中的地球断网图标表达，对应连线同步变浅；备用线路保持蓝色高亮。图标绝对定位，不挤占供应商文字宽度，颜色沿用主题变量。

SDK 装饰展示旧地址删除线和当前配置地址，新旧行明确用 -/+ 区分；实际复制示例仍只有当前地址。公开首页通过 homeAddress 复用 normalizeBaseUrl 清理尾斜杠和协议后缀；已知元衡 cn/nan 根级 HTTPS 旧地址统一到 https://meta-api.vip，SDK 展示、Python/cURL 和端点复制共用结果。第三方地址、非默认端口、自定义子路径及其他元衡线路保留配置。首页挂载后仅对白名单快速开始/FAQ 锚点定位，清理待执行帧，避免跨页异步加载时丢失位置。页脚复用真实路由、导航模块配置、定价登录约束与政策开关，不填虚构社交账号或政策链接。用户本轮明确要求移除公开页可见的“设计与开发由 New API”行；只调整这一展示行，源码许可证、项目元数据及其他页面归属保留。

检索公开首页、PublicHomeShell、首页卡片：既有[首页设计](2026-10-24-public-home-redesign.md)部分重叠，复用其入口与数据边界；本篇替代静态卡片表达及其公开页归属行展示约定，互链保留原因。[地图动态](2026-10-24-world-map-ambient-motion.md)只涉及点阵，继续独立生效，不调整。

## Alternatives considered

- 纯 CSS 定时切换全部状态：代码短，但难以保证失焦、运行时减少动画与模型/线路同步，使用小型可测试状态机协调。
- 故障时切换到不同模型：画面直观，但实际重试按相同模型、分组、权限和预算选渠道，会误导用户，选择单轮保持模型。
- 直接复制参考页所有页脚栏目：栏目丰富，但本项目没有对应博客、社交账号或政策配置，选择只展示可用入口。

## Testing

- 失联节点展示修正：Chrome 宽屏亮/暗主题与 390px 手机端确认文字渐淡、居中断网图标、浅色连线及备用线路高亮，手机端无横向溢出；25 项状态机回归、定向 ESLint/Prettier、生产构建与五页预渲染通过。
- Chrome 实际应用壳：持续商标滚动、Claude/OpenAI/Gemini 轮换、同轮连接中断后备用线路接续；离屏状态为 paused，返回恢复。
- 320/390px 与宽屏、中英文和亮暗主题无横向溢出；长地址保留完整 title、视觉省略，正常配置地址完整可见。
- 从下载页进入快速开始和 FAQ：发现异步加载会丢失原生锚点，修复为默认首页挂载后的可取消 RAF 定位；配置接口延迟 1.6 秒时两个目标均位于视口顶部约 90px。
- 页脚真实渲染 6 组/25 断言覆盖定价登录、导航开关、政策开关、自定义首页；浏览器确认政策启用后显示有效路由、自定义首页保留紧凑版权页脚。
- 25 项卡片状态机、31 项地图回归、下载/鉴权跳转/运行时文档检查通过；定向 ESLint/Prettier、完整生产构建与五个公开路由预渲染通过。

- 首页地址 4 项/42 断言覆盖旧地址、尾斜杠与 /v1、第三方和子路径保留及无效配置回退；运行时文档 7 项回归通过。Chrome 实际复制 Python、cURL 和 /v1/responses 均使用 https://meta-api.vip，SDK 展示相同。

## Consequences

插图不表示真实账号模型可用性或供应商健康，实际能力以配置和模型广场为准；发布不自动部署生产。
