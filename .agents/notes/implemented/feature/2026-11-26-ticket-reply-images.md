# Agent Note: 图片随工单回复提交

Status: implemented

## Problem

独立附件上传立即触发活动与通知，回复草稿中的图片需要与正文、内部可见性同时生效。用户、管理员和申诉详情各自实现回复框，纯文本显示丢失粘贴格式。

## Decision

三个入口共享编辑器。JSON 文本回复保留原契约，图片回复使用同一路由的 multipart 请求，每次一张，复用附件存储、内容嗅探、授权下载及 message_id。工单锁内写入消息和图片并更新活动。富文本剪贴板经 Turndown 转为 Markdown；ReactMarkdown 渲染对话文本，远程图片地址显示为可点击链接。仅绑定工单的图片自动通过鉴权客户端获取。系统事件继续持久化，三端在展示层按发送者角色过滤，顶部状态仍反映最新流转。

## Alternatives considered

先调已有独立上传能够少改后端，但取消草稿、发送失败和内部备注都会提前公开附件并触发活动。

## Verification

路由测试覆盖跨账号、申诉范围、内部备注下载隔离、超过64KiB的纯图回复、伪装类型、配额失败回滚及文件清理。浏览器 fixture 覆盖三类入口、富文本粘贴、失败后重试、发送后预览、隐藏系统通知与至少20px底边距离。

## Consequences

图片与消息共用现有的工单附件配额。数据库回滚后删除暂存文件；进程在文件写入和事务完成之间崩溃仍可能留下孤立文件。已有工单与身份权限见[站内工单](../../implemented/feature/2026-11-18-support-tickets.md)与[权限边界](../../implemented/bug-fix/2026-11-19-ticket-access-and-delivery.md)。检索命中的桌面反馈、邀请与图标笔记属于其他模块。
