# Agent Note: 邀请返佣结算周期、账单与提前发放

Status: implemented

## Problem

即时结算无法承载按周期发放、观察期、异议期和抵扣欠款；重复出账及退款并发可能造成重复到账。

## Decision

台账仍是唯一写余额的单元，账单只汇总。Asia/Shanghai 自然月或 ISO 周确定周期；月结 T+3 发放，周结 T+3 出账、T+7 发放，且不得早于支付后七天。异议截止为实际出账后十五天。

出账任务每小时及支付唤醒运行；唯一周期键和 CAS 防重复。结算、出账、冻结、欠款和退款共用收款人锁；支付源锁先于收款人锁，多收款人按 ID 升序，随后更新 cap/debt/ledger。冻结及实名待审核延后一天、不耗重试次数；冻结在关闭新档位入池后仍有效。

新台账退款先扣邀请额度，再扣可划转钱包，不足形成欠款；已用收益抵扣的旧欠款在退款时恢复。旧金额版本保留原行为以满足关闭开关兼容要求。日限额按扣债前金额占用及释放；账单展示欠款抵扣、池扣减、实发及失效金额。

月度任务按未完成月份补偿计算，唯一月份回执防重复，仅下调未发放台账。差额 FIFO 进入下一周期账单并产生独立补足台账，保留原支付源以便退款一并撤销。开关关闭不丢弃旧账单、欠款或补足。

提前发放每人每 ISO 周一次，申请及审核均重验当前档位、冻结和欠款；只加速申请前已出账且过观察期的台账。提现门槛随当前档位变化，划转钱包保留原最低额。

## Alternatives considered

- **账单生成时一次性把汇总金额记入余额** — 写入路径简单、每周期只动一次余额；但会与逐行台账结算形成两套余额写入，撤销与重试需要同时维护两边一致性，违背已实现笔记“台账是唯一可结算单元”的决策，放弃。
- **保持即时到账、仅把观察期做成冻结余额** — 用户体验接近现状；但规则明确按周/月出账并以账单承载异议与扣减，冻结余额无法表达周期账单与提前发放审核，放弃。
- **冲回不足时继续允许钱包为负** — 与现有行为一致；但负余额会阻断用户正常消费且无法在后续收益中可追溯地抵扣，规则要求“后续周期抵扣”，改为独立欠款记录。


## Consequences

完整实现使新周期功能可由管理员启用，默认不影响旧入池路径。SQLite、MySQL 与 PostgreSQL 共用 GORM；跨库回归覆盖唯一索引迁移、并发回调、并发结算和退款交叉。浏览器验证桌面/移动入口、空态和分页；自动化检查记录见 [验收记录](../../../../docs/reviews/2026-11-19-invite-tier.md)。

生产启用仍需要备份和迁移预检；本次版本发布不等于生产部署。实名与设备数据须使用持久化密钥，丢失密钥无法解密原有记录；辅助信号和人工审核不能替代实名核验供应商。
