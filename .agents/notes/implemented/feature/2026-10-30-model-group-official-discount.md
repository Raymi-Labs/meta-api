# Agent Note: 分组价与官方参考价逐项对比

Status: implemented

## Problem

官方参考价已经独立维护，分组卡片仍仅显示本站金额且位于快速开始之后。用户要求官方价下方直接列出分组价，以划线官方价和降幅呈现对比。

## Decision

[逐档价格表](2026-11-01-group-tier-comparison-table.md)部分取代官方档位下拉/本站首档对比和全部缓存时长公开展示；保留本篇其余计价、来源及权限规则。

将既有 ModelGroupRows 移到官方参考价后，保留筛选、分页和健康。每张分组卡片上方直接显示输入/补全/缓存读取/缓存创建各自标签与金额，不再重复显示“价格”和“缓存”组标题；桌面价格横向并排，手机仍并排输入与补全、缓存另行展示；首字均值/输出速度/Uptime以独立横行放在价格下方，手机按可用宽度换行。复用计价函数的未舍入美元金额、分组和时间倍率，逐项对比所选官方档位；输入/输出/缓存不合成单一折扣。多档官方价允许显式选择并展示档位名；动态分组继续使用本站首档金额，按用户要求移除每组重复的“本站首档”名称提示，不将单价对比当作完整请求报价或宣称两个档位条件相同。

分组价沿用当前 USD/充值/套餐显示模式。官方价按独立公开 USD/CNY 参考汇率转换到相同币种，不能套用充值/套餐折算率。顶部官方价不变；未配置汇率、EUR/自定义币种不能换算、不同单位、倍率视图及无明确 TTL 的缓存创建不比较。缺失仍未知；官方零价不可作分母。只有实际更低才划线并显示降幅，持平/更高如实显示。K/M 同步换算而不改变折扣。

服务端公开 `GET /api/pricing/exchange-rate` 固定读取 ECB 每日 XML，以同日 EUR/CNY 除以 EUR/USD 求 USD/CNY；不传用户、模型、密钥或账单数据。返回 `usd_cny/date/source/source_url/fetched_at/stale`，前端显示日期及 ECB 来源。进程内互斥缓存成功6小时，失败15分钟后重试，8秒超时、禁止重定向、64KiB上限；有效报价小于7天，临时失败使用缓存并注明，超期/缺失时不比较跨币种价格，同币种仍比较。前端15分钟刷新，网络失败保留有效缓存。原 `status.usd_exchange_rate` 是额度展示配置，可能为1，不能代表公开外汇价。分组中的人民币官方参考价四舍五入显示两位小数，美元参考价保留原6位有效数字；本站计算单价最多显示12位有效数字，消除分组倍率与汇率连乘产生的浮点尾差，去除无意义末尾零并保留极小非零价；直接维护的官方价格式不受影响，百分比仍使用未舍入金额。

按用户 2026-10-31 的展示要求，分组标题复用信息提示组件，将倍率/价格模式、独立参考汇率及日期/来源、所选官方档位的比较口径放入悬浮内容，保留真实状态与条件。详情移除分组列表下重复的基础价格与完整动态阶梯表；计价表达式、管理员配置和其他复用入口不变。

## Alternatives considered

- 将本站单价固定保留两位小数虽然可隐藏尾差，却会把千Token或极小单价显示成零；仅在分组对比的最终渲染处限制有效数字，不舍入计算输入、不改变折扣和实际计费。

- 直接把分组倍率当优惠率很简单，但基础价未必等于官方价，且遗漏时间倍率与充值/套餐成本，改用实际单价比较。
- 将首个官方档位静默作为统一折扣基准省去选择，却掩盖多档差别；提供显式官方档位选择；区域说明保留动态首档的比较范围，每组不重复展示首档名称。

- 直接修改 USDExchangeRate 虽能修正当前显示，却同时影响额度/充值等既有口径，因此保留它，单独读取公开参考汇率。固定人工汇率无需联网但需要持续维护；用户明确选择自动公开汇率并显示日期。

## Consequences

输入、输出、可比缓存及按次/小时价格分别展示对比；未配置官方价、缺失汇率、不兼容币种/单位或TTL仅保留原分组价。官方零价不计算百分比；同价显示持平，更高显示增加比例；仅更低使用删除线及绿色降幅。显示精度不参与百分比计算，非免费价格不会四舍五入成降低100%。

管理员仍需维护官方价。对比是选定档位的单位价格，不代表完整请求优惠，也不推断两个档位的条件等价。顶部官方表保留原币种；分组中的官方金额可按明确USD/CNY汇率换算，缺失汇率不借用充值汇率。分组列表前移后快速开始在其后，保留分组搜索/分页；详情不再额外展示完整动态规则表。增加只读公开参考汇率接口，无数据库、权限或扣费逻辑变更，未升级生产或执行真实模型调用。
