# Agent Note: 创建令牌按厂商筛选、多选分组并排序

Status: implemented

## Problem

令牌早已支持多分组（`routing_config`），但创建/编辑界面主区是单选分组列表，多选藏在「高级设置 → 访问限制」里一个名为「按模型配置多个分组」的开关后，只能用下拉框按选择顺序排列，看不到价格、健康和支持模型，也无法调整顺序；主区另有一道必答的「故障时是否自动切换分组（Auto）」，与多分组是两套切换逻辑，用户难以分辨。分组越来越多后，一次摊开全部分组也难以挑选。用户要求：主界面直接多选；先选厂商再挑分组（搜索可按厂商或模型，模型搜索结果仍显示为厂商）；「自动切换」保留为可选勾选。

## Decision

- **三栏选择器 `TokenGroupMultiPicker`**：左栏列出厂商（含「全部厂商」「我的收藏分组」），数字为能跑该厂商模型的分组数；搜索框可输入厂商名或模型名，按模型匹配时仍显示所属厂商并在其下列出匹配的模型名；左栏只用于筛选，中栏显示能跑所选厂商任一模型的分组；中栏勾选分组（保留倍率、价格标签、说明、收藏，已勾选的显示「首选 / #2」）；右栏「使用顺序」可上移、下移、移除，一键「便宜的排前面」（按本人适用倍率稳定排序，未知倍率排最后），并在按厂商筛选时提示所选分组中有几个支持该厂商的模型。布局按选择器自身宽度（容器查询）在三栏、两栏加下方顺序、单栏之间切换，编辑窗口与手机可用。
- **数据来源**：模型 → 分组目录复用 `GET /api/token/models?detail=true`，以账号全部显式可用分组（不含 auto，最多 100 个）作为草稿 `routing_config`，`group` 取第一项以满足服务端「首选分组必须是第一项」校验；模型厂商取自 `/api/pricing` 的 `vendor_id`，取不到归入「其他」。不新增接口。
- **表单映射不变**：勾选 1 个分组 = 原单分组令牌（`group`，`routing_config` 为空）；2 个及以上 = 原多分组令牌（`routing_enabled`，`routing_config.groups` 按顺序，`group` 为第一项）。auto 分组只能单独选择；可售令牌保持单选。原「按模型配置多个分组」开关移除，`TokenRoutingEditor` 只保留「按模型指定分组（可选）」，选 2 个以上分组时出现；移除分组后被清空的模型规则保留为空并提示重选，不静默放宽。
- **自动切换改为可选勾选框（默认不勾）**：「所选分组都不可用时，再按平台顺序尝试其他分组」，创建与编辑都可改（可售令牌与 auto 分组不显示），并提示可能按更贵的平台分组计费。单分组令牌仍写 `auto_group_fallback`；多分组令牌写入 `routing_config.auto_fallback`。服务端 `TokenConfiguredGroups` 仅在 `auto_fallback` 为真时，在令牌自己的分组之后追加用户可用的平台自动分组；模型有单独规则时不追加，已被撤权为空的范围不回填。令牌目录与渠道选项对无模型规则的模型同步包含这些分组。
- **旧数据不变**：生产只读核对时 149 个多分组令牌中有 133 个旧 `auto_group_fallback=1`（此前对多分组不生效），因此多分组的切换不读旧字段；编辑这些令牌时勾选框按 `routing_config.auto_fallback` 显示为不勾。

## Alternatives considered

- 让旧 `auto_group_fallback` 对多分组令牌生效：后端改动最少、语义统一，但会让 133 个现有多分组令牌上线后突然开始使用平台分组并可能更贵；改为新的显式选项。
- 拿掉自动切换只留多选：最简单，用户多选即可表达备用；用户要求保留为可选勾选。
- 只在现有单选列表上加复选框、不做筛选栏：改动小，但分组变多后仍要逐个辨认；用户要求先选厂商。
- 左栏直接列出模型：能精确到单个模型，但 200 多个模型列表过长，且用户挑分组时关心的是厂商；改为厂商列表，模型名只作为搜索入口。
- 拖拽排序：直观，但需引入拖拽依赖且键盘、触屏可达性差；采用上移/下移按钮与一键按价格排序。

## Consequences

收益：多分组从高级设置移到主区，一次完成选模型、勾分组、排顺序；顺序与「智能路由总开关」的整组跳过使用同一份分组顺序；自动切换的价格影响就近说明。

代价与限制：每次打开窗口多两次请求（模型目录与价格页厂商数据）；可用分组超过 100 个时厂商栏只统计前 100 个分组；厂商栏只筛选不限制令牌可调用的模型（模型限制仍在高级设置）；厂商取自价格页的模型厂商设置，未设置厂商的模型归入「其他」。旧必答单选题的提示文案仍留在语言文件中未清理。`web/scripts/token-create-selector.browser.mjs` 与 `web/scripts/token-routing.browser.mjs` 仍按旧单选与必答题编写，本机无 Playwright 未更新，需要另行改写。
