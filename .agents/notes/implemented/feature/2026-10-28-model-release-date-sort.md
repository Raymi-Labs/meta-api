# Agent Note: 模型广场默认按发布日期排序

Status: implemented

## Problem

当前默认排序只比较同系列模型名称的自然版本号，不能把不同厂商最新发布的模型排到最前。数据库创建和更新时间属于平台维护记录，也不代表模型发布日期。

## Decision

扩展现有模型能力自动同步链路，读取同源完整模型库的 `release_date`，以跨数据库兼容的字符串保存 `YYYY-MM-DD` 或 `YYYY-MM`。日期保留原精度；不使用 `last_updated`、平台录入时间或模型名称推断日期。复用现有供应商优先级与人工值所有权保护，缺失/非法数据不覆盖本地值，管理员可校正精确模型的日期。

`/api/pricing` 仅向精确匹配的模型投影日期，不让家族规则将一个日期复制给所有代际。目录默认选择“最新发布”，按日期倒序，只有月份时以该月起点比较，同日期及缺失日期保持确定的模型名称顺序；未知日期在最后。排序发生在筛选后、分页前，卡片与表格共用。旧自然版本排序和价格排序继续可选，详情返回保留用户明确选择。

- [模型能力自动同步](../../implemented/feature/2026-10-27-model-capability-sync.md)：扩展字段，源、锁、人工优先与失败保留规则不变；互链。
- [模型价格排序](../../implemented/feature/2026-10-17-model-price-sorting.md)：部分重叠，仅扩展默认项，价格口径不变；互链。
- 模型独立详情和展示指标笔记涉及共用 pricing，但不改变它们的权限和统计口径。

## Alternatives considered

- 继续按名称版本号排序无需新字段，但跨系列无法判断谁更新，不符合用户要求。
- 按后台录入/编辑时间排序最省开发，但一次同步或编辑会把旧模型推到前面，语义错误。
- 每家厂商抓取发布日期来源更直接，但需要多套长期维护流程，现有同源模型库已提供结构化日期；先复用并保留手工校正及来源边界。
- 同名模型跨供应商取最新日期会把渠道上架时间混进模型发布日期；继续现有确定性优先级，不追求最大日期。

- 本地完整 Go 服务和浏览器实测跨厂商排序、未知日期排尾、10 条分页、卡片/表格一致、价格排序及详情返回、重置与刷新。390px 窄屏暗色无横向溢出。
- 模型管理验证非法日期拒绝保存及有效月份保存；来源实时同步能补齐精确模型日期，失败保留现值由测试覆盖。主站、独立文档构建及笔记门禁纳入提交检查。

## Consequences

用户首次进入目录即可优先看到有发布日期的新模型，明确选过其他排序时按原选择返回。自动同步沿用原来源、开关与周期，模型管理可纠正来源错误，不修改价格、调用路由和权限。

外部模型库并非逐家官方接口，日期可能滞后或错误；同月缺少日的记录只有月份精度，排序使用月份起点并保留原文本。无日期模型不会假装最新。旧客户端遗漏新字段时保留现值，显式传空才能清除。新增 varchar 字段和内部同步状态兼容旧数据，发布不代表生产部署。
