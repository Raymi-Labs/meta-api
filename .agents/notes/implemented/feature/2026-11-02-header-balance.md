# Agent Note: 顶部余额入口复用账户状态

Status: implemented

## Problem

用户希望通知与头像之间直接显示“余额”和金额，点击进入已有钱包，不影响计费、充值或其它页面，也不新增用户币种设置。

## Existing capabilities and impact

`PageLayout` 已读取 `/api/user/self` 并写入 UserContext；钱包刷新及兑换后的服务器刷新也写入相同状态。`WalletOverview` 使用 `renderQuota`，站点状态管理额度显示类型。`UserArea` 已有登录用户的钱包链接。本次仅扩展共享 Header 的展示，不改变这些数据契约。

## Decision

余额组件只读现有用户快照并使用钱包相同的格式化函数；未登录不显示、未知额度或缺少显示配置时显示破折号。账户切换或钱包刷新时跟随上下文，不增加请求、计时器或存储。提醒色复用有效的用户 quota_warning_threshold，未设置时仅在非正余额提醒。320px窄屏余额标签与金额分两行，保留既有顶栏入口；长金额在窄屏内截断，完整金额与钱包目的地通过 title/aria-label 保留，点击钱包可查看。

## Alternatives considered

- 新建余额轮询：增加接口负载和账户切换竞态，与“仅增加显示”的范围不符。
- 新增币种切换：会产生与钱包不同的显示口径；用户已确认本轮仅显示，沿用站点设置。
- 用固定美元阈值判断余额不足：忽略用户预警偏好和站点单位，改用已配置的原始 quota 阈值。

## Verification

真实 Header 与 WalletOverview 组件回归通过登录/退出/账户切换、钱包刷新、缺失与零/负余额、四种显示单位、320/390px 和深色场景；网络断言无新增余额请求或写请求。公开页面使用独立 PublicHomeShell，同样复用此入口，懒加载避免将完整控制台依赖提前加入匿名首屏；公开文案复用17语言现有译文，已验证英文与320/390px布局。

格式与 ESLint 通过；公开语言19项、语言资源和钱包请求26项测试通过，直接 Vite 生产构建通过（保留既有大包等警告）。make verify-notes 通过。测试与构建进程清理完成。不连接生产账户，不调用支付或模型。

## Consequences

显示共享快照，不承诺实时账本。若其它设备消费，刷新原有账户/钱包入口后更新；本次不更改全站刷新策略。
