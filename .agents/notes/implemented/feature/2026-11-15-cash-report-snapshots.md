# Agent Note: 现金报表后台快照与移除核对工作台

Status: implemented

## Problem

现金收益和现金流共用同步 GetCashReport，每次 GET 都扫描日志与账本。现金流还额外读取全站待核实资金列表。用户要求去掉核对记录入口，并让两个页面直接读取预加载快照。

## Decision

移除待核对标签、资金批次核实列表及状态提示，保留收益、现金流、上游账单入口与已有账本数据/API。未能计算的金额仍为空，不伪造凭证或利润。两个页面共用按账户/UTC日期隔离的快照；每进程启动预热最近7/30日，五分钟更新。GET只校验账户、日期并读取/登记快照，不执行统计；自定义日期由后台调度生成。后台限两路、30秒超时，失败保留旧结果并显示时间和错误。最多保留128个查询范围，常用范围定时登记，自定义范围闲置30分钟回收，正在计算项不驱逐。前端保留同范围旧值、两秒轮询准备状态，生成后五分钟读取；切换收益/现金流共用已有结果。

## Existing notes audit

[现金账本](../../implemented/feature/2026-11-03-upstream-cash-ledger-v1.md)部分被取代：移除日常核对界面，不删除审计数据、不改变资金计算。其权限和资金不变量继续适用。[消耗快照](../../implemented/bug-fix/2026-11-13-openrouter-finance-snapshot.md)部分重叠：保留原官方消费采集，现金报表独立限流和日期缓存。现金利润后续提案不用于自动核实资金。

## Alternatives considered

- 只隐藏标签：现金流仍读取资金批次且报表每次计算，无法解决性能和流程负担。
- 将未知自动核实或补零：显示完整但会把来源不明的额度算作现金，不能用于现有利润报告。
- 缓存首次同步查询：简单但冷启动/过期访问仍等待计算，因此采用后台预热与异步登记。

## Verification

Go cash/OpenRouter/账户 model/controller/router 回归及 snapshot race 通过；覆盖GET不计算、7/30日预热、日期/账户/凭据隔离、删除、失败保留、并发与容量上限。真实Chrome组件覆盖冷启动轮询、切换标签复用报表、无资金核实请求、账单录入/作废、筛选分页/CSV、错误保留、账户切换竞态、权限与390px窄屏。

完整前端构建、Chrome预渲染、Go构建、verify-notes与29项发布脚本回归通过。浏览器夹具关闭文件监听/HMR，避免本地文件同步事件重载正在操作的测试。CSV使用与页面相同的额度格式器，不导出内部quota原值作为闪电数。生产部署与真实性能尚未验收。

## Consequences

内存快照重启需预热，多副本各自统计。首次自定义范围不能预知，后台完成前明确准备状态。账本修订与同步最多滞后五分钟加计算时间。底层仍维护既有审计，不能把移除入口理解成删除历史或获得完整现金利润。
