# Agent Note: 全站统一语言偏好

Status: implemented

## Problem

公开页 17 语言与控制台七语言分别保存偏好，返回首页、读取旧账户设置及跨标签事件会恢复不同语言。Semi 组件除英文外错误回退简中，原词典有空值造成界面留白。仅增加菜单不能让其他界面同步变化。

## Decision

建立与 React 无关的全站语言状态，17 种语言共用目录、归一化、持久化及事件。公开壳和控制台按需载入各自词典并订阅同一选择；组件库采用准确 locale。最新用户选择优先于迟到的账号偏好、翻译加载和保存响应；统一账户保存入口，切换账户或退出后旧响应不得更新当前用户。

补齐当前源代码用到的界面词条及空译文，保留已有有效译文与变量、技术标识和复数分支；新增语言资源构建期生成并提交，不在用户浏览时将页面或账户数据发给翻译服务。独立生图应用的界面同步使用相同语言偏好。用户已明确要求文档、政策及协议正文同步翻译：对仓库文档和政策保存段落译文，保护代码及技术标识；后台配置协议仅在完整原文匹配当前已翻译版本时使用译文，更新后显示最新原文和提示，保留查看原文入口。用户输入和模型输出不自动翻译。

## Related decisions

- 部分替代：[公开页面 17 语言](../../implemented/feature/2026-10-24-public-languages.md)，改为全站规范语言，保留轻量公开资源和加载竞态边界。
- 部分重叠：[公共政策与隐私选择](../../implemented/feature/2026-10-25-public-policies.md)，其正文语言与界面语言分层仍需明确。
- 首页/下载其他笔记只涉及布局、动态和分发，不改变其功能。

## Alternatives considered

- 继续同步两个存储键改动少，但会保留账号恢复和两个状态中心互相覆盖的问题，改用单一语言来源。
- 新语言只回退英文能够降低翻译量，但选中语言与其他页面实际语言不一致，补齐实际界面词条。
- 浏览器运行时自动翻译可以覆盖硬编码内容，但会发送用户页面数据、破坏插值和异步状态，不使用。

## Validation

公开页与控制台双向切换、登录/刷新、跨标签同步、快速选择、加载与保存失败、旧账户响应隔离均有回归；17 语言词条非空、插值一致；Semi 组件和独立生图界面使用正确语言；桌面和窄屏真实壳验收后构建、提交和发布。

核心语言、账户竞态、Semi 与请求语言隔离的 58 项检查通过；资源、正文与发票 35 项检查通过；筛选下拉框切换语言并保留选中值的独立回归 1 项通过；独立生图 190 项测试、类型检查与生成产物门禁通过；16 组既有前端回归通过。完整构建及五页真实 Chrome 预渲染通过。

免费服务恢复后已补齐 17 语言资源：每套主界面覆盖 6425 个当前源键、公开界面 184 个键、正文 940 个片段、生图 805 个键。翻译在本地生成后随构建提交，运行时只下载本站静态资源。校验变量、数值、代码、技术标识、空链接及临时翻译标记，定向校对余额、额度、兑换码和正式产品名。旧词典中的成段英文回退也已补齐；这些检查不等同于所有语言逐句母语审校。

真实浏览器逐一验证 17 种控制台和文档语言，覆盖英文登录继承、繁体令牌页、跨标签同步、保存失败重试与刷新保留、协议原文切换、390px 和暗色阅读。生图切换语言保留输入、任务与令牌。账户恢复下载在退出、换账号或卸载后立即失效；GET 去重键和请求头使用发起时的同一个语言，防止快速选择时错配。后台协议必须完整原文匹配，不能将旧版本译文套在新条款上。

发布环境补充：.75 的镜像构建暴露 oven/bun 基础镜像中 `node --test` 被 Bun 兼容入口当普通脚本执行的问题；本地真 Node 未复现。构建门禁改用显式 `bun test` 和 `bun`，保留同一组资源/正文/发票断言。直接 Bun 运行 35 项均通过，发布标签保持不可变，以 .76 完成修复。

## Consequences

新增大批译文需要术语校对；不能把本地界面翻译等同于用户内容、外部网页、上游错误和后端所有消息均支持 17 语言。后台账户偏好写失败时应保留已成功加载的本地选择并明确提示，不谎称全设备保存成功。

独立文档域名复用本决定的内容或入口，跨域与发布边界见[独立文档站](2026-10-25-docs-subdomain.md)。
