# Agent Note: 模型统一基础价与真实目录报价

Status: implemented

## Problem

luna 等低价模型叠加分组优惠后无法覆盖服务成本。分组与用户专属倍率没有模型维度，逐组抵消折扣容易遗漏新组；只更改扣费会导致模型广场报价失真。

## Decision

复用 Root 专属 option 配置保存 NoDiscountModels 精确模型 ID 列表，默认空。现有模型价格设置提供可搜索多选与独立保存。命中后统一使用本站基础价，分组（含企业、个人特殊与零倍率）和时间倍率均为 1；付费服务档位、基础输入输出/缓存价、充值套餐折算和权限路由不变。基础价不自动等同官方参考价。

统一取价捕获请求级策略，重试不因配置变更切换政策，任务继续保留已持久化计价快照。pricing 在请求响应中附加模型策略，避免修改共享目录缓存；前端卡片、表格、排序、详情和分组比较复用计算入口应用相同覆盖。

## Related notes

检索活跃笔记后：[企业分组倍率](../../implemented/feature/2026-11-13-enterprise-group-multiplier.md)部分重叠，本规则是显式模型例外，企业组有效性校验保留；[官方价比较](../../implemented/feature/2026-10-30-model-group-official-discount.md)部分重叠，比较基准不变，本站报价使用有效倍率。其余目录卡片、缓存和视频展示笔记仅涉及渲染，原决定保留。没有可完全吸收的旧提案。

## Alternatives considered

- 提高基础价无需新能力，但不同组折扣无法统一抵消。
- 新建专用组可复用现有配置，但需要调整渠道、用户令牌并处理企业独立倍率，新增分组容易漏配。
- 时段规则反向补偿可快速配置，但每个用户组/渠道组组合都要维护，改变分组倍率后还需重算。

## Verification

全量 Go 测试通过；补充异步任务改动后重跑 service/controller/model/helper，真实钱包及令牌余额验证任务按原基础价快照扣差额。覆盖非法配置不污染旧值、精确模型名与别名、个人/企业/自动切组/原免费组、时段规则、请求内开关快照、阶梯表达式及付费加速保持。目录测试覆盖输入/输出/缓存、按次、动态价格、排序与各组一致，23项前端价格回归通过。17种语言的36项资源检查通过。生产前端构建、真实Chrome预渲染与Go构建通过。

隔离Chrome使用实际设置组件和详情分组组件、模拟本地API：选择模型、保存失败保留、成功刷新、三折及零倍率组统一基础价、桌面/390px手机无横向溢出；脚本为 web/scripts/model-discount.browser.mjs。无生产调用。

任务 BillingContext 在既有JSON列增加可选 no_discount，命中时重算使用原模型/分组倍率；老任务保持旧语义，无schema迁移。时段预览接口同步显示有效1倍和策略说明。

## Consequences

开启会提高命中模型的新请求售价，应明确展示例外。精确 ID 不自动涵盖别名，需要管理员选中所有公开收费名称。配置沿用现有多实例同步周期。默认空，不猜测生产 luna ID，不自动修改线上售价或部署。
