# Agent Note: 模型管理跟随模型广场补齐目录

Status: implemented

## Problem

模型广场从启用 abilities 生成目录，管理页只读取 models。现有能力同步只有远端精确命中才补建，未知模型和来源故障时的新增模型无法进入管理列表。

## Decision

复用启用 abilities 和原有模型创建事务锁，独立补齐本地展示记录，不把远端收录作为建档前提。管理员列表及搜索在分页前补齐；主节点每分钟检查本地目录，新增记录触发原有官方优先属性同步，之后继续默认24小时刷新。列表仅进行本地操作，用合并通知唤醒后台，关闭后台时仍能展示本地模型。

新增精确记录保留未知属性；人工非空、同步关闭、软删除及已有前缀/包含/后缀规则继续保护。规则覆盖的模型仍由已有规则行及其匹配列表管理；渠道下架不删除历史配置，避免临时停用丢失人工信息。成功来源和失败保留行为复用现有同步，不改渠道、计费、协议或权限。

## Existing notes audit

- [原能力同步](../../implemented/feature/2026-10-27-model-capability-sync.md)：部分重叠；拆出创建事务供本地补齐复用，解除本地建档对远端精确命中的依赖，其字段所有权和规则保护保留。
- [官方属性](../../implemented/feature/2026-10-30-model-attributes-official-sources.md)：部分重叠；直接复用官方优先、社区补空和逐字段来源，不重复实现适配器。
- [元数据展示](../../implemented/feature/2026-10-25-model-catalog-metrics.md)：部分重叠；继续由同一 models 记录向 pricing 展示属性。

## Alternatives considered

- 只缩短远端同步周期改动少，但未知模型永远无法建档，且增加无用的外部请求。
- 每次打开页面同步请求官方资料能立即显示最新值，但外部超时会阻塞列表和翻页，因此本地补齐与后台资料更新分开。
- 清空并重建为当前广场目录能严格保持条目一致，但渠道临时停用会丢失人工信息和匹配规则，因此增量补齐并保留已有配置。

## Verification

SQLite、MySQL 8、PostgreSQL 16 的目录补齐及现有属性同步回归通过，覆盖未知 ID、多组去重、幂等、人工值、规则/软删除、渠道停用保留、官方来源不降级和并发创建。管理员 handler 回归验证列表/搜索在分页前补齐、pricing 同源、来源429失败仍可建档且不报告同步成功。

后台循环的隔离回归验证本地检查不请求远端、新模型提前获取属性、未变化目录不每分钟请求远端。页面提示同步17语言，说明官方优先和人工保护。合并官方价同步主分支后 Go 全量测试、Go 构建/版本检查、前端与文档构建、Chrome 公开页预渲染、17语言资源检查及资料同步/属性前端回归通过。`make verify-notes` 与发布策略检查通过。

## Consequences

管理员列表读取会进行有界本地增量写入；属性更新异步，刚建档时仍可显示未知，后台完成后刷新查看。规则及软删除继续作为显式人工边界，目录不是对所有历史配置的破坏性镜像。128字符上限及无首尾空格的模型管理名称约束保持；异常渠道名称不自动建档。关闭后台任务仍可在管理页补齐目录。

官方接口范围仍是现有 OpenAI 公开文档及可选 Claude/Gemini 专用凭据；不声称所有厂商均有官方适配，复用主分支新增的 OpenAI 文本官方参考价同步，不自动设置销售价格、FAQ 或介绍图标等原向导字段。发布不包含生产部署。
