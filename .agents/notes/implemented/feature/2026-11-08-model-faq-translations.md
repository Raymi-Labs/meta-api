# Agent Note: 模型 FAQ 多语言翻译

Status: implemented

## Problem

模型 FAQ 只有原文，切换站点语言后问题和回答仍未翻译，管理界面也缺少校正入口。

## Decision

复用介绍的系统翻译队列、内容哈希缓存、17语言与人工优先规则。问答分别按完整原文匹配缓存，每条 FAQ 内保存人工覆盖，派生自动译文仅用于响应。编辑、排序与删除保持原有 FAQ 整体保存契约，详情及对比共用语言投影。仅当前已发布目录进入后台任务，复用现有串行调度与退避；原文变动自动切换缓存；人工校正保留并可恢复自动。继续使用原 TEXT 字段及60000字节保存上限，无数据库迁移。人工问题/答案译文允许800/8000字符以容纳语言长度膨胀；公开响应移除编辑辅助字段，并对有效译文应用既有公开元数据过滤。

## Alternatives considered

- 新建独立 FAQ 翻译服务与任务表会重复租约、失败恢复和计费处理，因此扩展现有队列。
- 整体问答 JSON 交给翻译模型可能改变顺序和字段结构，因此按问题与答案分别翻译，前端维持有序结构。

## Verification

Go全量测试通过；SQLite、MySQL8、PostgreSQL16验证译文保存、人工优先、恢复自动、原文变化与深拷贝。后台模拟真实HTTP边界完成问答共34个语言任务，公开读取不触发翻译。真实Chrome验证17语言详情、对比页英日切换、手机390宽度、人工修改保存/重开/恢复自动；初次运行因测试页面热重载超时，关闭测试HMR后通过。浏览器验证发现并修复原提交映射丢弃新增翻译字段的问题。官方价格完整浏览器套件在折扣断言处失败（75%与92.9%）；未修改的主分支3352dc72d临时副本复现相同位置和结果，确认为既有失败，不计作本轮通过项。前端构建和ESLint通过；预渲染因本机无默认Chromium路径跳过，沿用后端元数据兜底。

## Consequences

后台翻译依赖已启用的系统翻译令牌与渠道，异步生成有延迟和费用；人工译文计入既有 TEXT 上限。无译文时保留原文。
