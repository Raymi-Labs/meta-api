# Agent Note: 公开轻量跳板监控与月流量估算

Status: implemented

## Problem

用户明确要求去掉监控登录，明细仅保留 24 小时，历史只留汇总数字，并展示月流量预估。原独立密码面板与每日表不再符合使用方式。

## Decision

移除此路径 Basic Auth，公开 HTML/精简 JSON；不公开密码、系统日志或采集脚本。沿用 vnStat 累计数据库，不清零。5 分钟桶和自有采样仅保留最近 24 小时，小时桶关闭，日/月/年保留数字汇总。预估用最近有效窗口实际流量除以观测秒数乘 30 天，显示接收/发送及短样本提示。

旧监控笔记部分保留：采集与指标隔离仍成立；访问权限决定由本篇替代，互链明确新旧边界。

## Alternatives considered

- 保留登录：更私密，但用户明确要求直接打开，因此公开只读统计。
- 用当前 2 秒速率乘整月：实现简单，但瞬时峰值偏差大，改用 vnStat 窗口累计。
- 重建统计数据库：容易清理，但会丢累计；只调整明细保留并清理超龄桶。

## Testing

线上无凭据 HTML/JSON 返回 200，真实浏览器直接打开并显示预估；JSON 不再输出完整 vnStat 历史，曲线全部在24小时内。4项估算回归覆盖初始部分桶、24h左界、缺失/零时间和零流量；静态脚本构建通过。清理前后 interface 收发累计逐项一致，日汇总与总计复核；采集和业务状态复验。

## Consequences

所有访客可见收发统计；预估不是套餐账单或承诺。回源与客户端收发会重复计入整机合计；公开页面不用供应商配额推断余额。

## Retention details

vnStat 设置为 `5MinuteHours 24`、`HourlyDays 0`、`DailyDays 1`、`TopDayEntries 0`；月/年及 lifetime 保留数字。自有 history 最多1440点，字段只含时间和两条速率。初次清理停止 daemon 后备份再事务删除；vnStat 的 day.date 是日期字符串而 fiveminute.date 含时间，二者比较边界必须使用各自格式。验收时已从备份恢复误删的当日日汇总，并叠加恢复期间的新增量；总累计始终不变。后续清理由 vnStat 保留规则执行，不新增常驻进程。

原认证文件移入 root 回退目录，不再由 Nginx 引用；旧登录信息不再适用。原采集/隔离原则见 [初版监控](2026-10-17-relay-traffic-monitor.md)，其中独立登录决定仅为历史。本次为运维更新，无应用版本发布。

## 服务器状态扩展

按用户要求沿用现有2秒网络采样窗口增加 CPU 使用率、逻辑核心数、可用内存口径、Swap、根分区容量、负载与运行时间；仅当前快照，不增加历史存储或服务。比额外安装常驻监控代理更符合轻量目标。公开 JSON 不输出进程、版本、环境变量或文件清单。系统指标失败显示缺失/错误，不能伪造零值或阻断流量采集。新增 CPU 空闲/等待排除、无效窗口和内存可用量回归，与已有4项预估测试合计7项通过。

服务器状态部署验收：systemd oneshot 返回 success/0，公开 JSON 各比例/容量边界有效且 errors 为空，首页与业务状态接口返回200。真实 Chrome 页面已显示并刷新 CPU、内存、系统盘、负载及运行时间，同时继续展示累计、月预估和曲线。SSH 直连中断时通过现有 NAN 管理跳转完成部署；未通过新增永久访问绕过。
