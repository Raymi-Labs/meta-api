# Agent Note: 自动同步模型上下文与模态

Status: implemented

## Problem

模型广场和详情已经读取模型管理的上下文、输入及输出模态，但逐个手工填写成本高。原“官方同步”只导入介绍、图标等字段，其 New API 格式没有结构化能力数据，也没有定时更新。

## Decision

[自动资料默认值](2026-10-31-model-official-defaults.md)扩展公开厂商来源、介绍/标签/供应商和自动更新入口；其新规则取代下文旧的字段范围与失败等待周期，人工保护及来源语义继续有效。

复用 `SYNC_UPSTREAM_BASE` 指向的模型库及其 `/api/all.json` 完整数据。默认来源是 basellm/llm-metadata，汇集 models.dev 与社区维护数据，并非各厂商官方 API；不将来源中的价格、性能或协议字段用于本地计费和路由。

主节点启动一分钟后、此后每24小时同步；管理员可立即同步。任务在进程内单实例执行，手动与定时任务互斥；请求有超时和大小限制，失败不重试风暴、不清空已有值。环境变量可停用后台任务或调整周期。

只精确匹配模型 ID，按来源的厂商优先级确定同名项。仅更新开启 `sync_official` 的精确模型规则；启用渠道中的未配置模型可补建展示元数据，不增加可用能力。空字段自动补齐，内部 TEXT 快照记录实际自动应用的值与来源。只有当前值仍等于上次自动值时才继续更新；人工非空值优先，并释放对应字段的自动所有权。缺失或非法源字段保留本地值；关闭同步可保留空配置。写入使用乐观条件保护同时发生的人工保存，MySQL 补充字节精确比较避免大小写排序规则绕过。补建尊重已有前缀/后缀/包含规则与软删除记录；自动、管理员和旧版同步的启用模型创建共用能力行事务锁，防止重复记录。已知源模态 pdf 映射到本地 file 类别，未知类型仍拒绝。

能力同步补建的零供应商元数据，由[pricing 统一展示回退](../../implemented/bug-fix/2026-10-28-pricing-vendor-fallback.md)恢复原本可从名称推断的归属。同步仍不写供应商字段，来源 Provider 仍只表示能力来源，不能代替模型厂商。

[模型属性与厂商优先同步](2026-10-30-model-attributes-official-sources.md)部分取代仅社区来源决定；沿用本篇人工所有权与并发保护，新增最大输出、逐键能力和来源展示。

本地目录补齐由[管理目录跟随广场](2026-10-31-model-catalog-reconciliation.md)扩展：列表/搜索和主节点每分钟使用同一能力行创建锁补建，远端未收录或失败不再阻塞建档；已有规则和软删除保护继续有效。

## Existing notes audit

- [模型展示元数据与分组指标](../../implemented/feature/2026-10-25-model-catalog-metrics.md)：部分重叠。本次仅放宽“同步不写新展示字段”为“可补空和更新自动拥有字段”，人工值保护、价格及性能口径继续有效。
- [独立模型页](../../implemented/feature/2026-10-25-model-detail-page.md)：部分重叠，复用已有 pricing 与详情数据路径，不改变公开权限。
- [Inception 厂商分类](../../implemented/feature/2026-10-21-inception-vendor.md)：部分重叠，不改厂商归类和真实可用能力。

[发布日期排序](2026-10-28-model-release-date-sort.md)将同源 release_date 纳入同一自动同步与人工保护链路；日期仅作用于精确模型展示和排序。

## Alternatives considered

- 逐家请求厂商 API 可获得更直接来源，但没有统一的上下文/模态接口，部分需要凭据；本次复用已经配置的免费模型库，并说明其来源边界。
- 从标签的“1M”等文字推算上下文实现简单，但会丢失精确值且依赖文案，使用结构化 `limit.context`。
- 仅补空实现最小，但之后无法自动更新能力变化；保存自动值快照可兼顾持续更新与人工优先。
- 无条件覆盖最省状态，但会破坏别名和人工校准，不能采用。

## Verification

- `go test ./...` 全量通过；SQLite、MySQL 8、PostgreSQL 16 同步回归连续多轮通过，包含 NULL 旧数据、重复迁移、人工修改、规则/软删除保护、自动与人工并发创建和大小写精确比较。
- 来源解析、超时、响应大小、429 保留、互斥锁、旧同步开关和中文 locale 回归通过；handler 到 DB、pricing 的集成测试确认同步成功刷新缓存、失败保留原值。
- 前端同步请求、卡片/路由/健康隔离、价格及17语言资源检查、主站和独立文档构建通过。
- 本地完整 Go 服务使用隔离 SQLite 与真实公开模型库：浏览器管理入口填入 Kimi 1,048,576 上下文与文本/图像/视频输入；人工上下文修改后再次同步保留，关闭同步的模型保持未配置。后台启动一分钟后实测自动填空，GPT 的 PDF 正确归入文件；卡片和详情读取同一份 metadata。未登录及普通用户均不能调用管理员同步接口，服务不可用时页面保留列表并提示失败。

## Consequences

外部模型库可能滞后或有误，保留人工覆盖及每模型退出。自定义别名无法精确匹配时仍需人工维护；能力同步不改变价格、协议或可调用范围。内部增加兼容 TEXT 字段，记录的是最后应用而非每次检查时间。多实例继续遵循主节点约定；SQLite 创建竞争可能返回可重试错误，不进行自动重试。源失败等待下一周期，不切换端点绕过限制。发布不包含生产部署。
