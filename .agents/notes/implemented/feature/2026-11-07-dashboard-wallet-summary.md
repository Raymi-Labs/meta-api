# Agent Note: 看板筛选旁的本人钱包摘要

Status: implemented

## Problem

用户希望登录后即可看到余额，并确认摘要紧邻数据看板右侧筛选按钮。已有钱包账户统计和个人总览，但看板没有余额与消耗预估。看板管理员统计可能是全站，日期筛选也任意，不能拿这些数据推算本人的钱包可用天数。

## Decision

复用钱包余额读取和金额显示，新增仅本人固定滚动24小时只读摘要。用户明确要求只要近24小时有用量即可估算，因此累加所有资金来源的留存消费与退款（补差也是金额变化），不因缺少来源字段停算。余额除以正的净消耗得到参考天数；退款后无净消耗时不做除零或无限预测。日志关闭、扫描失败/超限时不估算，余额独立保留。不改变日志写入和实际扣费。

摘要放在日期右侧、筛选按钮左侧；手机换行。点击显示24小时净消耗、预估说明及刷新；充值复用钱包入口。数据独立于看板日期与管理员筛选；账号切换取消旧请求，显式身份Header，禁止跨身份GET去重。不轮询；页面进入及显式刷新加载。

## Alternatives considered

- 用现有看板summary除余额：可能为全站/多日，不符合本人钱包预估。
- 仅钱包来源消费：虽更接近钱包实际扣款，但旧日志缺失来源会导致不估算；用户明确选择全部近24小时用量作为参考。
- 用本月平均值：用户认可近24小时，月平均会掩盖近期变化。
- 独立大卡：用户明确要求嵌入筛选旁，复用现有行并在窄屏换行。

## Verification

Go model/controller/router完整回归通过，覆盖24小时边界、本人/伪造账号参数、消费退款与补差、各资金来源与无来源历史、零/负净消耗、关闭日志、扫描超限/取消、日志查询失败保留余额。SQLite隔离测试，无表结构修改，未做MySQL/PostgreSQL实机验收。

Bun钱包与模型体验相关31项测试、Node账户隔离/SSE测试、36项语言测试和生图语言检查通过。真实Chrome验证摘要紧邻筛选、日期切换不改24小时口径、详情/Esc、五档宽度、手机深色/英文、失败与重试、账号切换和迟到响应、原钱包跳转。主站Vite构建和模型体验完整浏览器流程通过。初次广泛测试将Node专用SSE与需额外SDK环境的脚本误交Bun运行，修正为项目规定的Node命令；SDK集成未另行安装验证。

测试审查修正fixture重复aff_code和浏览器刷新等待时序；局部请求采用skipErrorHandler，失败/取消由组件处理，避免全局toast遮挡充值。新组件无轮询、后台任务或收费调用。同步main的53bf4ef后按键合并17语言资源，保留主分支对路由方案的撤回；前端、两套浏览器、构建与259篇笔记校验再次通过。

## Consequences

留存/写入延迟会影响预估；钱包余额与日志不保证事务快照。按用户确认计入所有来源，因此参考天数并非套餐/钱包的精确耗尽承诺。8秒/25万行/2并发槽限制，失败不显示部分总额；日志未启用不伪造零消费。余额为零不能断言套餐也无法使用；无净消耗时不显示无限天数。无生产部署。
