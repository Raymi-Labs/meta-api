# Agent Note: 邀请推广素材与短链点击统计

Status: implemented

## Problem

邀请链接能绑定注册并结算返佣，但注册页缺少产品说明，邀请人无法直接取得嵌入网站的推广素材，也无法知道链接访问量。

## Existing capabilities and impact

已核对 InvitationCard → /api/user/aff → User.AffCode、/i/:code → RegisterForm → 注册/OAuth 的邀请码绑定；管理员已有用户邀请关系侧栏，返佣沿用现有台账。检索活跃笔记“邀请|推广|invite|affiliate”未发现归属笔记。扩展现有入口，不更换域名、身份归属或返佣规则，不写死模型倍率等易过期承诺。

## Decision

邀请注册页以“好模型，就用元衡”为主视觉，展示用户提供的满血 CC Max / GPT Pro 卖点和模型卡片，以深墨绿、青柠色按钮及两种浅色卡片建立层级；一 Key 多模型、用量可查、按需选择作为辅助信息。桌面使用品牌区与注册表单双栏，手机保留直接跳到表单的按钮。邀请奖励页提供同步视觉的文字、按钮、横幅 HTML 和预览。素材只有静态 HTML/CSS 与本站短链，不注入脚本、追踪像素或第三方资源。前端与素材共用优势文案，保留项目署名。

后端对有效启用用户的短链 GET 聚合计数，按邀请人 ID、UTC 日期、固定来源 link/text/button/banner 保存原子递增计数，不存访客 IP、UA、指纹。忽略显式预取，禁缓存；无效码不计，统计失败不阻止注册跳转。入口复用限流框架。统计只包含上线后的短链访问，刷新/机器人可能计入，不宣称 UV、广告展示或注册转化；直达 /register?aff 不重复记数。更换邀请码保留用户历史统计。

用户接口由登录身份限定自己的近30天数据；管理员在原邀请关系侧栏查看同口径统计。固定30日边界避免不受控查询，不引入明细分页。数据库采用 GORM 复合唯一索引与 upsert，兼容三种数据库。

## Alternatives considered

- 前端注册页埋点：能覆盖直接注册链接，但 JS 禁用、重渲染、拦截及 OAuth 回跳更易造成漏记/重复；采用短链服务端计数，并明确口径。
- 第三方分析或保存逐条访客事件：可分析 UV/漏斗，但带来隐私数据与更多运维，当前需求只需聚合点击。
- 独立邀请落地页：可自由设计，但与注册重复且增加一步；在现有表单旁展示优势，覆盖邮箱及 OAuth。

## Consequences

点击为限流后原始请求次数，不用于支付或返佣。来源可伪造，仅用于推广观察。没有上线前历史点击，不补造或计算错误口径的转化率。新表通过普通/快速迁移入口创建，旧应用回退可保留新表；生产部署和数据库实机验证独立进行。HTML素材沿用邀请码与当前域名，改码后已投放代码需要更新。统计表不存访客标识；原有临时限流及日志保持各自策略。
