# Agent Note: 显式服务档位的选路与计费

Status: implemented

## Problem

Muze codex_pro提供priority（Fast）2倍、ultrafast 6倍，元衡已有service_tier开关和请求表达式，但计费冻结的是原始请求，渠道过滤/覆盖在后，可能多收或漏收。用户授权Meta实现，并要求独立新渠道归入OpenAI · 鹈鹕王，客户端另窗实现。

## Decision

复用现有ChannelOtherSettings JSON，按精确对外模型登记paid_service_tiers；显式登记的模型进入受管档位，其他模型保留原语义。注册包含停用渠道，防止临时停用后静默回到普通路由。注册查找失败不默认放行。受管模型只接受default/priority/ultrafast，普通缺省仍1倍；支持范围由管理员声明，不能因上游回显default改变已确认的请求档位。首选、亲和、指定渠道、重试与回退共享档位约束；无合格线路返回明确错误。出站前复查实际字段，禁止降档、强制加速和伪造内部标记。优先支持OpenAI类型渠道的Chat/Responses路径；其他协议不隐式丢弃。

使用现有tiered_expr预扣/结算快照，将原完整表达式乘2/6，不改模型基础价格或分组倍率；原表达式已有service_tier规则时拒绝重复乘算。日志明确requested_service_tier与service_tier_multiplier。新增本人模型/分组能力接口，返回标准及当前可用加速档位，无渠道和密钥信息；前端仅单模型显示可选档位，模型/分组切换清空旧授权状态，不自动降档发送。客户端交接固定同一接口契约。

## Existing notes audit

检索service_tier/服务档位/加速档位未发现所属活跃决策。既有模型体验能力、计费表达式和路由排序能力继续复用，不修改其默认计费或排序含义。

## Alternatives considered

- 仅开透传并在所有模型加表达式：参数可能被别的渠道删除，无法保证实际档位。
- 独立fast/ultrafast模型别名：可隔离配置，但复制模型目录和定价增加维护，用户选择原模型加档位更直接。
- 根据响应回显结算：Muze实测三次均回显default但已按2/6倍扣费，不能据此降价或宣称未加速；按授权请求和出站一致性冻结。

## Consequences

上游default回显记录为兼容性事实；短请求不证明吞吐提升。已有同名模型priority使用者在登记后进入严格策略，需要上线说明；删除最后一项注册等同取消策略，须管理员明确操作。内存注册索引随渠道缓存更新，非内存模式只查settings字段并设置超时；异常不默认放行。显式service_tier不会从客户端伪造内部授权；输出守卫读取最终JSON并保持原字节，受既有请求大小限制。生产开启仍需受保护发布流程。
