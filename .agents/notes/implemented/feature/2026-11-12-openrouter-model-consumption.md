# Agent Note: OpenRouter 模型消耗对照

Status: implemented

## Problem

默认现金收益页依赖资金凭证、手动密钥归属和完整日账；用户只需要上游模型消费与本站闪电消耗，财务核实门槛阻挡了运营查询。

## Decision

默认复用 finance 页面和官方 activity，按模型/UTC日汇总上游 USD 与本站日志额度。官方 keys 自动匹配当前渠道密钥，不写现金绑定；混合账户渠道排除。日志中的 upstream_model_name 优先，未映射日志保留原模型名，不使用当前映射倒推历史。只查询最近30个完整UTC日，返回日期边界，前端沿用平台额度显示配置。上游与本站独立失败；账户上游可能包含站外请求，本地日志可能已清理、渠道可能换过密钥，页面明确范围而不推算利润。

## Existing notes audit

- 2026-11-02-openrouter-account-finance：部分重叠，扩展其只读消费入口。
- 2026-11-03-upstream-cash-ledger-v1 与 proposed/feature/2026-11-03-upstream-cash-profit：保留资金核算决定；本篇调整默认入口，不改账本。

## Alternatives considered

- 继续补齐现金凭证：可得核实收益，但与本次只看消耗的目标不符。
- 用所有 OpenRouter 渠道合计：简单，但多账户会串账；用官方 keys 核对当前归属，明确历史局限。
- 根据当前渠道模型映射回填历史：能多匹配一些模型，但映射变化会误归属；优先历史日志字段。

## Verification

模型与每日合计一致，日期和搜索共用筛选；本站独有/上游独有模型保留；部分失败不补零；排除今日和其他账户，管理员权限不变；相关 Go/Bun 回归、前端构建与笔记校验通过。真实 Chrome 合成数据验证新增/编辑/删除、密钥保留、分页、模型筛选、每日汇总、闪电显示、部分失败、清空及账户切换竞态；390px手机无页面横向溢出。Go构建通过，未执行生产升级或生产数据库验证。

## Consequences

日志保留期与当前密钥归属不能证明历史完整性；USD和闪电不可直接相减。官方 activity 不是网站实时自定义时区活动接口。
