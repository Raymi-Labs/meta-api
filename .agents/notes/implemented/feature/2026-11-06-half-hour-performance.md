# Agent Note: 性能对比每30分钟采样

Status: implemented

## Problem

用户要求模型详情性能对比每30分钟一个节点，并将自动渠道测试周期设为30分钟。既有小时聚合无法无损拆分，小时健康历史和目录汇总仍有消费者。

## Decision

复用健康采集、指标算法、权限和查询入口，额外保存半小时快照；小时表保持原样以兼容旧服务与回退。详情性能查询显式请求1800秒，24/72小时分别返回48/144点，缓存按粒度隔离；折线只连接相邻半小时。测试补充按半小时最多一份证据。旧小时数据不拆分、不伪造半小时历史；小时健康历史和批量摘要继续读取原表。新表同样保留7天。

自动测试默认周期与设置页面默认值同步为30分钟。本次已将线上启用中的测试周期由10分钟改为30分钟，保留原值备份并读回确认；运行环境没有覆盖该值的 CHANNEL_TEST_FREQUENCY。当前正在等待的旧周期可能完成一次，后续循环读取新设置；不重启服务。

## Existing notes audit

[渠道测试历史](../../implemented/bug-fix/2026-10-31-uptime-channel-probe-history.md)继续约束渠道证据归属和旧小时回填；[72小时健康历史](../../implemented/bug-fix/2026-10-31-uptime-72h-measurement-reference.md)保持小时状态条；本次只为性能趋势新增粒度。

## Alternatives considered

- 全局将3600改为1800：代码更少，但旧小时数据会被误作半小时数据，窗口、历史补证据、旧服务与回退读数都受影响。
- 同表增加粒度列：能减少公共字段定义，但旧版本读表没有粒度过滤，会重复统计，不能满足回退兼容。
- 前端插值：无需新增存储，但会制造未经测量的节点，不能满足用户要求。

## Verification

相关Go包通过，集成测试覆盖整点/半点边界、48/144点窗口、真实请求与探测隔离、旧表不重复、授权与非法粒度、快照重试和7天保留；SQLite、隔离MySQL 8与PostgreSQL 16均通过。前端指标、状态与图表回归通过，完整主站构建及Chrome五页预渲染通过；浏览器验证性能详情、P50、历史参考、移动端布局、真实测量优先和缺失数据。

## Consequences

新增一份聚合存储和写入；半小时数据从应用新版本上线开始积累，本次运行配置更新不等于应用部署。渠道测试只补Uptime证据，首字与速度继续取真实调用；禁用测试或供应商失败不保证每个节点都有成功数据。相同采样在小时和半小时表分别存储，查询只选一种粒度，不能将两表相加。新表使用独立索引名称，兼容PostgreSQL schema内索引名称唯一性。
