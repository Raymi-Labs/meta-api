# Agent Note: 邀请返佣档位与单笔分配引擎

Status: implemented

## Problem

旧入池路径无法表达六档矩阵、成员部长位、月基数、晋级和永久切断上游。分配基础已修复，但缺少资格奖励与推广者生命周期，不能独立开放。

## Decision

复用支付事务、用户邀请关系、额度台账和现有提现入口。`InviteTierSettings` 默认关闭；启用要求持久化加密密钥，首次启用时间持久化且不可通过配置补丁重置。历史邀请不补发注册奖励，历史下级不计入晋级人数。开关关闭只改变新支付路径。

矩阵按收款人身份取行、一级档位取列。支付回执、奖金唯一记录及月基数共同保证重试幂等；基数用人民币整数分和 bigint quota，换算走 decimal。六种收益均保留当时比例、档位及周期快照。成员与部长签约切断上游，退出仍保留切断。

自动晋级取本月/上月较高业绩档；专员前两个月免考核，第三个月起检查上月新增资格，保级人数可配置。部门成员主动退出次月生效，连续三十天没有新增资格由每日任务移出并回到免考核专员档。部长晋级会结束旧成员记录，避免旧部门任务误降档。人工覆盖保留独立优先级和截止时间，支持覆盖到普通档。

用户申请、管理员审核和部门退出复用身份鉴权与日志。实现入口为 `model/invite_tier_promotion.go`、`controller/invite_tier.go`、`router/invite-tier-router.go`；钱包和用户邀请关系页复用统一档位组件。

## Alternatives considered

- **在现有两个比例选项上叠加档位倍数** — 改动最小、迁移最少；但二级比例同时依赖收款人与一级档位、成员还要拆出部长位，倍数无法表达矩阵，也无法保证每种组合不超池，放弃。
- **结算时按收款人当时档位重算金额** — 档位变化可即时反映到未结算台账；但同一笔支付的金额会随考核结果漂移，冲回、对账与异议都无法复现，且与已实现的“支付时金额快照”决策冲突，放弃，改为支付时快照。
- **用 Redis 计数维护二级月基数与达标奖金去重** — 性能好；但计数必须与台账同事务提交/回滚，Redis 无法与三种数据库事务原子，失败补偿复杂，放弃，改用数据库计数行与可空唯一键。
- **把用户金额列改成 decimal** — 精度直观；但现有额度全部是整数语义，decimal 会改变大量扣费/统计代码与索引行为，bigint 已有先例（`PulsePaidQuota`、发票金额），选 bigint。


## Consequences

完整实现使新周期功能可由管理员启用，默认不影响旧入池路径。SQLite、MySQL 与 PostgreSQL 共用 GORM；跨库回归覆盖唯一索引迁移、并发回调、并发结算和退款交叉。浏览器验证桌面/移动入口、空态和分页；自动化检查记录见 [验收记录](../../../../docs/reviews/2026-11-19-invite-tier.md)。

生产启用仍需要备份和迁移预检；本次版本发布不等于生产部署。实名与设备数据须使用持久化密钥，丢失密钥无法解密原有记录；辅助信号和人工审核不能替代实名核验供应商。
