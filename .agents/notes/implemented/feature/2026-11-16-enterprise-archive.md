# Agent Note: 企业结清后的不可恢复归档

Status: implemented

## Problem

冻结企业仍占用成员关系、计费分组引用和所有者注销保护。验收企业收尾后无法通过受支持入口退出生命周期；物理删除则会破坏消费、调账和审批记录。目标是结清后安全退出，保留平台可查的历史，不能将归档当作退款或抹账。

## Decision

复用平台企业管理、Root权限、企业钱包调账、成员余额归并及现有用量/流水/审计查询。增加`archived`终态、归档时间/操作者/原因。默认列表排除归档，独立已归档筛选提供只读历史。冻结仍可解冻；归档不可恢复。

Root先读取预检，提交时精确确认企业名称、填写原因。事务内锁企业行，再按ID锁全部成员代次，重算账本并核对：已冻结、守恒式成立、未分配加成员可用及预留的净余额为零、每个成员预留为零、没有未终结预留、没有未完成或未确认结算的Task/Midjourney。未知状态和数据查询失败阻止归档。预检不是提交凭证，实际提交必须重新检查。

同一事务把成员可用余额通过已有归并流水收回（只做企业内部转移），撤销邀请、失效申请、停用企业令牌，释放active_user_id，记录归档审计。所有成员代次加归档标记，成员锁统一拒绝新的计费写入；Task持久化也获取相同成员锁，阻止迟到任务插到已归档企业。管理写入口统一拒绝终态。普通用户路径不变，冻结时既有任务仍可结算。企业令牌编辑取得同一成员锁，防止陈旧的启用状态覆盖归档停用。

同步企业请求的违规费在原预留释放之前持久化，封闭退款后补扣的归档窗口。Midjourney在本地准入失败、尚未向上游发送时明确结束零费意图；未知响应/超时仍保留待对账，不能按时间猜测。

历史企业保留Owner数字ID与原分组名称，但不再阻止该账号注销/重新加入，不再阻止分组维护。归档后分组名称仅是历史归属，不用当前组倍率冒充历史价格。重复归档返回原结果，不重复审计或划拨。

调账继续要求Root和明确原因。金额输入支持现有原始额度单位，避免界面两位小数无法处理微额。归档不自动核销、退款或改变净入账；历史测试企业的负余额仍需要操作者单独处理。

## Alternatives considered

- 物理删除或直接清零：失去审计/费用证据，不能采用。
- 只增加归档按钮并隐藏列表：迟到结算和旧成员关系仍可写账，不能满足终态。
- 每次调用都锁企业行：简单但使同企业所有成员计费串行。归档锁全体成员，计费复用成员行锁和归档标记，保留现有并发粒度。
- 只检查未分配余额或预留金额：零额预留、已初次扣费的异步任务仍可能退款/补扣，须同时核对持久任务终态和结算确认。
- 要求每个内部预算也逐项为零：会使Owner负预算无入口回收；净余额为零时归档事务按现有流水归并内部余额，不改变企业资产总额。

## Verification

SQLite覆盖Root权限、名称/原因、正负微额、守恒破坏、零额预留、未知/未结算任务、归档回滚、重复提交、并发请求/Task插入、全部成员代次封闭、分组引用释放、Owner注销和重新加入、个人余额与令牌隔离。真实Task/Midjourney终态结算后可以归档；增量迁移连续两次保持已有状态、资金与归属。HTTP加合成上游证明企业违规费落账时原预留尚未释放，已归档企业令牌拒绝而个人目录保持。

model/service/controller/router/middleware/relay六包完整回归通过，企业/违规费相关race通过。真实组件合成API浏览器覆盖桌面与390×540短屏、微额调账、错误重试、精确确认、提交保护、只读历史和迟到响应，外部请求为0。15项企业前端逻辑、36项语言资源、ESLint与生产构建通过。304篇笔记门禁和diff检查通过；本轮测试/预览/构建进程均退出，遗留工作进程为零。测试命令、操作入口及已知验证缺口见[本地实现与验收](../../../../docs/reviews/2026-11-16-enterprise-archive.md)。

## Consequences

保留历史且释放真实成员/分组约束；代价是归档前要结清资金并解决所有未确认任务，不能用超时或零价猜测结束。净余额为零时允许按既有流水归并内部正负预算，真实消费不变。归档锁定全部历史成员，单个企业成员代次很多时该管理事务可能阻塞计费；常规调用仍只锁自己的成员行。

归档是终态，后续修账需要专门设计迁移，不能借解冻恢复。旧版本不认识归档和成员封闭字段，已有归档数据后的版本回退必须核对状态兼容，不能只因新增字段有默认值就声称安全。所有者注销后部分展示名可能只剩ID，账务归属与审计仍保留。

MySQL/PostgreSQL的可丢弃实例未配置，本轮子测试明确跳过；Redis多实例及生产schema没有现场演练，未用旧CI记录代替本轮三库验证。主库成员关系是调用权限依据，缓存失效不是唯一保护。本轮只做本地实现，未推送/发布、操作线上企业或调用收费上游。
