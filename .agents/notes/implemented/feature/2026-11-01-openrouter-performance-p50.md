# Agent Note: OpenRouter P50 补齐缺失性能

Status: implemented

## Problem

新接入、低用量模型缺少首字与输出速度，现有健康接口只提供本站聚合和七天内有效历史。用户明确要求仅为这两项补充 OpenRouter P50，页面不显示来源标签。P50 不能称为均值，上游吞吐亦不等同本站生成时段速度。

## Decision

复用登录后的模型/分组健康摘要权限，在独立 performance_reference 字段返回补充值；不修改均值、样本、Uptime、小时序列、计费、模型配置和令牌。卡片及详情分组摘要逐项优先使用本站有效值（含零）及已有历史首字参考，最后使用新鲜 P50。使用 P50 的首字标题改为首字时间，无来源徽标或来源提示；后台保留来源、模型、服务商及抓取时间供诊断，不将外部值写入本站统计。

仅查当前启用且在用户授权模型/分组范围内的 OpenRouter 渠道，精确应用站内模型映射及既有参数覆盖引擎。根据服务商允许/排除、限价和状态过滤，低价排序选可调用候选的参考，不取任意最快服务商。请求只允许固定 OpenRouter HTTPS 主机的 GET 元数据路径，使用对应渠道的现有可用凭据，禁止重定向且不向前端暴露凭据。已有官方厂家资料同步不借用中继凭据的契约保持，本功能是独立的同上游性能读取。

有界缓存与合并并发请求，成功五分钟复用，失败一分钟退避，过期值不展示；多模型抓取限制并发和总时间。无可核对路由、缺字段或失败继续空态，不影响本站数据接口。新参考仅用于当前摘要，不倒填性能图或健康历史。

## Alternatives considered

- 覆盖 avg 字段最简单，但把 P50 当均值、外部值当本站观测；使用独立参考字段。
- 直接取模型最快服务商更好看，但可能不在当前允许/限价范围；按实际配置筛选。
- 浏览器逐模型抓 OpenRouter 少后端代码，但暴露认证凭据、绕过授权范围且产生大量重复请求；服务器有界缓存。
- 显示来源标签更直接，但用户明确要求简洁；取消视觉来源标记，首字使用中性名称，原始来源留在接口。

## Verification

- 使用生产现有渠道对 OpenRouter 元数据执行只读认证 GET，确认 latency_last_30m.p50 为毫秒（1915 显示 1.92 秒）、throughput_last_30m.p50 为 tokens/s；未执行模型推理。公开匿名响应可能不含性能字段。
- Go 全量测试及 service/controller/group_health 相关竞态测试通过；覆盖映射、禁用与精确权限、状态/限价、重定向拒绝、响应大小/模型校验、缓存合并/过期/失败退避。
- Chrome 合成接口验收覆盖卡片与详情 P50、无来源标注、无虚构 Uptime、本站实测优先、空参考保留未知、390px 深色无横向溢出。浏览器截图仅为本地验收数据，不作为线上指标。
- 前端完整构建通过；设置现有 Chrome 路径后五页预渲染通过。应用发布与生产部署分别验证。

## Consequences

参考不包含本站网络/排队耗时，路由回退或服务商变化仍可造成实际差异；API 可能没有某些模型的 P50，不能保证所有空缺补齐。多服务商 P50 不合成为全平台 P50；选中的服务商和模型保留在内部元数据中。
