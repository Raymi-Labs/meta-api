# Agent Note: 个人总览承载月用量与调用日历

Status: implemented

## Problem

用户认可个人总览独立页面，用于账户、本月用量、年度调用日历和令牌概况。原日历草稿挂在数据看板统计卡下，和模型分析用途混淆。已有个人设置、钱包和令牌管理足够承担管理操作，不能再做平行编辑页面。

## Decision

侧栏保留内容自适应高度，同时对普通菜单行、聊天子菜单标题及文字容器显式垂直居中；避免40px最小行高使图标居中但文字靠上。样式限定sidebar-nav，不改菜单权限和路由；浏览器回归位于web/scripts/sidebar-alignment.browser.mjs。

个人中心分区首项增加overview（/console/overview），沿用侧栏管理员/用户模块控制与PrivateRoute安全next。日历从数据看板移走，个人总览默认展开；数据看板本身不改。账户复用user/self并前端脱敏邮箱，不复刻截图账户。月统计新增本人固定自然月读接口，复用dashboardUsageAccumulator消费/退款/补差及Token语义，按浏览器IANA时区算月初、实际日期活跃数，支持31天及DST，不放宽旧self30天接口。令牌只读摘要数据库聚合，全账户统计不依赖第一页；最近5条独立DTO仅含名称/状态/创建时间/掩码，不返回完整Key，排除系统生图临时令牌。已启用状态不承诺实时有额度或可调用。

模块独立加载失败/重试，账号切换重挂载取消旧请求，禁止跨身份通用GET去重。月用量沿用原留存消费记录口径，年度不与月筛选混合；查询固定上限/超时，不自动调用模型或修改配置。快捷入口复用钱包、日志、设置、令牌路由。17语言与明暗/手机适配。

## Alternatives considered

- 数据看板加更大个人区：已有模型统计面向分析，用户明确偏好个人入口，移出日历。
- 个人设置页面加统计：设置与使用总览任务不同，容易打断安全/账户操作。
- 前端拉全量令牌或累加分页：暴露不必要Key并易只数第一页，采用服务器聚合与脱敏DTO。
- 复用30天接口直接查自然月：31天月末或DST会失败，新增固定自然月本人接口复用计算器而不放宽任意时间查询。

关联：个人调用日历原草稿布局被本篇接管，数据口径/限制继续；个人设置与钱包保持管理职责。
