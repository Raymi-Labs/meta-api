# Agent Note: 同一对话的多文本模型并发回答

Status: implemented

## Problem

模型体验已有同一历史下的模型标签切换，但一次只请求当前模型。用户明确需要一条文本问题同时发给多个模型；把现有最后一条消息更新器直接并发复用会串写回复、混用停止控制器，并可能把先完成的答案发给后启动的模型。

## Decision

复用账户存储、当前分组可调用模型目录、buildApiPayload、useApiRequest 和原 /pg/chat/completions 鉴权计费。增加显式多模型模式，最多五个已声明文本对话模型，同一轮构建独立负载且共享相同历史快照。每个回复有独立请求实例、停止与失败重试，重试复用原始快照，不自动重发成功模型。状态写入按消息ID定位，禁止更新其他回复；身份变化卸载所有请求。

同轮结果选择一条成功完整的文本回复作为下一轮上下文，未选择不能续发；完成后仍展示全部回答。保留每条模型/分组与轮次元数据，保存/刷新不自动请求；图片、工具历史、自定义JSON不进入并发文本模式。单模型入口与代码导出共用分支过滤，不把未选结果发送上游。多模型选择受当前分组权限约束，换组期间禁发。

## Existing notes audit

[工作区](../../implemented/feature/2026-10-30-playground-workspace.md)的单模型默认保持，本篇扩展可选并发；[能力控制](../../implemented/feature/2026-10-30-playground-model-controls.md)保留原工具流程，不在并发文本中实现工具；[账户隔离](../../implemented/bug-fix/2026-10-17-playground-account-storage.md)继续约束存储和迟到响应；[SDK导出](../../implemented/feature/2026-10-31-playground-sdk-export.md)仅导出选中上下文和单个模型，不宣称一份代码会并发多模型。

## Alternatives considered

- 新增后端批量代理接口可以统一调度，但扩大计费、权限和流式协议范围，现有独立请求已满足目标。
- 将所有回答放入下一轮历史最省交互，但比较不公平且上下文持续放大，采用显式选择一条继续。
- 一套新的SSE解析器便于控制并发，却重复维护错误、工具和取消边界，采用每条回复独立复用原请求hook。

## Testing

- 独立Chromium合成API覆盖两模型共享负载、单模型503后仅重试该模型、同轮显式选答续发、五模型请求与第六项禁选、单条停止及全部停止保留已完成回复、迟到响应忽略、非流式请求、身份变化不落盘、刷新不重发、撤销本轮。桌面与390px页面截图核对，无真实模型调用或费用。

## Consequences

多模型意味着独立费用；停止不保证上游完全没有消耗。目录声明不等于真实可用，单个失败必须可见且不得自动切模型。历史重试快照只在当前页面内存保留，不在刷新后根据已变化配置悄悄重建。

新增独立的并发呈现组件是因为现有Chat只处理末条回复和单请求；底层发送、解析和鉴权仍完全复用。默认单模型不变，模型候选取当前分组权限与文本协议声明交集。左侧参数按各模型能力分别生成负载；代码预览仍是当前单模型，未选择上下文时禁用导出并提示选择。没有完成可用答案时可撤销本轮重新提问；切组后旧组重试禁用。首次多模型选择与重试快照不跨页面持久化，用户刷新后需重新选择模型。
