# Agent Note: 钱包低余额自动充值

Status: implemented

## Problem

钱包能手动充值或提醒余额不足，Stripe 套餐续费则按日历周期收费。用户需要按自己的钱包余额和阈值决定扣款。

## Decision

用户确认触发阈值、每笔实际扣款和到账额度，经 Stripe Checkout setup 授权。后台扫描已授权账户，核对已结算余额后建立充值订单，先持久化未确认的 PaymentIntent，再离线确认同一笔付款。支付成功复用钱包入账、支付记录和返佣。关闭设置使未完成的绑卡链接失效。

## Alternatives considered

在 API 请求中直接扣款会将支付延迟引入模型调用，并让并发预扣和退款产生多次触发。Stripe 日历订阅无法观察本地余额。

## Consequences

新账户默认关闭。授权设置记录本人的本地余额阈值、Stripe 固定价格、币种、每次购买份数和到账基数。向浏览器提供实际报价，提交时再次读取 Stripe Price 比对。支付方式保存在 Stripe，本站只记录支付标识。更换设置需要完成新的授权；停用立即阻止新订单，已开始的订单保留到确定成功或失败。

主节点约每分钟检查一次符合条件的用户。领取订单时重新锁定用户和设置，钱包余额加回尚未结算的同步钱包预留。成功到账仍低于阈值时等待余额恢复，避免持续低余额形成连续扣款。余额已恢复时可在下次跌破后再次触发。价格 ID 或到账比例变更需重新授权。

授权与扣款分别使用 setup_intent.succeeded、payment_intent.succeeded，已有 Checkout 完成回调也可核对授权。PaymentIntent 在调用确认前先持久绑定，一次充值始终确认同一笔支付。后台可查询 Stripe 状态追回丢失的成功回调，继续使用原 TopUp 账本、权益归因和返佣入口。失败、需持卡人验证或异常报价会暂停自动充值；结果未知时保留原订单。

[钱包支付](2026-10-28-wallet-experience.md)记录付款展示，[余额摘要](2026-11-07-dashboard-wallet-summary.md)记录看板统计。[套餐续费](2026-11-24-stripe-renewal.md)仍由套餐管理员选择是否开放，与钱包授权独立。

## Testing

签名回调与模拟 Stripe HTTP 端点覆盖阈值相等、临时预扣、重复领取、停用后的陈旧授权、结果未知、重复通知、金额不符、充值后仍低于阈值和恢复后再次触发。SQLite、隔离 MySQL 8 和 PostgreSQL 16 均经过实际入账校验。生产构建的浏览器流程覆盖输入阈值、展示实际扣款和到账金额、提交授权与停用。测试使用本地模拟 Stripe 端点。
