# Agent Note: 企业与个人API能力对等

Status: implemented

## Problem

用户明确企业客户应使用普通用户全部现有API，只切换企业价格及资金来源。现有企业白名单、异步后续结算及实时增量扣费只接个人资金，导致企业服务范围不足；单独去掉拦截会误扣退个人钱包。整体UI暂不调整，首页缺失四词条仅同步公开语言包。

## Decision

同步请求复用现有EnterpriseFunding；异步任务/MJ持久化原企业、成员、令牌和请求标识，完成差额与失败退款按绝对最终金额及持久事件幂等处理。实时会话的增量预留与最终结算归入同一企业账本，不走个人PostConsumeQuota。后台完成不依赖成员仍在职，不以当前个人身份重新推导付款人。保持个人调用和既有价格计算路径，企业合同价通过现有BillingGroup特殊倍率复用；模型权限仅来自明确配置，不以协议类型额外裁剪。

已移除企业专属入口类型白名单，复用现有路由。任务重试、迟到回调、进程恢复、重复退款与跨企业访问必须覆盖。体验区复用同一付款上下文，默认个人，不因账号加入企业自动改变个人请求付款人。

## Alternatives considered

只放开入口会在后台退款时写个人钱包；为每类模型复制计费框架会形成不一致账源；将企业成员直接换个人Group/充值个人钱包会破坏资金隔离。复用资金会话与持久企业事件，并在现有任务流程增加付款快照。

## Verification

八包完整测试及企业相关race通过；合成Sora全路由合同倍率0.5/失败退款、显式体验payer企业/个人隔离、任务恢复/并发/回滚、MJ多主体与退款、双WebSocket收尾、价格身份与授权隔离均有回归。新增字段采用GORM默认列，SQLite迁移通过，本次MySQL/PostgreSQL实机尚未执行。前端40项相关及36项语言检查通过。完整结果与局限写入[本轮验收](../../../../docs/reviews/2026-11-13-enterprise-api-parity.md)。已获用户授权推送并合并main，合并前运行本次三库CI；本轮不部署。

## Consequences

异步成功已经返回但任务落库失败不能盲目退款；保留账务证据待对账。不得以任务状态CAS替代资金事务幂等。暂未完成的入口不能在文档冒充支持。
