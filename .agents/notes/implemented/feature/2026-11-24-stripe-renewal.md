# Agent Note: Stripe 周期扣费与套餐权益

Status: implemented

## Problem

套餐 Checkout 原先固定创建 Stripe 订阅，但服务端只消费首次结账事件。后续账单可能已付，本地没有对应订单或权益。

## Decision

用户在套餐支付时明确选择周期扣款。单次购买与按期订阅共用套餐价格。每张已付订阅账单绑定本站原始订单，使用账单行的服务期发放当期额度，重投同一账单不会重复发放。登录用户可按原始订单在期末停止扣款。

## Alternatives considered

本地到期任务自行扣卡需要管理支付方式、扣款授权与失败重试；Stripe 已经承担这些职责。仅延长最早到期的同款套餐容易把同一用户的不同购买混在一起。

## Consequences

管理员先在现有 Webhook 加入 invoice.paid、customer.subscription.updated、customer.subscription.deleted，再为对应套餐开启自动续费。新增协议只支持与套餐同价、同币种、同周期的固定价格。一次新购多份表示每期购买同样份数；手动顺延走单次支付。价格只在下单时读取，存量协议使用首单价，后续发放沿用本站套餐的额度配置。

已付账单按原服务期创建独立的套餐实例；账单镜像、权益流水、发放状态和返佣待办同事务提交。已过去的服务期直接记为过期。其他同款套餐、单次购买及钱包充值沿用各自的订单。旧版的 Stripe 周期合约用 Checkout 的本地订单号与明细恢复绑定，首期继续由历史 Checkout 完成。历史已人工补发的账单需要先核账再决定是否重放。

[余额充值入口展示](2026-10-12-stripe-checkout-display.md)负责钱包支付入口的名称和图标；邀请返佣、钱包体验和上游利润笔记不负责订阅协议生命周期。

## Testing

签名 Webhook 经过实际处理入口，覆盖新旧账单字段、首期晚于第二期、重复投递、支付失败、过期服务期和按用户取消；本地 Stripe HTTP 模拟返回原始 Checkout 并核对取消参数。SQLite、隔离 MySQL 8.0 和 PostgreSQL 16 完成同一回归。钱包页面以模拟 API 验证单次支付、主动选择续费及期末取消。验证未调用真实 Stripe 扣款。
