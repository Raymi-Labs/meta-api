# Agent Note: 模型目录四类筛选与管理协同

Status: implemented

## Problem

目录把上下文、模态、能力、家族名都直接作为原始标签展示，缺乏任务筛选。管理员已有模态、能力、标签和自动同步，前台分类必须复用这些字段，并提供不会被同步覆盖的人工纠正入口。

## Decision

目录常驻供应商、功能、标签、输入模态四行；计费、协议和上下文阈值在更多筛选。供应商和功能多选为 OR，标签和输入模态多选为 AND，跨维度 AND。结果、选项数量和健康关联共用一个纯过滤函数；排序与筛选先于分页，历史仅保存展示状态。零匹配项置灰且已选项保留。

功能采用稳定 ID，从已确认模态、专用协议或明确任务标签保守派生，不根据名称猜测，不把 Chat 协议当作任务声明。新增 function_overrides 可空 TEXT 布尔映射，缺省自动、true 包含、false 排除；模型 CRUD 省略保留、空对象恢复自动，后台同步不写该字段。管理编辑器即时展示有效功能并可逐项调整；标签/能力/模态继续复用原字段。

前台标签归一化已知能力名称，能力显式 false 优先于遗留标签；上下文数字、模态、家族、弃用原始标签不放入常用标签。除已定义的系列/模态/任务保留词外，人工标签保留原文，已知标签和功能名使用17语言词典。厂商仅归一明确别名，保留数据归属及权限。

## Alternatives considered

- 仅重命名原始标签无需数据迁移，但不能清晰区分功能与模态，也无法纠正自动派生。
- 建立另一套供应商/模态/能力库可独立配置，但会与管理和同步事实分裂；只增加人工功能覆盖，复用其余元数据。
- 仅凭模型名称或 text/image 输入输出组合判断全部任务更容易覆盖，但会把看图模型误标为生图、把参考图输入误标为编辑；仅采用有证据的规则。

## Consequences

未收录且缺少资料的模型保持未分类；新任务需扩展白名单。自定义标签没有可靠译文时原文保留。发布不部署生产。

## 2026-11-01 系列标签遗漏修复

现有系列过滤仅覆盖 glm/qwen，自动能力同步又将上游 family 与 type 合并写入 tags，因此 claude-haiku、gpt-mini 等在四类筛选中重新出现。扩展原有分类契约：自动能力同步不再把任意 family 写入标签（含未来未知系列）；type 继续提供明确任务线索。历史数据由共用 getCatalogTags 排除已知系列保留词，目录选项/计数、卡片、模型管理预览及手机抽屉一致生效。speech 作为模糊媒体类型隐藏，不能据此猜测语音合成或识别。

使用精确保留词，不按 gpt-/claude- 等前缀笼统删除，不改原始人工标签、旧同步导入接口或数据库；gpt-workflow、speech-quality 等自定义标签仍可筛选。拒绝仅保留能力白名单，否则会破坏自定义标签；拒绝批量清库，因为旧数据没有可靠的逐标签人工来源。自动快照接管与管理员覆盖保护继续复用原机制。此修复不新增数据字段、不迁移数据库、不改变模型名称搜索、供应商归属、路由或计费。

验证：新增回归先复现原始系列标签泄漏；修复后目录分类 10 项测试通过，覆盖截图系列、大小写、精确匹配、正常自定义标签、模糊 speech 及显式 TTS。controller/model 全套测试及 Go 构建通过；真实 Chrome 在本地模拟目录中验证桌面与手机筛选、卡片、管理预览不显示系列，管理保存保留原始 tags，正常自定义标签计数/过滤及 17 语言流程通过。主站构建、语言资源、发布策略与笔记检查通过；本机默认 Chromium 路径不存在，显式指定本机 Chrome 后五个公开页面预渲染全部完成。无需数据库迁移，未部署生产。
