# Agent Note: 模型广场厂商横栏与分组侧栏

Status: implemented

## Problem

模型广场把厂商、分组及高级筛选都放在宽侧栏中，常用分组不易定位。钱包支付说明与支付按钮挤在一起，兑换码入口不够突出且文案容易让人误以为所有余额均可转赠。

## Decision

复用 `/api/pricing` 的可用组、模型 enable_groups 和适用倍率，顶部完整展示厂商并换行，左栏仅显示分组搜索、倍率降序列表与后台说明。保留不适用的当前选中组及解除入口，不自动换组；厂商列表不受当前分组限制。高级筛选移到桌面和移动共用弹窗，所有选组统一更新筛选与价格分组。复用价格计算、详情和健康页，不更改后台权限或计费。钱包保留双栏和充值档位，只整理到账/实付及支付说明，并将兑换码按钮改成描边。

桌面默认表格，手机默认卡片以免价格藏到横向滚动区域，两端保留视图切换。表格直接展示输入/单价、输出及缓存读取；动态计费复用首档解析并明确为参考价，其余价格与条件仍见原详情。复制模型名不触发整行详情。表格分页与共享筛选状态同步。重置及移动选组统一调用 handleGroupClick，避免筛选组与 selectedGroup 价格状态分离。

边界审查发现 BILLING_VAR_REGEX 的数字字符集合会吞掉无空格加减运算符，令 `p*10+c*20` 的系数解析成 NaN。改为明确的有符号十进制/科学计数匹配，覆盖普通与首档展示；不更改后端表达式求值。7 种语言同步文案。

## Alternatives considered

- 搜索式分组下拉框节省宽度，但用户频繁比较分组价格，固定侧栏减少切换步骤且不遮挡模型。
- 保留原侧栏可免去迁移高级筛选，但厂商与多组条件混杂，无法满足厂商始终可见、分组便捷切换的目标。
- 重写价格计算便于统一视觉，但容易破坏动态计费与单位规则，故复用现有计算和详情。

## Verification

`pricing-filter-browser.test.mjs` 在桌面与手机暗色覆盖共享组、零倍率、无权限组、已选不适用组、搜索、重置、健康汇总/具体模型/错误/权限。`pricing-wallet-layout.browser.mjs` 用合成 API 检查分组顺序、倍率换算、首档价格、按次/小时单位、复制与详情、到账/实付、支付说明位置和原兑换码弹窗，不提交真实支付或兑换。

`billing-price-coefficients.test.mjs` 覆盖相邻运算符、小数、科学计数、符号和零。现有 currency、tiered-billing-display、pricing-filter-items 回归及主站 Vite 构建通过。没有修改生图子应用，未重建该子应用或声明已部署。Bun 在本机不可用，make verify-notes 无法启动；相同的三个 TypeScript 校验脚本使用 Node 24 执行。

## Consequences

侧栏占用 260px 桌面宽度，窄屏改用筛选弹窗。分组说明较长时允许折行。未匹配的已选组保留并提示，需用户明确重新选择。高级筛选需额外打开弹窗，但厂商与分组入口保持直接可见。复杂表达式无法解析单价时显示见详情，不把未知值伪装成零。新布局不改变渠道、令牌、余额、权限与后端计费。
