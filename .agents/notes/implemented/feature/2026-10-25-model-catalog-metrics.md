# Agent Note: 模型展示元数据与分组指标

Status: implemented

## Problem

独立模型页已有真实价格、声明协议和24小时分组健康，但卡片缺少上下文与性能，模型管理不能配置模态，详情的分组价格和健康需要切换标签。用户希望整张卡片进入详情，并比较多个分组的性能与用量。

## Decision

[OpenRouter P50 补充](2026-11-01-openrouter-performance-p50.md)扩展卡片与分组摘要的缺失值展示：本站当前值及已有历史首字优先，无数据时可使用当前授权路由的 P50，不显示来源标签；首字标题使用中性名称。外部值只在独立参考字段返回，不改小时图、Uptime 和聚合。

[72小时与性能参考](../bug-fix/2026-10-31-uptime-72h-measurement-reference.md)部分取代本篇缺失性能留空/断线的展示决定：Uptime固定72小时，缺失首字/完成延迟和缓存率可沿用最近有效小时并标明来源；性能/用量图仍可选24/72小时，原始统计与样本数不变。

[低样本测试补充](../bug-fix/2026-10-31-uptime-low-sample-probes.md)扩展模型广场与详情的Uptime：同组/模型/小时有效调用不足30次可由测试补充，并按补充后的结果着色；真实请求口径和其他请求视图的低样本规则继续保留。

[分组价与官方价对比](2026-10-30-model-group-official-discount.md)将分组列表前移到官方参考价之后，逐项展示所选官方档位与分组价的差额；完整动态规则仍在快速开始之后，顶层官方表和实际计费不变。

[模型头卡与官方参考价](2026-10-30-model-official-pricing.md)扩展顶部展示，介绍继续复用 description；独立官方参考价置于本站价格之前，本站计费与分组明细保持原口径。

[模型能力自动同步](2026-10-27-model-capability-sync.md)部分扩展本篇的同步边界：上下文和模态允许补空及更新自动拥有的值，人工配置继续优先。

[模型发现与接入路径](2026-10-26-model-discovery-experience.md)更新搜索与筛选布局、缺失状态、快速开始入口和首页手动公告规则；本文其余数据及权限契约继续有效。

复用模型管理的 description，新增可选 display_name、context_length、input_modalities、output_modalities，模型ID继续作为路由和请求标识。空值表示未配置，供应商同步不得覆盖本地新增展示字段。卡片和详情的上下文长度共用 K/M 简写，百万级保留最多一位小数、千级取整数，并向下取值避免夸大容量（1,050,000 → 1M）；悬停显示精确 tokens，存储和同步值不变。详情将输入/输出模态并列放在模型介绍与价格摘要后、分组价格前，上下文长度放入顶部模型元信息；使用对应图标与文字，导航顺序与正文一致。

沿用登录后的分组健康权限，默认24小时，可选择72小时；扩展已有小时聚合记录成功请求实际Token和流式输出速度，不查询原始日志，不推断历史缺失数据。用量为平台授权分组的采集统计，不是个人账单；成功率为请求成功率，不是按运行时长计算的可用率。卡片仅在普通或阶梯式 Token 计费时显示上下文、首字均值与输出速度；按次、视频按秒/表达式及按小时卡片隐藏整个指标块（含登录、加载与失败占位），按已有计价结果和视频表达式标记判断，不按模型名称猜测。卡片汇总通过有界批量查询取得，详情最多对比4个分组。分组价格复用现有计价函数，Uptime按钮展开已有健康时间条。

性能图表继续复用小时聚合与原生 SVG，采用三列/两列/单列响应式卡片、淡网格、细线和底部分组汇总，支持独立放大与统计明细。首字均值、平均完成时间在展示层统一从 ms 换算为秒并保留两位小数，坐标、悬浮提示、明细和汇总共用格式化函数，API 字段及统计精度不变。汇总直接使用服务端加权聚合，不平均小时均值；缺失小时断线、低样本成功率保留灰色标记，真实零值不当作缺失。成功率坐标根据数据收窄并明确标注下界，不改变请求成功率口径。

用量图沿用同一小时数据和分组筛选，Tokens/请求次数改为直接切换。坐标与分组汇总统一为 K/M/B/T 简写（超出千 T 使用科学计数），避免不同语言的 compact 规则产生长数字；悬浮提示、汇总悬停与统计明细保留完整计数。纵轴按标签长度留白，请求/Token 坐标使用整数刻度；分组汇总桌面横排、窄屏换行，明细只在表格内部滚动。点击采样点固定显示提示，避免 mouseenter 后 click 将提示立即收起。

快速开始的声明协议选择由[协议下拉与模板](2026-10-26-model-protocol-examples.md)部分扩展，支持显式查看未声明的文本模板并提示确认。结构化请求生成Python、TypeScript、Go、Java、C#、Ruby和cURL示例；不执行请求。整张卡片导航保留标题原生链接，复制、选择和拖选文本独立处理。

- [低样本健康颜色](../../implemented/bug-fix/2026-10-22-group-health-limited-gray.md)：沿用小于30次灰色，不把稀疏样本画成稳定绿。
- [健康筛选](../../implemented/bug-fix/2026-10-17-group-health-filters.md)：保留分组和模型权限，不通过聚合暴露不可访问组。

## Alternatives considered

- 复用旧性能接口可直接展示吞吐，但其首包延迟与首个有效输出口径不同、权限过滤不足，不混入新健康视图。
- 以个人 quota_data 绘制用量可复用小时桶，但没有分组维度；修改账单统计范围会导致比较不一致，因此使用同一分组健康采集范围并明确标注。
- 复制参考站的30天图和性能数据视觉完整，但没有本站证据；使用已有7天保留内的24/72小时，新增指标从部署后真实采集开始。

- 引入新的图表库可以复用交互，但现有 SVG 已覆盖最多4组的轻量场景；通过统一单位、按小时断线和响应式放大扩展即可，不新增依赖。平滑曲线可能掩盖小时突变或越过真实极值，因此保留细折线。

- 仅裁切溢出或省略号能保持固定宽度，但会隐藏数值；仅依赖浏览器 compact 在部分语言仍会输出长数字。采用有界单位简写，同时在提示与明细提供完整值。

## Consequences

管理员可通过已有模型管理维护卡片介绍和能力元数据；价格继续来自原计价函数，卡片性能和详情图表共用健康统计。每页最多批量请求100个模型，详情最多4条分组曲线，避免大量分组挤满界面。

新增采集字段旧数据为空且不能回填。多副本升级期间指标样本可能少于请求样本；模型详情按用户要求隐藏属性底部标签、平台统计范围/更新周期、指标定义、用量口径文字、历史缺失说明和逐组有效样本尾注，采集口径、缺失值和图表计算保持不变。吞吐仅统计已观测真实 usage、首个有效输出到适配器完成的流式输出时段；不含数据库结算耗时。模型权限同时检查原始和规范化名称，防止别名绕过当前账户的模型限制。生产部署不在本任务范围。

模型属性的最新布局与来源契约见[模型属性与厂商优先同步](2026-10-30-model-attributes-official-sources.md)：官方参考价之后、分组价格之前独立五栏，最大输出和能力同源配置。

模型专属问答通过[模型 FAQ](2026-10-30-model-faq.md)扩展同一元数据链路，人工维护，不参与自动属性同步。
