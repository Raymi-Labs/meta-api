# Agent Note: 路由方案独立售价与健康选路

Status: implemented

## Problem

[逐次尝试遥测与影子决策](2026-11-06-route-attempt-telemetry-shadow.md)只观测不调度。[托管路由提案](../../proposed/architecture/2026-11-05-managed-token-routing-and-pricing.md)的下一步要求：能按健康真正选路；企业客户换线路时单价不变；管理员能看数据、维护采购成本并管理方案。原有计费按实际落到的分组收费，自动换组会改变客户价格，因此不能直接把跨组健康/成本选路放给普通令牌。

## Decision

两个开关都默认关闭，管理员（超级管理员可改）在「智能路由」页确认影子数据后再开启：

- **健康选路（`route_routing_setting.health_routing_enabled`）**：普通令牌只在当前请求可用的分组内跳过 `unhealthy` 渠道（在 `buildChannelSelectionFilters` 加过滤），不换组、不改价。只有当渠道所在的每个路由组都还有非 unhealthy 候选时才跳过，所以不会把可服务的组清空；`unknown` 从不跳过。会话亲和遇到 unhealthy 渠道时释放给正常选择。
- **路由方案（`route_plans` 表，令牌 `route_plan_id`）**：方案定义有序线路分组、授权（用户 ID / 用户组，空授权谁都不能用）、默认售价倍率和按模型倍率，每次编辑版本加一。令牌绑定方案后：
  - 鉴权时每个请求重新校验方案启用与授权，失败直接 403，不回退到手动分组计费；通过后把 `types.RoutePlanSnapshot` 锁在上下文，重试和换组全程使用同一快照。方案授权即是方案分组池的访问权限，不再与用户可用分组求交集。
  - 计费：`HandleGroupRatio`、`service/quota.go` 用方案倍率替代分组倍率、用户组专属倍率；时段倍率不适用（`RelayInfo.PricingTimeRatio`）。异步任务把方案 ID/版本写入 `TaskBillingContext`，后续按量重算沿用提交时的方案倍率。消费日志记录方案 ID、版本、名称；实际分组仍照常记录。
  - 选路：`route_routing_setting.plan_routing_enabled` 开启时，`preferredGroupCandidates` 在全部方案分组、全部优先级的已授权候选中用 `routeinsight.Tier` 排序：先健康，健康分相差 0.02 内视为等价，等价且都有采购价时取最低价；返回同组、同状态的等价集合，再交给原有权重/容量准入/亲和。关闭时方案令牌沿用方案分组顺序回退，价格仍是方案价。
  - 半开恢复：`probe_percent`（默认 2，上限 20）按每次尝试抽签，中签时把一个 unknown 或 unhealthy 渠道单独交给调度，避免故障恢复后的线路永远没有新数据。
- **管理与客户界面**：管理员侧栏新增「智能路由」（`/console/smart-routing`）：线路观测（开关、影子对照、渠道逐次尝试、分歧样本）与路由方案 CRUD（有令牌引用时禁止删除）。渠道编辑新增采购成本倍率与故障域。令牌编辑在有授权方案时出现「路由方式」，列表显示方案名与默认倍率；客户只看到方案名称、说明和价格，看不到线路池、采购价或其他客户授权。`GET /api/route_plan/self` 只返回当前用户被授权的方案。
- 旧客户端更新令牌省略 `route_plan_id` 时保留原绑定；可售令牌不能绑定方案。方案缓存 30 秒，本实例编辑立即失效。

## Alternatives considered

- 让普通令牌也跨组按健康/成本切换：可用性收益最大，但会按实际组改变客户价格，违反已有自动切组的计费契约；跨组只对锁定方案价的令牌开放。
- 把方案做成一个固定倍率的专用分组：无需新表，可以马上试点；但无法表达授权、按模型价格和版本，也不能跨多个已有渠道池选路。
- 健康选路直接过滤所有 unhealthy 渠道：实现最简单，但只剩故障渠道时会让本可返回的请求变成“无可用渠道”；改为仅在有替代时跳过。
- 方案请求同时保留时段倍率：能复用现有时段运营，但时段规则按实际分组匹配，换组会改价；首期方案价不叠加时段倍率。
- 不做探测：最保守，但 unhealthy 线路在 15 分钟窗口内无新证据后会长期停留在 unknown，健康线路永远被优先，恢复的线路得不到流量；保留可配置、可设为 0 的小比例探测。

## Consequences

收益：管理员可在同一页面看到证据、开关路由；企业方案客户的单价与线路选择解耦，换到更贵线路不加价；普通令牌可在不改价的前提下避开故障线路。

代价与限制：影子决策与两种选路都只读内存渠道缓存，未启用 Redis 且未设 `MEMORY_CACHE_ENABLED=true` 时不生效（观测页会提示）。方案按倍率表达售价，不是每计费项的独立价表；模型广场/价格页仍显示分组价，不显示方案价。未实现逐次尝试的采购成本账本、全请求总时限与最大尝试预算、外部 SLA、合成探测和多实例共享半开配额（探测按实例随机）。等价集合在容量满载时会排队而不会自动降到下一档，重试排除失败渠道后才重新排序。健康阈值未用真实流量校准。方案表与新列只在 SQLite 验证。
