# Agent Note: 企业定制页与统一顶部导航

Status: implemented

## Problem

公开页和控制台分别维护顶部链接，首页、下载与控制台排在模型入口之前，用户希望按模型广场、模型体验、企业定制、文档、控制台组织入口，通过 Logo 返回首页。已有操练场、通知铃铛和全站语言可复用，但还没有本平台企业介绍页。

## Decision

共用顶部链接规则，保留模型广场模块开关及登录要求，模型体验复用原页面并使用与 `/console` 同级的 `/playground`，保留全局顶栏但不显示控制台侧栏。顶栏、页脚及直接访问共用该目标并保留登录回跳；旧 `/console/playground` 使用 replace 跳转并保留查询参数和锚点。侧栏、管理员和个人侧栏设置移除体验入口，已有存储中的 playground 可见性键不迁移，也不能恢复该入口或制造空聊天分区。后端 `/pg/chat/completions`、分组权限、账户隔离和计费不变。企业页 `/enterprise` 与 `/enterprise/` 使用公开壳和既有主题、语言、通知及页脚，自定义首页不覆盖企业子页；下载继续保留页脚和首页入口，并以共用 `HeaderDownloadLink` 在顶栏操作区提供常驻、蓝色描边的下载入口。主站直接进入公开 `/download`，独立文档使用主站地址并带上当前语言；窄屏压缩为有名称的下载图标，不进入隐藏或横向滚动的导航菜单。小屏 Logo 保留返回首页能力。控制台顶部菜单在有余量时靠右，与公开页保持一致；内层自动左边距配合外层滚动窗，溢出时保留正常起点，不用可能造成负向溢出的右对齐。Logo 和操作按钮不被菜单挤压。首页与 HeaderBar 共用 `site-header` 导航外观，使认证页和控制台的字重、字号、按钮及宽屏边距与首页一致；保留两套壳原有菜单交互，避免为了样式复用引入首页移动菜单隐藏规则。

企业页参照用户给出的布局，以元衡品牌和已有能力编写正文：三协议代码切换、模型生态、配置管理对比、令牌控制、用量记录、备用线路演示和合作咨询。演示不执行模型请求，不宣称参考网站的规模、可用率、自动降权或团队组织权限。所有联系销售入口使用用户明确提供的 `nanashiwang@gmail.com` 邮件草稿，不搭建没有收件后端的提交表单。页面正文与导航补齐 17 语言；代码、地址及产品标识保持准确。

## Alternatives considered

- 仅移除侧栏链接并继续使用 `/console/playground`：改动最少，但页面仍带控制台侧栏，与同级独立入口的要求不符；迁移到根路径并保留旧链接兼容。

- 直接跳转参考站企业页：可以立即展示完整内容，但会把咨询和模型示例引向其他服务，采用本站独立页面。
- 只增加公开页链接：改动较少，但进入控制台后顺序会变化，统一两套导航规则。
- 新建销售表单和后台：能够收集结构化线索，但目前用户提供的是邮箱；用邮件入口即可完成联系，不增加存储个人资料的系统。

- 只把下载加回普通导航列表：手机首页菜单默认隐藏，控制台窄屏菜单需要横向滚动，不利于发现；采用常驻操作区按钮，复用已有下载页与17语言文案。

## Consequences

企业方案须以实际沟通为准，不能因展示能力卡承诺未落地 SLA 或规模。长译文使用自动换行和局部代码滚动；不同协议支持依赖模型和渠道，示例保留占位模型与密钥。

发布与生产部署分开：按既有流程发布 Linux 附件和双架构镜像，生产升级不属于本轮操作。

独立文档域名复用本决定的内容或入口，跨域与发布边界见[独立文档站](2026-10-25-docs-subdomain.md)。

模型体验页内部布局与聊天交互见[模型体验三栏工作区](2026-10-30-playground-workspace.md)，本笔记继续约束根路径与统一导航。
