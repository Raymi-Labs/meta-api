# Agent Note: 令牌级 Claude 官方备选模型

Status: implemented

## Problem

上游可用 HTTP 200 和正常 SSE 结束帧报告 refusal。渠道故障重试已经结束，文件生成客户端此时可能没有可用内容。一次接续会改变模型与费用，每个令牌需要独立选择。

## Decision

普通令牌在高级设置选择是否允许 Anthropic 把 Opus 5.5 的请求交给 Opus 4.8。默认关闭。适配器在最终出站请求上核对首选型号，再核对备选型号的角色、令牌模型限制、当前分组、同一渠道与模型映射。费用快照复用当前付款身份及各模型的计价规则；备选预留不足时继续按首选模型发送。渠道只接收一次生成请求，原生 Messages 和 Chat 转 Messages 共用这个入口。

供应商可在首个输出之前、流式输出中途或服务端工具完成之后接续。流内已有的事件按顺序交付，终态以收到的消息结束帧为准。上游的每次尝试用量优先于顶层最终用量；后者只代表最后一个模型。已知拒答类别及是否产生输出共同决定该次用量是否计费。使用日志展示逐项金额，钱包与令牌完成一次结算。上游实际返回的消息 ID 和已知拒答类别进入管理员诊断。

## Alternatives considered

- 跨渠道重放便于复用同模型故障重试，但已交付的流片段和已执行的工具难以安全重放。
- 全局为上游启用备选可以减少调用方配置，但会改变未选择回退的令牌成本与模型权限。
- 仅处理零输出拒答能限定接续时机，供应商服务端协议还可处理中途拒答。令牌维护者选择允许官方流内接续。

## Consequences

支持协议的上游负责判定是否切换。备选也可能拒答，后续会话可能直接命中备选；日志按实际上报的尝试数记录。缺少可靠用量时标记不完整，只对可核实的部分计价。开启回退不会修复超时、无效工具选择等独立问题。

## Verification

控制器测试通过本地上游响应、SQLite 钱包和令牌余额验证流式、完整响应、主备均拒答、按模型分价和单次结算。Chrome 实际操作覆盖创建时关闭、打开保存、重新编辑及关闭。旧令牌迁移在 SQLite、MySQL 8 与 PostgreSQL 16 重复执行两次，并核对旧 Redis 哈希默认关闭。使用官方协议样例，未重放生产请求。
