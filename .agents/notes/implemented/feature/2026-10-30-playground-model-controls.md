# Agent Note: 模型体验的信息卡与能力控制

Status: implemented

## Problem

三栏体验的左栏只有模型 ID，缺少目录已有的上下文、输出限制、价格及能力信息；思考和工具调用必须进入真实请求，不能只有视觉开关。

## Decision

复用 `/api/pricing` 的模型、厂商、能力、分组及时间倍率，保留 `/api/user/models?group=` 为可调用模型的唯一权限来源。左栏采用整栏滚动的模型信息卡、能力卡与参数卡。价格统一美元每百万 token，明确分组；自动分组、缺失数据和动态计费不假定固定价格。

思考使用可选 `reasoning_effort` 覆盖，默认不发送，关闭选项注明需要模型/渠道支持，不修改各渠道适配策略。工具使用 OpenAI 函数定义与调用策略；流式按 index 合并 tool_calls，非流式保留调用及工具轮推理内容，人工输入所有结果后以 tool_call_id 继续，不自动执行模型生成的代码或网络请求。未回答的调用阻止普通用户续发；工具回合保留复制及失败/中止重试，不允许单条编辑/删除破坏协议；待回填结果时锁定模型和参数，清空对话仍可用。停止或异常的未完成调用不进入下一次请求。

## Related decisions

- 部分重叠：[三栏工作区](../../implemented/feature/2026-10-30-playground-workspace.md)，延伸信息及请求能力，保留共享会话、账户隔离、代码预览和旧路由规则。
- 复用：[模型属性](../../implemented/feature/2026-10-30-model-attributes-official-sources.md)，不重建元数据来源，不推测未知能力。
- 相邻但不变：渠道 reasoning profiles 负责渠道专用适配；本轮不统一各供应商的关闭思考语义。

## Alternatives considered

- 硬编码参考截图的信息：视觉可快速复现，但无法跟随模型、分组及站点计费，采用本站数据。
- 只增加 tools 请求编辑：实现较小，但空文本工具响应不可见、后续会话失效，必须支持调用展示和人工回填结果。
- 自动执行工具：体验更省步骤，但当前项目没有浏览器工具运行沙箱及执行授权边界，本轮只手动提供结果。

## Testing

- 本地生产构建配模拟 API：模型/分组切换刷新卡片和请求，VIP 倍率 0.8 的输入/输出/缓存价与目录一致；目录失败显示未知并可重试，权限不被目录扩展。
- 参数和代码一致；已知不支持能力的模型不携带该能力参数；自定义 JSON 保持独立。
- 浏览器验证流式/非流式工具、两工具结果续发、草稿结果同步代码、停止半截参数与重新发起；10 条工作区测试覆盖分片交错、无效定义/重复工具、已知不支持能力、未完成调用、零值/图片与三种代码的实际本地执行。账户隔离与 SSE 既有回归通过。
- 桌面、390px 手机参数抽屉及暗色检查通过，手机 document.scrollWidth 等于 viewport 390；17 种语言、完整前端和文档构建通过，提交前执行目标 lint 和 verify-notes。

## Consequences

模型和渠道支持的推理档位各异，页面只表达传入请求及目录声明，不承诺所有档位可用；本地模拟验证不替代真实上游验收。
