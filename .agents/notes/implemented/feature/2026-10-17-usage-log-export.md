# Agent Note: 按当前筛选导出使用日志

Status: implemented

## Problem

现有日志页支持厂商、渠道集合、用户、分组及请求 ID 筛选，但缺少文件导出。上游 633b4c5b1 使用不同前端且附带日志查询范围策略，不宜整段迁移。

## Decision

在既有日志页增加 CSV 导出，复用列表筛选和用户脱敏函数。管理员与普通用户使用独立鉴权接口；普通用户强制当前账户。导出限定明确起止时间、最多 31 天及 10000 行，超过时明确失败而非静默截断。按 ID 游标读取并在临时文件完成后交付，避免请求中途失败被当成完整文件；相同用户单次导出互斥，数据库查询跟随取消。

## Existing notes

[渠道用量](2026-09-29-channel-usage-in-management.md)及 [日志筛选说明](../../../../docs/LOG_GROUP_CHANNEL_FILTERS.md)约束跳转筛选和时间边界，本次沿用日志列表的闭区间筛选。普通用户脱敏继续由 `model/log.go` 的 `formatUserLogs` 提供。不引入上游对历史查询和看板的额外限制。

## Alternatives considered

导出浏览器当前页容易遗漏数据；无界全量导出会消耗日志库和内存。采用有界服务端导出，页面明确范围并沿用筛选。

## Verification

控制器测试覆盖 250 条分批、501 条游标及期间插入、10001 条拒绝、时间与输入校验、用户脱敏、CSV 公式转义、取消。内存/Redis 互斥与过期旧锁释放通过；定向 race 通过。真实页面以普通账号从 10 条当前页导出 26 条记录，文件内容与筛选一致、无另一用户记录或管理员字段；普通账号管理员导出被拒绝。管理员按用户名与请求 ID 联合筛选导出，确认文件仅包含一条匹配记录及对应用户 ID。模拟超限响应只显示一次具体错误，不下载部分文件。

## Consequences

大范围需分次导出；CSV 数值额度保留原始 quota 单位并标明，避免汇率和历史价格歧义。
