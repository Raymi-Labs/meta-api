# Agent Note: 多模型体验的选择与上下文展示

Status: implemented

## Problem

多模型模式同时保留单模型标签和多选框，左栏资料仍指向单模型，当前模式按钮展示切换目标而非状态。用户难以判断调用对象、参数归属和下一轮上下文；逐条大卡片使同轮比较需要过多滚动。

## Decision

模式改为明确的单模型/多模型选择，多模型时隐藏单模型标签。多选是唯一调用名单；独立资料查看对象仅驱动左栏资料和单模型代码预览，不改变请求名单，不自动发送。当前分组可调用模型与文本资格仍为唯一候选来源，换组裁剪选择，账号切换重建状态。

左栏多模型列表用于查看各自资料，完整价格和能力按需展开；共用思考/流式/参数明确标注作用范围，按每个模型已有能力判定构建请求。单模型保留原工具与图片流程，多模型仅允许关闭已开启的工具/图片，不新增并发工具支持。

同轮问题紧凑展示，模型回答按轮分组，桌面默认双列、可切列表，手机纵向；生成/成功/失败/停止状态与本轮完成数从真实消息状态派生。最新一轮下方展示选答提示或“下一轮使用模型X的回答”，历史选择标记保留。布局和资料切换不触发新请求；仅发送、明确重试产生调用。

## Existing notes audit

[并发文本](../../implemented/feature/2026-10-31-playground-parallel-text.md)保留5模型上限、独立请求、计费、停止/重试、相同历史和选答契约；本篇只扩展其信息结构。[工作区](../../implemented/feature/2026-10-30-playground-workspace.md)、[能力](../../implemented/feature/2026-10-30-playground-model-controls.md)、[SDK导出](../../implemented/feature/2026-10-31-playground-sdk-export.md)保留公共接口与账户隔离，无后端改动。

## Alternatives considered

- 仅缩小现有卡片能节省空间，但仍保留两套模型选择和资料归属歧义。
- 每个模型独立参数面板更灵活，但扩大状态与预览契约；本轮沿用共用设置并明确能力例外。
- 五列并排方便瞬时比较，但三栏工作区中文本列过窄；采用双列/列表切换和手机单列。

## Testing

- Chromium合成接口复跑既有5模型并发、单条失败重试、停止/迟到回调、非流式、账户隔离、刷新与撤销流程；额外验证多模型时无单模型标签、资料查看及模式切换不发请求且选择不丢失、列表/双列只改布局、选答提示与历史标记一致。
- 分组切换到只允许一个模型后，调用名单与资料对象同步裁剪，发送禁用，无额外请求。恢复带并发历史的自定义配置时回到原单请求编辑器，避免无法退出的混合模式。
- 实际页面1440px双列和390px纵向布局、已选上下文、深色界面截图核对；浏览器无脚本错误，未执行收费模型调用。
- 相关38项工作区/并发/协议/17语言资源回归、原Node SSE与账户隔离、ESLint/Prettier和主站Vite构建通过；保留既有Browserslist、第三方eval与大包警告。没有运行完整SDK执行矩阵或生产验收。

## Consequences

资料与公共参数必须明显分区，不能暗示左栏价格是整轮总价。并发请求成本不可由静态价格冒充实扣。本轮无生产调用或部署；用户授权后在公司main 4cae3c532的独立工作区复跑38项回归、浏览器、源码检查、主站构建与笔记校验，测试进程已回收。

完整资料增加一次展开，但把聊天与本轮比较放在首位；模型资料与代码预览共用独立查看对象，查看不选择上下文。历史回复的分组仍保留原发送时值。回答仅按真实消息状态显示生成/完成/失败/停止，不虚构耗时和费用；已结束数量包含失败与停止，不等同成功数。选择仍只在当前账户页面内存保留，刷新不自动重发。
