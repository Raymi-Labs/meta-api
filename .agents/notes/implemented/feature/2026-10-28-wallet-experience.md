# Agent Note: 钱包余额、充值与转赠入口的层级

Status: implemented

## Problem

余额在充值页签内部，有套餐时自动切到套餐导致余额不常驻；邀请和兑换入口与主充值流程争夺空间。用户需区分钱包余额、可转赠额度、订单实付和套餐权益，不能用外观简化掩盖规则。

## Decision

顶部常驻余额、可创建兑换码额度、刷新与创建入口，充值为默认页签，保留套餐和待发放。充值与辅助功能分层，付款记录以本人 self 接口的最近5条摘要展示，完整账单/发票/管理员对账继续复用已有弹窗。保留后台报价及创建兑换码原子扣款、同 request_id 重试契约；增加前端同步防重与身份边界。

余额刷新和最近记录独立失败状态，未知不显示零。确认支付固定当前报价对应的金额/方式，输入变化使旧确认失效；不新增支付服务或自动扣款。未知兑换请求保留原标识与额度，不允许误改额度重发。

充值配置信息的独立加载、失败重试及兑换码优先于邀请的辅助区顺序，见[界面恢复补充](2026-10-28-ordinary-user-ui-hierarchy.md)；不改变本篇支付确认与兑换码重试边界。

## Existing capability review

- 钱包 → user/self、topup/info、amount/pay 与订阅接口 → controller/topup.go / model/topup.go；用户上下文提供 quota/transferable_quota，金额复用现有 currency/quota helpers。
- 创建兑换码 → controller/redemption.go → model/redemption.go 的事务、余额与可转赠额度校验、request_id 幂等；重试不能换标识。
- 支付摘要 → payment-records/self → model/payment_record.go；所有角色首页仅看本人，支付记录管理弹窗保持管理员范围。
- [旧钱包布局](../../implemented/feature/2026-10-21-pricing-wallet-layout.md)部分重叠：接管钱包双栏与入口层级，保留到账实付及可转赠语义；模型广场无关。
- [稳定币支付](../../implemented/feature/2026-10-09-epay-usdt-trc20.md)部分重叠：保留网络与CNY订单金额语义，不能虚构链上币额。
- 发票、推广、提现及套餐现有组件保持；不是重新实现账单系统。

## Alternatives considered

- 直接复制参考站自动充值涉及新的扣款授权和后台，不属于当前UI范围。
- 重做完整账单页面会扩散到风控和发票审批；首页摘要复用原接口，完整管理继续使用现有能力。
- 只移入口不检查异步金额与重复操作，会放大资金操作风险。

## Verification

真实页面使用合成 API 验证余额100/可转赠30独立展示、默认充值及套餐价格、失败隐藏旧余额与创建入口、本人交易失败重试；管理员首页仍请求 self 最近5条，原账单保留支付/发票/提现/对账/异常单管理。币种、未知支付金额、钱包购买额度展示复用完整账单的 helper，不把稳定币支付订单CNY金额当作币额。

创建30额度的兑换码模拟服务端扣款但返回503，关闭并刷新后余额70/可转赠0，再打开重试仍使用同一 request_id 和15000000 quota，返回原兑换码不再次扣款；创建输入在请求与不确定状态锁定，已提交额度不被InputNumber新的余额上限夹断。兑换他人合成码后余额100→110，可转赠仍30，两字段来自重新读取服务端。

支付双击确认只发出一个订单；旧报价挂起、切到100额度Stripe新报价后释放旧响应，确认仍显示100额度/US$20；报价失败显示未知且不打开确认。手机390px与深色页面/兑换弹窗无页面横向溢出。真实资金、支付服务、提现审核及发票发送均未操作。

自动回归覆盖创建/支付实际处理函数的重复点击、未知重试、余额缩小、取消与账户离开；复用既有支付跳转测试（Stripe、Waffo、Creem与网关桌面/手机）、货币测试、语言资源测试；最终29项 Node 回归与4项 Bun 货币测试通过；支付跳转回归通过桌面/手机10条网关路径及无效响应、危险地址清理。修改源码 ESLint/Prettier、主站 Vite 构建、笔记门禁与 diff check 通过；既有大包、Browserslist 与第三方 eval 提示保留。预览标签、5198服务及测试浏览器均已清理，本轮遗留测试进程为零。

提交前同步公司 main 710f71b40 的模型发布日期排序与同步更新，无代码冲突；33项钱包/语言/模型排序回归、笔记门禁及主站构建再次通过，保留双方翻译与功能地图。

## Consequences

前端防重不能代替后端幂等。离开页面无法撤销已发送写入；支付跳转不能证明到账。首页记录不是完整消费流水，钱包购买显示额度而不是伪装法币。

支付确认取消会使旧响应失效，但不能撤销已创建的服务端订单。创建兑换码未知请求只在当前身份页面内存保留原标识，整页刷新后的历史恢复能力仍依赖原有本人兑换码列表，不宣称实现跨刷新请求持久化。
