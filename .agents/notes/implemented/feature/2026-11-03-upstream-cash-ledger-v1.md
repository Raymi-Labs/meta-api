# Agent Note: 上游现金收益首阶段账本与工作台

Status: implemented

## Problem

用户已要求根据收益设计稿落地。现有 OpenRouter 页面仅有 credits/activity；钱包已有 Pulse 付款额度凭证，但它证明的是付费额度资格，不包含净到账金额、手续费、汇率或完整资金批次，不能直接当作现金收益。

## Decision

复用账户、管理员权限、钱包事务锁与官方只读接口，新增持久的财务旁路账本和真实工作台。现金收益、现金流、待核对均由服务端返回真实数据，不在产品内保留演示数字。首次启用由超级管理员完成；初始余额未知，收益从实际采集起点开始，不宣称回补旧调用。

钱包收入按资金批次 FIFO；同一事务记录付款批次及预扣/结算/返还的批次分配，不改变用户 quota 或 Pulse 资格判定。净到账凭证由超级管理员核实，记录原币、手续费、汇率、到账时间和凭证引用；更正保留修订链。普通未知变动、套餐、异步结算及不能追溯的转赠保持未知；不把 Pulse paid-first 资格规则迁移为收入确认规则。

OpenRouter 按实际推理密钥指纹归属，服务端核对 Management Key 下的 keys，浏览器不接触渠道密钥。账户总用量与选中密钥用量均持久同步，独立记录完整日覆盖和失败状态。上游现金成本采用 UTC 日移动加权平均：期初剩余 credits 的现金基础加当日实际购款成本，扣除全部账户消耗后将对应成本分配给本站密钥；站外用量同样消耗成本池，不能让本站使用重复的廉价额度。该口径是明确的成本分摊政策，不能称为逐请求实测采购价。

对账必须检查原始成本范围、资金来源、首次采集时间、日账完整性、共享密钥、BYOK 外部账单、未关联的结算记录；不完整则利润为未知，并保留已知部分。全站客户现金到账与单一上游付款分别标注范围，不相减形成伪账户净现金流。资金录入、映射、启用和更正仅超级管理员；管理员可查看、同步。

财务迁移只新增独立表；多数据库使用 ORM、定点整数和带锁的事务。钱款计算用整数/decimal，保留明细和修订，幂等键绑定载荷，重放不得新增金额。锁定 user 后操作钱包账本；锁定 account 后操作购款及同步，避免跨领域锁反序。已有账本的账户删除/类型更换受保护，管理凭据轮换须验证全部已绑定调用密钥仍归属同一账户。调用和官方请求数量必须一致；精确渠道成本不补估值。账户直接费用、BYOK 账单和退款差额尚未分配到具体模型时，账户利润与已知模型成本保留，但不核实模型的完整成本与利润，避免不同粒度冒充相同口径。购款退款从池内退出对应加权现金基础，和实际净退款的差额记作当日费用/回收，避免退清 credits 后遗失手续费。

只有启用后才写钱包财务账本，新增审计写入失败须让同事务的额度变化回滚，不能产生已扣费却缺资金来源的“已核实”记录；消费元数据写入失败需要明确留下未关联结算缺口。

## Alternatives considered

- 仅把设计图转为 UI：上线快，但没有净到账和购款凭证会产生空壳或虚假利润，必须同步交付可补录、可核对的数据链路。
- 扫描 logs 重建资金：能快速补部分历史，但日志会清理且缺少资金来源；主库持久记录新事件，历史保持未知。
- 用 Pulse paid_quota 乘当期收款比率：可以复用计数，但付费资格不是现金基础，旧余额、优惠和转赠无法正确计价。
- 逐请求 FIFO 上游成本：需要完整的上游请求时间和充值顺序，官方只给完整 UTC 日活动；先采用显式的按日加权平均政策，保持真实现金总成本守恒。

`go test ./model ./service ./controller ./router` 通过。新增现金测试覆盖 FIFO、部分退还、全额退款、并发、幂等载荷、事务回滚、凭证版本、已知/未知资金、日加权成本、站外用量、BYOK、退清 credits 的退款手续费、日志关闭、同步重放/失败/空日以及管理员写权限边界。

SQLite 用例通过；隔离 MySQL 8.0.46 导入生产相关表的空 schema（不含业务数据），使用相同 utf8mb4 / utf8mb4_unicode_ci，再执行重复迁移、收款及并发结算；PostgreSQL 15 重复迁移和并发结算通过。可用 `META_CASH_TEST_MYSQL_DSN` / `META_CASH_TEST_POSTGRES_DSN` 运行 `TestCashDatabaseCompatibility`，仅接受本机 cash_test 数据库。

真实 React 组件的浏览器用例使用合成 API 数据，覆盖启用、账单/到账录入、审计、作废、绑定、分页/筛选/CSV、失败清空、账户切换竞态、管理员只读和 390px 手机布局；截图人工检查发现并修复空 Tabs 占高、取消请求误报及手机图表字号问题。前端 17 语言检查和生产构建通过；正式 Release 产物另行核实。

## Consequences

不能从欠缺历史凭据推导真实净到账；首次启用当日不完整。元数据与支付事务仍有时间差，未关联结算阻止核实。订阅、异步、旧数据、转赠等暂不自动证明现金来源，必须在页面和发布说明明确。同生产引擎和空 schema 的迁移演练已通过；发布不等于部署。当前报告按最新凭证和官方日账重算，尚无封账或官方日账版本回溯；客户付款风险仍须人工核对，不能把权益回收认定为现金退款。回退旧程序期间的采集缺口不会自动变成已核实。使用流程见 [现金收益核对](../../../../docs/openrouter-cash-accounting.md)。
