# Agent Note: 企业开通与定制联系申请

Status: implemented

## Problem

公开企业服务两个联系入口仅打开邮件，用户无法在站内留联系方式，平台也没有统一审核队列。

## Decision

登录用户提交两类申请：开通仅企业名称、联系方式类型与账号；定制仅联系方式。复用企业开关、登录权限和平台管理员权限，新增持久申请表及分页状态筛选。开通审核由管理员选择既有计费分组，在同一事务内创建企业、所有者与审计并更新申请，初始资金为零；不允许用户指定所有者或价格。定制标记已联系，不创建企业。申请结果和拒绝理由对本人可见，每类只保留一个待处理申请，历史保留。重复审核拒绝，不重复开通。

## Alternatives considered

继续邮件咨询无需新表，但无法支持站内审批自动开通。复用成员额度申请会混淆企业创建前身份与已有企业成员权限，因此单独建联系申请，复用创建企业事务内部函数。直接自助创建企业更短，但跳过管理员计费分组配置与准入审核，不采用。

## Related notes

部分取代[企业公开入口](../../implemented/feature/2026-11-13-enterprise-services-entry.md)保留邮件且不收集申请的决定，保留其导航与角色规则；扩展[企业工作空间](../../implemented/feature/2026-11-11-enterprise-workspace.md)平台开通规则为审批后平台开通。分组维护与企业资金笔记不变；其余检索结果属于渠道或导航，无关。

## Verification

验收范围为两类最小表单、必填与长度、登录回跳、本人查询隔离、管理员列表分页筛选、重复申请、拒绝重提、并发/重复审批、非法分组失败回滚、已入企业不可重复开通。沿用三库兼容的GORM与现有测试矩阵。验证前端构建和企业回归。

## Consequences

联系方式仅本人和平台管理员可见，不执行自动加好友；开通不赠送余额。企业开关关闭时接口仍拒绝。新表随启动迁移，生产部署仍需单独授权与预检。

## Validation results

本地企业相关 model、router、controller、service、middleware 回归通过（SQLite）。三库测试由既有CI执行。语言资源36项和企业导航23项通过，完整前端构建通过；随后指定本机Chrome执行静态预渲染通过，Go主程序构建通过。新增浏览器合成API验收覆盖提交失败重试、分组加载失败保护、审批开通、工作台入口、定制留资与标记已联系，手机弹窗宽度及底部按钮均可见。没有调用生产或真正添加好友。

申请创建使用可空唯一键排除重复待办，不持有用户行锁等待唯一键，避免与审批申请行、分组配置、用户行的锁序形成环。审批沿用分组锁与企业创建事务。

原企业计费分组浏览器回归通过：编辑绑定、免费组、失败保留草稿、刷新及乱序响应保护均通过。测试等待刷新响应、瞬时提示消失并只点击可见按钮，避免手机提示遮挡与隐藏页签同名按钮干扰；申请队列只在选中审核页签时加载。
