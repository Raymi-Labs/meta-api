# Agent Note: 手机令牌筛选与充值信息恢复

Status: implemented

## Problem

手机令牌次级筛选占据首屏，钱包充值配置失败后缺少明确恢复入口。界面精简必须保留已输入的筛选条件，也不能让充值配置错误阻断兑换码和账户信息。与最新主线的钱包支付确认、兑换码幂等重试改动合并时，需要保留既有资金操作边界。

## Decision

复用现有组件与接口，落实手机令牌筛选与充值信息恢复两项。767px及以下保留主搜索，次级筛选可展开且字段持续挂载；折叠按钮显示基本与高级筛选数量，桌面保留全部筛选。充值信息有独立加载与失败状态，骨架结束后失败显示重试，成功恢复支付方式和额度选择；兑换码与账户区域独立可用，邀请卡位于兑换码之后。

查询、统计、导出、计费、权限、路由、支付请求与协议能力不变。验证使用隔离合成 API，不发送真实支付请求。模型详情重排和普通用户日志摘要视图由[后续决策](2026-10-29-model-detail-log-view.md)实现并独立验收；协议展示由独立的[协议笔记](2026-10-28-model-protocol-display.md)管理。

## Existing notes audit

- [令牌管理](2026-10-27-token-management-experience.md)：部分重叠，保留移动卡片、完整列、筛选和复制契约，只改变手机筛选默认展开方式。
- [使用日志](2026-10-28-usage-log-experience.md)、[模型详情](2026-10-25-model-detail-page.md)与[参考布局](2026-10-26-reference-layout-alignment.md)：本轮不改变其行为，保留已有能力；原草案相关想法未落地。
- [控制台概览](../../implemented/feature/2026-10-27-dashboard-overview.md)：现有普通用户视图已经符合目标，不重复改造。
- [模型目录](../../implemented/feature/2026-10-25-model-catalog.md)：四列紧凑目录和表格切换是近期明确决定，不在本提案中翻转。
- 钱包与[钱包优化](2026-10-28-wallet-experience.md)部分重叠，保留其余额、支付确认、幂等重试和最近交易；本篇仅补充配置加载恢复，不另建支付流程。

## Alternatives considered

- 全面照搬 AiHubMix 的两列模型卡片、简表和移动导航能获得表面一致，但会增加本站长列表滚动，丢失价格与排障信息，并让公开页导航失去入口，因此只借鉴主任务层级。
- 再做一套普通用户看板看似能简化页面，但现有 self 统计、四卡和三个快捷入口已经满足目标，重复实现会制造第二套状态与权限分支。
- 直接修改日志默认列并写回存储实现简单，却会永久覆盖用户已有完整列组合；使用独立展示模式和派生列。

## Testing

- Chromium 实际页面在320、700、1440px下验证筛选展开、折叠后值保留、查询发送原条件且页面无横向溢出。700px用于验证JS与CSS使用相同断点。
- 390px钱包合成请求挂起时显示骨架，失败后可重试恢复支付方式；失败期间兑换输入仍启用，无写请求和页面脚本异常。
- 合入最新main后，协议、价格、排序、详情权限、支付确认/导航、兑换码重试及语言资源共68项测试通过；修改源码ESLint通过。
- 36项语言/文档测试、主站Vite构建、五路页面预渲染、笔记门禁和diff检查通过；构建保留既有大包、Browserslist和第三方eval警告。浏览器与本轮预览服务已关闭。

## Consequences

手机主任务更清楚，但访问次级筛选多一次展开；隐藏字段仍参与查询，数量提示不能省略。充值配置失败明确显示未知并可恢复，不把失败误报成支付关闭。客户端恢复不能保证真实网关可用，支付与兑换码测试也不证明生产到账。日志摘要和详情重排由[后续决策](2026-10-29-model-detail-log-view.md)接管，保留偏好、权限和现有协议展示。

## Classic wallet presentation

[经典钱包布局](2026-10-30-wallet-classic-layout.md)恢复蓝色账户统计与深绿色邀请卡、双栏和兑换入口位置，并将最近交易统一收回完整账单；本文支付防重、幂等重试、金额语义及加载失败恢复等适用边界继续保留，其他页面不变。
