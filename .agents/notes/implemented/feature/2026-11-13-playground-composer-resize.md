# Agent Note: 模型体验输入区顶部调高

Status: implemented

## Problem

用户需要在底部输入区编辑长提示词，要求通过顶部拖动调节高度。单模型固定72px，多模型浏览器原生右下角resize操作方向不一致，也没有统一的布局边界。

## Decision

两种输入共用顶部拖拽柄与高度逻辑，只改变textarea高度，工具栏保持在输入区域之外可见。使用Pointer Events与pointer capture，支持鼠标/触屏/取消；键盘上/下调节、Home/End及双击复位。高度最少72px，最多420px且不超过可见窗口45%，进一步按实际聊天容器剩余空间限制，为回答区保留120px。窗口/容器变化重新限制高度，不修改草稿、请求参数或发送流程。不落盘，不跨账户共享偏好；当前组件生命周期内保留高度。

## Alternatives considered

- 原生resize: 底部向下拖动与底部停靠输入区方向不符，手机和键盘支持不统一。
- 自动随文本无限增高: 长提示词挤掉回答和工具栏，不满足用户自主控制。
- 整块对话缩放或宽度拖动: 改变整页布局且无必要，当前需求是编辑空间高度。

## Verification

真实浏览器验证两种模式上拖增高/下拖收缩、上下限、长文内部滚动、草稿保留、工具栏可见、不触发请求、键盘与触屏、pointercancel、会话切换及小窗口。相关单测/语言/构建和笔记校验通过，测试进程清零。

## Consequences

虚拟键盘会缩小可见视口；监听visualViewport并限制高度。隐藏会话的尺寸为零时不覆盖用户选择。仅新增小拖拽柄及读屏名称，不加常驻说明。局部修改，不涉及版本发布或生产部署。

实际验收：22项会话/并发/工作区单测、36项语言测试与生图语言覆盖检查、局部ESLint、Vite主站构建通过。真实Chrome的完整既有流程通过，新增两模式拖拽、键盘、触屏取消、长文本与短视口测试；没有收费调用。初次自动化修正了工具API与移动设备切换自动刷新造成的测试问题。

对抗验收发现多模型顶部存储错误条会使原固定视口高度布局超出窗口，改为外层固定可用高度、内部flex分配，移除工作区固定最小高度，错误条占实际空间；820×600下工具栏可见。桌面与390px手机截图已核对。
