# Agent Note: Images GIF 帧参数与固定规格上线

Status: implemented

## Problem

Images 请求已保留 output_format，但 frame_count/frame_duration_ms 落入 Extra 并在 JSON 序列化时丢失。1652 的旧覆盖无条件强制 PNG。用户要求 URL+Key 直接调用 GIF，不增加权限查询或估价步骤。

## Decision

复用 Images JSON 入口、原始响应转发及现有按次计费；DTO 显式保留两项整数帧参数，不打开未知 Extra 整体合并。线上先通过现有条件覆盖提供固定 512x512/medium/9帧/200ms GIF，其他请求保留原静态规格；本地字段补丁独立验证，不宣称已部署或开放自定义帧参数。

## Alternatives considered

全量请求体透传可避免丢字段，但绕开更多规范化逻辑，范围过大；新增视频任务接口增加用户步骤且不适合同步 GIF，均不采用。只有修改 output_format 会使帧数被静默丢弃，因此不足。

## Related decisions

检索 image/GIF/图片：输入输出分项计费笔记（2026-10-31-image-input-output-pricing）部分相关，但阿里价格引擎不变；未找到已有 GIF 帧参数契约。

## Verification

JSON转换保留帧参数，缺省不注入，非法整数拒绝，未知字段仍不透传；GIF响应字节不改写；渠道覆盖回归静态请求不变、GIF注入固定配置。线上确认实际动图帧数、时长、出站渠道和扣费。

## Consequences

用户随后授权本地字段补丁随v1.23.0合并发布；发布仅保留客户端明确帧参数，不自动更改1652固定覆盖或开放任意帧数。下述生产记录属于2026-11-05的既有验收，本次未重复发付费请求或重新修改生产。

实际尺寸可不同于请求，HTTP200不等于动图；上游型号/成本需按账单确认。自定义帧数需部署字段补丁并另行验收成本。Skill与分享包本轮不改。

本地 dto/relay-common/openai 包全量测试与Go构建通过。Sunburst元衡生产验收9帧/200ms/循环GIF，实际439×390，42.22秒；用户0.5闪电，上游0.04元。线上只热更新1652条件覆盖，未部署本地DTO补丁。后续开放自定义帧数应先部署补丁，再调整固定覆盖和成本边界。

Flare生产验收同样9帧/200ms、1.8秒循环，实际437×387，31.86秒；两款均命中1652、扣0.5闪电，上游各0.04元。参数覆盖已回读8项操作且请求体透传关闭。
