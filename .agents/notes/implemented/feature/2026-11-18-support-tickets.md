# Agent Note: 站内工单与封禁申诉

Status: implemented

## Problem

平台需要在站内追踪用户问题、管理员回复与封禁申诉，客户端反馈是独立的单向报告，不能承载对话。2026-11-18提出的工单实现缺少生产路由、迁移和登录接线；构建通过掩盖了 Semi UI 运行时错误、申诉请求契约错误、Redis同秒限流绕过和附件权限缺口。

## Decision

复用原三张工单表、UserAuth/AdminAuth、NotifyUser及Semi UI，不增加角色或外部系统。普通用户页面 `/console/tickets`、管理页面 `/console/ticket-admin` 与公开 `/appeal` 对应 `/api/ticket`、`/api/admin/ticket`、`/api/appeal`。SetApiRouter统一登记工单路由；两种生产迁移登记三张表，main启动主节点定时任务。

### 身份与数据隔离

密码正确后仍检查二步验证（查询失败关闭放行），验证成功才进入setupLogin；统一复查账号状态。OAuth、微信、Telegram、Passkey在身份验证后对封禁用户签发申诉会话。Passkey必须完成签名验证，不能在凭证查找阶段凭ID签发会话。二步验证只保存一次最终Cookie。

申诉会话15分钟，清空普通登录和pending键，只保存appeal_user_id与过期时间。AppealAuth每次复查用户存在且仍封禁，过期或解封返回401；普通工单接口另复查数据库角色和状态，防止旧Cookie在封禁/降权后继续访问。前端遇到签发标记清本地用户并跳转申诉页，申诉请求自行处理401。申诉只访问本人且category=appeal的工单，不能获得普通控制台权限。

普通创建接口禁止appeal分类，申诉接口独立载荷只要求subject/body并由服务端指定分类。正文最多5000字符，允许换行、回车、制表符，拒绝其余控制字符和空白正文；标题最多100字符且拒绝控制字符。请求ID限定原64字符规则。管理员关联日志同时按request_id和工单所属用户查询，用户响应不返回日志或内部备注。

### 状态、限流与筛选

普通创建每小时3次、回复每小时10次、申诉每日1次；Redis滑动窗口每请求使用UUID成员，内存降级保持原计数。普通未结工单最多5个；申诉只统计本人的未关闭申诉（含resolved），不能被普通工单阻断。创建事务锁定用户行后计数，避免MySQL/PostgreSQL并发超额。

管理员公开回复默认waiting_user，内部备注不改状态或通知用户；用户回复waiting_user/resolved重开为open，closed禁止回复；用户可关闭，管理员可修改状态并重开。指派只改变处理人，不隐式覆盖状态；取消指派使用null。状态变化保留条件更新及事件消息。

管理员筛选在数据库分页和计数前应用：状态、分类、关键词、指派给我、未指派、未读；页面提供状态筛选。申诉列表先按分类过滤再取最多100条。铃铛从真实userState取登录身份，分别请求本人未读和管理员待处理数，提供工单页签入口；全体管理员共用staff_unread，任何管理员查看均清除该标志。

waiting_user与resolved需状态时间和最近消息时间均超过7天才分别自动解决/关闭；执行更新时再次核对两时间，防止扫描后发生新活动仍被关闭。主节点每30分钟扫描，每批200条，条件未匹配不生成事件。

### 附件与前端

附件沿用已实现的工单级附件：用户及申诉用户在创建后打开详情上传，管理员查看下载。单个5MB，每工单10个，PNG/JPEG/GIF/WebP/PDF/TXT；使用内容嗅探而非客户端MIME，存储为随机文件名，清理显示名路径/控制字符并按UTF-8安全截断。在multipart解析前限制整个请求为5MB+64KiB；上传每账号每小时20次，关闭工单拒绝上传。数据库事务锁工单后复查数量；数据库失败删除物理文件。附件不自动绑定回复，也不支持管理员上传内部备注附件；读取既有内部消息附件时仍严格隔离。

所有附件操作复用同一权限判断：管理员可读用户证据，用户只能访问本人公开附件，申诉限本人申诉。下载为attachment，nosniff和private/no-store，用带鉴权头的API取blob后下载。只嗅探内容类型，不解码或在服务端渲染媒体。目录为data/ticket_attachments，按需创建，不因控制器初始化而要求文件系统可写。多实例须共享目录，备份须包含目录。

表单采用Semi getFormApi + ref；折叠日志采用Collapse.Panel；去除不存在的Empty子组件。创建后直接打开详情，request_id预填与?id=通知深链都可用。新增文案覆盖17种语言，状态/分类/发送人标签经t翻译。管理员通知链接进入管理详情；申诉回复通知允许发送给封禁账户，链接指向登录。

## Alternatives considered

- **扩展客户端反馈为工单。** 能复用现有表和后台页面，改动最少；但反馈表的字段（版本、系统、错误摘要、报告ID幂等）是为单向报告设计的，加入对话、指派、状态流转和附件后两种语义会混在一起，客户端已有的幂等约定也要随之改变。选择新建工单表，反馈保持原样。
- **接入外部工单系统或客服邮箱。** 功能成熟，不用自建状态机和附件存储；但需要另一套账号体系，无法直接关联平台用户、请求日志和封禁状态，被封用户的身份也难以验证。用户要求站内处理，所以不采用。
- **新增客服角色。** 权限划分更细，可以让客服只看工单；但需要改动角色常量、鉴权、侧栏权限和用户管理，团队目前也没有独立客服。用户选择所有管理员可见并支持“指派给我”。
- **公开表单加邮箱提交申诉。** 不需要改动登录链路；但任何人都能以他人名义提交，管理员要靠邮件往来核实身份，也容易被刷。选择在完成原有登录验证（含二步验证）后签发只能访问申诉的会话。
- **在普通登录会话上给封禁用户加接口白名单。** 不需要新的会话键；但authHelper和所有依赖会话的中间件都要识别这种“半登录”状态，任何遗漏都会让封禁用户访问到普通接口。选择独立的申诉会话键和中间件，普通鉴权保持不变。
- **附件存数据库BLOB。** 备份和迁移简单，多实例天然共享；但三种数据库的二进制类型和单行上限不同，大字段也会拖慢备份和查询。沿用发票附件存放在`data/`目录的方式；多实例部署需要共享该目录，这是已有发票附件同样存在的前提。


## Verification

- 隔离回归覆盖同秒100请求仅放行10个、多行正文、申诉载荷/普通工单不阻断申诉、解封失效、内部附件和管理员降权边界、上传大小/伪装类型/长后缀、自动关闭竞态。
- 密码错误不签发申诉，启用二步验证的封禁账号必须验证验证码；最终Cookie只有申诉范围且15分钟过期。
- 浏览器测试挂载真实React/Semi组件（API使用确定性fixture），验证用户/管理/申诉表单、回复载荷、关联日志、请求ID预填、通知计数。API fixture不替代服务端权限测试。
- `go test ./router ./controller ./common ./model ./service -count=1`全部通过；`go test -race ./router ./controller ./common -run "Ticket|Appeal" -count=1`通过。通知队列显式排空后才释放测试数据库，替代原sleep等待，移除控制器重复启动goroutine。
- `go build ./...`、`bun run build`（含17语言检查和Chrome真实预渲染5页）、`node web/scripts/ticket.browser.mjs`、`make verify-notes`、发布策略与发布脚本单测及diff检查通过。浏览器fixture快照提交载荷，避免form.reset改变已记录对象而产生误报。

## Consequences

- 本地SQLite覆盖功能和事务，MySQL/PostgreSQL真实引擎并发尚待CI/部署预检；GORM锁语义在SQLite由写锁兜底，冲突返回错误而不承诺自动重试。
- Cookie仍沿用项目会话存储，申诉有效期由服务端时间校验，不放宽普通鉴权。
- 本地附件多实例共享、备份是部署前提；历史20MB附件可继续下载，新上传收紧为5MB。
- 发布应用不等于升级生产，仍走受保护newapi-update入口；本轮不部署生产。
