# Agent Note: 缺失可用率采用匹配端点的24小时参考

Status: implemented

## Problem

用户要求本站没有可用率统计时展示官方已有数据。已有OpenRouter性能服务只读取P50速度，忽略同一官方接口返回的uptime_last_1d。2026-11-17公开GET核实Flint与North两个精确免费模型均提供该百分比及5分钟/30分钟字段。把空样本填0或将厂商整体状态当本站比例均不真实。

## Decision

复用现有鉴权健康摘要、精确模型/分组路由映射、允许/排除/价格限制、服务档位过滤、缓存与请求合并，向display-only performance_reference增加uptime_rate及uptime_window_seconds=86400。只采用明确有限0..100数值，保持零；缺失、非法值不推算，不由status正常生成100。来源时间跟随五分钟缓存，失败/过期不展示。

分组健康接口在只有可用率缺失时也请求参考；模型卡片摘要仍沿用原P50需求，不增加无用请求。分组标题仅在采用外部数据时改为参考可用率并注明24h，说明置于既有信息按钮；保留来源与精确端点在参考字段供诊断，公开视觉文案不暴露内部渠道。本站有效比例包括0始终优先，外部数据不写入小时图、样本数、健康快照或价格；参考没有本站历史下拉。匿名及禁用健康仍遵守现有权限。

[指标参考一致性](2026-11-17-metric-reference-consistency.md)将可用率参考扩展至空图、图例、放大与跨模型对比，同时统一速度参考的五分钟时效；原服务读取与鉴权保持。

## Existing notes audit

部分扩展[OpenRouter性能](../../implemented/feature/2026-11-01-openrouter-performance-p50.md)仅首字/速度的范围；保留其匹配路由、权限、限价和不得写统计的边界。[明确状态](../../implemented/bug-fix/2026-11-17-numeric-zero-health-states.md)仍用于无参考、过期、未登录、关闭、失败等状态。没有制造厂家原生API或整个厂商的SLA。

## Alternatives considered

全平台状态页只说明服务整体状态，无法代表精确模型或本站分组；本次已有精确端点数据，优先复用。新增抓取调度/数据库/匿名通道扩大契约且不必要。选取所有服务商中最高比例会偏离实际路由，因此保留已有优先级/价格规则选定的可调用端点。参考比例只覆盖当前可调用端点；无可调用匹配时保持明确状态，不保证所有模型可补。

## Verification

通过实际官方样本的数字与单位复核；后端保留0%、拒绝未知/越界、按原选路而非最大百分比选择，只有可用率仍能返回参考。前端本站0优先，过期/未来时间/错误来源/非法周期/无权限不补，外部百分比有参考标签且无历史展开。正常实测的展开继续工作，免费价格保持数字0。相关测试/构建/视觉与进程清理通过。

## Consequences

24小时平台端点统计不是本站72小时可用率，必须区分周期和来源；缓存生效时间不是官方原始事件时间。服务商状态变化与路由重试可能造成差异。仅支持当前既有OpenRouter路由，其余来源待有精确证据后扩展。实现本地未发布。

实际验证：service与controller定向测试通过，覆盖真实公开响应解析、0/100/非法比例、仅可用率字段、选路限价、未知不补及过期；前端13项含参考纯函数、权限与零值状态回归通过。浏览器逐项确认外部100%、本站0优先、外部0、过期、缺字段、匿名、失败、关闭，共8种场景；参考值无本站历史按钮，24h说明和更新时间可展开，手机312px有效视口无溢出。缩放后弹层首次重新打开出现第三方组件过渡状态，重新载入手机布局后正常；未将其误报为数据问题。主站/图片构建、17语言、ESLint与五页预渲染通过，机械UI检查无命中。没有执行生产应用发布或收费推理。
