# Agent Note: 钱包整体布局与支付费用说明

Status: implemented

本方案已按用户要求由[撤销钱包设计](../simplification/2026-11-06-wallet-design-revert.md)撤回；以下保留原取舍与验证记录，不作为当前钱包行为。

## Problem

用户要求将已展示的整体设计落到钱包页面。当前充值数量和支付方式并列、档位位于下方，支付按钮只显示名称；Stripe 美元计价和人民币实付差异无法在选择时理解。历史三笔 100 额度订单的人民币实付为 20.81，同额当前易支付报价为 20；4.05% 是样本价差，不能作为固定手续费或新收费依据。

## Decision

复用 TopUp → user/self、topup/info、amount/pay、payment-records 和既有邀请/兑换弹窗。页面顶部集中账单/发票；左侧蓝色余额与充值、右侧绿色邀请与兑换码；充值按档位/自定义 → 方式卡片 → 金额摘要 → 原确认流程排列。原套餐页签、Creem/稳定币/Waffo、权限、失败恢复与资金操作保持。

报价比较复用原只读报价接口，当前方式的确认仍重新请求并锁定原快照；比较失败不补零，不影响其他方式，不让旧额度/旧身份响应覆盖新状态。CNY/USD 分开显示，不以展示汇率伪造收银台金额。

topup/info 可选返回当前 Stripe 通道历史参考：从最近30天的最多20笔成功、USD结算/CNY实付订单中选最多3笔相同额度、且实付美元符合当前用户对应充值报价的样本；至少3笔才显示。按当前支付宝报价比较，注明样本额度、数量、最新日期、原币和人民币均值；不输出用户或订单身份。缺少配置、TOKENS模式、记录不足或查询失败就省略，不阻断充值。不保存固定4.05%、不改支付金额、计费或数据库schema。

## Existing capability review

- [经典布局](../../implemented/feature/2026-10-30-wallet-classic-layout.md)：部分重叠，保留双栏配色与完整账单，扩展为本次确认的层级和费用说明。
- [钱包资金交互](../../implemented/feature/2026-10-28-wallet-experience.md)：部分重叠，保留防重、取消/旧报价隔离及兑换幂等，不恢复首页最近交易请求。
- [Stripe显示](../../implemented/feature/2026-10-12-stripe-checkout-display.md)：部分重叠，仍按内部stripe类型路由，名称图标不证明实际支付工具。
- 邀请实时结算、开票最低金额、稳定币网络、现金利润、模型价格等命中笔记不改变；资金/开票手续费不能混为充值附加费。

## Alternatives considered

- 直接静态写“手续费4.05%”最省改动，但会把历史跨币种价差变成固定承诺，且可能导致重复加收；不采用。
- 手工维护带日期的参考配置便于运营控制，但需要持续维护及防止忘记过期；现有订单已包含原币与实付，采用受限的只读样本计算。
- 全面重做支付/账单服务能统一新契约，但超出本次展示优化；复用已有报价、创建订单和记录接口。

## Verification

- `go test ./controller ./model` 全包通过；新增样本过滤、数量、价格变化、过期、零价/负价/非有限值、同额度和隐私投影回归。只使用GORM通用查询，无schema迁移；本地查询集成用SQLite，未将其声称为MySQL/PostgreSQL实机验收。
- `node --test` 的 wallet-cost-reference、wallet-payment-request、wallet-redemption-request、payment-navigation、payment-record-view 共14项通过；跳转脚本另覆盖桌面/手机的Stripe、Waffo、Creem及网关表单。
- `wallet-cost-layout.browser.mjs` 用合成账户隔离实际React应用，验证1440px双栏、390px单栏及深色截图、无横向溢出，报价币种与参考、低额提示、确认、本人账单和发票、兑换码、划转、套餐切换余额常驻，以及失败重试和旧响应失效。屏蔽所有实际写请求与外部网络，未创建支付或资金操作。
- 17种语言资源及相关ESLint/Prettier检查通过，主站Bun构建、图像工作台构建、5个公开页面Chrome预渲染、Go构建通过。保留既有大包/第三方eval提示。
- 旧 `pricing-wallet-layout.browser.mjs` 的钱包断言随本次文案更新；整套脚本在进入钱包前的旧模型广场表头背景色断言超时。本次独立钱包脚本覆盖受影响流程，不扩大为模型广场样式改动。

## Consequences

选择方式时可以比较真实报价，历史价差有样本和失效边界；不更改支付价格或额外扣费。比较请求按provider合并、400ms防抖与10秒超时，最多增加3个只读报价请求；topup/info额外使用2秒上限、最多20条的历史读取。样本不满足时仅显示币种/收银台说明；若未来需要更多支付通道或运营控制，应单独设计费用配置与真实报价契约，而不是扩大这段启发式样本。

参考价差受当前报价与有限历史样本影响，不是实际通道手续费、当前汇率或未来付款承诺。Stripe显示标签不证明样本实际使用微信；原始参考仅聚合通道数据，不输出用户或订单身份。合成页面和代码验收不证明真实支付到账，发布不等于生产部署。
