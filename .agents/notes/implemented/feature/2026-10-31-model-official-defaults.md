# Agent Note: 所有接入模型的自动资料默认值

Status: implemented

## Problem

模型目录已经自动建档，但介绍、标签、供应商仍留在手工导入流程。官方来源只有 OpenAI 文档和需要独立凭据的 Claude/Gemini API；后台启动延迟、全批次 30 秒预算和失败后等待一天，让编辑页面长期出现空值，用户无法把未修改字段作为官方默认信息使用。

## Decision

所有精确模型自动参与同一资料同步流水线，复用人工值所有权和数据库乐观更新。增加介绍、标签和供应商归属；官方明确数据优先，社区资料仅补缺并保留社区来源。官方网页通过经过验证的模型身份及结构解析；公开文档无需逐模型配置密钥，不从模型名字猜规格或把社区价格冒充官方价。

后台启动立即执行，网络总预算独立于单次 HTTP 超时，部分失败采用有界退避重试，成功后保持日常刷新。模型详情读取触发过期资料自动刷新，首次编辑等待有界更新并在失败时保留已有数据；同模型请求合并，管理员输入不被迟到同步覆盖。表单用 `capability_overrides` 只提交修改的能力键（null 删除为未知），数据库行锁事务合并当前能力，避免修改一个开关时覆盖其他能力的新自动值。

## Existing notes audit

- 属性官方来源、官方价格同步：部分重叠；继续采用逐字段来源、官方失败不降级及手工优先，扩展公开来源覆盖。
- 目录补齐、管理厂商一致性：部分重叠；目录来源仍为 enabled abilities，只读推断厂商不冒充已保存值，确认来源的厂商进入自动所有权。
- 原能力同步：部分取代介绍不参与自动同步的范围限制，扩展同一状态及并发保护。
- 发布日期排序：继续只接收确切日期，不把文档更新时间或模型 ID 日期当作发布日期。

## Alternatives considered

- 每次使用手动“同步”按钮可以复用已有导入器，但不满足用户明确要求的自动维护。
- 仅在前端把社区资料设为表单默认值较快，但保存时会错误变成人工值，也无法保证广场与管理的一致性，因此自动值持久化并标记来源。
- 所有厂商必须配置 API 密钥能获得结构化信息，但公开文档已提供大量规格，不能把密钥配置变成每个模型自动填充的前提。

## Verification

- Go 全量测试通过；原厂商同步集成测试补全官方域名隔离，避免新适配器意外请求真实文档使固定测试资料漂移。
- SQLite、MySQL 8、PostgreSQL 16 验证介绍/标签/厂商所有权、官方来源、手工值及大小写并发修改；旧表单省略字段在 SQL UPDATE 层保持后台新值。
- 浏览器复用完整模型官方价格回归，验证编辑、保存、FAQ、能力、桌面/窄屏与表单未改字段不提交；截图位于本次测试输出目录。前端字段补丁、来源/未知和价格测试12项通过。
- 公开页面实测读取9个厂商样例；首轮 xAI 超时，第二轮 Claude 超时，其余各轮均得到独立成功来源。下载的官方页面验证 Claude/Gemini/xAI/GLM 解析；第二轮读取 Gemini、DeepSeek、MiMo、Z.AI 价格，Claude 本地页面验证缓存两档。模型页身份不符、未声明字段、复杂未知布局不猜测。
- 前端生产与文档构建通过；语言资源和笔记校验随提交执行。版本发布及附件验收在发布流程中完成，生产部署另行授权。

## Consequences

无需逐模型人工同步；未人工修改的数据持续采用当前官方资料，来源不足时由社区补缺。公开文档来源覆盖不等于所有字段都有官方数据：Kimi 解析介绍及官方HTML静态表的USD/MTok价格和缓存TTL档位（见[补齐决策](../bug-fix/2026-10-31-kimi-metadata-completion.md)），其他规格仍由社区补缺；部分价格和私有别名尚无可验证结构，继续保持未知或保留已有资料。文档字段支持范围集中列在 `docs/MODEL_CAPABILITY_SYNC.md`，不把未解析字段称为官方未公布。

网页结构变化及地区访问限制会降低覆盖；自动重试保留旧值，所有厂商字段失败互不影响。背景总预算180秒，官方单次10秒，编辑总预算15秒且预留写入时间；新请求不会无界占用网络。短期结果缓存为进程内状态，重启后重新检查。K/M 是官方文档的十进制简写，解析为1000/1000000；官方 API 若给出完整整数则优先使用该整数。

旧有模型介绍/标签/厂商非空且没有自动快照时作为人工配置保留。资料没有更改时不产生无意义更新时间；价格快照与来源继续独立于计费、路由和权限。

模型介绍的动态17语言缓存与人工覆盖见[模型介绍全站语言](../bug-fix/2026-10-31-model-description-locales.md)，不改变本笔记的原文同步或页面权限约定。

阿里旧别名的定向数据修复和同步入口边界见[阿里厂商归一化](../bug-fix/2026-10-31-alibaba-vendor-normalization.md)；普通人工归属保护继续适用。
