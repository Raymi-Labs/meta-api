# Agent Note: 企业资金操作回执与原子人工对账

Status: implemented

## Problem

企业管理的调账、分配和回收在响应丢失后重试可能再次动账；成员操作落账后的详情查询失败还会将成功显示成失败。人工预留处理的金额和审计原来分开提交。用户授权先在本地实现资金可靠性，生图成本与普通用户退款策略暂缓。

## Decision

复用已有钱包事务、企业→成员锁序、权限规则与弹窗，在最新main 0ae972087上实现第一批：

- 新增EnterpriseOperation回执，操作者+操作键唯一摘要，绑定企业、动作、原成员ID、金额、原因和回收快照；回执、金额、审计同事务。HTTP缺键拒绝，内部原函数签名保留。读取回执不依赖当前余额，归档后Root仍能读取。
- 操作与重放均读取当前主库账号状态/角色及当前成员代次。Root会话过期权限不能重放；账号授权在线性化前的入场查询生效，不增加反序用户行锁。自动调用仍只锁原成员，不通过新管理操作协调器。
- 人工预留处理提取adjustEnterpriseReservationTx，以企业/原成员锁内复核review状态，金额、令牌统计、审计与回执同事务；不在此批补Task/MJ未知结果结清。
- 前端sessionStorage保存最小原操作，按账号/企业/动作隔离。先核对回执协议，再提交；请求错误保留原键、原金额；重新打开一次查询，支持同键重试，没有常驻轮询。预留处理保留最小显示上下文，待对账列表外保留当前账号的查询入口；刷新后即使原预留已离开列表仍可恢复。恢复弹窗显示并锁定原方向、金额和原因。旧服务缺回执只允许查询，不重发。所有服务节点升级到支持版本后才能开放新管理写，不能混部旧写节点。
- 已完成后刷新失败不改操作结果。全部回收绑定点击时整数余额；变化后拒绝，不回收后来新增额度。十进制BigInt换算，原始单位、空白/零/上限独立校验，累计金额检查int64溢出；回执累计值为字符串。
- 更新/回退工具增加离线--data-capabilities命令，按不可变镜像ID验证。回执表存在即要求enterprise_operations_v1，空表也受保护，避免检查后首次写入的竞态。自动失败恢复复用同一保护。预检同时以迁移后的临时schema检查当前镜像能否恢复，不兼容时在旧服务仍在线时中止。副作用：部署创建此表后不能自动回到不认识回执的版本，即使尚无回执；首次升级会被此保护拦住，需要单独安排兼容过渡发布，不能把有一份修复镜像当成已经具备自动恢复能力。此基础只覆盖本批回执，不声称已实现完整归档/人工终态能力管理。

本批在现有UI中补状态与操作，不重做整体界面。父方案继续保留待实施状态；本地实现完成不等于三库验收、发布或后续批次完成。

## Alternatives considered

- 仅禁用按钮或缓存锁：开发成本小，但无法覆盖断网/刷新/多实例；采用主库唯一回执。
- 只给流水添加操作键：避免新表，但无法稳定表达结果与原子人工处理；独立小回执不承载第二套余额。
- 保留缺键HTTP请求：兼容旧页面，但无法保证资金只处理一次；旧页面刷新升级，明确不兼容边界。
- 只在有回执时拦回退：更宽松，但预检与首次写入存在竞态，需要跨节点写门控；本批选择空表也拦的保守能力屏障，未来部署门控完善后再缩窄。

## Consequences

首次升级在迁移预检阶段就要求当前运行镜像支持回执；不支持时保留旧服务并拒绝切换。兼容过渡发布仍需后续单独设计并验收，本地实现不能直接视为可上线；本轮不发布。退出登录清理本地草稿，服务器回执保留；缺失关联的历史不伪造。sessionStorage被清除后不能靠同金额推断旧操作，需从审计核对。混合旧服务节点不属于此版幂等保证。
