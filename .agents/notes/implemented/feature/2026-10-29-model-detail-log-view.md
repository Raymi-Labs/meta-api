# Agent Note: 模型接入顺序与日志派生视图

Status: implemented

## Problem

模型详情重复显示同名模型 ID，空描述占据介绍区，完整阶梯和分组价格先于快速开始。普通用户日志默认展示多列计费与排障信息，但直接减少默认列会覆盖用户已有偏好，管理员也不能失去现有排障入口。

## Decision

模型详情始终保留模型名称复制按钮，仅在友好名称与模型 ID 不同时额外显示 ID 文字，无描述时不渲染占位。保留价格摘要与能力，将快速开始移到完整动态价格和分组价格之前，不改协议、价格、健康或示例数据。

普通用户日志使用独立持久化的摘要/完整展示模式。摘要通过派生列只显示时间、模型、类型、花费、用时/首字、输入和输出；完整模式恢复原 `visibleColumns`。打开列设置时进入完整模式，避免设置弹窗与可见结果不一致。充值、管理和系统日志的原始正文放入既有展开详情，避免隐藏详情列后只剩时间与类型；空内容不添加空展开项，Pulse奖励正文不重复。管理员保持现有完整行为，模式切换不改变查询、统计、导出、分页、展开详情或角色权限。

## Alternatives considered

- 直接修改默认列并写回存储实现简单，但会永久覆盖旧偏好，因此使用独立模式键和派生列。
- 把完整价格全部移到快速开始之后能减少首屏信息，却会削弱价格透明度；保留顶部价格摘要，只后移动态阶梯和分组明细。
- 同时调整模型目录列数、看板和移动顶栏会扩大回归面，且近期决定仍成立，本篇不做。

本轮修复复核：37项相关 Node 测试、修改源码 ESLint、笔记门禁和主站 Vite 构建通过；合成页面确认充值/管理/系统摘要可展开正文，同名/无展示名有复制按钮且异名显示真实ID，390px复制入口可见且无横向溢出。浏览器脚本补充断言，本轮实际页面验收通过内置浏览器完成；没有调用真实模型或修改后端。

## Consequences

普通用户默认看到较少日志列，但完整模式恢复此前保存的精确组合；摘要不会减少导出字段或详情。打开列设置会进入完整模式，这是保持设置与结果一致的有意行为。详情先提供价格摘要和接入示例，再展示完整计费，不删除任何价格或协议信息。没有后端、数据库、权限或生产配置变化，未使用真实账号、支付或模型调用。
