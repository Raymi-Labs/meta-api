# Agent Note: 公开导航的系统公告入口

Status: implemented

## Problem

公开首页只有延迟自动弹出的单篇公告，语言菜单旁没有常驻查看入口。控制台已有铃铛，但同时处理管理员提现与发票，直接复用会把私人待办依赖带入公共页。原控制台关闭时把未展示公告一并标为已读，不能用于跨页一致的未读提示。

## Decision

在 PublicHomeShell 的语言选择右侧增加轻量 Bell 按钮与蓝色未读圆点，扩展已有 PublicNoticeModal 显示公开系统公告列表和单篇公告。数据继续来自匿名可读的 /api/status.announcements 与 /api/notice；不新增接口、后台配置或权限。页面打开后延续 4.5 秒的公告检查，首页保留原今日关闭自动提示规则；手动按钮始终可用，手动打开/关闭后不再被迟到自动请求重新打开。

公开页与控制台使用统一的本浏览器已读工具，保留 notice_read_keys 的旧公告键格式；只将成功展示的内容记为已读。单篇公告按完整正文独立比较，notice_close_date 仅控制今日自动提示。坏值和禁写采用会话回退，同页/跨标签更新订阅。控制台管理员待办继续使用原权限与数据链路，现有按钮只移动到语言右侧。

弹层区分加载、空数据和失败，提供重新加载；使用原 RichContent 净化内容，后台动态正文保留原文。弹层支持 Escape、焦点约束/返回、背景滚动锁定、浅暗主题和窄屏。公开按钮界面词条覆盖已有 17 语言。

## Alternatives considered

- 直接挂载控制台 NoticeModal/useNotifications：可复用完整界面，但同时引入 Semi/i18next 和管理员待办；公共页只复用公开数据和已读工具。
- 仅增加装饰铃铛或固定蓝点：实现短，但不能查看真实内容，也会虚构未读状态。
- 仅以 notice_close_date 判断未读：能沿用旧状态，但它代表当天自动提示偏好，不能识别更新后的公告。

## Testing

相关测试共 63 项通过，覆盖已读状态、公开语言、协议、页脚和接入地址；登录重定向与客户端下载检查通过。ESLint、Prettier 与差异检查通过；正式前端构建成功，Chrome 完成登录、注册、模型广场、下载和关于页面的预渲染。

真实 Chrome 验收覆盖桌面和 320px 窄屏、浅色/暗色、焦点循环与 Escape 返回、加载中关闭、失败重试和空列表。查看后未读圆点消失，新增公告再次提示，另一标签页同步已读；今日关闭后刷新不自动弹出，手动入口仍可打开。公共页面请求记录不含提现、发票及额度私人通知接口。路由切换中的手动请求正常完成，避免弹层持续加载。

## Consequences

已读偏好仍为本浏览器共享，不宣称账户级服务端同步。旧列表键为发布时间和正文前30字，保留兼容性，其碰撞限制未在本次更改。生产发布与部署分开确认。
