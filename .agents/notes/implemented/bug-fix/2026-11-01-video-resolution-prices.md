# Agent Note: 视频分辨率与充值人民币单价

Status: implemented

## Problem

MiniMax-H3 已保存按分辨率的秒价，但旧提取器不识别 invalid_video_duration 分支，目录与详情只显示“见价格详情”。其他多分辨率表达式只展示范围，用户无法确定具体规格的售价。用户要求与百万 Token 价格一样，按本站充值比例显示实际人民币成本（当前 1 元 = 5 额度）。

## Decision

复用 `/api/pricing` → useModelPricingData → getModelCatalogPricing 的可见模型、分组/时间倍率和 displayPrice.toAmount。精确反解后台生成的 H3 与通用视频秒价模板，并重新生成整个表达式比较，确认没有遗漏附加费用或条件；按分辨率和时长区间列出每秒价。卡片复用两位金额和微小非零提示，表格与详情保留精度，详情显示请求时长计费及多份语义。充值/套餐/基础额度模式保持现有规则，不使用官方美元汇率折算本站价格。

未知表达式保留既有安全范围或明确动态计费提示；不猜分辨率，不把配置预览零值当售价，不执行表达式。只读展示，不修改生产配置、渠道、任务、结算或官方参考价。

## Alternatives considered

- 只允许 invalid_video_duration 并展示最低/最高价，改动最小，但仍无法知道每个分辨率对应的价格。
- 新建后端价格表可以描述任意视频规则，但需要迁移既有表达式、修改配置和接口契约；本次优先复用已保存的价格。
- 前端通用表达式求值可以推算更多规则，但无法保证样例参数覆盖所有收费条件，故只反解完整已知模板。

## Verification

纯函数与实际计价代码回归覆盖 H3 全型号、通用秒价模板重复分辨率/时长、科学计数与极小价格、零价、缺失/负倍率、额外乘数/非线性与修改条件的回退。H3 2.5/4 × 分组0.8 × 充值0.2 = ¥0.4000/¥0.6400；组选择、时间倍率、基础额度、套餐换算、K/M、原缓存与文本阶梯用例通过。实际表格渲染回归覆盖两个规格均出现在单价列，输出/缓存列保持不适用；详情渲染不错误关联官方Token价格。

本地 Vite 项目页使用只读公开 H3/站点配置快照及隔离模拟 API，通过卡片→K/M切换→表格→详情验收；截图核对桌面和390px暗色布局，两档金额与时长均完整。初次表格验收发现旧 video-second 键过滤漏行，修复后复验通过。相关 ESLint/Prettier、17语言资源、完整前端/生图构建、Go构建通过；默认Linux Chromium路径不适用于本机，指定已安装Chrome后五页预渲染通过。发布状态与附件完成情况以本轮Release核验为准。

## Consequences

已知模板展示每个分辨率的本站售价，卡片复用两位金额和小于0.01提示，详情/表格保留四位精度，极小非零金额保留小于标记。价格换算读取现有充值/套餐设置，不硬编码0.2、不使用官方汇率；不修改生产价格、结算、渠道或历史账单。

严格模板比对可能拒绝人工改写的等价表达式，保留动态计费比错误报价可靠。未知线性表达式仍可沿用原范围摘要，但不猜分辨率。当前充值价是配置口径，不重算历史充值折扣或已发生的账单。没有执行收费生成或生产部署。
