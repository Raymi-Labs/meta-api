# Agent Note: Claude 缓存时长结算与展示一致性

Status: implemented

## Problem

同一 Claude 缓存用量经过 Messages、Chat 兼容及阶梯入口，1小时写入、缓存only和未细分余量处理不一致。普通价格页没有1小时预览，日志公式丢弃部分细分之外的余量。

## Existing capabilities and impact

复用原生Claude解析器、PostClaudeConsumeQuota、Chat结算器、BuildTieredTokenParams、模型价格API和日志渲染。普通配置CreateCacheRatio仍是5分钟价，1小时仍按1.6倍派生。不改现有价格、分组、数据库结构、历史余额或路由。

已检索活跃笔记：[跨协议完整性](../../implemented/bug-fix/2026-09-29-kimi-request-stream-integrity.md)部分重叠于失败边界，保持原决定；K3用量修复与本次计价语义独立；令牌倍率和生图不纳入本次。

## Decision

- 统一写入组成：总量、5分钟、1小时、未细分余量；总量不重复累加明细，总量缺失时允许明细推导，显式零与缺失区分。
- 原生解析标注语义，阶梯同时认可最终Claude格式，保留未细分余量及完整len；未独立定价的缓存按表达式基础输入价处理。
- 普通Chat兼容入口使用时长分项，缓存only不得被无用量判断清零。保持原生取整行为；兼容Claude采用相同取整，非Claude不变。
- 矛盾/负数缓存用量按异常上游响应拒绝成功结算，遵循现有错误退款机制、不在输出后重试；不自动进行历史补扣或退款。
- 普通后台标明5分钟基价和派生1小时预览；价格API通过明确能力字段下发时长信息，价格页复用。日志摘要/公式/旧阶梯展示保留未细分余量。

具体映射为 `cc=明确5分钟+未细分余量`，`cc1h=明确1小时`；完整输入len在子类独立计价之前计算。未被表达式单独计价的子类计入p，避免省略变量变成免费；Messages使用OpenRouter等上游时按最终用量格式决定，不能因为客户端路径而把含缓存总量再次加缓存。

[跨协议输入缓存语义](2026-10-24-cross-protocol-cache-semantics.md)补充落盘计数契约及历史统计兼容：新日志明确标注prompt是否包含缓存，Messages→OpenAI普通倍率先扣读写缓存后分项计价。旧日志仅凭可靠阶梯长度证据解释误标，不修改历史账单；本篇原生时长组成与取整决策继续有效。

在原生解析器及普通relay结算入口前校验负数、拆分溢出、总量/明细冲突；有异常时错误退款而非生成成功消费。流式字段按累计快照处理，显式零可以清除旧值；只更新输出时保留已有缓存证据。变化的总量不能携带未同时报告的旧TTL细分。

普通价格API给出TTL能力及派生1小时价；管理员option接口按已启用模型缓存配置和Anthropic端点元数据下发只读预览信息。前端不按模型名猜测，不将预览元数据写入选项。新建未启用的模型缺能力信息时保留通用价格提示。存在部分细分时，消费日志另存unclassified字段，界面明确列出该部分；旧日志冲突提示不回写历史金额。

## Alternatives considered

- 仅修文案最小，但无法修少扣；只把所有Claude改阶梯也不行，当前阶梯变量链路本身有问题。
- 新增独立1小时配置灵活，但扩大配置/同步/迁移范围，本轮保留1.6派生，特殊合同另行设计。
- 冲突取最大值能够继续返回，但可能多扣；选择异常响应，不制造已知用量。不改变一般断流/用户取消的既有政策。

## Consequences

[Claude HTTP断流处理](2026-10-31-claude-stream-terminal.md)在后续独立范围内替代HTTP上游异常不完整流仍结算的路径：上游异常且没有实际交付message_stop则失败并沿用预扣退款，已观察usage仅供管理员诊断。下游取消继续按既有已用量结算；不改变本篇缓存分项守恒、非流式及AWS事件流决定，也不追溯历史余额。

修复少扣后未来账单可能比错误路径增加，但配置价格不变。不能由通过模拟推断所有上游返回正确。公开模型能力不等于供应商价格认证。不涉及历史核账或生产部署，提交合并不代表上线。

代价是新增一份共享缓存组成及只读价格元数据；原生/兼容的缓存费用与展示能复用同一分项。冲突响应会成为显式失败，避免继续用矛盾数字成功扣费，但有异常上游的请求可用性可能下降。一般断流、用户取消与独立工具调用收费政策未一并改写，不能把本次修复称为Claude所有计费路径全面审计。

第一性原理审查重点是输入证据与结算分项守恒，而非统一改价；对抗审查覆盖旧TTL污染新总量、cache-only被判为0、同一用量换入口价格变化、全部缓存被重复算入len、字段显式0被旧值替换、把余量伪造成1小时、以及界面新增字段误提交。拒绝只加语义标签的最小补丁，因为它会使无时长明细的总量丢失；拒绝一键改所有模型阶梯，保留既有配置。
