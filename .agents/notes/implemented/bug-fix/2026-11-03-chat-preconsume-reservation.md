# Agent Note: 同步聊天预扣估算与请求级额度拒绝

Status: implemented

## Problem

生产普通聊天在余额仍充足时被异常大的预估费用拒绝。钱包工厂先校验完整估算，后执行信任免冻结；Claude tool_result 将嵌套图片 Base64 整体当文本估算。额度拒绝不区分余额耗尽与单次请求超过余额，连续三次会禁用整个令牌。失败日志缺少估算分项。

## Decision

复用 BillingSession、PulseWalletReservation 和主库用户行锁，不增加数据库结构或第二套账本。普通同步 Chat/Messages/Responses/Gemini 的钱包、无限额非周期令牌，在锁内余额高于已有信任线（10 计费单位）时使用有界首笔预留：输入与最多4096输出 Token 按现有倍率估算，取原预估、信任线和初始估算的最小值，收费请求至少1 quota。余额较低时保留原完整预估。各在途请求真实占用钱包，下一笔使用扣除占用后的余额；最终按真实用量补扣/返还。请求 max_tokens 不改写。有限额令牌、套餐、按次、阶梯、音频、图片和异步请求保留原路径。

Claude 工具结果通过显式栈提取文本和媒体，Base64 图片/PDF 不进入文本计数；工具输入仍计为 JSON，保持原请求不变，避免递归调用栈和深度截断。诊断仅记录数值和策略于 admin_info，复用普通用户脱敏。

结构化额度拒绝区分 exhausted、request_exceeds_available、in_flight。只有明确耗尽继续累计自动禁用；正余额单请求不足和在途占用拒绝不禁用令牌。订阅预扣拒绝保留最大可用单订阅余额，不能把多个套餐相加。请求级拒绝仍不调用上游且不内部重试；在途拒绝不发送充值提醒。历史禁用令牌不自动恢复。

无限额令牌在实际结算时一次性累计用量，首笔只占钱包，退款不凭空增加令牌剩余额度。资金来源回退成功保持成功；备用来源耗尽时，保留首选来源正余额不足或在途占用的原因，避免误禁用。

相关活跃笔记：[自动禁用](../../implemented/feature/2026-11-01-token-quota-auto-disable.md)部分替代“所有本地额度拒绝计数”的决定；[健康归因](../../implemented/bug-fix/2026-11-02-quota-health-attribution.md)继续保留可信错误链与数据库故障归因；[额度提醒](../../implemented/feature/2026-10-24-quota-blocked-notifications.md)保留请求级不足提醒，排除暂时在途；[现金账本](../../implemented/feature/2026-11-03-upstream-cash-ledger-v1.md)继续复用资金批次结算；其他视频、音频、断流笔记只共享生命周期，不更改其规则。

## Alternatives considered

- 直接把信任判断放到余额检查前：改动最小，但仍零冻结，多个请求可同时消耗同一份余额。选择真实原子预留。
- 全量按照最大输出预扣：覆盖最坏费用，但与长上下文、缓存和大输出上限的日常客户端不匹配，继续造成误拦。
- 先假设缓存命中再估价：可降低占用，但缓存命中未知，不能当成事实。仅最终结算采用供应商实际用量。
- 新增分布式租约/第二套额度表：可进一步限制请求数量，但扩展崩溃恢复和账务边界；现有事务预留已经保证首笔占用不超过钱包。

## Verification

- 嵌套工具图片只算媒体，混合文本/工具输入仍计数，原请求原样转发。
- 会话回归复现余额521.87/原估算536.74进入上游；真实 TokenAuth → Relay 在 Chat、Messages、Responses、Gemini 四协议分别验证成功、上游错误、客户端取消，预留/结算/退款正确，转发128000输出上限保持不变。未使用真实付费上游。
- SQLite、MySQL 8.0（utf8mb4_unicode_ci）和 PostgreSQL 16 隔离库验证20并发预留总额不超过余额、重放幂等、失败无部分扣费及真实费用高于预留时的结算；现金批次分摊与退款守恒。
- 余额正数不足不禁用，真实零余额仍三次禁用，重置代数及健康分类保持；订阅回退成功不误累计。
- 日志分项不含正文/密钥，普通用户不能读取管理员分项；17语言提示和复制诊断不泄露管理信息有回归。
- `go test ./dto ./relay/... ./service ./model ./controller ./middleware ./router ./types` 通过；新增范围保护覆盖生成音频/图片、音视频输入、有限额令牌及周期包。Bun前端生产构建通过，本机无Chromium而跳过静态预渲染，运行时保留后端元信息兜底。

新增钱包/会话/真实Relay回归在三数据库环境下的 `go test -race` 通过；Go服务端构建、6项前端失败提示回归、发布策略和 `make verify-notes` 通过。媒体范围与诊断低余额分支的最终定向回归通过。

## Consequences

预留不是最终费用上限，长输出尾款和并发结算仍可能透支；本次降低零冻结风险，不声称实时限制供应商费用。同步进程崩溃后的未结预留沿用现有持久账本运维边界，不按超时自动退款。发布与生产升级分别验证。
