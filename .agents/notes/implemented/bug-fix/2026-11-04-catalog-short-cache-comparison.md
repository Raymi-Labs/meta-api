# Agent Note: 模型广场缓存创建按较短时长对比

Status: implemented

## Problem

Claude 已有官方 5m/1h 缓存创建价及本站基础/1h 创建价，但 groupPriceComparison 因支持 TTL 全部拒绝比较，1h 项也未映射官方字段。官方表按 TTL 展开，分组重复显示相同价格。用户要求模型广场统一用较短时长的创建价计算。

## Decision

复用 /api/pricing → getModelCatalogPricing → ModelGroupRows/groupTierRows → ModelGroupPrice；TryUserAuth、角色可见模型、分组及账户/时间倍率继续沿用。官方表和分组匹配共用 visibleOfficialTiers：同单位、同其余标签条件下，解析明确的 cache Nm/Nh 后缀，保留最短时长，展示去掉后缀以匹配原上下文条件。重复的最短档仍保留，不以数组顺序猜测。未知标签与单独档位保留；原始厂家元数据不改。

目录、表格、详情共用的本站价格投影在存在基础创建价时隐藏对应1h项（含倍率及动态 cc/cc1h），保留原始计算数据与5分钟标签；基础缺失时保留已有1h项但不把它冒充基础价。取消基础缓存创建项的全量 TTL 禁比，按投影选定的参考价计算折扣。这里统一的是展示参考口径，不声明保留时长完全等价；不同单位、缺失字段、无有效汇率仍不比较。

## Existing notes audit

- [分组官方折扣](../../implemented/feature/2026-10-30-model-group-official-discount.md)：部分取代 TTL 禁比，币种、未舍入计算及权限边界保留。
- [逐档价格表](../../implemented/feature/2026-11-01-group-tier-comparison-table.md)：部分取代仅30m/12h的展示投影，扩展为各条件下最短时长；仍不把Claude改成30m。
- [档位匹配](../../implemented/bug-fix/2026-11-02-official-tier-matching.md)：保留条件匹配、原因说明及峰谷规则；基础缓存项不再因TTL能力拒比。
- 官方同步、官方覆盖审计、缓存计量及跨协议语义笔记不涉及本次展示口径，保留运行时与原始来源。

## Alternatives considered

- 为5m、1h分别解析和计算折扣能展示全部时长，但违背用户统一较短时长的要求，也继续产生重复档位。
- 只删除TTL禁比改动最少，却会在1h官方行把本站5m价用于对比，且留下不支持的1h项；需同时统一两侧展示投影。
- 改写服务端官方元数据可减少前端处理，但会丢失来源及长期价、影响管理和同步，因此仅在模型广场展示层投影。

## Verification

42项价格与真实React组件回归通过，覆盖5m/1h与30m/12h、逆序、长上下文/地区/单位、重复/未知标签、零/缺失价格、普通/动态、K/M及币种换算；币种、动态计费和6项缓存语义回归通过。Chrome完整详情和模型广场流程通过，新增普通/动态Claude真实页面验证仅保留一个官方档、一个创建价、USD折扣50%以及K/M一致，1440px和390px暗色无整体溢出；已有筛选/分页/管理编辑/导航复制回归通过。完整前端构建（含图片子应用与17语言检查）及五页Chrome预渲染通过。

本次公开生产pricing读取遇到连接中断/超时，未取得完整快照；根因由用户展示与实际源码确认，浏览器使用隔离合成API，无真实推理或生产写入。

## Consequences

广场统一展示和比较较短时长的创建价，消除重复行及无意义TTL禁比。若仅有1h本站价，保留明确的1h项且不冒充基础价；未知官方标签不解析。原始官方资料、配置、实际长缓存费用及权限保持原状。发布不代表生产已部署。
