# Agent Note: 定价接口厂商范围跟随本次可见模型

Status: implemented

## Problem

用户指出公开pricing仍返回无可见模型的Venice厂商。页面按模型生成按钮，但接口直接返回全局vendorsList，既包含空记录也可能透露只有其他角色可见模型的厂商。仅公开模型列表为空不能证明后台无引用，因此不直接删除。

## Decision

内容层进一步采用[公开资料边界](./2026-11-06-public-model-provenance.md)：保留本篇角色/引用交集规则，已知第三方平台的公开厂商归属去除而后台记录不删除。

在GetPricing完成既有角色可见性裁剪后，以本次返回模型的非零VendorID求厂商交集。构造独立切片，不原地删改共享缓存；只按ID关联，不按名称屏蔽，保留原元数据顺序，未知/零ID不补造厂商。模型data、价格、分组说明/倍率/路由完全不变；管理员厂商CRUD列表仍可管理全部记录。空目录返回vendors:[]而不是null。每次请求重新投影，角色切换/权限撤销不继承之前的厂商范围。

活跃笔记：公开描述整理部分重叠，本篇收紧元数据返回范围，保留文字规范化；厂商别名归并是身份处理不改；模型权限规则继续作为唯一授权来源。

## Alternatives considered

- 只删除Venice：未经后台引用核查会误伤隐藏模型/规则，且其他空厂商仍泄露。
- 全局缓存只存有模型厂商：无法处理不同角色可见范围，可能跨请求污染。
- 前端隐藏：已有页面本就不显示空厂商，不能解决公开JSON。

## Verification

`GOMAXPROCS=4 go test -p 2 ./controller -count=1 -timeout=240s` 控制器完整回归通过。新增真实pricing回归覆盖匿名/普通/管理员/再次匿名、空Venice、隐藏厂商、角色专属和共享厂商；缓存内容不变，权限撤销后不重新构建pricing仍正确裁剪，模型JSON（包含价格）与原有可见性过滤结果深等，分组备注及倍率保持。后台所有厂商及Venice记录仍存在，无数据库写入变更。纯投影测试覆盖无模型、零/未知ID、重复关联、元数据不变及修改返回切片不污染共享缓存；Venice如有可见关联仍正常返回，不以名字封禁。

初次回归直接比较反序列化结构触发omitempty的nil/空map差异，改为比较实际JSON；CommonOnly按现有规则包括游客，空目录用例同时撤销公开和普通角色模型，未改现有权限语义。

前端厂商匹配/排序脚本、10项目录筛选回归及36项完整主站语言正文检查通过；图片语言覆盖通过；make verify-notes校验247篇及封印通过，git diff --check通过。本轮遗留测试进程零，无收费调用。

## Consequences

仅依赖当前已存在的模型可见性规则，不额外改变分组权限或调用权限。外部工具若把pricing.vendors当作完整后台厂商表，将不再收到未引用记录，应使用授权管理接口；正常按模型名调用无影响。无数据库迁移或生产删数据，代码合并不代表部署。
