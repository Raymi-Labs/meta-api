# Agent Note: 用户身份分组一致性与规则批量编辑

Status: implemented

## Problem

独立用户分组不能与渠道同名，但旧空分组令牌仍将身份当作渠道。批量迁移分批提交后才删缓存，后批失败留下部分变更；表格重复名称被序列化覆盖；两类分组互换名称时单字段保存无法通过中间态校验。

## Decision

复用鉴权、TokenRoutingGroups 与令牌列表倍率服务的统一空分组解析：保留存在的旧同名渠道及 auto；仅已登记且无同名渠道的身份可回退到存在且获授权的 default，用户身份与特殊倍率不变，不改写令牌。显式渠道与多组配置不扩权。

迁移在同一 GORM 事务中锁定用户并分批更新，提交后失效实际迁移用户缓存。失败全部回滚。两类分组通过原 root option 接口的 UserChannelGroups 组合键一起校验与保存，单字段入口共用写锁与校验，且按固定顺序锁定数据库配置行校验最终组合，数据库提交后发布配置。复用现有多实例配置同步，不引入热更新强一致协议。

鉴权同时设置生效的令牌首选分组供 relay 重试与分组限流使用，原用户身份 context 保留，避免后续入口重新继承错误身份名称。

表格以 trim 后的原始行校验空名、重名和长度，校验错误阻止提交；保持用户输入直至修正，不能通过序列化丢掉错误。默认行保护绑定初始行身份，输入 default 的重名行仍可修正。渠道表格改在 effect 中发布变更，相同值不更新状态，避免移动端卡片重新挂载时重复触发相同值更新导致页面循环。

用户追加的多选需求复用特殊倍率和特殊可用分组两个编辑器：用户分组可一次添加多个分组的规则，规则目标支持多个渠道分组。相同用户下同倍率、同操作与说明的旧规则合并展示，保存展开原嵌套 JSON；倍率 0、原说明、添加/移除/追加前缀和旧名称保留。重复目标导致覆盖时阻止保存；删除整个分组一次过滤全部行，避免循环回调的旧状态残留。

检索：令牌倍率笔记与本次部分重叠，本篇扩展其空组解析规则；多组选组笔记部分重叠，沿用其显式范围与回退边界；视频定价提案、价格展示与统计笔记无关，无需归档。见[令牌倍率](../../implemented/feature/2026-10-07-token-list-group-ratio.md)与[多组选组](../../implemented/feature/2026-11-07-token-group-multi-picker.md)。

## Alternatives considered

- 让身份和渠道继续同名可保留旧继承，但违背已经发布的分离规则；选择仅保留真实存在的旧渠道兼容。
- 自动选任一可用渠道或强制 auto 更易恢复请求，但可能改变价格和回退范围；只采用获授权的 default。
- 前端先删除旧名称再保存最终配置可避开冲突，但中途失败会遗留丢失配置；选择数据库事务保存最终组合。
- 迁移失败后返回部分成功数可避免事务，但权限和缓存处理更复杂，管理员也不能获得全量操作语义；选择整批回滚。

## Testing

相关 Go 模块完整测试与新增回归通过；race 覆盖组合配置、批量迁移、身份继承与倍率。SQLite、隔离 MySQL 8.4（utf8mb4_unicode_ci）、PostgreSQL 16 的实际统计、1203人迁移、第二批故障回滚、配置交换及保存失败回滚通过；未实测最低数据库版本，也未连接生产数据库。前端11项辅助函数测试覆盖多选展开、旧规则往返、零倍率、删除选择及冲突拦截。真实 Chrome 加载完整设置组件与合成 API，验证空白/重名拦截、名称双向交换、失败保留输入、两个区域多用户/多渠道选择、保存后格式和390px页面；浏览器脚本隔离并拦截所有API，结束关闭服务和浏览器。

## Consequences

default 不存在或未授权时仍需显式选择渠道，不能猜测价格。大批量事务延长锁持有时间；Redis 故障沿用缓存失效错误日志和 TTL，多实例配置沿用周期同步。生产上线独立于代码发布。
