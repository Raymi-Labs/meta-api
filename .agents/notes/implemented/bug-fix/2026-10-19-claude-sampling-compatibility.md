# Agent Note: Claude 采样参数拒绝的共用兼容与诊断

Status: implemented

## Problem

Claude 渠道将 Chat 转为 Messages 后，上游明确返回 `does not support non-default temperature`，现有两个入口共用的参数自愈只识别 deprecated / unsupported parameter，未识别该文案。通用失败提示也把本地模型不可用与上游参数拒绝混在一起。单个供应商的拒绝不能证明同名模型在所有渠道都不支持采样。

## Decision

复用 `relay/claude_param_heal.go` 与现有 Chat、Messages 入口，在当前请求的真实 HTTP 400、结构化 invalid_request_error 中识别明确的采样参数拒绝；只删除 temperature/top_p/top_k 中明确指认且实际存在的一项，并在原渠道最多重发一次。不缓存或传播供应商能力，不新增模型前缀名单、渠道 ID 特判或配置表。

错误体有界读取且完整恢复，取消、已输出响应、透传、错误类型不符、歧义或语义参数拒绝均不新增重放。沿用既有空 thinking 修复。使用已有管理员 attempts 记录原始拒绝与调整参数，成功只结算最终响应，失败保留退款链。模型不可用给出模型名/令牌分组的具体提示，不静默替换模型。

## Alternatives considered

- 针对渠道 1427 配置温度删除最直接，但会把该渠道所有请求都改写且新渠道仍需重复配置，无法覆盖两个入口的共同缺口。
- 将 Haiku 5.5 加入全局删除表可以省一次请求，但当前只掌握一个供应商的拒绝证据，不能推断其他渠道及别名能力。
- 新建按供应商缓存的能力表可减少后续失败请求，但引入过期、账号差异、并发和配置覆盖语义；当前复用单请求证据足以修复，不引入跨请求状态。

## Consequences

移除采样参数会放弃调用方的采样偏好，因此仅接受上游明确拒绝，并通过 X-Param-Adjusted 响应头和管理员 attempts 暴露调整。每次拒绝仍可能多一次同渠道请求，不将其宣传为无重试或所有 400 自动修复。模型不存在的请求仍按原权限范围失败，只改善排查提示。

沿用现有参数覆盖后自愈顺序：被上游明确拒绝的最终字段可移除；需要原样传递的渠道保留透传模式。没有新配置字段、数据库迁移或生产渠道变更。若此额外请求成为实际延迟瓶颈，再凭供应商合同和流量证据评估预先规则或缓存。

## Testing

- 20 个完整 Relay / SQLite 场景覆盖 Chat、Messages 的 JSON/SSE、两个渠道 ID、同渠道自愈、修复后仍失败、透传、上游接受自定义/默认温度。请求内容除温度外一致，成功仅一条消费记录且钱包/令牌只扣最终用量，失败预扣全退；普通用户日志移除管理员尝试和供应商标识。
- 单元覆盖明确拒绝、其他错误类型、错误字段中的旁带文案、多采样参数歧义、无参数、非 JSON、64 KiB 上限、读取失败、取消、已输出、同请求只重发一次、传输失败与底层响应关闭。既有空 thinking 回归通过。
- relay、service、controller、middleware、model、Claude 适配器完整包回归与定向竞态检查通过；七种语言的公开排查信息翻译及私密诊断隔离测试通过。前端生产构建和五个公开页 Chromium 预渲染通过；Go 构建通过。
- 未向真实付费供应商发送复测请求，未部署生产；模拟通过不代表上游现场已经恢复。
