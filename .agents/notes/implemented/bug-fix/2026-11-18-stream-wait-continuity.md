# Agent Note: 流式等待保活与下游交付诊断

Status: implemented

## Problem

11月17日03:30至18日03:30（北京时间）生产只读样本有1383次客户端断开，873次发生在20秒内。不同调用方分别跨渠道集中在4秒、16.2秒、30秒；144次图片编辑均在等待响应头。现有15秒最大心跳及仅观察上游正文的日志不足以判断等待期间是否成功写出保活或有效内容。固定耗时只能提示调用方/代理期限，不能证明超时原因。

## Decision

复用既有请求级保活与scanner，启用后的首次心跳约1秒开始，持续间隔限制为5秒；保留显式禁用、非流式协议和所有重放门槛。管理设置展示实际有效间隔，旧超大值兼容归一化，新增写入校验。通过既有Chat、Responses、Messages SSE写入入口，在write与flush成功后记录心跳/有效内容时间和写入失败；仅保存计数与耗时，不保存正文。取消时冻结，管理员失败详情展示，普通用户与复制报告继续隔离。成功写出只代表服务器可观察的交付，不代表客户端已消费。

## Existing capability and notes audit

- [取消诊断](../../implemented/feature/2026-11-09-cancellation-diagnostics.md)：部分重叠，沿用中间件、admin_info与冻结规则，扩展下游证据。
- [流式交付生命周期](../../implemented/bug-fix/2026-10-24-stream-delivery-lifecycle.md)：部分重叠，复用writer交接、关闭上游与退款；本篇调整启用保活的时间策略。
- [响应头切换](../../implemented/bug-fix/2026-11-15-header-timeout-failover.md)、[上游能力拒绝](../../implemented/bug-fix/2026-10-12-upstream-capability-failover.md)：相邻约束；不扩大已提交响应的通用重试，不复用有副作用请求。
- 其他检索命中为Claude终态、DeepSeek精确补救、视频等待与渠道容量，保持各自决定；无完全吸收或过时提案。

## Alternatives considered

- 全局延长等待：服务器已允许长连接，不能延长客户端硬期限，放弃。
- 断开后继续生成并自动重放：同步接口没有重连取回契约，会浪费费用或重复执行工具，放弃。异步图片需独立持久任务与客户端支持，不伪装成本次同步接口修复。
- 立即发送心跳：最快但会把所有快速鉴权/参数错误变成HTTP200流内错误；保留1秒宽限。
- 只补日志：有助归因但不改善等待保活，本次同时缩短启用后的心跳间隔。

## Verification

真实HTTP验证三协议长等待首帧、准备期保活、错误终态；既有心跳停用、换路/取消/退款回归通过。诊断覆盖心跳不算内容、flush失败不计交付、取消冻结、未支持协议未知、历史未知、用户权限隔离。`go test -p 2 ./...`通过；相关service/helper/controller定向race通过，三协议准备期另行race通过。前端失败详情8项测试、17语言资源检查及Bun生产构建通过，Go构建通过。发布策略与Python发布工具测试通过。

首次全量测试与前端目录重建重叠造成主包embed缺失；前端完成后完整重跑通过。默认Chromium路径缺失，项目预渲染按既有策略跳过，不能视为浏览器实测。本轮不新增SQL/schema或生产写入，未做MySQL/PostgreSQL实例演练；生产统计为实施前只读证据，效果待受保护部署后按相同窗口与调用方验证。

## Consequences

更早提交SSE会更早失去普通HTTP错误状态与部分重试机会；保留受控响应头切换，明确流内错误。更多小帧增加流量与唤醒；不承诺解决主动停止、固定总时限、读取SSE注释后仍不重置的客户端期限。未部署前不能宣称生产断连率下降。
