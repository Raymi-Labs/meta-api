# Agent Note: Uptime 在有效样本不足时补充测试

Status: implemented

## Problem

用户澄清“不是没调用时，而是有效样本不足时”。v1.4.0 只允许 request_count=0 的小时桶使用测试，1—29 次仍遗漏测试证据并显示灰色，与需求不符。

## Decision

[渠道与历史证据修正](2026-10-31-uptime-channel-probe-history.md)补充证据来源：对应渠道测试可以使用其他模型，启动后台补最近72小时已有成功记录；本文阈值、加权与着色继续适用。

复用现有测试采集、小时桶与30次样本门槛。先跨副本合并同分组/模型/小时，request_count<30 且存在测试时补一个测试样本；任一对应上游通过记成功、只有失败记失败。达到30次不再补充。排除的用户错误不凑有效样本，判断不使用整个24/72小时汇总数。

保留真实请求与测试补充的加权公式，不覆盖真实失败、不将一轮测试伪造为30次请求。Uptime 有补充证据时按计算结果着色并显示来源；没有补充时沿用原样本门槛。真实请求成功率、用量、延迟及缓存保持原口径。数字、小时条、对比图和来源说明同步。

## Existing notes audit

- [测试补空闲时段](../../implemented/feature/2026-10-31-model-uptime-probes.md)：部分取代只补零调用和低请求量仍灰色的决定；采集归属、跨副本、权限、幂等持久化及加权公式继续沿用，旧篇保留并互链。
- [不足三十次统一灰色](../../implemented/bug-fix/2026-10-22-group-health-limited-gray.md)：真实请求视图继续适用，Uptime 的测试补充另有证据来源。
- [目录指标](../../implemented/feature/2026-10-25-model-catalog-metrics.md)和[请求结果](../../implemented/bug-fix/2026-10-22-group-health-outcome-accounting.md)：仅扩展Uptime，调用终态与计费不变。

## Alternatives considered

- 只改后端阈值：改动最少，但前端仍会将有测试证据的低样本画灰；同步修正展示。
- 用测试替换少量真实调用：能直接显示测通状态，但会丢失真实调用失败；保留加权补充和原始结果。
- 一个测试补足到30次：能跨过原颜色门槛，但虚构权重；每桶最多一个测试样本。

## Consequences

测试仅代表某次上游可用，不代表持续在线。达到30次时补充样本退出，Uptime可能变化，真实成功率不变。无新增存储变更，已采集历史测试按新查询口径生效。
