# Agent Note: PITR 已知对象按键读回

Status: implemented

## Problem

生产归档分段和回执序号已超过四万。对已知文件使用普通 `rclone cat` 时，同目录对象的遍历占用了单轮 45 秒预算，导致旧分段在重试时完成、新分段又在解密读回期间超时。监控也需要读取同一远端目录。

## Decision

共用 crypt reader 给完整对象路径传入 `--no-traverse`。归档、监控、全备和隔离恢复继续用同一个流式接口，调用方照常核对进程退出码、内容和回执。显式文件列表、前缀枚举和对象存在性检查有各自的用途，保留原实现。

复用[连续归档的期限与恢复目标](../process/2026-10-23-mysql-pitr.md)以及[读回错误分类与恢复通知](2026-10-26-pitr-readback-and-recovery-alerts.md)。本次针对已知远端键的查找成本，无需改变错误处理和回执格式。

## Alternatives considered

延长期限可以临时容纳较慢的读取，但每轮仍需遍历不断增长的目录，独立监控也有单独的时间预算。传入父目录和单文件列表也能快速读取，实测与直接加参数相近，却增加了列表输入和文件选择逻辑。

## Consequences

生产 rclone v1.75.0 对同一份 994 字节回执的读取由 13.88 秒降至 0.41 秒，对同一份 2,456,518 字节分段由 20.77 秒降至 0.53 秒。两种方式取得的完整内容均与原回执 SHA-256 一致。独立生产周期通过新写入的状态和通知回执验收。运维脚本可原子替换，旧脚本可独立回退，原有归档链可继续使用。
