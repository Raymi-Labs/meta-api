# Agent Note: 缓存命中率排除模型测试

Status: implemented

## Problem

模型测试记录与实际请求共用消费日志，但测试缓存不代表用户调用表现。测试日志缺少缓存语义时还会降低看板缓存指标的记录覆盖率。用户明确要求缓存命中率不计算模型测试。

## Decision

复用现有看板独立指标聚合与使用日志缓存扫描。仅当 token_id 为零且 token_name 精确等于“模型测试”时识别系统测试；真实令牌即使同名仍保留。看板在缓存候选判定之前排除测试，不计入缓存读取、输入、纳入或异常排除记录数。使用日志页在缓存扫描限制之前排除同一集合。综合单价、消费、请求总数、Token 总量和日志展示不变，不修改历史数据或测试写入。更新提示和缓存命名空间。

## Existing notes audit

- [独立指标覆盖](../../implemented/bug-fix/2026-11-04-dashboard-partial-metrics.md)部分重叠，保留有效子集和单价规则，本篇收窄缓存候选范围。
- [统一结算日志](../../implemented/bug-fix/2026-11-03-dashboard-settlement-statistics.md)与[五项指标](../../implemented/feature/2026-10-30-dashboard-five-metrics.md)保留布局、日志来源和权限；缓存候选由本篇补充。
- 检索命中的模型目录、探测历史、72小时性能参考、跨协议语义和概览布局笔记不涉及本次缓存候选排除，不更改其决定。

## Alternatives considered

- 仅补齐测试日志语义仍会把测试流量计入缓存率，不符合用户要求。
- 从所有统计查询删除测试会连带改变金额、请求和综合单价，超出本次范围。
- 只按令牌名排除会误伤同名真实令牌，因此同时要求零令牌 ID。

## Verification

SQLite 隔离回归及 race 通过，覆盖混合日志、仅测试、缺语义测试、同名真实令牌、管理员/用户聚合、使用日志扫描上限前过滤，且金额、Token 与单价保持原有结果。10项前端回归、36项语言资源检查、生图与主站构建、五页预渲染、普通用户桌面/管理员窄屏隔离浏览器验收通过。语言检查首次受默认5秒超时影响，显式60秒上限重跑全部通过。SQL 使用 COALESCE 和参数绑定，无引擎专属语法；本轮未做 MySQL/PostgreSQL 实机验证。

## Consequences

缓存覆盖率基数为范围内非测试的 Token 请求，测试不算异常排除。综合单价仍可能因测试日志语义不明确产生排除计数，符合仅调整缓存率的范围；可见覆盖提示由[展示精简](../simplification/2026-11-04-dashboard-hide-coverage-copy.md)移除，API 计数保留。无数据库 schema 或生产变更。
