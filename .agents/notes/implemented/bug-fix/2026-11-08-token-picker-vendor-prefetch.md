# Agent Note: 令牌分组选择器的厂商随目录返回并预加载，新令牌默认勾选自动切换

Status: implemented

## Problem

创建令牌时左栏厂商出现得慢。选择器打开窗口后要依次请求：先取可用分组（`/api/user/self/groups`），再取模型目录（`/api/token/models?detail=true`），同时另取整份 `/api/pricing` 只为拿到「模型 → 厂商」。2026-11-08 从用户本机实测，`/api/pricing` 压缩后约 325 KB，三次总耗时 6.1–8.6 秒（经本机代理，TLS 握手占 3–8 秒，服务端净耗时未能单独测到：当时 SSH 被服务器断开，未重试）。每次打开窗口都重新请求，没有任何缓存。另外用户要求「所选分组都不可用时，再按平台顺序尝试其他分组」对新令牌默认勾选（[多选分组决策](../feature/2026-11-07-token-group-multi-picker.md)中原为默认不勾）。

## Decision

- **厂商随目录返回**：`/api/token/models?detail=true` 的每个模型增加 `vendor`（厂商名），取自进程内一分钟的定价缓存（`model.GetPricing()` 的 `vendor_id` + `model.GetVendors()`），与模型广场一致；没有厂商元数据的模型不带此字段，前端仍归入「其他」。选择器不再请求 `/api/pricing`。只给已经可见的目录项填厂商，不扩大可见范围。
- **前端共享缓存与预加载**（`web/src/components/table/tokens/tokenGroupCatalog.js`）：按「用户 ID + 分组列表」缓存目录与厂商 5 分钟；同一时刻的重复请求合并为一个。令牌页打开 0.8 秒后在后台预取（先取可用分组，再取目录），用户点「创建令牌」时窗口直接用缓存，无需等待；缓存超过 5 分钟则先显示旧数据再后台刷新，刷新失败保留旧数据，只有完全没有数据时才显示加载失败。目录只用于筛选提示，保存时服务端仍按当时权限校验分组。
- **新令牌默认勾选自动切换**：表单初始值 `auto_group_fallback` 改为 `true`。单分组令牌写 `auto_group_fallback`，多分组令牌写 `routing_config.auto_fallback`，语义不变。编辑已有令牌仍显示保存的值（多分组读 `routing_config.auto_fallback`，不读旧标志）；可售令牌与 auto 分组不显示该选项，行为不变。

## Alternatives considered

- 只在前端缓存 `/api/pricing`：第二次打开会快，但第一次仍要下载整份定价数据，且令牌页从不需要价格以外的内容；改为让目录接口顺带返回厂商。
- 新增专门的「模型 → 厂商」接口：多一个接口和一次请求；目录本来就按模型列出，顺带一个字段更省。
- 只预加载、不缓存：每次进入令牌页都会请求，打开第二次窗口仍要等；缓存 5 分钟后再次打开窗口不请求。
- 把可用分组也放进缓存以省掉打开窗口时的分组请求：分组请求小且决定可选范围与权限提示，保留每次打开都重新获取。

## Consequences

收益：打开创建/编辑窗口时厂商与分组同时可用，不再下载数百 KB 的定价数据；重复打开窗口不再请求目录。

代价与限制：进入令牌页会多发两个后台请求（可用分组与目录），即使用户不创建令牌；后台调整分组或模型厂商后最多 5 分钟内窗口显示旧的厂商归类（刷新页面即更新）；新令牌默认允许按平台顺序换到其他分组，可能按更贵的平台分组计费，勾选框下方已有提示。
