# Agent Note: OpenRouter 消耗看板后台快照

Status: implemented

## Problem

账户列表读取已有余额快照，CRS/CPA 概览也读取已保存数据；OpenRouter finance 每次 GET 串行调用官方接口并扫描 30 日日志，页面等待远端和统计计算。

## Decision

为 finance 增加进程内快照，每个服务进程启动预热并每五分钟后台更新。GET 只验证当前账户并读取快照，冷启动立即返回准备状态。相同账户合并刷新、全局限制并发两次、单次超时两分钟。密钥配置变化隔离缓存，删除/停用不再读取。失败保留同日期范围内失败分项的上次有效值与保守生成时间，健康分项继续更新并显示错误；页面每五分钟读快照，准备期间短轮询，不清空当前数据。手动刷新读取最新快照，不绕过后台限流。

## Existing notes audit

OpenRouter account-finance 与 model-consumption 笔记部分重叠，继续定义官方接口和金额口径，本篇仅负责读路径与后台生命周期；现金账本及其收益提案仍独立，不缓存资金写操作或用户自选日期报告。其余检索命中的模型目录、路由监控快照不相关。

## Alternatives considered

- 仅浏览器缓存：回访快，但首次进入和其他管理员仍重复触发昂贵计算。
- 数据库持久化整份报表：重启可立即读取，但需要新增存储契约、清理及多节点锁；本次先使用每进程有界刷新和显式冷启动状态，无 schema 迁移。
- 同步 TTL 缓存：实现短，但过期后的首个请求仍等待外网，不满足打开即读。

## Verification

Go model/controller/router 相关回归、快照 race 检查和 Go 构建通过。覆盖冷启动立即返回、重复请求合并、两路并发限制、密钥变化隔离、失败保留、节流和部分恢复。前端构建通过，指定本机 Chrome 后预渲染通过。真实 Chrome 组件回归覆盖冷启动准备提示与自动读取、失败保留、账户切换竞态、CRUD、分页筛选和窄屏；17 种语言补齐快照提示。生产加载耗时尚未验收，发布不代表部署。

## Consequences

每个副本各采集一份，重启需要预热；快照可能滞后五分钟加采集时间，失败时更久，必须展示时间与错误。
