# Agent Note: 容器过载哨兵采样与连续性

Status: implemented

## Problem

现有公共监控读取宿主机 CPU/内存，middleware 单次超限即拒绝；其他容器负载、瞬时尖峰和失效快照会误伤 relay。

## Decision

适配上游 09109ec31，复用现有监控配置、后台入口及中间件：优先有限额的 cgroup v1/v2 CPU 与内存工作集，无法读取时回退原宿主口径。5 秒采样，连续 3 次超限才拒绝，回落即恢复，超过 30 秒的快照不拒绝；运行时关闭/调高阈值立即生效。保留本地错误类型和三协议路由，不改配置默认值。

## Alternatives considered

- 仅提高阈值易配置，但宿主与容器分母不同，无法解决误判来源。
- 永久关闭哨兵可避免误杀，但失去持续真实压力的保护。选择口径修正及连续性判定。

## Testing

公共包和中间件完整回归通过；定向竞态与构建覆盖 v1/v2、分数核与 cpuset 上限、缓存扣除和下溢、无限额回退、连续/恢复/过期及配置变更。使用临时 cgroup 文件，不改变系统资源限制，不代表生产容器验收。

## Consequences

容器未暴露限额时仍回退宿主口径，不能声称所有部署都隔离；三次采样延迟拒绝，需运维关注容量。未修改数据库或生产配置。活跃笔记检索无已有哨兵决定；日志并发和 Kimi 请求体笔记不相关。
