# Agent Note: 企业工作空间交接后的安全与闭环优化

Status: implemented

## Problem

用户要求接手a4321cc05后的本地工作，并提供优化框架、功能细节及进度Markdown。伙伴已补齐首期页面，但上轮审查发现自邀绕过、账号缓存污染、邀请结果因刷新丢失、空白名单不可保存、全部状态遗漏退款。现有测试通过不能证明这些边界。首期第一批计费仍需完整本地调用闭环及关联功能核对。

## Decision

复用已实现企业身份/预算/令牌/计费及前端，不重写企业功能，不修改个人钱包语义。按以下顺序实现：

1. 邀请创建和接受都拒绝同账号自授；接受时重新验证邀请人的有效角色，成员退出/停用撤销其待接受邀请，防止陈旧授权恢复。当前没有平台邀请路由，本次不新增平台代邀；不允许把缺少成员关系的签发人当作平台身份。
2. 企业身份缓存按账号隔离，异步结果只回当前账号；同账号后台刷新保留页面，跨账号立即隐藏旧数据。邀请成功链接保留到用户主动关闭，不因统计刷新卸载。
3. custom空模型清单允许保存，危险收窄需确认；用量列表/汇总/导出全部状态显式all，防止默认口径误用。请求迟到不能覆盖当前筛选。
4. 真实TokenAuth/relay接本地合成上游完成消费、耗尽、申请审批、继续调用，断言个人余额不变、企业账务守恒；覆盖自动停用规则与手动恢复边界，不把补额度默认为自动解除停用。
5. 核查上游现金成本、个人/企业消费统计、通知对象、用户限流，逐项记录复用点及缺口。第二批体验区/异步任务/MJ/实时语音逐项列出付款方与恢复改造清单，未完成端到端资金接入前保持拒绝，禁止只放开路由白名单。
6. 输出正式交接文档，明确代码完成、模拟验证、三库/真实上游/第二批未验收。数据库若本机缺少，不读取生产DSN或安装系统服务绕过，使用可用隔离测试并报告。

## Alternatives considered

仅在UI禁止自邀挡不住直接API和存量邀请，须事务内验证。刷新整个布局虽简单会丢失一次性结果，改为同账号保留旧快照并展示刷新状态，切号例外。空白名单用继承替代会扩权，保留后端显式空集。仅给第二批入口加白名单会让退款落到个人钱包，不作为功能完成。

## Verification

漏洞先有失败回归再修正；邀请权限/角色变更/离职及旧邀请不能自授；账号快照不串号；邀请结果与表单刷新不丢；空集可保存、全部状态一致。第一批本地合成请求完整结算、审批补额、重试/停用边界通过；原个人路径无余额变化。构建、定向测试、笔记门禁通过，遗留工作进程为零。所有结果写入docs/reviews交接文档，不推送、不发布、不收费调用。

## Consequences

旧平台邀请与企业邀请不能凭邀请者当前角色混淆，需明确持久来源。新授权语义应兼容已有数据，保守失效邀请可重发但不自动扩大权限。当前一个账号一家企业、有界首笔预留及欠额是伙伴已确认设计，不恢复早期多企业/严格预留方案。大范围第二批计费和三库验证仍是对外开放门槛，不用本轮安全修复冒充已交付。

关联[企业首期实现](../../implemented/feature/2026-11-11-enterprise-workspace.md)部分扩展，保留已修订产品决定；原本地tmp进度作为交接输入而非实现依据。
