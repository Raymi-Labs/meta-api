# Agent Note: 全备读回失败诊断与恢复告警闭环

Status: implemented

## Problem

生产全备在远端读回阶段报告 gzip 截断，随后 systemd 重跑全量备份成功。当前校验先解析 gzip、后检查 rclone 退出码，下载中断可能遮蔽真正的读取错误；仅凭该报错不能断言远端对象损坏。历史失败对象已在独立恢复机完整读回：3450881292字节、SHA-256与原上传记录一致，gzip通过，读取进程退出0。原对象内容正常；旧版未保留原读取进程退出原因，无法进一步区分连接中断、超时或其他读取失败。不能把此次归因写成gzip算法缺陷。

管理员收件箱已存在对应 FAILURE 和 RECOVERED 邮件，但恢复邮件发于全备重试启动时，早于新全备内容校验完成。systemd 在新一次启动时重置 Result，监控同时接受上一份成功回执，因而把“正在重试”当作“已恢复”。

新生产A/B隔离演练准备验证数千份归档回执时，又发现恢复工具的远端读取管道只在整个流程结束后关闭。私有进程集合保留了已结束子进程的stdout，长链会耗尽文件描述符；这是恢复工具的独立问题，不是原全备读回故障的归因。

长链实际校验随后在第4138个分段安全拒绝预检库DDL：受保护发布流程导入schema时，MySQL会为 `DROP TABLE IF EXISTS` 自动附加 `/* GENERATED BY SERVER */`，原严格词法器把它与未知注释一并拒绝。该窗口共有76条精确形式，均位于规范的 `newapi_preflight_<时间戳>_<PID>` 临时库中；既有集成夹具覆盖了预检库创建和修改，却没有覆盖这种服务器生成的DROP尾注。

## Decision

复用现有流式备份、crypt 读回、原子回执、监控状态机和隔离 A/B 恢复，不重建备份系统。EOF 后核对读取子进程退出码，对明确读取失败最多重读同一不可变对象三次，沿用全局期限；完整性错误、信号中断和超时不得通过重试或跳过校验变成成功。每次尝试通过 `readback_attempts` 记录校验器收到的解密后gzip字节数、读取退出码、时间与分类，最终 SUCCESS 门槛不变，不因一次网络读回失败立即重新扫描生产库。

监控持久保存全备失败水位。自动重试启动不清除故障；仅失败之后的新全备通过既有远端清单和覆盖校验后，才能解除水位并发送 RECOVERED。正常首次备份运行不误报，坏水位失败关闭，SMTP 失败不推进通知状态。仅解析得到的真实服务失败建立或更新水位；systemctl查询失败不等于全备失败，不锁住正在正常完成的备份。水位保存安全诊断，清除后fsync状态目录。新回执的时间与远端manifest/SUCCESS绑定，不能用本地旧回执改时间解除故障。

恢复工具在每次读取回执或分段完成及异常退出时立即关闭自身stdout管道；保留退出码、字节数、内容哈希和连续链校验，仍由原进程集合负责异常收尾。不修改共享进程管理或再次部署生产备份/监控。

仅在严格预检默认库上下文中，识别已观测到的无库名前缀、单个反引号标识符的 `DROP TABLE IF EXISTS` 及精确服务器尾注，再进入既有作用域检查。分类不改写真实binlog。其他注释、可执行注释、多语句、跨库名称以及普通业务库注释规则保持拒绝。

本轮长链恢复先从R2并行取回至新的私有本地crypt缓存，保持原始元数据字节；独立绑定A/B成功标记及清单、epoch根和覆盖B的第4591份终止回执指纹。缓存中的19份原件须与R2读回字节一致，最终完整回执链的末项还须匹配原R2的canonical receipt digest。缓存复制成功或内部自洽不能代替这些来源锚及完整恢复核对。缓存方式只改变运输位置，仍用相同恢复入口校验所有分段；耗时须计入准备过程，不将本地读取速率解释为直接逐对象读取R2的性能。

## Alternatives considered

- 仅增加 systemd 重试能继续恢复任务，但每次都重新扫描生产库，且不能修复错误分类和提前恢复通知，因此不作为本次修复。
- 对所有 gzip 错误无差别重试可减少报错，却会掩盖真实损坏；仅对明确读取进程失败有限重试。
- 以 service 重新启动作为恢复信号简单直接，但未证明新备份可用；采用持久失败水位和新全备验证。
- 仅提高恢复机文件描述符上限会延后失败，无法限制长链资源积累；修复每次读取的资源释放，不绕过默认系统限制。
- 全局剥离注释或跳过范围错误会削弱跨库及多语句保护，因此只识别已验证的精确预检DROP形式；原始binlog保持不变。

## Consequences

网络读回仍有成本，三次尝试受原总期限限制。恢复需独立磁盘容量，不能为演练删除现有备份。只安装备份/监控修复，不重启业务与 MySQL，不清理源 binlog，不把合成告警输入描述为生产真实故障。
