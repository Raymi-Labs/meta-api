# Agent Note: 多厂商视频任务共同契约

Status: implemented

## Problem

现有各厂商任务出站转换与表达式计价分离，默认时长和 metadata 可以造成报价不同于出站；多个适配器把空结果标为成功。新视频任务必须保留提交密钥且避免不确定结果后自动重复付费提交。

## Decision

在已有视频任务适配器上增加共同出站快照：先转换一次，表达式读取该快照派生的规范时长/分辨率及原生字段，发送同一字节。旧按次/适配器倍率规则保留。Sora multipart 先保留原路径，表达式缺乏可靠规范体则明确拒绝，不伪称支持。

所有原生视频平台保存提交 Key、使用已有终态 CAS；付费提交开始后禁自动重发，响应缺失说明结果不确定。查询错误/未知状态不写成功，成功需可下载结果（Sora内容接口例外）。保留各厂商协议，不新增虚构模型能力。后台补可配置的任务按秒/固定档位表达式模板，模板不定义供应商支持参数，参数白名单与实际协议仍由适配器负责。

已配置固定任务价格的快照设置 PerCallBilling，避免上游 Token 用量覆盖原固定单位；未明确固定价的旧用量路径不更改。旧表达式不统一改写分辨率大小写；仅新模板按大写匹配，样本数从出站获取，缺省单份。Seedance -1 自动时长允许旧用量路径，模板拒绝缺有效秒数；即梦保留 frames，不猜 FPS。

Kling 无图请求同时更新真实 action（避免只改 context 导致走 image2video），支持现有首尾帧；即梦保存转换后的 req_key 并在轮询复用，不再所有任务硬编码同一个旧 req_key。Ali 按映射后模型选择默认值，透传统一首尾帧；Gemini/Vertex 明确只支持已有文生输入，不默默丢弃参考图。各家缺任务 ID、缺输出、未知状态本地回归，Sora id/task_id 均换为公开 ID。

模板只对已注册协议家族提供，不对安全识别范围内的 Runway/Luma/HappyHorse 等暗示可用。新模板在目录/详情标明视频参数计费，不把配置预览0元或文本Token首档当视频售价；尚未实现公开交互报价器。表单生成同步更新父表单，保存/重开保留完整表达式和现有附加规则，17种语言同步。

## Alternatives considered

- 为每家复制计价流程可快速覆盖但会分裂金额口径，因此共享规范快照。
- 只扩展名称/价格最省事，但不会修复实际请求与查询，故不采用。
- 所有新型号均当旧协议兼容，容易无声丢字段；仅列出现有协议的验证范围，新协议保留待验收。

## 提交前非视频隔离复核

新增跨模型回归首先复现：按 `jimeng_`、`wan2.` 全家族识别视频，会使已有即梦图片和万相图片模型的端点提示及默认测试入口变为视频。修复为即梦明确的视频任务前缀与万相 t2v/i2v/r2v/v2v/s2v/flf2v 类型；H3端点提示单独支持大小写规范化，正式提交的精确型号校验保持不变。

common回归覆盖12个文本/图片反例，controller直接调用默认端点选择验证普通文本、图片与H3，以及显式端点不被覆盖。此修复不扩大生成能力或改变模型请求名称。

## Verification

`relay/video_request_snapshot_test.go` 覆盖九类转换和同源参数、时长冲突、metadata路径、缺ID、成功缺结果、未知状态、保存Key、即梦查询型号、公开ID与模板后端金额。既有资金/终态/退款和适配器回归全通过；H3与共性专项 race 通过。controller 估价复用完整参数与适配器，不发上游，开始提交后429/5xx均不重发。

`video-pricing-template.test.mjs` 覆盖秒价/固定档位、零价/缺价、重叠区间和型号范围，并与Go共享fixture验证SmokeTest和真实计价。浏览器模拟完整编辑器验证H3和Grok模板生成、保存、重新选择、重开、固定档位切换、M2.5隔离及公开价格不显示免费/Token单价。源码ESLint、语言校验和主站Vite构建通过；未重建未修改的生图子应用、没有执行生产请求。

## Consequences

默认计费参数变为实际出站值后可能纠正历史少扣，旧表达式需复核；不确定提交不自动重试会增加人工核对。未真实验收的型号不声明上线。通用实际用量、崩溃原子结算仍属原提案。

按次旧默认价格回退仍存在，预检应提示缺明确任务价；新模板是已有表达式的配置辅助，不是通用供应商能力验证。不支持的协议/模型版本、multipart表达式、参考素材额外成本、GCS-only输出与新Google视频接口不能声称已接入。支持清单见 docs/channel/video_support_matrix.md。密钥持久化只补新任务，无法重建历史未保存Key的任务。
