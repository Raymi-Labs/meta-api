# Agent Note: 企业计费分组维护保护

Status: implemented

## Problem

企业直接选组定价已实现，但分组维护仍可删除被企业引用的组；企业管理页仅首次加载倍率，其他页面改价后编辑窗口会显示旧值。用户说明目前仅测试、没有正式企业，不需要其执行客户价格迁移。

## Decision

复用GroupRatio配置事务校验企业引用（包括冻结企业及关闭企业开关），删除或改名被引用分组时拒绝并提示先调整企业计费分组。企业创建/换组和配置写入共用GroupRatio数据库行锁，顺序为配置→企业→成员/用户，阻止并发删组后仍绑入；按事务内配置验证，不依赖实例旧缓存。传统、命名空间与组合保存入口共用保护；保留普通用户分组和计费逻辑。配置键大小写/空格归一，其他由SQL排序规则命中受保护键的通用写入被拒绝，不能绕过引用校验。失败不发布新倍率。

新旧倍率配置并存时保留旧加载顺序；修改UserGroups不删除旧倍率别名、不发布倍率，身份名称必须与两套已存渠道组都不冲突。只有明确保存GroupRatio或组合配置才统一为标准键并删除别名。企业开通/换组遇到两套配置冲突时返回明确业务错误，要求管理员确认后保存，不擅自选价。

企业管理打开编辑/开通窗口、页面重新获得焦点和保存成功后刷新分组。使用请求序号隔离迟到响应；读取失败清空可保存选项并提供重试，读取期间不可提交，不覆盖管理员已输入的企业资料。

## Alternatives considered

- 只在删除按钮提示无法保护接口调用和并发；采用服务端事务约束。
- 只用进程锁实现简单，但多实例可能穿过检查；共用现有配置行锁。
- 自动给企业换到default会改变价格，不采用；管理员先明确选择替代组。
- 旧配置冲突时强行让标准键覆盖可能把原0.8恢复成1，保留原加载语义并要求显式保存后再绑定。
- 轮询倍率增加持续请求，采用打开/聚焦/保存这些交互节点刷新。

## Verification

SQLite回归覆盖引用组单键/组合/别名删除与大小写改名拒绝、冻结/关闭开关仍保护、未引用组可删、零倍率可改、十轮并发绑定/删除、过期缓存不能创建悬空绑定、两套旧配置冲突不改价以及配置键绕过拦截。model/service/controller/router完整测试通过，相关race复验通过。Chrome合成API验证桌面/手机选组、打开和保存后刷新、读取失败禁用与重试保留输入、迟到响应隔离；Vite构建、292篇笔记门禁及界面静态检查通过，本轮遗留测试/浏览器/构建进程为零。没有连接生产数据库或真实供应商；随后提交b984ec515的[GitHub数据库CI](https://github.com/Raymi-Labs/meta-api/actions/runs/43565710616)通过MySQL5.7/8.0.46、PostgreSQL9.6及SQLite的企业套件，并完成HTTP/计费/个人隔离检查和测试容器清理。

## Consequences

跨实例价格显示仍受原配置同步周期约束；只锁管理操作，不锁每次调用。测试fixture补齐生产已有的options/enterprise表；不修改schema。不会更改生产数据或替用户重配测试企业。
