# Agent Note: 官方分档对比缺失的匹配与说明

Status: implemented

## Problem

生产 v1.14.0 的 deepseek-flash 已有 PEAK/OFF-PEAK 官方价格，但分组表仅匹配简单输入长度边界，导致峰谷两行均没有参考价。线上数据复现还发现中文上下文标签、MiniMax Standard 文案无法匹配；其他缺来源、单位或条件冲突也被静默隐藏，用户无法判断原因。

## Decision

沿用 ModelGroupRows → groupTierRows → ModelGroupPrice、公开 pricing 与独立汇率。不改模型单价、表达式、元数据、路由或结算。精确峰谷同义标签允许对应唯一官方峰谷档，显示明确提示：这是按命名档位比较单价，生效时段以各自规则为准，不推断当前命中档位或节假日日历等价。保留本站标签，不用数组顺序配对。上下文匹配扩展中文“输入…Tokens”、英文大小写K/M和明确Standard的MiniMax折扣说明；地区、Priority、未知条件、重复来源保持不自动选择。

缺官方来源、单位不一致、条件未匹配在每组/每行说明一次；已有匹配但缺分项/TTL、汇率或币种不可比时在该分项解释，原价格始终保留。信息不靠悬停才能读到，窄屏换行。

## Existing notes audit

- [逐档表](../../implemented/feature/2026-11-01-group-tier-comparison-table.md)：部分取代仅长度可匹配与静默回退，保留30m投影和不按数组顺序匹配。
- [分组官方折扣](../../implemented/feature/2026-10-30-model-group-official-discount.md)：复用独立汇率、K/M和逐项金额；保留不推断完整请求折扣的边界。
- 既有官方同步/价格校准记录不改变；本次使用公开API快照，不以生产写配置解决展示问题。

## Alternatives considered

- 将本站首档与官方首档直接比较实现简单，但DeepSeek两边顺序相反，会把峰时和谷时错配。
- 只把中文标签换成英文可绕过部分显示限制，但现有匹配器仍不识别时段，且改变计费配置没有必要。
- 解析任意计费表达式并推断所有地域/模式条件覆盖面大，但等同另建计费解释器，浏览器不应猜测未知规则。采用有限明确标签与边界；未匹配时给出原因。

## Verification

2026-11-02：公开价格快照回归覆盖 DeepSeek 峰谷逆序、Gemini 中文输入边界与 MiniMax Standard/Priority 区分。22项价格/真实React回归、6项缓存语义回归和币种/阶梯脚本通过；新增用例覆盖逐项价格、三种组倍率、USD/CNY、K/M、重复/地区/未知标签、单位、TTL与汇率失败原因。Chrome完整详情流程通过1440px与390px暗色、320px原有边界、搜索/分页/筛选、单位/币种切换及管理编辑；峰谷输入/输出/缓存官方价逐项核对，缺官方/单位冲突/地区歧义可见且本站价格保留，页面无整体横向溢出。17种语言资源、ESLint与完整前端构建（图片子应用和五页Chrome预渲染）通过。仅使用隔离浏览器合成API响应，未发送真实模型请求或写入生产配置。

## Consequences

峰谷标签对应不表示生效时间相同，页面必须保留说明；未知公式不自动估计折扣。部分型号仍不能可靠比较，显示原因比给出虚假折扣更准确。发布与生产验收分开记录。
