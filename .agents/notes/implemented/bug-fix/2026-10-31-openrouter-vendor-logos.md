# Agent Note: 补齐 OpenRouter 厂商 Logo

Status: implemented

## Problem

OpenRouter 接入后的生产厂商表多数未填写 icon，模型广场供应商筛选直接显示空图标；Inception、Z.AI 等字段有名称但当前图标包不支持，只显示首字母。用户要求修复当前生产展示。

## Decision

沿用供应商 icon 字段、管理员 CRUD、公开 pricing 与共用 getLobeHubIcon/providerIcons 解析链。已有图标使用已打包品牌组件，未收录品牌从公开图标项目或上游目录核对真实标志并纳入本地资源；运行时只解析固定注册的资源，不开放任意 URL 或 SVG 字符串。供应商图标字段通过管理 API 补齐，保留品牌归属、描述、模型路由和价格。真实名称对应的 Logo 同时覆盖筛选、目录卡片和详情等既有入口。

新增资源与当前依赖分离，避免只为厂商 Logo 整体升级图标库。小尺寸、亮暗主题及不同入口使用一致的可见尺寸与回退策略。无品牌身份的“未知供应商”不冒用其他厂商 Logo。

## Existing notes audit

- [图标兼容与厂商回退](../../implemented/bug-fix/2026-10-31-model-icon-fallback.md)：部分重叠，复用解析和回退，不改变显式图标优先级及小米配色。
- [OpenRouter 接入](../../implemented/feature/2026-10-31-openrouter-vendor-onboarding.md)：部分重叠，修复导入中缺失的展示字段，不改变接入范围或计费。
- [Inception 厂商分类](../../implemented/feature/2026-10-21-inception-vendor.md)：补充真实图标，替代当时因依赖缺失而使用的首字母展示；分类与协议边界保持不变。

## Alternatives considered

- 仅填写已有图标名称最快，能修复部分主流厂商，但当前库没有很多新厂商品牌，仍会留下空白或首字母。
- 整体升级图标依赖能一次获得更多品牌，但跨多个主版本会改变全站图标组件和构建范围；只补充缺失的本地品牌资源。
- 直接热链上游图片无需打包，但图标可用性受第三方请求和用户网络影响；采用有来源记录的本地资源。

## Verification

45 条映射覆盖 43 个空字段以及 Inception、Z.AI 两个无法解析的标识。11 个新品牌单色组件按 MIT 许可从 @lobehub/icons 6.13.0 单独纳入，Meituan 复用现有 Simple Icons，19 份图像使用有来源和校验和的本地资源。

注册表 4 项测试和目录筛选 9 项测试通过；36 项语言检查在本机延长超时到 60 秒后通过（首次默认 5 秒因负载超时）。生图子应用和主站生产构建通过；预渲染按既有规则因本机无 /usr/bin/chromium 跳过。CUA 浏览器检查 45 个 Logo 无空白、无失败图片，亮暗主题均可见；Inception 厂商筛选、模型卡片、详情和 390px 手机详情验证通过。发布和生产更新单独记录，配置写入不得先于新图标资源可用。

## Consequences

品牌资源属于各自权利人，保留公开来源和许可说明，不将自创符号当成官方标志。并行发布可能更新主线与版本号，发布前核对最新标签；生产部署只使用受保护入口，现有服务在备份与预检期间保持在线。
