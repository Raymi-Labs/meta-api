# Agent Note: 现金页面解除凭证依赖并读取真实运营数据

Status: implemented

## Problem

线上v1.31.2已部署，现金绑定/上游账单/到账凭证均为0，已有1197718条cash usages且近7天757532条消费日志。上次只移除了核对UI，报表仍读取依赖绑定/凭证的财务计算，因而展示空值。合成测试提供了完整报告，未覆盖生产的无凭证状态。

## Decision

日常cash/report快照改用独立运营数据生成器：官方credits/activity/keys，自动匹配完全属于当前账户的渠道；消费日志直接在数据库按渠道/本站模型/UTC日聚合，不受现金启用、绑定、凭证或5万条明细上限限制。现金收益标签显示本站额度与请求、上游支出，现金流显示官方累计购入额度、累计消费、余额；明确USD和额度不可相减成现金利润，累计购入credits不冒充含手续费现金实付。旧GetCashReport/账本维护保留，不自动核实或修改数据。维持后台预热/5分钟刷新，远端与本地独立报错，不将未知显示为0；查询超官方30日范围时上游区间金额未知。本地消费统计沿用当前密钥归属和留存日志边界。

## Existing notes audit

[快照与移除核对](../../implemented/feature/2026-11-15-cash-report-snapshots.md)部分取代：保留调度，替换日常报告源。原现金账本仍负责既有审计。[模型消耗](../../implemented/feature/2026-11-12-openrouter-model-consumption.md)复用自动归属口径，日常表的模型为本站日志模型，不与官方模型强行对齐。

## Alternatives considered

- 自动创建凭证/启用关联：可填满旧报告但无法证明实际收付，且违背用户去掉核实的目标。
- 缓存空报告或增加重试：不能修复无绑定导致无数据的语义错误。
- 拉全量日志再汇总：沿用旧代码方便，但线上百万条规模需数据库聚合，避免明细上限和内存扫描。

## Verification

无cash表集成测试覆盖50001条消费的非空汇总、混合/外部密钥排除、日期/日志类型边界及官方分页；model/controller/router相关回归通过。SQLite测试与线上MySQL只读聚合均返回有效分组。真实Chrome覆盖无启用/核对前提、频道分页/搜索/导出、官方累计额度、两个标签共享快照、部分失败/旧值保留、账号切换和手机布局。部署前线上接口10ms成功返回快照，但channels=0、requests=0、quota=0，证明不是加载问题。Chrome闪电显示与CSV、前端构建/预渲染、Go构建、race、verify-notes及29项发布脚本回归通过。生产部署后另行回读验收。

## Consequences

当前渠道归属不代表历史归属；已清理日志不能补回。官方累计credits不是逐笔现金付款；不显示虚假的现金利润。现场部署仅通过受保护更新入口。
