# Agent Note: 数字零价与明确的健康状态

Status: implemented

## Problem

用户明确要求零价保持货币、数字和单位格式。此前把0替换为免费造成价格列格式不一致。截图中的可用率是未登录预览：useGroupHealth不请求鉴权接口，但ModelGroupRows仍把空值传入formatHealthRate，显示破折号和不能使用的下拉箭头；无样本、错误及未启用也混成同一空白。

## Decision

撤掉本站价格的免费文本映射，回到原有数字金额格式，不修改收费、倍率或官方参考价。本站价格优先顺序继续保留。

复用既有健康请求状态及真实统计，提供分组指标状态组件：未登录为可点击登录后查看，初始加载为加载中，失败可重试，管理员关闭为暂未开启，无样本为暂无统计数据，已有少量样本但无可用比例为样本不足；真实0显示0.00%。仅有效数值提供历史展开按钮，无数据不渲染空箭头。首字/完成时间和输出速度同步显示明确状态。删除分组列表顶部重复状态段，操作放到对应指标位置。沿用接口权限和统计阈值，不填造0%/100%或混入其他模型统计。

[外部可用率参考](../feature/2026-11-17-external-uptime-reference.md)补充无本站比例时的有效数据来源：精确匹配端点的24小时参考，明示参考范围与周期，仍不造本站实测；本文明确状态用于参考也不可得时。

## Existing notes audit

部分取代[本站价格优先](../../implemented/feature/2026-11-17-marketplace-site-price-first.md)的免费字样，保留本站价前置与官价区块规则。沿用[性能质量](../../implemented/bug-fix/2026-11-16-model-performance-quality.md)的有效数据和非文本指标限制；不修改后台聚合、缓存身份隔离或探测规则。

## Alternatives considered

无数据填0%会误导为全部失败，填100%会伪造可用性。只隐藏空白区仍无法说明原因；保持破折号不符合明确的用户要求。用其他分组的统计填充会越过权限和指标语义，因此采用可操作的明确状态。

## Verification

零价与付费保留同一货币和单位格式，无免费文字替代金额。未登录、加载、失败、未启用、无样本、样本不足及0%/100%都有明确非空显示；失败重试调用现有refresh，登录链接返回当前模型，只有有效比例有历史按钮；错误不显示缓存旧数值。桌面手机无横向越界，统计权限不变。相关测试及构建通过，所有自有测试进程清理。

## Consequences

没有统计数据时只能展示真实状态，不能生成实际可用率；上游无样本需等真实请求或已有后台探测。变更只在本地，不代表已发布或生产统计正常。

验收：实际组件浏览器场景覆盖未登录、加载中、请求失败与点击重试、未启用、无数据、样本不足、0%、100%、少量请求与仅探测；失败后重试计数增加并恢复真实比例。有探测可用率不虚构首字和速度。桌面与390设备宽度（浏览器有效312px）均无横向溢出。常规模型详情显示数字零价与登录入口，不再出现disabled空箭头。旧uptime回归中图表应沿用历史参考值的断言与已实现“历史缺口不填充”规则冲突，本轮更正为null，未改变运行时图表行为。

最终验证：19项价格回归和31项指标/组件回归通过；ESLint、17语种资源校验、主站与生图构建、五页预渲染、314篇笔记校验通过。10种状态浏览器检查及点击重试通过。测试页删除，浏览器临时页关闭，开发/构建/预渲染进程全部结束，遗留进程为0。
