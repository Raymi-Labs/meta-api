# Agent Note: 模型性能统计质量与适用范围

Status: implemented

## Problem

模型广场当前可能把极短或缓冲后集中返回的流式请求计算成异常高的输出速度，并将最近有效速度延续到历史空时段，导致曲线看起来像每个时段都有该速度。嵌入、重排、音频和结构化决策等模型也会进入首字/Token 速度展示，但这些协议没有可比较的聊天 Token 生成语义。

## Decision

- 流式适配器记录首个与最后一个有效文本/推理/工具输出时刻；只有首尾间隔至少250ms的成功请求才写入输出速度样本。Token 用量、可用率和首字时间仍按各自证据独立记录。
- 历史性能图只绘制该时段实际保存的指标，不把 `last_valid` 参考值复制成历史节点；卡片和分组摘要仍可沿用最近有效值，保持空数据时的可读性。
- 由模型的输出模态、端点类型和流式能力决定是否展示首字/Token 速度。嵌入、重排、音频、决策端点及明确不支持流式的模型隐藏这些指标；文本聊天模型仍展示未知而不是补零。

## Alternatives considered

### 直接给输出速度设置上限

不采用。固定上限会把真实的高吞吐模型截断成看似正常的数字，无法解决短窗口本身缺乏测量证据的问题。

### 删除所有历史参考值

不采用。卡片和分组摘要在调用稀疏时仍需要最近有效值；本次只收窄历史曲线的语义，不改变摘要和结算数据。

### 为没有聊天 Token 语义的模型填充零或复用相近模型

不采用。零值会伪装成真实性能，跨模型复用会把别名或其他协议的统计错误归属到当前模型。

## Consequences

短回答与高效模型会有更多未知速度，性能时间序列也会出现更多空档；摘要仍保留最近有效值，避免用户因稀疏调用失去所有可比较信息。首末有效事件时间受上游缓冲影响，指标是网关可观察的输出区间速度，不是 token 逐个生成的硬件计时。现有数据库中的异常样本不重写，等待查询窗口滚动；如需立即修复历史展示以外的旧数据，需另行评估迁移。
