# Agent Note: 模型介绍跟随全站语言

Status: implemented

## Problem

模型介绍同步到单一 description 后，卡片和详情始终显示同一语言；全站已有 17 种语言，界面词典无法翻译动态数据库内容。

## Decision

保留 description 原文和现有同步所有权。增加独立的内容哈希与目标语言译文缓存，后台使用既有免费 Google 翻译端点补齐全站 17 语言，不在浏览请求中调用外部服务。只处理当前目录已发布介绍，禁止读取渠道密钥或发送用户请求。模型名、数字、URL、代码和占位符保护后发送，恢复校验失败不发布译文。

原文改变即选择新哈希，旧译文不伪装成新内容；缺失时显示原文。管理员按语言修改，逐语言合并，清空恢复自动版本。手工覆盖独立存储，不被同步回写覆盖。卡片、详情、侧栏与搜索共用语言投影，不修改 API 模型 ID、价格或权限。

后台使用数据库租约单实例、持久化全局退避，固定端点、串行请求，遵守 Retry-After；重启不清除限流。网络失败不阻塞模型元数据同步或用户浏览。兼容旧数据库/表单，支持 SQLite/MySQL/PostgreSQL。

## Existing notes audit

- [自动资料默认值](../../implemented/feature/2026-10-31-model-official-defaults.md)：部分重叠；原文所有权不变，新增派生译文。
- [全站语言](../../implemented/feature/2026-10-25-site-language.md)：部分重叠；复用 17 语言偏好，扩展数据库发布内容，不翻译用户输入/模型输出。
- [模型详情](../../implemented/feature/2026-10-25-model-detail-page.md)：部分重叠；详情和目录复用同一数据。

## Alternatives considered

- 将动态介绍塞入静态界面词典成本低，但新同步内容需重新发版，不能自动维护。
- 浏览器即时翻译无需存储，但每个访客重复请求、切换延迟和限流不可控，因此使用服务端内容缓存。
- 仅同步模型库的中英日文可直接复用已有资源，但覆盖不了 17 语言，且译文可能与当前厂商原文不同版本；保留原文，统一生成同版本译文。

## Testing

- Go全量测试、介绍专项竞态检查通过；SQLite/MySQL8/PostgreSQL16验证字段迁移、人工所有权、并发语言合并与租约/冷却。
- 前端专项7例、17语言资源36例通过；Chrome使用真实页面组件逐一切换17语言，验证卡片/详情、中文搜索、390px无横向溢出、人工编辑及恢复自动；语言切换不重复请求pricing，外部请求为0。
- 前端生产构建通过；本机没有 `/usr/bin/chromium`，预渲染按现有脚本跳过，页面SSR元数据仍由后端兜底；浏览器验收使用已安装Chrome。
- 免费端点实测首次请求429后立即停止，未切换端点，不能称为在线17语言生成验证成功。GPT-6 Astra当前公开原文提供随版本校对译文，按完整内容匹配，通用后台生成由可控HTTP测试覆盖。

## Consequences

免费服务可能持续限流，因此不能承诺发布即填满生产所有模型。自动翻译存在术语质量限制；保留原文和管理员校正。新缓存表属于附加数据，不改变计费记录。原文更新使旧哈希不可达；当前不删除历史缓存，长期内容频繁更新时可另设清理策略。程序发布不部署生产，也不代表所有线上模型已经完成翻译。
