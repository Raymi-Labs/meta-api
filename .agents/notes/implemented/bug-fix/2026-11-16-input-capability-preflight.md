# Agent Note: 输入能力预检与明确失败反馈

Status: implemented

## Problem

生产排查中 Chat Completions 视频请求进入 Claude 转换后才被拒绝，Responses 进入未实现转换的适配器；文件 MIME 拒绝又在用户日志显示成通用请求错误。客户端仅看 HTTP 200 时还可能将流内失败误认成完成或断流。

## Decision

复用 distributor → service 选渠过滤 → Relay 的原有权限、分组、优先级和容量流程，排除已知不支持当前端点/输入的适配器。预检仅读取结构化内容块类型，不下载附件、不解码视频、不记录正文。指定渠道也检查，未知能力保持交给上游；透传尊重既有语义。所有候选不适配时返回明确 400 与稳定错误码，不自动改模型或扩大授权。

复用失败日志为明确视频/文件拒绝提供分类与修复提示，保留原始上游状态和管理员诊断。Responses 的最终流错误采用其原生 error 事件，不能输出成功终态；已有输出后不重试、计费/退款边界不变。补自研脚本的失败终态说明。

## Existing notes audit

- [模型能力同步](../../implemented/feature/2026-10-27-model-capability-sync.md)：相邻能力，展示数据不是渠道协议承诺，不用于拒绝或路由。
- [流交付生命周期](../../implemented/bug-fix/2026-10-24-stream-delivery-lifecycle.md)：部分重叠，复用失败终态与现有计费，不新增断流重试。
- 其余检索命中（展示筛选、资料发现、音视频生成和体验区）不持有本次输入预检决定。

## Alternatives considered

- 用目录模态全量拦截容易统一，但别名、渠道协议与元数据更新延迟会误伤有效请求，因此仅约束已知本地转换限制。
- 将所有视频转普通文件或抽帧可让部分接口接受，但会改变语义、丢失音轨且不能保证支持，因此不自动转换。
- 对所有格式错误切换渠道可掩盖部分故障，但输出后的重放存在重复执行风险，因此不扩大重试。

## Testing

service 单元测试覆盖结构化视频块、文本提及不误判、图片不误判、模型别名、AWS Nova 与 Vertex Gemini 不误挡、端点、透传和错误分类。middleware 的完整 Distribute 路径在数据库和内存缓存模式验证低优先级兼容渠道、原始正文保持、令牌白名单、指定渠道、无候选与容量候选范围；拒绝请求不会进入 Relay。controller 验证 HTTP 200 已提交后的 Responses error 事件与不重复发送上游错误，不输出成功终态。完整 Go 回归、相关竞态测试、前端构建与五页预渲染、Go 构建、发布脚本测试及 make verify-notes 通过。首次整库检查与前端构建并行导致临时嵌入资源缺失；前端完成后串行重跑全量通过。本机 iCloud 随后恢复带空格序号的生成资源副本，使普通 Go 构建卡在占位文件读取；使用仅排除这些生成副本的临时 Go overlay 完成构建，不删除用户文件，发布 CI 使用干净检出。

生产 v1.35.0 已经受保护更新入口上线，企业级受限临时令牌验证两类明确 400、未选上游与未扣费，令牌已删除；Claude/Gemini 普通完整流测试通过。[发布、过程失败恢复与生产验收](../../../../docs/channel/stream-reliability-20261116.md)保留具体证据，外部自研脚本仍未修改。

## Consequences

复用现有预检、路由和日志，避免已知不兼容请求进入上游或预扣费；增加一次仅投影内容块类型的请求扫描，不复制附件内容用于分析。错误分类不改变状态、退款和重试规则；Responses 的本地最终错误从通用 Chat envelope 改为该协议 error 事件，客户端须按协议识别失败。

未知第三方视频能力仍须上游验证，不承诺所有视频都可自动成功；HTTP 200 流错误需要客户端正确消费事件。不能凭服务器变更宣称已修好未提供源码的自研脚本。不修改数据库、渠道配置或价格，也不回填旧日志。生产部署与 Release 验收分别记录，生产部署另走受保护入口，不以测试通过代替生产验收。
