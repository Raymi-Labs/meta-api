# Agent Note: K3 流式用量保留与来源诊断

Status: implemented

## Problem

截图以缺少 cached_tokens 判定未命中，以缺少 reasoning_tokens 判定思考启用规则失败。元衡边界实测确认部分响应没有这些计数，但未取得对应供应商入站响应，不能将责任直接归于某一层。修复前本地归一存在可独立复现的边界：后续相同总量的usage快照覆盖前块细项；单choice里的思考计数未参与兼容。

## Existing capabilities and related decisions

- [用量字段保真](2026-09-29-kimi-usage-field-preservation.md)部分重叠，继续使用其真实来源、标准值优先、未知不造数和模型隔离约束。
- [用户体验实测](../testing/2026-09-29-kimi-user-experience-usage-probe.md)保留线上旧版结果。本次不追加收费测试、不声称该次缺字段由新发现的边界造成。
- [流式完整性](2026-09-29-kimi-request-stream-integrity.md)要求首块即时交付；不能为等usage而缓存完整响应。
- 复用RelayInfo和消费日志已有admin_info，不增加数据库列或管理页面；已有用户日志会删除admin_info。

## Decision

- 仅在现有K3原生Chat范围内工作，增加请求内的计数快照。后块没有对应计数、且对应输入/输出总量明确相等时，保留前块的真实计数；不累加快照。
- 当前块明确0/null/非法值、对应总量改变、响应标识改变时，不用前块覆盖当前证据。不能证明总量相等时不跨块恢复。
- [冲突一致性修复](2026-09-29-kimi-usage-conflict-consistency.md)要求源块/后块的两套对应总量都合法且相等；总量别名冲突不能作为快照依据，也不能在后续恢复旧值。输入和输出维度仍独立判断。
- 在请求不是n>1、当前只有一个choice且index为0/省略时识别其usage中的嵌套或平铺思考计数；多个choice不求和，也不把多答案流的单个分块当作全量。响应级来源始终优先。
- 在管理员日志记录缓存/思考的reported、missing、unknown或invalid状态、固定字段来源、有效计数及是否来自前块；不记录提示词、思考正文、密钥、用户标识或完整响应。
- 返回字段和内部结算使用同一归一结果；客户端关闭usage时不泄露usage。非K3模型/其他协议不受该新规则影响。
- 截图测试器没有在本仓库发现，保留其断言纠正说明；不将“字段存在”当缓存命中、不把没有计数的供应商改成伪造数字。

## Alternatives considered

- **全部缺字段补0**：输出最稳定，但把未知变成测量结果，也可能让错误的存在性断言误报通过；拒绝。
- **无条件沿用历史最大计数**：能覆盖更多供应商形状，但会把不同累计总量或不同响应的计数混合，影响真实结算；只在相同总量的明确快照间恢复。
- **记录完整供应商响应排查**：归因资料最全，但会保存用户正文、增加体积和隐私风险；本次只保存固定元数据，原文对照另行授权和脱敏。
- **自动改路由或强制选命中渠道**：可能改善一部分体验，但改变业务分配且不能保证供应商能力；本轮不修改路由。

## Verification

- 两个新增回归在修复前分别复现缓存80被尾块覆盖成0、单choice思考18漏读；修复后通过。
- 回归覆盖明确零、字段/容器null、非法与超界计数、总量变化、响应ID/模型变化、旧状态失效、多choice/n>1、usage隐藏、强制格式化和非K3隔离。
- 隔离SQLite控制器的6种字段形状×流式/非流式验证钱包、令牌、日志一致；流式额外追加只有相同总量的尾块，仍按真实缓存80扣48内部额度，明确缓存0扣120，思考不重复增加输出用量。
- 管理员日志保存值副本，后续元数据修改不改变已生成日志；普通令牌日志接口移除来源诊断。正文标记不进入元数据。
- 真实loopback HTTP/SSE验证首段正文、思考、工具输出不等待后续用量，客户端断开后handler退出。
- 全仓 `go test -p 2 -timeout 120s ./...` 通过；controller、OpenAI handler、relay/common、service的相关定向race重复2次通过。未新增生产数据库结构或SQL，不将SQLite验证当作三个数据库的部署验收。
- `go build -p 2 ./...`、`make verify-notes`、`git diff --check`通过；启动的测试/构建会话全部退出，末次进程检查没有Go构建/测试残留，本轮遗留进程为0。未推送、部署或重新发起收费模型测试。

## Consequences

保留已报告数据并给部署后的定位提供低隐私风险证据，代价是每次K3请求增加两个计数快照和少量管理员日志元数据。完全没有真实计数时仍无法保证截图变绿；missing只代表未找到可安全使用的已知来源，不能断言供应商没有任何自定义用量字段。相同总量快照之外的任意增量协议不在本规则内，不能用本地模拟通过代替供应商能力验收。详见[字段与诊断说明](../../../../docs/KIMI_USAGE_FIELDS.md)。
