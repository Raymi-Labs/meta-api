# Agent Note: 生图会话默认福利分组与 gpt-6-sol 规划

Status: implemented

## Problem

生图入口自动创建/复用临时令牌，旧候选顺序受历史 AutoGroups 影响，当前线上新令牌仍选择 OpenAI · 优质。默认规划模型 gpt-5.5 仅在企业级组可用，生图组与规划能力分离，电商模式因此不可用。用户明确要求所有新建生图会话优先使用福利分组，并将规划模型改为 gpt-6-sol；随后明确选择福利优先、失败时自动切组，仅影响生图令牌。

## Decision

复用现有分组候选、用户权限、启用渠道能力检查与会话刷新流程，在当前用户组和 AutoGroups 之前加入福利候选；继续优先选择同时支持生图和规划的有效分组。福利无权限、已移除或模型能力不足时沿用现有能力回退，不扩张用户可用分组。后端启动参数及前端电商默认规划模型统一为 gpt-6-sol，提示与 17 语言资源同步。创建及刷新均启用已有 auto_group_fallback；备用组按全局 AutoGroups 中当前用户可用的顺序路由，遵守模型、渠道权限及重试预算，按实际组计费。刷新时清除会覆盖该规则的自定义 routing_config 和旧 auto 专用 cross_group_retry。已有临时令牌在重新进入会话时按原流程刷新；不批量修改旧令牌、不更改全局 AutoGroups 或计价。

活跃笔记检索：Playground 账户存储隔离笔记属于聊天工作台，与本次图片工作台无关；单 Key 多模型分组笔记是曾考虑的复用方案，保留原决定；没有本次默认选组规则的活跃归属。

## Alternatives considered

- 只改某个令牌：操作小，但下次会话刷新会覆盖，无法满足所有新会话。
- 调整全局 AutoGroups：无需代码改动，但会影响其他令牌的自动路由，不符合本次范围。
- 生图与规划按模型拆组：能处理 gpt-5.5 仅在企业级的现状，但用户选择的福利组已有启用的 gpt-image-2 与 gpt-6-sol 渠道，继续使用单组更简单。
- 增加独立管理员路由设置：便于后续自由配置，但本次只要求明确默认值，现有候选/权限/能力回退足够，不扩展设置界面。

## Verification

相关控制器、服务及中间件定向 Go 回归通过，覆盖新建/复用令牌、双模型选渠失败后回退、旧路由清理、Key/过期时间保持，以及无权限、已移除、禁用渠道边界。图片子应用 192 项测试通过，新增测试检查真正发出的规划 Responses 请求采用 gpt-6-sol，生图 profile 保持不变。主站及生图 TypeScript/Vite 构建、17 语言校验通过；显式指定本机 Chrome 后五个公开页面预渲染通过；静态产物门禁、Go 构建、make verify-notes 及发布策略检查通过。

## Consequences

福利的当前分组倍率为 0.6，默认选组和失败切组均按实际所选组的既有倍率计费；不会改写价格或历史账单。复用首选组回退机制，因此令牌首选组字段仍是福利，自动回退开关开启，而不是把它设为不含福利的全局 auto。备用组受当前 AutoGroups 配置影响。

GORM 数据结构和迁移不变，数据库执行回归使用 SQLite；未声明 MySQL/PostgreSQL 实机验收。单元测试和只读渠道核对不能替代真实供应商调用；本轮不发付费模型请求，不隐式部署生产。
