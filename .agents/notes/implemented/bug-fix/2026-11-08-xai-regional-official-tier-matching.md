# Agent Note: xAI 地区官方档位与本站阶梯匹配

Status: implemented

## Problem

xAI 官方模型页会为同一模型按地区输出多组价格。`grok-4.7` 的官方快照包含 `us-east-1`、`us-west-2` 和 `us-central-1`，而本站分组表达式只描述输入上下文阈值，没有地区条件。原有匹配器要求官方标签直接以 `Standard` 或输入边界开头，因此带有地区前缀的官方档位被全部判定为“尚未匹配”。

## Existing notes audit

- [官方分档对比缺失的匹配与说明](2026-11-02-official-tier-matching.md)：继续保留未知地区、未知条件不自动推断的边界；本笔记补充 xAI 官方页面默认地区的确定性选择。
- [官方参考价缺失盘点与条件价格解析](2026-11-01-official-pricing-coverage.md)：同步仍完整保留官方地区档位，本次只修复详情页分组对比匹配。

## Decision

当本站只有长度条件、官方档位标签带地区前缀时，使用官方快照首个地区作为官方页面默认地区，并只在该地区内匹配相同的上下文边界。其他地区继续显示在官方参考价表中，不与默认地区混配，也不从本站分组名或渠道名猜测地区。

## Alternatives considered

- 将所有地区的同条件档位合并为一个价格：会丢失地区差异，导致官方对比金额不确定。
- 直接取所有地区中的最低价或第一条匹配价：最低价没有业务依据，跨地区第一条也会绕过默认地区语义。
- 继续显示未匹配：不会产生错误价格，但会把已知的官方档位误报为缺失，`grok-4.7` 的分组价格无法提供对比。

## Verification

- 前端回归覆盖 `grok-4.7` 的多地区官方 tier，确认两档长度条件匹配到 `us-east-1` 默认地区，且不会选中 `us-central-1` 的不同价格。
- 运行前端相关测试、格式检查和生产构建；线上生产页面仍需在部署后重新读取 `/api/pricing` 并浏览器验收。

## Consequences

`grok-4.7` 的详情分组价格可以显示官方档位对比；地区差异仍在官方参考价表中可见。若未来本站需要按地区路由或按地区计费，必须把地区作为显式模型/分组条件扩展，不能继续依赖默认地区选择。
