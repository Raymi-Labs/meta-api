# Agent Note: 模型广场厂商切换与默认版本顺序

Status: implemented

## Problem

用户切换到新厂商后仍受旧厂商专属分组过滤而看到空表；每次选组都会叠加通知遮挡内容。原模型名称升序也不便于找到较新版本。

## Decision

主动切换厂商时以完整可见模型的 vendor_name、enable_groups 及 usable_group 判断旧组是否适用；适用则保留，否则同时清空筛选组与价格组到 all。点击同厂商、搜索空结果及刷新不触发自动选组。移除选组成功通知，保留内联价格口径与错误提示。

默认使用名称中的自然版本降序，同系列内按数值比较而非字符串比较；无版本名不虚构日期，按稳定名称顺序处理。保留旧默认顺序和价格排序选项，菜单明确“版本从新到旧”而非官方发布时间。现有 /pricing 没有发布时间，Model.CreatedTime 是后台录入时间，不用于伪装发布日期。

厂商顺序为 Anthropic、OpenAI、DeepSeek、Google、Moonshot、xAI，别名同排名但不合并身份，剩余名称稳定排序；全部最前、未知最后。右侧加回使用现有 cover-4.webp 的紧凑蓝色标题条，普通文本和价格区域维持纯色。

## Alternatives considered

- 保留旧不适用组可避免改变价格上下文，但用户反馈证实跨厂商浏览易陷入空表，故仅在主动切厂商时明确重置到全部。
- 总是清空分组实现简单，但会丢失仍适用的跨厂商组，故按真实模型关系判断。
- 以数据库创建/更新时间降序有时间依据，但属于后台录入或编辑时间，不代表模型发布；当前采用明确标注的版本顺序，未来有官方日期字段再扩展。

## Verification

`pricing-vendor-selection.test.mjs` 覆盖专属组清空、共享/零倍率保留、未知/全部厂商、权限交集、厂商别名排名和版本自然降序/稳定性/不修改输入。`upstream-optimizations.test.mjs` 验证原价格排序及分组/时段计算。

`pricing-filter-browser.test.mjs` 与 `pricing-wallet-layout.browser.mjs` 覆盖桌面/手机实际筛选入口、切厂商后模型与价格同步、重置、搜索空结果保持分组、无选组通知、版本顺序与厂商顺序、健康及钱包流程。截图使用合成数据目视检查紧凑蓝色标题条；测试进程在 finally 关闭。

## Consequences

版本排序不能代表跨系列的官方发布时间；不解析任意别名背后的真实模型。修改只作用于浏览筛选和展示，不改变令牌、渠道或扣费。

不适用旧分组自动回到全部后，各模型显示最低适用倍率参考价，内联文字持续说明该口径，用户可再选择具体分组。重置事件中不将原分组重新写回：只有切厂商计算出的分组确实变化时才写组状态。所有高级筛选仍由用户控制，不因空搜索而悄悄清除。
