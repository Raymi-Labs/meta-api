# Agent Note: 看板使用统一结算日志口径

Status: implemented

## Problem

小时 quota_data 只累加 prompt + completion，漏掉 non_cache 口径的缓存用量。金额包含缓存费用却用不完整分母计算综合单价。任意秒级时段用整点过滤小时桶，缓存率又独立扫描日志，产生范围和时效差异。按次费用混入单价，异步任务退款与补扣没有同步小时表，内存汇总写失败无可靠重试。

## Decision

概览 data 接口复用保留的 consume/refund 日志、既有 prompt 语义解析，以单次有界扫描生成同一快照的卡片和图表；精确半开区间过滤后才分小时展示。金额按事件发生时间记消费减退款，任务差额不增请求次数。完整 Token 与单价分母分开：综合单价只纳入有明确 Token 计费证据的金额与用量，未知口径显示限制。退款可使净消费为负。缓存率使用同一批 Token 请求的输入。

保留旧小时表及其写入用于兼容；概览不再依赖其落库、重试或历史重算，从源日志重新读取不重复扣款、不改余额。所有历史结果明确限于保留日志，不声称证明日志完整。统计有超时、扫描行数、桶数量和并发上限，超限报错而非抽样；新前端拒绝没有统一 summary 的旧响应。

## Existing capabilities and notes audit

- [五项指标](../../implemented/feature/2026-10-30-dashboard-five-metrics.md)的布局、角色隔离、币种和请求版本保护继续保留；独立缓存请求与旧小时数据来源由本篇取代。
- [概览状态](../../implemented/feature/2026-10-27-dashboard-overview.md)保留筛选草稿、空/失败状态、图表和快捷范围；后台按精确范围过滤。
- [模型目录指标](../../implemented/feature/2026-10-25-model-catalog-metrics.md)有独立统计入口，本篇不更改其产品规则。
- 现有 model/log.go 已有 non_cache/inclusive/历史 Claude 解释，不新造按模型名判断规则。

## Alternatives considered

- 给小时表补缓存字段并重算，可保持长周期查询速度，但无法恢复任意秒级边界、未写成功的缓冲和退款；需要额外事件游标与幂等迁移。本轮采用现有日志为来源，若扫描规模超过保护上限，后续独立建设可重放的统计投影。
- 只修前端分母变更最少，但小时表没有缓存明细，也无法解决数据快照、异步差额和非 Token 费用，不采用。

## Verification

Go 回归验证 Claude 缓存只计一次、OpenAI 不重复加、缓存-only、分 TTL、未知/损坏用量、按次和按时长排除、负净消费、任务补扣/退款不增请求、秒级边界、权限/精确用户过滤、超限/取消不返回部分结果。模型与 controller 使用 SQLite 隔离数据库并通过 race；service 相关结算回归通过。截图 221 条样本复算为 27,082,015 Token、184.9463 闪电、6.8291 闪电/M。

前端单元与组件回归、主站 Vite 构建通过。隔离静态站与模拟 API 的桌面普通用户、390px 管理员页面验证统一请求、金额与用量、负净消费、未知口径、旧接口拒绝及错误状态，所有外部请求被拦截；不访问生产账号或付费模型。验收脚本位于 web/scripts/dashboard-settlement.browser.mjs，浏览器和本地服务器在 finally 关闭。

## Consequences

日志扫描成本高于小时表，采用20秒查询时限、每实例2个并发、100万行/25000桶上限及15秒整份快照缓存，缓存键包含精确秒级范围和认证范围。管理员超过31天、普通用户超过30天均拒绝；超限必须缩短周期或指定用户，不能抽样伪装全量。更大规模报表需要独立的可重放统计投影，不能通过无界扫描解决。

清理过的日志无法恢复，页面常驻说明仅统计保留日志；旧小时表不删除、不重算，概览和用户排行不再依赖其异步写入可靠性。其他专项报表保留各自既有口径，不能宣称所有报表都统一为净消费。不得用当前价格倒算历史费用。数据库查询沿用跨引擎 GORM，但本轮没有 MySQL/PostgreSQL 实机验收或生产压测；上线前需核实索引与长周期负载。仅新增日志计费单位标记，不改变报价、余额、结算、权限或数据库 schema。
