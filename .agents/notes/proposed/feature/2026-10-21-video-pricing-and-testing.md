# Agent Note: 通用视频模型定价与异步测试

Status: proposed

## Problem

视频模型需要按秒、分辨率和生成方式报价，用户计划逐步接入字节、快手可灵、MiniMax 等厂商。现有后台与模型广场主要沿用文本按量、按次和音频小时价格，视频请求已经能够进入部分任务适配器，但配置、报价、测试和实际结算没有形成统一流程。

本轮范围是能力审计与实施设计；不修改生产价格、渠道、余额，不发起付费生成，不将本提案标记为已实现。截图中的金额仅是用户提供的展示样例，不是已确认的本站售价或厂商成本。

## Existing capabilities and evidence

- `router/video-router.go` 已提供 `/v1/videos`、`/v1/video/generations` 的提交和查询，以及可灵、即梦的部分原生入口。截图中的 `/alibailian/api/v1/services/aigc/video-generation/video-synthesis` 不是本站现有路由。
- `relay/relay_adaptor.go` 已注册 Ali、Kling、Doubao/VolcEngine、MiniMax/Hailuo、Sora、Gemini/Vertex、Vidu 和 xAI 的任务适配器。已有适配器不代表已覆盖各厂商最新模型、参数或实际账户权限。
- `relay/relay_task.go` 复用鉴权、分组、渠道映射、预扣与任务记录；`service/task_polling.go` 提供后台轮询、终态处理和退款；`model/task.go` 已有任务私有计费快照。
- `relay/helper/price.go` 的任务表达式可读请求参数；非表达式路径由部分适配器提供时长、分辨率倍率。未命中模型价格时仍有通用默认价格回退；新的明确视频定价模式应拒绝未配置档位，不能静默套用该回退。
- `controller/relay.go` 将表达式任务标记为 `PerCallBilling`，现有轮询结算会跳过用量调整。表达式按请求参数估价不能直接当成按实际视频 Token 结算。
- `model/pricing.go` 普通价格只区分 Token、按次、音频时长；模型广场没有结构化视频档位，表达式展示也主要围绕文本 Token。
- `ModelTestModal.jsx` 下拉未提供视频端点；`controller/channel-test.go` 已能对部分视频模型发起真实上游请求，但固定为 1 秒、480p，且只处理提交响应。可灵、即梦、豆包视频、Vidu 等类型被明确排除；已有视频测试没有走正式任务持久化与完整轮询流程。
- 2026-10-21 01:37（北京时间）公开 `/api/pricing` 返回 `grok-imagine-video` 的分辨率/时长表达式；`grok-imagine-video-1.5` 没有返回专用视频计价规则。公开列表未出现 HappyHorse；这不证明管理员隐藏模型或所有渠道均无相关配置。

活跃笔记审计：[Vidu 计价字段保真](../../implemented/bug-fix/2026-10-17-vidu-billed-fields.md)部分重叠于出站参数和计价一致性，保留原决定；[Claude 缓存计费一致性](../../implemented/bug-fix/2026-10-08-claude-cache-billing-consistency.md)只复用展示与结算同源原则，不迁移其 Token 语义。Kimi 的视频理解笔记与视频生成任务不同，无需合并。

## Proposal

### 1. 模型能力与价格分别配置

在现有模型管理、价格编辑器和任务适配器上扩展，不另建一套渠道或钱包系统。

为每个具体模型声明视频能力：协议适配器、文生/图生/参考生/编辑模式、允许的时长、分辨率、宽高比、画质、音频开关和输入素材要求。按完整模型标识匹配，保留映射后的上游模型，未知新版本不自动继承旧版本全部能力。

能力中的参数约束与管理员售价分开。能力不包含渠道密钥或成本；公共输出仍遵守可见模型与可用分组，不能用能力声明绕过令牌限制。

### 2. 统一视频价格规则

增加结构化的视频定价配置及对应编辑表格，复用现有 option 存储、JSON 包装、分组/用户分组倍率、时段倍率和金额换算。规则支持：

| 单位 | 规则维度 | 计算方式 |
| --- | --- | --- |
| 输出秒 | 分辨率、生成模式、画质、有声/无声 | 对应档位单价 × 计费秒数 |
| 固定任务 | 分辨率、生成模式、固定时长档位 | 如 5 秒、10 秒各自定价，不强制线性折算 |
| 视频 Token | 用量种类、分辨率、输入素材模式 | 可信最终用量 × 对应单价，预估与实际分开 |
| 组合费用 | 输入视频秒、输出秒、额外素材或固定附加费 | 各明确分项相加，再应用适用倍率 |

首期实现按输出秒和固定任务档位，契约同时保留实际用量结算能力；视频 Token/组合费用只有对应适配器完成验收后才允许启用，不能只有配置选项没有结算支持。

显式配置计费步长、进位方式、最低费用和零价格，区分未配置与免费。基础金额复用后台现有计价币种，前端按站点设置换算显示；不把截图人民币价格直接写入美元价格字段。不同分组的最终价格来自既有倍率，不在页面维护第二份价格表。

`/api/pricing` 增加只读视频价格与能力描述，模型广场卡片、表格、详情、筛选和排序共同消费。复杂或无法推导的旧表达式保留“动态计费”，不得猜出一个零价或错误的每秒价。新规则只对明确迁移的模型启用，保留旧 `ModelPrice`、表达式和历史任务行为；旧客户端对新计费模式的回退展示必须单独验收。

### 3. 计价参数与最终请求一致

后台先规范化并校验请求，再同时生成出站载荷和计价输入。`duration`/`seconds`、`resolution`/`size`、metadata 覆盖、供应商默认值与模型映射不能在报价后悄悄改变收费条件。

报价接口和提交接口复用同一个后台计算器；前端只展示。报价标明模型、档位、时长、单位、分组/时段倍率、配置版本、估价及有效时间。提交重新校验权限、版本和参数，过期报价不能静默按新价格扣费。

任务保存规则版本、价格/倍率、有效参数、估计额度和用量来源快照。请求确定的秒数或任务档位按快照结算；需实际用量的模型在终态读取可信用量后调账，不能使用旧的表达式按次短路。缺少用量进入待核对状态，不能把缺失当零。价格变更不改写已提交任务，旧任务继续按旧快照处理。

沿用现有结算与退款组件，但验收重复轮询、进程重启、终态并发、钱包/订阅/令牌额度与日志一致性。短暂查询错误或前端等待超时只表示未确认结果；异步提交响应不确定时不盲目重发，避免产生多个付费任务。报价预留范围不足及上游终态缺用量时需提供可审计的人工处理入口。

### 4. 两种测试方式

- **预检与估价**：不调用生成上游，检查价格是否完整、参数组合、素材要求、模型/分组/令牌权限，展示实际出站参数摘要与预计费用。不能把预检通过标记为上游可用。
- **真实生成测试**：使用明确的测试账户/令牌及正常计费流程，管理员可在授权范围内固定渠道；普通用户不能指定未授权渠道。先展示费用和计费主体，再以显式 POST 提交一次，默认选择该模型允许的最低成本组合，不能统一使用 1 秒/480p。

真实测试复用正式任务记录和轮询链路，展示“已受理、排队、生成中、成功、失败、待核对”。只有终态成功且获得结果才标记生成成功，展示播放/下载、任务 ID、耗时、请求 ID、预估与实际费用。关闭窗口停止前端等待，不取消后台对账；支持重新进入后查看结果。

全渠道批量测试、定时连通性测试默认排除付费视频生成。需要视频测试时显式选择模型/数量及预算上限；查询超时不得自动重新生成。已有渠道测试“提交成功”应单独标识，不能混同于完整生成通过。

### 5. 分阶段接入

1. 通用能力/定价配置、报价与模型广场展示，先用线上已有 Grok 配置和离线夹具证明兼容，人工选择迁移，不自动重写生产表达式。
2. 完整视频测试和任务结算闭环，再按用户优先级逐一补齐字节、可灵、MiniMax 的明确模型版本；每家单独核对协议与参数，不以厂商名称宣称全系列支持。
3. 在同一框架接入 HappyHorse、万相、Vidu、Veo 等，扩展参考视频、视频编辑、声音等组合费用。

## Alternatives considered

- **只增加“按秒”标签和价格表**：实现小、截图效果快；但显示价格可能与真实扣费不一致，测试仍只提交任务，无法支持未来多厂商，故不采用。
- **继续全部手写表达式**：已有引擎灵活，短期可表达按秒/档位；但难以自动生成可靠表格和参数表单，现有异步表达式又跳过实际用量调整。保留为高级模式，不作为视频的默认配置方式。
- **每家独立页面和收费逻辑**：最容易完整呈现一家厂商特性；但会复制报价、退款、权限和测试流程。保留厂商适配器差异，共用计价与任务生命周期。
- **统一强制所有视频按秒收费**：用户容易理解；但会误表达固定档位、实际 Token 和输入素材成本。站点可自主设置按秒售价，但必须将售价规则与供应商实际用量/成本区分。

## Acceptance criteria

- 配置、预览、保存重开、公开卡片/表格/详情、真实消费日志对同一组参数的金额一致；覆盖零价、缺价、档位缺失、币种、分组/用户倍率及时段变化。
- 按秒和固定时长档位覆盖文生/图生模式；不支持的分辨率/时长/素材组合在发出请求前失败。支持字段别名、映射和 metadata 冲突回归。
- 各厂商模拟服务覆盖提交受理后成功、业务失败、查询暂时失败、缺用量、重复终态、结果过期、关闭窗口重开，以及提交结果不确定时不重复生成。
- 每个已启用实际用量模型验证估价、实际结算、退款、重启恢复及并发幂等；钱包、订阅、令牌额度与审计记录相符。
- 权限覆盖管理员固定渠道、普通用户仅本人任务、模型/分组/令牌限制；公开能力和结果不泄漏上游密钥、私有任务 ID 或其他用户素材。
- 浏览器验收价格编辑、模型广场、测试任务和日志关联入口，覆盖窄屏、暗色、失败和旧配置；中文及现有国际化语言完整。
- 执行 `make verify-notes`、相关 Go/Bun 回归及前端构建；配置持久化与状态更新覆盖 SQLite/MySQL/PostgreSQL。模拟成功不替代具体渠道的真实验收，发布不等于生产部署。

## Risks

通用规则增加了维护能力资料和迁移旧表达式的成本，但能使售价、实际扣费与用户展示共用同一来源。不能根据任意表达式、模型名称或营销描述自动认定支持全部参数。实际模型版本、上游协议、素材上传方式、本站售价和测试预算须在具体接入时确定。

现有任务超时退款、提交后持久化失败、结算幂等和超出预估额度的处理需要随实现检查，不能仅新增表单就宣称资金闭环完成。真实调用会产生上游费用；本次没有调用，不能声称任何新增厂商已接入生产。
